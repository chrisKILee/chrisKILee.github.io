Claude Code vs. Codex

CLAUDE.md 중심의 메모리·스킬·에이전트 생태계 vs AGENTS.md 중심의 범용 에이전트 구성. 구조 비교부터 같은 저장소에서 두 도구를 교차 사용하는 세팅 방법까지 정리합니다.

한 줄 핵심

Claude Code = CLAUDE.md 중심의 Claude 전용 확장 구조  /  Codex = AGENTS.md 중심의 범용 에이전트 공통 구조

둘을 같은 저장소에서 함께 쓸 수 있습니다. AGENTS.md를 canonical로 두고 CLAUDE.md에서 참조하거나, 파일을 분리해서 독립 관리하는 두 가지 전략이 있습니다.

TOOL A

Claude Code

Anthropic · CLI + IDE 확장 · 2025~

CLAUDE.md를 프로젝트 메모리로 삼아, 스킬·서브에이전트·MCP 서버를 Claude 생태계 안에서 통합 관리한다. "역할 기반 전문가 에이전트" 느낌.

  • 기본 지시CLAUDE.md
  • 전역 설정~/.claude/CLAUDE.md
  • 스킬 경로~/.claude/skills/ · .claude/skills/
  • 서브에이전트.claude/agents/ (마크다운)
  • 설정 파일.claude/settings.json
  • 스킬 호출/skill-name 또는 자동 매칭
  • 하위 디렉터리파일 접근 시 온디맨드 로드
TOOL B

Codex CLI

OpenAI · CLI · 2025~

AGENTS.md를 기본 프로젝트 지시로 삼고, 하위 디렉터리까지 지시 체인을 구성한다. Open Agent Skills 표준에 맞춘 범용 구조. "병렬 spawn 분해" 중심.

  • 기본 지시AGENTS.md · AGENTS.override.md
  • 전역 설정~/.codex/AGENTS.md
  • 스킬 경로~/.agents/skills/ · .agents/skills/ · /etc/codex/skills
  • 서브에이전트.codex/agents/*.toml (TOML)
  • 설정 파일~/.codex/config.toml
  • 스킬 호출$skill-name · /skills · 자동 매칭
  • 하위 디렉터리현재 디렉터리까지 체인 구성 (32KiB 제한)

교차 사용 세팅 가이드

⚠️
먼저 읽어야 할 핵심 원칙 같은 저장소에서 두 도구를 동시에(같은 파일을 동시에) 실행하면 충돌합니다. "한 번에 한 도구만" 원칙을 지키면 파일 구조만 잘 정리해도 대부분 문제없이 교차 사용할 수 있습니다.

  1. 지시 파일 분리 or 공유 전략 선택

    두 가지 방법 중 하나를 선택합니다.

    방법 A — 파일 분리 (가장 단순, 권장)

    repo-root/
    ├── CLAUDE.md     # Claude Code 전용 지시
├── AGENTS.md     # Codex 전용 지시 (별도 작성)
└── ...

    장점: 각 도구에 맞게 최적화 가능. 단점: 공통 내용 동기화 부담.

    방법 B — AGENTS.md canonical + CLAUDE.md 참조 (DRY)

    CLAUDE.md
    # @AGENTS.md 로 공통 지시 참조 (Claude Code import 문법)
@AGENTS.md

# Claude 전용 추가 지시
## Claude-Specific Rules
- hooks: settings.json 기준
- 스킬 경로: .claude/skills/
...
    ℹ️
    Claude Code의 @import 문법은 공식 문서에 명시되어 있으나 정확한 구문은 버전별로 다를 수 있습니다. 실제 사용 전 claude --version 버전과 릴리즈 노트 확인 권장.

  2. 디렉터리 구조 세팅

    설정·스킬·에이전트 경로가 완전히 분리되어 있으므로 파일 충돌은 없습니다. 아래 구조를 그대로 사용하면 됩니다.

    repo-root/
    ├── CLAUDE.md                  # Claude Code 지시
├── AGENTS.md                  # Codex 지시
│
├── .claude/                   # Claude Code 전용
│   ├── settings.json          # 권한, 모델, hooks
│   ├── settings.local.json    # 개인 로컬 (.gitignore)
│   ├── agents/                # 서브에이전트 (.md)
│   │   ├── reviewer.md
│   │   └── architect.md
│   └── skills/                # 프로젝트 스킬
│
├── .agents/                   # Codex 전용
│   ├── skills/                # Codex 스킬
│   └── ...
│
├── .codex/                    # Codex 설정 (신뢰 프로젝트)
│   ├── config.toml
│   └── agents/                # Codex 에이전트 (.toml)
│       └── codex-reviewer.toml
│
└── .mcp.json                  # Claude Code MCP 서버

  3. .gitignore 설정 — 런타임 파일 배제

    두 도구가 생성하는 세션 캐시·로그를 각각 gitignore에 추가합니다.

    .gitignore
    # ── Claude Code 런타임 (커밋 불필요) ──
.claude/projects/
.claude/file-history/
.claude/debug/
.claude/todos/
.claude/tasks/
.claude/session-env/
.claude/cache/
.claude/history.jsonl
.claude/settings.local.json  # 개인 로컬 오버라이드
.claude.json                 # OAuth 상태 (개인)

# ── Codex 런타임 (커밋 불필요) ──
.codex/history.jsonl
.codex/sessions/
.codex/cache/
.agents/history.jsonl
.agents/sessions/

# ── 공통 ──
.env
.env.local
*.log
    ✅
    커밋해야 할 것 vs 말아야 할 것 CLAUDE.md, AGENTS.md, .claude/settings.json, .claude/agents/, .claude/skills/, .codex/config.toml, .codex/agents/ → 팀 공유를 위해 커밋 OK.
    settings.local.json, .claude.json, history.jsonl → 개인/런타임, gitignore.

  4. 스킬 이름 충돌 방지

    두 도구가 각자의 경로에서 스킬을 검색하므로 기본적으로 충돌하지 않습니다. 단, 스킬 이름을 도구별로 구분하면 디버깅이 더 쉽습니다.

    .claude/skills/
    claude-review/SKILL.md     # Claude Code 전용
claude-deploy/SKILL.md
    .agents/skills/
    codex-review/SKILL.md      # Codex 전용
codex-test/SKILL.md

    공통으로 쓰는 절차라면 SKILL.md 내용을 복사하거나, AGENTS.md/CLAUDE.md에 직접 인라인으로 작성하는 방법도 있습니다.

  5. 동시 실행 충돌 방지 — Git 워크트리 활용

    두 도구를 동시에 같은 파일에서 실행하면 충돌합니다. 아래 두 방법을 권장합니다.

    방법 1 — 한 번에 하나씩 (가장 단순)

    bash
    # Claude Code 작업
claude

# 완료 후 Codex로 전환 (같은 저장소)
codex

    방법 2 — Git 워크트리로 분리 실행

    bash
    # Claude Code용 워크트리
git worktree add ../my-project-claude feature/claude-work
cd ../my-project-claude
claude

# Codex용 워크트리 (다른 터미널)
git worktree add ../my-project-codex feature/codex-work
cd ../my-project-codex
codex
    ✅
    워크트리 방식은 같은 저장소를 두 위치에서 독립적으로 체크아웃합니다. 각 도구가 다른 브랜치·디렉터리에서 동작하므로 파일 충돌이 없습니다.

  6. 환경 변수 충돌 방지

    두 도구가 같은 이름의 환경 변수를 사용하면 덮어쓸 수 있습니다. 도구별 prefix를 붙이세요.

    ~/.codex/config.toml
    [env]
CODEX_MODEL = "gpt-4o"
CODEX_DEBUG = "true"
    ~/.claude/settings.json
    {
  "env": {
    "CLAUDE_MODEL": "claude-sonnet-4-6"
  }
}

교차 사용 체크리스트

초기 설정 공통

  • CLAUDE.md와 AGENTS.md 양쪽 모두 repo root에 생성
  • .claude/settings.json과 .codex/config.toml 분리 생성
  • .gitignore에 양쪽 런타임 파일 추가 (위 4단계 참고)
  • 스킬 이름에 도구 prefix 부여 (claude-* / codex-*)

Claude Code 전용 Claude

  • .claude/agents/*.md에 서브에이전트 정의
  • .mcp.json에 MCP 서버 등록
  • .claude/settings.json에 hooks / 권한 설정
  • CLAUDE.md에서 @AGENTS.md import (공통 지시 공유 시)

Codex 전용 Codex

  • .codex/agents/*.toml에 서브에이전트 정의
  • ~/.codex/config.toml에 전역 모델·권한 설정
  • AGENTS.md 최상위에 공통 지시 작성 (32KiB 제한 주의)
  • 하위 디렉터리에 디렉터리별 AGENTS.md 배치 (지시 체인)

일일 운영 공통

  • 한 번에 한 도구만 실행 (동일 파일 동시 편집 금지)
  • 동시 사용 필요 시 Git 워크트리로 분리
  • CLAUDE.md와 AGENTS.md 공통 내용 주기적 동기화
  • 환경 변수 충돌 모니터링 (CODEX_* vs CLAUDE_*)
