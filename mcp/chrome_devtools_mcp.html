01 배경

기존 에이전트의 한계

코딩 에이전트는 코드를 수정해도 브라우저 결과를 스스로 확인할 수 없었습니다. "생성하고 기도하는" 방식이었죠. Chrome DevTools MCP가 이 문제를 해결합니다.

이전
  • 코드 생성 후 브라우저 결과 확인 불가
  • 콘솔 에러를 에이전트가 직접 볼 수 없음
  • 성능 문제 측정 불가, 추정만 가능
  • 네트워크 오류·CORS 진단 불가
  • 개발자가 직접 브라우저 확인 후 다시 설명
Chrome DevTools MCP 이후
  • 스크린샷·DOM 검사로 시각적 검증
  • 콘솔 로그·에러 실시간 분석
  • 실제 Core Web Vitals 측정 (LCP, FID, CLS)
  • 네트워크 탭에서 정확한 CORS 에러 확인
  • 에이전트가 관찰→분석→즉시 수정
02 핵심 기능

3가지 핵심 기능

성능 분석 · 브라우저 디버깅 · 자동화. 26개 도구가 카테고리별로 제공됩니다.

👁
성능 분석

Core Web Vitals (LCP, FID, CLS)를 실측하고 Lighthouse 감사를 실행합니다. Google CrUX API와 연동해 실사용자 데이터도 분석합니다.

  • 페이지 로드 트레이스 기록
  • LCP 병목 이미지 진단
  • Lighthouse 접근성·SEO 감사
  • 모바일·느린 3G 환경 시뮬레이션
performance · lighthouse · crux
🐛
브라우저 디버깅

콘솔 에러, 네트워크 요청, DOM 스냅샷을 직접 분석합니다. 번들 코드에서도 소스맵 스택 트레이스로 원본 파일을 추적합니다.

  • 콘솔 로그·에러 메시지 수집
  • CORS·API 실패 네트워크 진단
  • 스크린샷·DOM 스냅샷 캡처
  • 힙 스냅샷으로 메모리 누수 추적
console · network · memory · screenshot
🤖
자동화

Puppeteer 기반의 스마트 대기 메커니즘으로 안정적인 브라우저 자동화를 제공합니다. 폼 작성부터 파일 업로드까지 복잡한 상호작용도 지원합니다.

  • 클릭·폼 입력·드래그 & 드롭
  • 파일 업로드·키 입력
  • 기기·위치·CPU 에뮬레이션
  • 버튼 클릭 후 데이터 로딩 대기
puppeteer · emulation · automation
03 설치 방법

에이전트별 설치 방법

Node.js 20.19+ 와 최신 Chrome이 필요합니다. 에이전트에 따라 설치 방식이 다릅니다.

시스템 요구사항
Node.js 20.19.0 / 22.12.0 / 23+ · Chrome 최신 안정화 버전 이상 (또는 Chrome for Testing)
1
Claude Code — CLI 명령 한 줄
Claude Code CLI에서 직접 등록합니다.
bash 
claude mcp add chrome-devtools npx chrome-devtools-mcp@latest
2
Cursor / VS Code Copilot / Cline — settings.json
MCP 설정 파일에 아래 내용을 추가합니다. (~/.cursor/settings.json 또는 각 에이전트의 MCP 설정 파일)
json 
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}
3
고급 옵션 — 기존 Chrome 인스턴스 연결
이미 로그인된 Chrome에 연결하거나, 경량 모드로 실행할 수 있습니다.
json 
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": [
        "chrome-devtools-mcp@latest",
        "--slim",                               // 성능 트레이싱 없는 경량 모드
        "--no-usage-statistics",                // 사용 통계 비활성화
        "--browser-url=http://127.0.0.1:9222"  // 기존 Chrome에 연결
      ]
    }
  }
}
기존 Chrome 원격 디버깅 활성화
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222
04 활용 예시

실제 사용 시나리오

에이전트에게 자연어로 요청하면, MCP가 Chrome DevTools를 직접 제어합니다.

시나리오 01
📊 Core Web Vitals 성능 최적화
"페이지 성능 분석해서 개선 방법 알려줘"
  1. navigate_page → 대상 페이지 이동
  2. performance_start_trace → 트레이싱 시작
  3. performance_stop_trace → LCP 병목 분석
  4. 에이전트: 이미지 프리로딩, 압축 코드 제안
시나리오 02
🐛 JavaScript 에러 자동 진단
"모바일에서 발생하는 에러 재현하고 원인 찾아줘"
  1. emulate_device → 모바일 환경 시뮬레이션
  2. 사용자 동작 시나리오 재현
  3. get_console_messages → 에러 스택 트레이스 분석
  4. list_network_requests → CORS·API 실패 확인
시나리오 03
🧪 메모리 누수 진단
"앱이 시간이 지나면서 메모리가 증가해요"
  1. take_heapsnapshot → 초기 메모리 캡처
  2. 반복 작업 시뮬레이션
  3. take_heapsnapshot → 이후 메모리 캡처
  4. analyze_heapsnapshot → 누수 경로 추적·수정안 제시

지원 AI 도구 & 알려진 한계

MCP를 지원하는 20개 이상의 코딩 에이전트와 연동됩니다.

에이전트 설치 방식 지원 수준

Cursor settings.json 공식 1차 지원
VS Code Copilot 마켓플레이스 or settings.json 공식 1차 지원

Gemini CLI, JetBrains AI MCP 확장 2차 지원

알려진 한계

⚠️ 인증 세션 제한
MCP가 실행하는 Chrome 인스턴스는 확장 프로그램 설치 불가 → OAuth·Cookie 주입이 어렵습니다. 기존 로그인된 Chrome에 --browser-url로 연결하는 방법을 사용하세요.
⚠️ Chrome 전용
Chrome DevTools Protocol(CDP) 기반이므로 Firefox·Safari는 공식 미지원입니다.
🔒 보안 권장사항
민감한 정보가 있는 페이지를 디버깅할 때는 별도의 Chrome for Testing 프로필 사용을 권장합니다. --no-usage-statistics --no-performance-crux 플래그로 데이터 전송을 차단할 수 있습니다.
