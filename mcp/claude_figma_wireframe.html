01 워크플로우 개요

3단계 기획 자동화 흐름

아이디어에서 피그마 와이어프레임까지, 각 단계에서 AI가 어떤 역할을 하는지 전체 구조를 먼저 파악합니다.

핵심 포인트
AI가 초안을 만들고 사람이 검토·지정하는 방식으로, '수정이 거의 없는 기획안'을 목표로 합니다. 와이어프레임을 처음부터 완벽하게 만들려 하지 말고, 반복 루프를 설계하는 것이 핵심입니다.
02 도구 구성

워크플로우를 구성하는 3가지 도구

각 단계마다 다른 도구를 사용합니다. 역할이 겹치지 않으므로 함께 사용할 때 효과가 극대화됩니다.

📋
Manyfast (매니패스트)

한국 스타트업 리오랩이 만든 기획 전용 AI 에디터. 아이디어를 채팅으로 입력하면 PRD(제품 요구사항 문서), IA(정보구조도), 기능명세서를 자동 생성합니다. 기획 시간을 평균 2개월에서 1주일로 단축하며, AI 제안은 사람 승인 후에만 반영됩니다.

03 연결 방법

Claude ↔ Figma MCP 설정하기

Claude Code(터미널)와 Claude Desktop 앱 모두 지원합니다. Remote 방식이 캔버스 쓰기(Write)까지 가능해 와이어프레임 생성에 적합합니다.

시작 전 준비
Figma 계정 필요 (Pro 이상 권장) / Claude.ai Pro 또는 API 키 필요 / Figma 개인 액세스 토큰 발급 필요
1
Figma 개인 액세스 토큰 발급
Figma.com → 우상단 프로필 → 설정(Settings) → 보안(Security) → 개인 액세스 토큰(Personal Access Tokens) → 새 토큰 생성.
토큰 이름을 입력하고 만료일 없음으로 설정. 생성된 토큰값(figd_...)을 복사해 안전한 곳에 보관합니다. 창을 닫으면 다시 볼 수 없습니다.
2
Claude Code에 MCP 서버 등록
터미널에서 아래 명령어를 실행합니다.
bash 
# Figma MCP 서버 등록 (개인 액세스 토큰 방식)
claude mcp add figma \
  -e FIGMA_PERSONAL_ACCESS_TOKEN=figd_여기에_토큰_붙여넣기 \
  -- npx -y @figma/mcp-server

# 연결 상태 확인
/mcp
3
Claude Desktop 앱 설정 (선택)
Claude Desktop을 사용할 경우, claude_desktop_config.json 파일에 아래 내용을 추가합니다. 위치: ~/Library/Application Support/Claude/ (macOS) 또는 %APPDATA%\Claude\ (Windows)
json 
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "@figma/mcp-server"],
      "env": {
        "FIGMA_PERSONAL_ACCESS_TOKEN": "figd_여기에_토큰_붙여넣기"
      }
    }
  }
}
4
연결 테스트
Figma에서 테스트 파일을 하나 열고 URL을 복사합니다. Claude에게 아래처럼 물어보세요.
Claude 프롬프트 
이 Figma 파일을 분석해줘: https://www.figma.com/file/xxxxx
페이지 구조, 기존 컴포넌트, 색상 팔레트를 파악하고 요약해줘.
Claude가 Figma 파일 내용을 정확히 설명하면 연결 성공입니다.
연결 방식 캔버스 쓰기(와이어프레임 생성) 읽기(분석) 비고
Remote Server (npx) ✓ 지원 ✓ 지원 와이어프레임 생성에 필수. Pro 이상 권장
Desktop Plugin 제한적 ✓ 지원 선택(Selection) 기반 분석 중심
서드파티 MCP (claude-talk-to-figma) 부분 지원 ✓ 지원 Bun 런타임 필요, WebSocket 방식. 도형 수준 생성
04 실전 워크플로우

Claude로 기획하고 Figma에 전달하는 방법

PRD가 준비된 상태에서 Claude와 대화하며 와이어프레임을 만드는 실제 흐름입니다.

1
PRD 기반으로 화면 목록 확정
Manyfast에서 만든 PRD를 Claude에 붙여넣고, 어떤 화면이 필요한지 목록화합니다. 이 단계에서 MVP에 불필요한 기능을 제거합니다.
Claude 프롬프트 
아래 PRD를 바탕으로 MVP에 필요한 화면 목록을 만들어줘.
각 화면의 목적, 주요 UI 요소, 다음 화면 연결 관계를 정리해줘.
MVP 범위에 포함되지 않아도 되는 기능은 별도로 표시해줘.

[PRD 내용 붙여넣기]
2
FigJam에 유저플로우 다이어그램 생성
화면 목록이 확정되면 사용자가 어떤 순서로 이동하는지 플로우를 Figma에 직접 그립니다.
Claude 프롬프트 
아래 화면 목록을 바탕으로 FigJam에 유저플로우 다이어그램을 만들어줘.
FigJam 파일: https://www.figma.com/file/xxxxx

화면 순서: 스플래시 → 로그인 → 대시보드 → 상세화면 → 결제
분기: 로그인 실패 시 오류 메시지 → 재시도, 비회원은 게스트 모드로 진행
3
와이어프레임 1차 생성
화면별로 Claude에게 Figma 캔버스에 직접 그리도록 요청합니다. 한 번에 전체를 요청하지 말고, 화면 하나씩 요청하는 것이 품질이 높습니다.
Claude 프롬프트 
아래 Figma 파일의 'Wireframe' 페이지에 모바일 로그인 화면 와이어프레임을 만들어줘.
파일: https://www.figma.com/file/xxxxx

구성:
- 상단: 서비스 로고 (중앙 정렬)
- 중앙: 이메일 입력 필드, 비밀번호 입력 필드 (세로 배치)
- 하단: 로그인 버튼 (Primary), 소셜 로그인 버튼 (Google, Apple)
- 최하단: '계정이 없으신가요? 회원가입' 링크

기존 디자인 시스템 컴포넌트를 최대한 활용해줘.
프레임 이름은 'Login - Mobile'로 지정해줘.
05 반복 수정 루프

Human-in-the-Loop: 수정사항 반영하기

1차 생성 후, 피그마에서 수정이 필요한 프레임을 지정해 Claude에게 재요청하는 것이 핵심입니다.

반복 수정 사이클
AI
1차 와이어프레임 생성
Claude가 Figma MCP를 통해 캔버스에 직접 그립니다. 여러 화면을 한꺼번에 생성합니다.
인간
Figma에서 검토 — "수정사항" 프레임 지정
수정이 필요한 영역을 Figma에서 선택하고, 우클릭 → "Copy link to selection"으로 해당 프레임의 URL을 복사합니다. 또는 수정 필요 사항을 별도 "수정사항" 프레임으로 직접 표시합니다.
AI
프레임 URL + 수정 지시 → 재제작
특정 프레임 URL과 수정 내용을 Claude에게 전달하면, 해당 프레임만 정확히 수정합니다. 다른 프레임은 건드리지 않습니다.
인간
만족할 때까지 반복
보통 2~3 사이클로 디자이너에게 전달할 수 있는 수준에 도달합니다.
효과적인 수정 요청 프롬프트
"이 프레임의 헤더 높이를 64px로, 네비게이션 간격을 24px로 변경해줘: [프레임 URL]"
파일 전체 URL이 아닌 특정 프레임/노드 URL을 제공해야 정확하게 수정됩니다.
피해야 할 패턴
❌ 파일 전체 URL만 전달 후 "전체 수정해줘" — 의도와 다른 결과 빈번
❌ 한 번에 전체 화면 재설계 요청 — 화면 단위로 쪼개서 진행 권장
❌ 레이어 이름 없이 "중간 버튼"처럼 모호하게 지정 — 레이어 명에 의미 있는 이름 사용

토큰 소비 주의
