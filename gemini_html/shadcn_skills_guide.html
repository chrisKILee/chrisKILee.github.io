Skills가 뭔가요?

// 동작 원리 다이어그램
⚠ Skills 없을 때

AI가 내 프로젝트에 어떤 컴포넌트가 설치됐는지, Tailwind 버전이 뭔지, 파일 경로가 어디인지 모름. "일반적인 예시 코드"만 생성해서 실제 프로젝트에 바로 못 쓸 수 있음.

✅ Skills 있을 때

AI가 내 components.json 을 읽어 프레임워크, Tailwind 버전, 설치된 컴포넌트 목록, 아이콘 라이브러리, 파일 경로까지 정확히 파악. 내 프로젝트에 딱 맞는 코드 생성.

// 설치

설치 방법

1

shadcn/ui 프로젝트가 있어야 함

프로젝트 루트에 components.json 파일이 있어야 합니다. 이 파일이 Skills의 트리거(작동 신호)입니다.

아직 없다면: pnpm dlx shadcn@latest init 으로 먼저 초기화하세요.
2

Skills 설치 명령 실행

프로젝트 디렉토리에서 아래 명령을 실행합니다. pnpm dlx 는 전역 설치 없이 바로 실행하는 방식입니다.

pnpm dlx skills add shadcn/ui
3

AI 어시스턴트에서 자동 활성화

이제 Claude Code, Cursor 등 AI 어시스턴트에서 shadcn/ui 관련 작업을 시작하면, 스킬이 자동으로 shadcn info --json 을 실행해 프로젝트 컨텍스트(맥락 정보)를 AI에게 주입합니다.

더 자세한 내용은 skills.sh 공식 사이트를 참고하세요.
// 포함 기능

Skills에 뭐가 들어있나?

①

프로젝트 컨텍스트

매번 대화마다 shadcn info --json 을 실행해 현재 프로젝트의 프레임워크, Tailwind 버전, 별칭(alias), 기본 라이브러리(radix/base), 아이콘 라이브러리, 설치된 컴포넌트 목록, 파일 경로를 AI에게 전달합니다.

②

CLI 명령 완전 참조

init, add, search, view, docs, diff, info, build 명령의 플래그, dry-run 모드, 스마트 머지(합치기), 프리셋, 템플릿 사용법 전체를 AI가 알고 있습니다.

③

테마 & 커스터마이즈

CSS 변수, OKLCH 색상 체계, 다크 모드, 커스텀 색상 추가, border-radius, 컴포넌트 변형(variant) 방법을 Tailwind v3/v4 양쪽 버전 모두 안내합니다.

④

레지스트리 제작

자체 컴포넌트 레지스트리(컴포넌트 배포소) 만들기: registry.json 형식, 아이템 타입, 파일 객체, 의존성, CSS 변수, 빌드·호스팅 방법을 포함합니다.

⑤

MCP 서버 통합

MCP(Model Context Protocol) 서버를 통해 AI 어시스턴트가 여러 레지스트리를 자연어로 검색·설치할 수 있습니다. "로그인 폼 추가해줘"처럼 말하면 AI가 직접 컴포넌트를 찾아 설치합니다.

// 동작 방식

Skills가 작동하는 4단계

1

프로젝트 감지 (Project Detection)

AI가 작업을 시작할 때 components.json 파일을 찾으면 자동으로 Skills가 활성화됩니다. 별도 설정 없이 파일 존재만으로 트리거됩니다.

2

컨텍스트 주입 (Context Injection)

shadcn info --json 명령을 실행해 아래 정보를 AI 대화 컨텍스트에 자동으로 넣습니다:

{ "framework": "next", "tailwind": { "version": "4" }, "aliases": { "components": "@/components" }, "iconLibrary": "lucide", "installedComponents": ["button", "card", "dialog", ...] }
3

패턴 강제 적용 (Pattern Enforcement)

AI가 shadcn/ui 공식 컴포지션(조합) 규칙을 따릅니다. FieldGroup, ToggleGroup 같은 고급 패턴, 시맨틱 색상, 각 라이브러리(radix/base)에 맞는 정확한 API를 사용합니다.

4

컴포넌트 탐색 (Component Discovery)

코드 생성 전에 shadcn docs, shadcn search 또는 MCP 도구를 활용해 실제 컴포넌트 존재 여부를 확인합니다. 없는 컴포넌트를 만들어내지 않습니다.

// 활용 예제

이렇게 쓰면 됩니다

예제 1

"이메일과 비밀번호 필드가 있는 로그인 폼 추가해줘"

AI가 내 프로젝트에 이미 설치된 Form, Input, Button 컴포넌트를 확인하고, 내 파일 경로 규칙에 맞게 코드를 생성합니다.

예제 2

"사이드바, 통계 카드, 데이터 테이블이 있는 대시보드 만들어줘"

Skills가 없으면 AI가 임의 구조를 만들지만, Skills가 있으면 실제 설치된 shadcn 컴포넌트 + 내 프로젝트 alias 경로로 바로 동작하는 코드를 생성합니다.

예제 3 — 프리셋

"Switch to --preset ocean"

프리셋을 변경하면 AI가 자동으로 테마 전환 명령을 실행합니다. 색상 팔레트 전체를 한 번에 교체할 수 있습니다.

예제 4 — 외부 레지스트리

"Can you add a hero from @tailark?"

@tailark 처럼 네임스페이스가 붙은 외부 레지스트리 컴포넌트도 자연어로 설치할 수 있습니다. MCP 서버가 연결된 경우.

// MCP 서버

MCP 서버 설정

MCP(Model Context Protocol) 서버를 추가하면 AI가 레지스트리를 직접 검색하고 설치할 수 있습니다.

초기화 명령

pnpm dlx shadcn@latest mcp init --client claude

Claude Code용 .mcp.json 설정

{ "mcpServers": { "shadcn": { "command": "npx", "args": ["shadcn@latest", "mcp"] } } }
Cursor: .cursor/mcp.json / VS Code: .vscode/mcp.json 에 동일하게 설정

다중 레지스트리 설정

{ "registries": { "@acme": "https://registry.acme.com/{name}.json", "@internal": { "url": "https://internal.company.com/{name}.json", "headers": { "Authorization": "Bearer ${REGISTRY_TOKEN}" } } } }
인증이 필요한 사내 레지스트리는 headers 에 토큰을 환경변수로 설정
// CLI 레퍼런스

주요 CLI 명령어

명령어 역할 예시
shadcn init 프로젝트 초기화, components.json 생성 pnpm dlx shadcn@latest init
shadcn add 컴포넌트 추가 (소스코드를 프로젝트에 복사) shadcn add button dialog
shadcn search 컴포넌트 검색 shadcn search "data table"
shadcn view 컴포넌트 소스 미리보기 shadcn view button
shadcn docs 컴포넌트 문서 열기 shadcn docs card
shadcn diff 설치된 버전과 최신 버전 비교 shadcn diff button
shadcn info 현재 프로젝트 설정 정보 출력 (Skills의 핵심) shadcn info --json
shadcn build 커스텀 레지스트리 빌드 shadcn build
// 문제 해결

자주 겪는 문제

❌ MCP 응답 없음

설정 확인 → AI 클라이언트 재시작 → shadcn 설치 확인 → 네트워크 접근 확인

npx shadcn@latest mcp --help
❌ 레지스트리 접근 실패

URL 형식 확인 → 인증 토큰 확인 → 레지스트리 서버 상태 확인 → 네임스페이스 문법 확인

# .env.local에 추가 REGISTRY_TOKEN=your_token
❌ 설치 실패

components.json 유효성 확인 → 대상 경로 존재 여부 → 쓰기 권한 확인 → 의존성 확인

shadcn info --json # 설정 확인
❌ 도구·프롬프트 없음

npx 캐시 지우기 → MCP 서버 재활성화 → IDE 출력 패널에서 로그 확인

npx clear-npx-cache # 또는 rm -rf ~/.npm/_npx
