1. 토큰과 청크: 데이터의 조각화

AI 모델이 정보를 처리하기 위해서는 우리가 읽는 문장을 적절한 크기로 쪼개는 과정이 필요합니다.

# 1. 토큰(Token): 글자가 아닌 '의미 조각'

많은 분들이 1글자 = 1토큰으로 오해하지만 실제로는 다릅니다. AI 모델의 토크나이저(Tokenizer)는 자주 쓰이는 단어 조합은 하나로 묶고, 복잡한 단어는 여러 개로 쪼개어 효율을 높입니다.

예를 들어 한글의 경우 '안녕하세요'가 1개 토큰일 수도 있고, '안녕'+'하'+'세요' 3개일 수도 있습니다. 이는 모델 설계 시 결정된 알고리즘에 따릅니다.

TOKENIZER HIERARCHY: CHARACTER < TOKEN < CHUNK

# 2. 청크(Chunk): 토큰을 담는 컨테이너

청크는 검색 성능을 위해 AI 모델이 감당할 수 있는 크기(Context Window)로 토큰들을 묶은 단위입니다. 너무 크면 정보가 희석되고, 너무 작으면 문맥이 끊어집니다.

벡터 DB에 저장되는 실제 단위이며, 바구니(청크) 안에 사과(토큰)들이 담겨 있는 꼴입니다.

2. Vector DB: 의미를 숫자로

텍스트는 Embedding 모델을 통해 수천 개의 실수 배열로 변환되어 고차원 공간에 배치됩니다.

AI는 텍스트를 직접 비교하지 않습니다. 모든 청크는 AI 모델(Embedding)을 거쳐 수천 개의 실수 배열(Array)로 바뀝니다. 벡터 DB는 이 숫자들이 고차원 공간의 어디에 위치하는지 저장합니다. 벡터 DB는 이 숫자들 사이의 '거리'를 계산하여 유사도를 판별합니다.

"벡터 DB는 텍스트를 저장하는 것이 아니라, 텍스트의 '의미적 좌표'인 숫자들의 모음을 저장합니다. 따라서 '휴가'라고 물어도 '연차'에 대한 정보를 찾을 수 있는 것입니다."

3. Template: 응답의 제어

검색된 정보를 질문자의 의도에 맞게 재가공하는 정교한 작업 지시서입니다.

# Template: 톤앤매너의 제어

검색된 청크들을 그대로 보여주는 것이 아니라, 템플릿이라는 양식에 넣어 AI가 질문자의 의도에 맞게 정해진 포맷으로 재가공하게 만듭니다. 이를 통해 답변의 길이, 말투, 형식을 제어할 수 있습니다.
