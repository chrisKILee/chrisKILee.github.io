— 개발플랫폼 첫 인상 리뷰

개발플랫폼(Backstage 기반) 릴리즈에 앞서, 실제 사용자 입장에서 직접 써보며 발견한 이슈와 경험을 기록한 문서입니다. 기능 완성도·UX·보안·운영 흐름을 중심으로 검토하였으며, 발견된 문제점은 본문과 별도 리스트로 정리합니다.

🔗 플랫폼 URL: backstage.infra.nfw.vntgcorp.com
📅 검토일: 2026-04-09 ~ 10
🎯 검토 목적: 릴리즈 전 사용자 관점 문제점 식별
🚫
BLOCK ISSUE 발견
CI 미업데이트로 인해 Backstage 배포관리 화면에 프로젝트가 노출되지 않아 환경 설정을 진행할 수 없는 상태입니다. 릴리즈 전 반드시 해결이 필요합니다.

🔍 Backstage 메인 화면 탐색

Backstage 메인 화면 — http://backstage.infra.nfw.vntgcorp.com/

플랫폼에 최초 접속했을 때 보이는 메인 화면입니다. 탐색 중 아래 항목들이 확인되었습니다.

⚠️
[이슈 #3] Docs 최신화 안 됨
Docs 메뉴의 내용이 alpha 기준으로 작성되어 있어 현재 릴리즈 버전과 불일치합니다. 사용자에게 혼란을 줄 수 있습니다.
❓
[이슈 #1] API 메뉴의 실용성 불명확
상단 메뉴의 "API" 섹션이 실제로 사용되고 있는지, 어떤 용도인지 설명이 없습니다.
❓
[이슈 #2] GitHub Dashboard 연동 여부 불명확
GitHub Dashboard가 실제로 동작하는지 확인이 필요합니다.
🎨
[이슈 #4] 아이콘·Favicon 미변경
Backstage 기본 아이콘과 Favicon이 그대로입니다. 사내 플랫폼으로서 브랜딩 적용이 필요합니다.

🔒 보안 · 권한 (Authorization)

타 사용자의 서비스 목록도 조회 가능한 상태
🚨
[이슈 #5] Authorization 미구현 — 심각
현재 상태: 모든 사용자가 다른 사람의 서비스를 조회하고 수정까지 할 수 있습니다. 인가(Authorization) 로직이 전혀 구현되어 있지 않은 상태입니다. 프로덕션 릴리즈 전 필수 해결 항목입니다.
서버 스펙 변경 UI — 비용 정보 없이 사양 변경 가능
💸
[이슈 #6] 서버 Spec 변경 시 비용 안내 없음
서버 사양을 변경할 수 있는 UI가 있으나, 변경 시 발생하는 추가 비용에 대한 안내가 전혀 없습니다. 사용자가 비용 영향을 인지하지 못한 채 고사양으로 변경할 수 있습니다. 최소한 아래 스펙별 단가 정보가 필요합니다.

🧩 컴포넌트 등록 기능 탐색

❓
[이슈 #7] "Register Existing Component" 기능 설명 부재
"Create a new component > Register existing component" 메뉴의 목적과 사용 방법이 불명확합니다. 이 메뉴가 어떤 상황에서 사용되는지, 기존 Git 저장소를 등록하는 방식인지 설명이 필요합니다.
📄
[이슈 #8] 가이드 문서 미업데이트
컴포넌트 등록 관련 가이드 내용이 현재 버전과 맞지 않습니다. 사용자가 가이드대로 따라했을 때 다른 결과가 나올 수 있습니다.
🏢
[이슈 #9] ITGC 6개사 배포 프로세스 미정
계열사(ITGC 6개사) 환경으로의 배포 프로세스가 아직 결정되지 않은 상태입니다. 릴리즈 전 프로세스 정의가 필요합니다.

💻 개발자 경험 — 실제 코드를 올려보자

가이드 문서를 참고하여 로컬 환경을 세팅하고 실제 개발 코드를 플랫폼에 올리는 과정을 시도했습니다.

⚙️

로컬 개발 환경 세팅

Git 클론 → 브랜치 체크아웃 → pnpm install → 인프라 환경변수 설정 → Docker 컨테이너 실행 순서로 진행.

로컬 서버 환경 설정 진행 중
📌
이 섹션의 상세 가이드(Docker 설치, pnpm, git clone 등)는 내부 참고용으로 별도 관리가 필요합니다.
🖥️

프론트엔드 서버 기동 성공

pnpm nx serve chris-nolja-app 실행 후 프론트 서버가 정상적으로 올라왔습니다.

좌: 터미널에서 서버 기동 / 우: 브라우저에서 화면 확인
📋

기존 코드 이식 시도

플랫폼 프로젝트 구조에 기존 개발 소스를 복사하여 이식하는 방식으로 진행했습니다.

기존 소스 이식 후 서버 기동 시도
⚠️
[이슈 #10] 프레임워크 구조 불일치 — Next.js → Nginx 패턴 사용 불가
기존 코드는 Next.js 기반이었으나, 플랫폼의 프로젝트 구조가 달라 Nginx 서빙 패턴을 그대로 사용할 수 없었습니다. 구조가 다른 프로젝트로 전환하여 재시도했습니다.
🚀

dev 브랜치 머지 성공

다른 프로젝트 구조로 전환 후 로컬 개발환경에서 실행 확인, dev 브랜치에 머지했습니다.

🚫

🚫 BLOCK — Backstage 배포관리에 프로젝트 미노출

kmm 코드가 수정되었으나 CI가 업데이트되지 않아 Backstage 배포관리 화면에 프로젝트가 나타나지 않습니다. 이로 인해 환경 설정 자체를 진행할 수 없는 상태입니다.

Backstage 배포관리 — 프로젝트가 목록에 노출되지 않음
🚫
[이슈 #11] BLOCK — CI 미업데이트로 배포 환경 구성 불가
kmm 코드 변경 시 CI 파이프라인도 함께 업데이트되어야 하나, 이 연동이 자동화되어 있지 않습니다. 결과적으로 Backstage에서 환경 구성을 완료할 수 없어 릴리즈 블로커가 됩니다.
