😣 문제 정의 · 배경

기존의 어려움

  • 🏭 24시간 운영 공장에서 MES DB 데드락(ORA-00060) 발생
  • ⛓️ Level-2까지 연쇄 장애 → 작업지시 불가 → 생산 중단
  • ❌ 사전 감지 시스템 부재 — 장애 후 인지, 반복 악순환
  • 👤 경험 의존적 판단 — 전담 DBA 없이 현장 대응 어려움

✨ AI로 해결한 방식

  • 🤖 Isolation Forest(비지도 학습)로 데드락 전조 자동 탐지
  • 📊 5개 핵심 DB 지표 24시간 자동 수집 + 위험 점수(0~100) 산출
  • 💬 Gemini AI가 원인 분석 + 한국어 대응 가이드 자동 생성
  • 🌐 웹 대시보드 — 브라우저만으로 비개발자도 즉시 확인 가능

③ 업무 효율성 16/35

사전 감지 시스템 부재 → 24시간 자동 모니터링 체계로 전환. 절감 수치 미명시로 12~21점 구간 적용, 실제 운영 중 가점 +3 반영 (연 ~12시간 보수 추정)

④ 아이디어 적절성 22/25

공장 생산 중단이라는 명확한 문제를 Isolation Forest 비지도 학습으로 풀어낸 선택이 탁월. 전문 DBA 없이 대응 가능한 구조가 현실적으로 실용적

⑤ 확산 가능성 18/25

Oracle DB 기반이면 설정만 변경해 ERP·SCM에도 적용 가능. GitHub 전체 소스 공개. 단, Oracle Instant Client 설치 필요로 진입 장벽 존재

⑥ 조직 목표 연결 12/15

부서 중점과제 "AI 자동화를 통한 운영 업무 자동화"와 직접 연결. 공장 가동률에 직결되는 업무로 팀·조직 수준의 영향력이 있음

⚡ 주요 기능

🔍 DB 메트릭 자동 수집

  • 🔹 5개 핵심 지표 주기적 수집
  • 🔹 차단 세션 · 트랜잭션 락 · 교차 대기
  • 🔹 최대 대기시간 · ORA-00060 이력

  • 🔹 운영자용 한국어 대응 가이드
  • 🔹 RAG 방식으로 상황별 맞춤 분석

  • 🔹 브라우저만으로 비개발자도 접근

  • 🔹 수신자 · 조건 대시보드에서 설정
  • 🔹 발송 이력 UI에서 직접 확인

  • 🔹 기본 1440분(24시간) 주기 자동 실행
  • 🔹 최소 1분까지 주기 변경 가능
  • 🔹 수집→탐지→분석→알람 전 자동화

🧠 AI 활용 방식 · 기술 스택

데이터 처리 흐름

[Oracle MES DB]
    ↓  5개 지표 수집 (db_connector.py)
[Isolation Forest]  ←  scikit-learn 비지도 학습
    ↓  위험 점수 0~100 + 등급 산출
[Node.js Express API]
    ↓  Python spawn → JSON 결과 반환
[Gemini API (RAG)]
    ↓  메트릭 컨텍스트 주입 → 원인 분석 + 대응 가이드
[React 대시보드]
    ↓  Recharts 시각화 + SMTP 이메일 알람
