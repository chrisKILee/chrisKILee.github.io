SDD — Spec-Driven Development

코드보다 문서가 먼저다

핵심 원칙

/sdd-init 스킬은 새 프로젝트를 시작할 때 인터뷰 → 문서 → 테스트 → 구현 순서를 자동으로 강제한다. 코드를 한 줄도 쓰기 전에 "왜 만드는가, 무엇을 만드는가, 어떻게 만드는가"를 문서로 확정한다.

📄
Spec First

PRD / TRD / ADR / SPEC 문서를 먼저 작성. 구현은 문서 컨펌 이후에만 시작.

🧪
Test Before Code

Kent Beck의 TDD: Red → Green → Refactor. 테스트 파일이 없으면 구현 불가.

🤖
Autonomous After Confirm

impl-plan 컨펌 후 Claude가 테스트 → 구현 → 검증 → 커밋까지 자율 진행.

Phase 1 — 프로젝트 인터뷰

12문항, 반드시 1개씩

3
주요 사용자(타겟)
4
핵심 기능 3~5가지
5
기능별 우선순위
P0 필수 P1 중요 P2 선택
6

결제, 메일, SMS 등 / 없으면 "없음"

Phase 2 — CLAUDE.md 생성

프로젝트 헌법 (Constitution)

이 문서는 프로젝트의 모든 개발 관행에 우선한다. 수정 시 프로젝트 관리자 승인 필요.

포함 필수 항목

✓ 프로젝트 개요 (목적·타겟·MVP)
✓ SDD 워크플로우
✓ TDD 원칙 (Kent Beck)
✓ 기술 스택
✓ 코딩 스타일
✓ 자율 실행 원칙
✓ 보안 원칙
✓ Git 워크플로우

TDD 원칙 (반드시 포함)

Red-Green-Refactor 사이클 (이 순서 절대 변경 불가) ① Red — 실패하는 테스트 먼저 작성 (구현체 없음) ② Green — 테스트 통과하는 최소 구현 ③ Refactor — 중복 제거, 코드 명확화 구현 시작 전 체크: □ 테스트 파일이 존재하는가? □ 테스트가 현재 Red(실패)인가? → 모두 YES여야 구현 코드 작성 가능

자율 실행 원칙 (impl-plan 컨펌 후)

  • • 작업 중 사용자에게 확인 요청 금지
  • • 모호한 부분은 최선의 판단으로 결정 후 진행
  • • 완료 후 요약 보고 (구현 내용 · 테스트 결과 · 배포 상태)

Phase 3 — 4개 문서 스킬

CRITICAL — 절대 생략 불가, 순서 고정

인터뷰 요약 텍스트를 각 스킬의 ARGUMENTS로 전달한다. 하나 완료 확인 후 다음 스킬 호출.

1
/prd → .claude/docs/PRD.md
왜 만드는가
제품 요구사항 문서. 비즈니스 배경, 목표, 성공 지표, 사용자 스토리 포함.
2
/trd → .claude/docs/TRD.md
어떻게 만드는가
기술 요구사항 문서. 아키텍처, API 설계, DB 스키마, 비기능 요구사항 포함.
3
/adr → .claude/docs/ADR.md
왜 이 기술인가
아키텍처 결정 기록. 기술 선택 이유, 대안과 비교, 트레이드오프 명시.
4
/impl-plan → .claude/docs/IMPLEMENTATION_PLAN.md
무엇부터 만드는가

구체적인 구현 순서, 마일스톤, 테스트 전략 포함.

⚑ 이 문서 완료 후 → 사용자 컨펌 대기
컨펌 이후에만 구현 코드 작성 시작 가능

SPEC.md 별도 작성: /spec 스킬은 기능별 심층 인터뷰가 필요하므로 impl-plan 컨펌 후 별도 호출. "SPEC 작성해줘" 또는 /spec으로 시작.

Kent Beck TDD 원칙

테스트 없이 구현 코드 작성 금지

"테스트가 없으면 구현하지 않는다. 이것이 전부다."

— Kent Beck

① Red

실패하는 테스트 작성

  • • 구현체가 없어도 됨
  • • 컴파일 에러도 Red
  • • "무엇을 만들어야 하는가"를 코드로 표현
② Green

최소한의 구현

  • • 일단 동작하게만
  • • 지저분해도 OK
  • • 테스트 통과가 목표
③ Refactor

중복 제거

  • • 코드 명확화
  • • 테스트는 여전히 Green
  • • 기능 추가 ❌

한 번에 하나의 실패만

❌ 테스트 5개를 한꺼번에 작성하고 구현
✓ 테스트 1개 작성 → Green → 다음 테스트 1개 → Green → ...

구현 시작 전 체크리스트

→ 세 가지 모두 YES여야 구현 코드 작성 가능

개발 사이클

impl-plan 컨펌 이후

자율 실행 구간 (컨펌 후 사용자 확인 없이 진행)

테스트 위치 (이 프로젝트 기준)
영역 파일 위치 실행
백엔드 서비스 backend/src/**/*.spec.ts npm test
백엔드 E2E backend/test/**/*.e2e-spec.ts npm run test:e2e
권한 시스템 backend/src/**/*.spec.ts npm run test:permission
프론트엔드 frontend/src/**/*.test.tsx npm test
금지 / 필수 사항

❌ 금지

  • 구현 코드 먼저 → 테스트 나중
  • 테스트 여러 개 한꺼번에 작성
  • 테스트 없이 PR 생성

✓ 필수

  • 테스트 파일 먼저 생성
  • Red 확인 후 구현 시작
  • PR 전 전체 테스트 통과
