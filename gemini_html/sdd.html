2. Spec-Based (스펙 기반)

Antigravity 핵심

스펙이 '살아있는 문서'가 됩니다. 스펙을 수정하면 AI가 코드를 동기화합니다. 스펙과 코드가 유기적으로 연결되어 유지보수성과 유연성을 모두 잡습니다.

3. Spec-is-Code (스펙 일치)

No-Code / DSL

스펙 자체가 실행 가능합니다. (예: 저수준 코드 생성기, 엄격한 DSL). 생산성은 극대화되지만, AI의 창의적 해결책이나 복잡한 커스텀 로직 구현에는 한계가 있습니다.

      3. 주의사항 및 체크리스트

      Antigravity는 강력하지만, 올바른 제어가 필요합니다.
      안전한 비행을 위한 필수 점검 사항입니다.

      ⚠️ 주요 주의사항

      1. Hallucination (환각)

      스펙에 명시되지 않은 부분을 AI가 임의로 채워넣을 수 있습니다. 모호한 스펙은 버그의 원인이 됩니다.
      → 스펙을 최대한 구체적으로 작성하세요.

      2. Context Drift (문맥 표류)

      대화가 길어지면 AI가 초기 제약조건을 잊을 수 있습니다.
      → 주기적으로 새 세션을 시작하고 스펙 파일을 다시 주입하세요.

      3. 스펙-코드 불일치

      코드를 직접 수정하고 스펙을 업데이트하지 않으면 나중에 AI가 스펙 기준으로 코드를 덮어쓸 때 수정사항이 날아갑니다.
      → "스펙 수정 → 코드 재생성" 원칙을 고수하세요.
