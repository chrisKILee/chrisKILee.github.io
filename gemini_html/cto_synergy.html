2. 조직별 미션과 역할

2.1 플랫폼서비스실 (14명)

실 미션: Terroir 플랫폼과 전사 서비스의 안정적 기반을 제공한다 (Run & Operate)

기존 '기술지원실'에서 '플랫폼서비스실'로 명칭을 전환하면서, 수동적 IT 지원 조직에서 능동적 플랫폼 서비스 제공 조직으로의 정체성을 재정의했다.

플랫폼인프라팀 (9명)

팀 미션: 플랫폼 환경과 인프라를 안정적으로 제공하고, Terroir 운영 환경을 책임진다

역할 영역 세부 내용
Terroir 플랫폼 운영 Kubernetes 클러스터 운영, 컨테이너 런타임 환경 관리, GitOps 기반 배포 환경 운영
클라우드 서비스 GCP MSP, 하이브리드 클라우드(GCP+IDC) 운영, FinOps(클라우드 비용 최적화)
데이터센터 상암/가산 IDC 운영, 전국 지역 네트워크, DR센터 운영
시스템/DB 운영 통합 모니터링 운영, 시스템 운영, DB 성능 관리
통합 관측 Grafana LGTM 스택(Alloy-Kafka-LGTM) 기반 하이브리드 통합 관측 플랫폼 운영
네트워크 전환 드림라인→LG U+ 전환 대응, 공인 IP 변경 관리 (2026년 12월 완료)
자산 관리 ITAM 시스템 도입, IT 자산 생애주기 관리 자동화

플랫폼정보보호팀 (4명)

팀 미션: 중앙 집중형 보안 서비스(SECaaS)를 구축하여 그룹 전체 보안 수준을 상향 평준화한다

역할 영역 세부 내용
보안 서비스화 (SECaaS) 개별 프로젝트 대응에서 중앙 집중형 보안 서비스로 전환
그룹 보안 기준 S-MSB(그룹 공통 최소 보안 기준) 제정 및 적용
플랫폼 보안 Terroir 보안 아키텍처 운영, 컨테이너/클라우드 보안, EDR 도입
DevSecOps CI/CD 파이프라인 보안 통합, 취약점 스캐닝 자동화
컴플라이언스 ISMS 인증 유지, ISO27001/27017 인증 획득
보안 거버넌스 보안 정책/표준 수립, Zero Trust 아키텍처 도입

2.2 서비스개발실 (21명)

실 미션: Terroir 기반 솔루션을 개발하고, 프로젝트에 기술 역량을 제공하며, 제품화를 추진한다 (Apply & Deliver)

기존 '디지털솔루션개발실'에서 '서비스개발실'로 전환하면서, 솔루션 제품화와 프로젝트 리더십 강화에 초점을 맞추고 있다.

DataForge팀 (8명)

팀 미션: 팩토리 현장 데이터 수집·가공·분석의 핵심 경쟁력을 확보하고, 전체 데이터 플랫폼으로의 연결 고리를 주도적으로 설계·개발한다

역할 영역 세부 내용
현장 데이터 수집 제조/철강 설비 데이터 수집 표준화, 수집 자동화 체계 구축 (핵심 경쟁력)
엣지 컴퓨팅 엣지 단에서의 데이터 가공·분석·필터링, 실시간 처리 고도화
데이터 플랫폼 연결 팩토리 데이터 → 전체 데이터 플랫폼으로의 연결 아키텍처를 주도적으로 설계·개발
DataForge 제품화 서비스 운영 Web 기능, SLA 정책 수립으로 대외 사업 원년 준비
기술 교류 지역 센터로 기술 전파, R&D 개발 플랫폼과 통합, VNTG 조직 자산화
고객 과제 수행 설비기획실 과제, ID Tracking 개발, 국책과제 등

서비스개발팀 (12명)

팀 미션: 프로젝트 리더십을 강화하고, Terroir 기반 Multi-Stack 기술 역량으로 고객 프로젝트를 성공적으로 수행한다

역할 영역 세부 내용
프로젝트 수행 세아M&S MES 등 On-time Delivery
프로젝트 리더십 PM/PL 역량 향상, 멘토링 체계 구축, 영역별 전문가 육성
Terroir 기반 전환 차세대 개발 플랫폼 기반 PoC, Multi-Stack 기술 대응
AI 활용 AI-Assisted 개발 도구(Cursor, Claude Code, Copilot) 활용 강화
솔루션 개발 MES 등 패키지 솔루션 상품화, Terroir 기반 공통 모듈/컴포넌트 개발
기술 전파 Terroir 프레임워크 적용 가이드, 프로젝트 현장 기술 지원

2.3 R&D실 (6명)

실 미션: 차세대 기술을 연구하고 Terroir 플랫폼을 설계·구축한다 (Research & Build)

Chris님이 플랫폼서비스실과 겸직으로 이끌고 있어, Build(R&D)와 Run(플랫폼서비스) 간의 자연스러운 기술 연계가 가능한 구조다.

R&D 직속 (Brett님)

미션: 전사 기술 표준 설계, 신기술 연구, Enabling Team 역할

역할 영역 세부 내용
기술 연구 클라우드 네이티브 기술 검증, PoC, 신기술 도입 평가
Enabling 전사 기술 표준 정의, 아키텍처 가이드라인, 기술 컨설팅

플랫폼개발팀 (5명)

팀 미션: Terroir 프레임워크 코어를 개발하고, IDP(개발자 플랫폼)를 구축하여 전사 개발자 경험을 혁신한다

역할 영역 세부 내용
Terroir 프레임워크 코어 개발 (React, NestJS, Nx 기반), GA 릴리즈 목표 (Chapter 2 Beta → Chapter 3 GA)
플랫폼 아키텍처 Terroir 런타임 환경 설계, 마이크로서비스 패턴 정의
관측 아키텍처 설계 Alloy-Kafka-LGTM 스택 설계 (플랫폼인프라팀이 운영)
IDP 구축 Backstage 기반 개발자 셀프서비스 포털 구축, 정식 오픈
CI/CD 설계 GitOps 파이프라인, 배포 자동화 체계, GCP/IDC 하이브리드 환경
SDD 정착 Spec-Driven Development 방법론 개발, AI 도구 전사 도입 지원
공통 컴포넌트 공통 UI 컴포넌트, 코드 생성기, CLI, 템플릿 개발
문서화 개발 가이드, API 문서, 튜토리얼, Sandbox 환경

7. 조직 구조 특이사항 및 활용 포인트

Chris님 겸직 구조의 전략적 의미

Chris님이 플랫폼서비스실장과 R&D실장을 겸직하는 구조는 단순한 인력 부족 대응이 아닌, Build-Run 연속성을 확보하기 위한 전략적 선택이다.

장점:

기술 일관성

설계(R&D)와 운영(플랫폼서비스)의 기술 방향이 자연스럽게 정렬

의사결정 속도

Build→Run 이전 시 별도 조율 없이 빠른 결정 가능

자원 유연성

두 실 간 인력/역량의 유연한 활용

우선순위 조정

개발과 운영의 균형 잡힌 우선순위 결정

다만 조직이 성장하면서 두 실의 역할이 본격화되면, 각 실에 전담 리더를 배치하는 것이 장기적으로 필요할 수 있다.

서비스개발실의 규모 우위 활용

전체 42명 중 서비스개발실이 21명(50%)으로 가장 큰 비중이다. 이는 '적용과 전달(Apply & Deliver)'이 현재 CTO 조직의 핵심 실행력임을 의미한다. R&D실(6명)이 만든 플랫폼과 표준을 서비스개발실이 프로젝트 현장에서 증폭시키는 '지렛대 효과'가 핵심이다.
