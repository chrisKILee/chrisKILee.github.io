01

시스템 모니터링

eG-Enterprise 기반으로 서버·DB·가상화 인프라의 메트릭을 수집·알림. 로그는 수집하지만 실질적으로 참조하지 않음.

솔루션 구성
메인 솔루션
eG-Enterprise
AP(애플리케이션 성능) 모니터링 솔루션. 서버, DB, 가상화 환경의 주요 메트릭을 수집하고 임계치 기반 알림 발송.
보조 도구
eG-View + Flash 대시보드
보고서 생성 및 SMS 정책 관리용. 대시보드는 Flash 기반으로 현재 사실상 사용 불가 상태.
수집 메트릭 / 로그
구분 대상 수집 항목 실사용 여부
메트릭 전체 시스템 CPU, 메모리, 디스크, 네트워크 I/O, 프로세스 상태 등 ✔ 주로 참조
로그 Windows 이벤트 로그 (System, Application) ✘ 거의 미참조
로그 Oracle DB Oracle Alert 로그 ✘ 거의 미참조
로그 VMware Kernel 로그 ✘ 거의 미참조
주목

로그는 eG-Enterprise에서 수집하고 있으나 실제 운영에서 참조되지 않음. 장애 대응 시 메트릭 그래프에만 의존하며, 원인 분석이 얕아지는 구조적 원인이 됨.

지역 담당자 모니터링
  • 최초 구성 시 지역 담당자에게 eG-Enterprise 개인 계정을 생성하고 해당 지역 시스템 열람 권한 부여
  • 현재 지역 담당자 대부분이 시스템 접근을 하지 않음 — 사실상 잊혀진 상태
  • 이슈 발생 시: 인프라팀이 eG에 직접 접근 → 메트릭 그래프 캡처 → 의견을 덧붙여 지역 담당자에게 공유
알림 체계
📱 SMS
회사 + 지역 그룹 단위
담당자들은 본인과 관련된 시스템에 대해서만 수신을 원하지만, 지나친 세분화가 어려워 회사+지역 기준으로 그룹을 나누어 설정.

불필요한 알림으로 인한 피로 누적이 우려되어 세분화 요구가 있었으나 운영 한계로 타협된 상태.
💬 Google Chat
인프라팀 이중 수신
인프라팀은 SMS + Google Chat 이중 알림으로 수신.

지역 담당자는 Google Chat 알림 없이 SMS만 수신하며, 실질적인 모니터링 참여 없이 알림에만 의존.
02

네트워크 모니터링

Netis NMS(국내 솔루션)로 장비 상태·트래픽·포트·구성을 수집. 알림 과다로 인해 수신자가 사실상 1인으로 한정됨.

솔루션 구성
NMS 솔루션
Netis NMS — 국내 솔루션
네트워크 장비의 상태, 트래픽, 포트 Up/Down, 장비 Config 변경 이력을 관리하는 네트워크 전용 모니터링 솔루션.
수집 메트릭 / 로그
수집 방식 수집 항목 비고
Ping (health check) 장비 생존 여부 전체 장비 대상
트래픽 수집 회선별 트래픽량 In/Out bps
SNMP 포트 Up/Down 상태 주요 장비 대상
Config 수집 장비 설정 파일 정기 수집 및 변경 비교 변경 감지 목적
Syslog 장비 로그 수집 주요 장비에 한정
지역 담당자 모니터링
  • 지역 네트워크 담당자 전원에게 Netis NMS 접근 권한 부여
  • 실제로는 거의 접근하지 않는 것으로 파악됨 — 알림에만 의지하는 상태
알림 체계
📱 SMS
사실상 1인 수신
eG-Manager의 SMS 기능을 활용하나, 알림 수가 너무 많아 강신국M 단 1명만 수신하고 있음.

알림 과다 → 수신자 축소라는 악순환 구조.
💬 Google Chat
인프라 + 지역 네트워크 동일 채널
인프라팀 네트워크 담당자와 지역 네트워크 담당자가 동일 Google Chat 채널에서 알림을 수신.

채널 내 알림에 대한 실질적 반응 주체는 인프라팀.
03

현황 진단

AS-IS 구조에서 반복적으로 드러나는 문제 패턴.

"권한은 있지만 쓰지 않는다. 알림은 오지만 보지 않는다."

지역 담당자 모니터링 현황 요약
문제 ①
로그 활용 부재
시스템·네트워크 모두 로그를 수집하지만 실제 운영에서 참조하지 않음. 메트릭 단독 분석으로 근본 원인 파악이 어려운 상황.
문제 ②
지역 담당자 역할 공백
접근 권한을 부여해도 사용하지 않음. 이슈 발생 시 인프라팀이 직접 분석 후 정보를 전달하는 구조 — 지역 자력 대응 불가.
문제 ③
알림 피로 & 수신자 축소
알림이 너무 많아 수신자를 줄이거나 알림을 무시하게 됨. 네트워크는 사실상 1인 수신. 알림의 실효성이 낮아지는 악순환.
역할 현황 요약
조직 현재 역할 실제 상황
플랫폼 인프라팀 모니터링 전체 운영 + 알림 수신 + 분석 + 조치 사실상 전 단계 단독 처리
지역 센터 IT 담당 자체 모니터링 + 1차 대응 (의도) SMS 알림 수신 후 인프라팀 연락 대기
지역 네트워크 담당 네트워크 이슈 1차 확인 Google Chat 수신하나 대응 주체는 인프라팀
