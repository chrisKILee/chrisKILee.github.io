왜 만들었는가

수작업 라이선스 관리의 한계

세아그룹 수십 개 계열사의 Google Workspace 라이선스를 구글 시트 하나로 관리하다 보니 인사발령 때마다 담당자가 직접 시트를 수정해야 했고, 실수·누락이 반복되었습니다.

Before — 기존 방식

구글 시트 수동 관리

  • 인사발령 때마다 담당자가 직접 시트 수정
  • 계열사별 현황 집계를 수작업으로 확인
  • 월말 정산 시 엑셀 취합 후 수동 계산
  • 삭제·변경 이력 추적 불가, 감사 취약
  • 라이선스 잔여 현황을 실시간으로 파악 어려움
After — 이 시스템

DB 기반 자동화 플랫폼

  • 매주 목요일 밤 10시, 인사발령 시트를 자동 읽어 배치 처리
  • 계열사별 사용·잔여 현황을 대시보드에서 실시간 확인
  • 월별 정산 요약을 클릭 한 번으로 조회·다운로드
  • 모든 변경을 이력 테이블에 자동 기록 (감사 추적 가능)
  • 에러 건 별도 관리 및 수기 재처리 지원

잘 구현된 부분

비동기 이관 + 진행률 폴링
ConcurrentHashMap<String, ImportJobStatus> + CompletableFuture.runAsync() 조합으로 대용량 시트 이관 중 화면이 멈추지 않고 실시간 진행률을 클라이언트에 노출합니다. volatile 필드 사용으로 멀티스레드 가시성도 확보.
동적 헤더 컬럼 매핑
구글 시트의 열 순서가 바뀌어도 깨지지 않도록 헤더 행을 동적으로 스캔해 컬럼 인덱스를 매핑합니다. "계정사용시작일", "시작일", "START_DATE" 등 다양한 표기를 허용하는 방어적 설계. 실무에서 시트 포맷이 자주 달라지는 상황에 적합합니다.
배치 Apply — 건별 에러 격리
applyBatch()는 각 action_sn을 개별 try-catch로 감싸 한 건 실패가 전체 롤백을 일으키지 않습니다. 실패 건은 상태를 "E"로 마킹해 나중에 수기 재처리할 수 있습니다.
배치 가드 — isAvailable()
GwsSheetService.isAvailable()로 서비스 계정 키 파일 존재 여부를 확인 후 실행. 키가 없는 개발 환경에서는 배치 스킵 로그만 남기고 예외를 던지지 않아 개발·운영 환경 구분이 깔끔합니다.
cleanDate() — 날짜 데이터 방어 처리
"해당없음", "-", "N/A" 등 비날짜 문자열을 null로 변환하고, "2025.08.20" · "2025/08/20" 등 다양한 구분자를 yyyy-MM-dd로 정규화합니다. 실무 엑셀/시트 데이터의 불규칙한 날짜 포맷을 실제로 다뤄본 경험에서 나온 코드.
취소 가능한 장기 작업
cancelRequested 플래그로 진행 중인 이관 작업을 중간에 취소할 수 있습니다. 대용량 이관이 잘못된 시트로 시작됐을 때 전체 완료를 기다릴 필요가 없습니다.
⚠️

개선 포인트

🔴 importJobs — 서버 재시작 시 상태 유실
static ConcurrentHashMap에 진행 중인 Job을 보관하므로 서버가 재시작되면 모든 JobStatus가 사라집니다. 운영 환경에서는 Redis 또는 DB 기반 Job 상태 저장으로 전환해야 "이관 중 배포"에도 안전합니다.
🟡 Spreadsheet ID 하드코딩 (GwsScheduleService)
private static final String SPREADSHEET_ID = "1NUsPnISAbGcckE9nytDl8Wgp89kXHmcFd3_a6UJvce4"가 소스에 그대로 노출되어 있습니다. @Value("${gws.spreadsheet.id}")로 외부화하면 환경별 시트 교체가 쉬워집니다.
🟡 SN 생성 — System.currentTimeMillis() 충돌 가능
"GWS-" + System.currentTimeMillis()는 밀리초 내 동시 삽입 시 중복 SN이 발생할 수 있습니다. 이미 비동기 이관 로직에서 UUID.randomUUID()를 쓰고 있으니 SN 생성도 UUID 방식으로 통일하면 안전합니다.
🟡 Sheets 서비스 객체 매번 생성
getSheetsService()가 호출될 때마다 파일 I/O + HTTPS Transport를 새로 초기화합니다. Singleton Bean에 @PostConstruct로 한 번만 생성해 필드에 캐싱하면 배치 성능이 향상됩니다.
🟢 Map<String, Object> 전체 사용 — 타입 안전성 없음
Controller → Service → Mapper 전 계층이 Map<String, Object>만 사용합니다. 현재 시스템 컨벤션(MyBatis + 기존 코드베이스)에 맞춘 선택으로 이해되나, 신규 API 추가 시에는 DTO/Record를 도입하면 컴파일 타임에 오타·누락 필드를 잡을 수 있습니다.
🟢 syncLicenseFromHistory() — 미구현 스텁
public int syncLicenseFromHistory(Map<String, Object> param) { return 0; } 메서드가 존재합니다. Phase 2에서 이력 → 현재 상태 동기화 기능이 구현될 예정으로 보이며, throw new UnsupportedOperationException("미구현")으로 명시해두는 것이 명확합니다.
