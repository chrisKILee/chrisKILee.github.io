01 개요

왜 멀티 에이전트인가?

하나의 AI가 설계·구현·테스트를 모두 처리하면 컨텍스트가 뒤섞이고 품질이 낮아집니다. oh-my-agent는 실제 팀 구조를 그대로 모방합니다.

📦
포터블(Portable) 설계

.agents/ 디렉토리가 프로젝트와 함께 이동합니다. Claude Code, Gemini CLI, Cursor, Codex CLI 등 어떤 도구를 써도 같은 스킬 정의를 공유합니다.

vendor-agnostic
🎯
역할 기반 전문화

아키텍처·백엔드·프론트엔드·모바일·DB·QA·디버그 등 실제 팀 구조를 그대로 반영합니다. 각 에이전트는 자신의 도메인에만 집중합니다.

role-based
⚡
2계층 스킬 설계

공식 주장에 따르면 스킬을 핵심 로직과 컨텍스트 계층으로 분리해 약 75% 토큰 절감 효과를 냅니다. 각 에이전트는 필요한 컨텍스트만 로드합니다.

token-efficient

03 워크플로우

7개 슬래시 커맨드

개발 프로세스를 구조화하는 내장 워크플로우입니다. 자연어에서 자동으로 의도를 감지해 적절한 워크플로우를 활성화합니다 (11개 언어 지원).

/brainstorm
아이디어 발상
요구사항 브레인스토밍. 아키텍처 에이전트 참여, 기술 결정사항 도출.
/plan
작업 계획 수립
요구사항을 실행 가능한 작업으로 분해. PM + 조율 에이전트 처리.
/work
멀티 에이전트 실행
지정된 에이전트들이 병렬로 작업을 수행합니다.
/ultrawork
고급 품질 검증
5단계 품질 프로세스 + 11개 체크포인트 포함. 프로덕션 수준 결과물.
/review
코드 리뷰
보안·성능 감시. 아키텍처 + QA 에이전트가 감시합니다.
/architecture
아키텍처 분석
시스템 설계 검토. 확장성·복잡도·비용 트레이드오프 분석.
/debug
문제 해결
근본 원인 조사. 임시 대응과 영구 개선안을 구분해 제시.
자연어 자동 감지
"새로운 기능 계획 세워줄래?" → /plan 자동 활성화 / "Let's brainstorm the architecture" → /brainstorm 자동 활성화. 한국어·영어·일본어 등 11개 언어를 인식합니다.
04 시작하기

설치 및 기본 사용법

사전 요구사항: bun과 uv가 필요합니다. Windows 사용자는 두 의존성을 먼저 수동 설치하세요.

1
설치
한 줄 명령어로 설치합니다. 또는 bunx oh-my-agent@latest로도 실행 가능합니다.
bash 
curl -fsSL https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.sh | bash
2
프리셋 선택
설치 후 역할 기반 팀 구성을 선택합니다: All / Fullstack / Frontend / Backend / Mobile / DevOps.
3
워크플로우 실행
슬래시 커맨드나 자연어로 작업을 시작합니다.
bash 
# 아이디어 발상 → 계획 → 구현 플로우
/brainstorm OAuth 2.0 소셜 로그인 시스템 설계
/plan 마이크로서비스 백엔드 구현
/ultrawork React + Node.js 풀스택 완성

# 특정 에이전트 단독 실행
oma agent:spawn --agent backend --task "API 엔드포인트 구현"

# 여러 에이전트 병렬 실행
oma agent:parallel --agents frontend,backend --task "사용자 인증 기능"

# 시스템 상태 확인
oma doctor

# 실시간 대시보드
oma dashboard
4
HWP 문서 변환 (한국 사용자)
한글(HWP/HWPX) 문서를 Markdown으로 변환하는 oma-hwp 에이전트가 내장되어 있습니다. v5.12.0에서 추가된 기능입니다.
bash 
oma agent:spawn --agent oma-hwp --task "기술 스펙 문서 변환"
05 아키텍처

.agents/ 디렉토리 규격

프로젝트 루트의 .agents/가 모든 에이전트·스킬·워크플로우의 단일 소스입니다. 각 AI IDE는 이 디렉토리를 읽어 호환성 뷰를 생성합니다.

directory tree 
.agents/
├── agents/          # 에이전트 정의 (벤더 무관)
├── skills/          # 재사용 가능한 스킬 정의
│   ├── oma-architecture/
│   ├── oma-backend/
│   ├── oma-frontend/
│   ├── oma-db/
│   ├── oma-qa/
│   ├── oma-hwp/     # HWP 변환 (v5.12.0+)
│   └── _shared/     # 공유 유틸리티
├── workflows/       # 멀티 단계 오케스트레이션 (work, ultrawork, plan 등)
├── hooks/           # 트리거 기반 자동 스킬 주입
├── rules/           # 에이전트 동작 규칙
├── results/         # 출력/결과 저장소
├── mcp.json         # Model Configuration Protocol 설정
└── oma-config.yaml  # 메인 에이전트 설정
한 번 작성, 모든 벤더에서 사용
.agents/ 아래에 스킬을 한 번 정의하면 Claude Code(.claude/), Gemini CLI, Codex CLI, Cursor 등 각 도구가 자동으로 호환성 뷰를 생성합니다. 벤더를 바꿔도 스킬 정의를 다시 작성할 필요가 없습니다.
06 호환성

멀티 벤더 지원

Claude Code, Gemini CLI, Cursor, Codex CLI, Amp, GitHub Copilot 등 주요 AI 개발 도구를 모두 지원합니다.

벤더 호환성 방식 비고
Claude Code .claude/ 경로 + 네이티브 어댑터 태스크 기반 서브에이전트 완전 지원
Gemini CLI 마크다운 에이전트 파일 네이티브 태스크 기능
Codex CLI TOML 에이전트 정의 동일 벤더 네이티브 디스패치
Cursor / Amp / OpenCode 프로젝트 레벨 스킬 소스 직접 사용 기본 레이아웃
GitHub Copilot 선택적 symlink 설정 수동 설정 필요
Antigravity .agents/agents/ 직접 읽음 기본 레이아웃 지원
