Overview

앱 구성 한눈에 보기

AI Worker는 3개의 주요 화면으로 구성되어 있습니다. 상단 네비게이션 바를 통해 각 화면으로 이동할 수 있습니다.

📋

내 태스크

Jira 이슈를 필터링하여 리스트 또는 캘린더로 조회합니다. 우선순위, 상태 전환, 메모, 차트 등 업무 관리에 필요한 모든 기능을 제공합니다.

✦

AI 코칭

AI가 업무 데이터를 분석하여 개인화된 코칭 리포트를 생성합니다. 액션 플랜, 업무 그룹핑, 주간 목표를 제안합니다.

⚙️

설정

Jira 연동 정보와 AI 제공자 API 키를 설정합니다. 연결 테스트로 즉시 확인할 수 있습니다.

Quick Start

시작하기

3단계로 AI Worker를 시작할 수 있습니다.

설정 페이지 이동

상단 네비게이션의 설정을 클릭합니다. Jira URL, 이메일, API 토큰을 입력하고 연결 테스트 및 저장을 클릭합니다.

AI 제공자 설정

같은 페이지에서 AI 제공사(OpenAI, Gemini, Claude 중 택 1)를 선택하고 API 키를 입력합니다. AI를 사용하지 않아도 태스크 조회는 가능합니다.

업무 조회 시작

내 태스크에서 기간과 필터를 선택하고 조회를 누르면 Jira 이슈가 표시됩니다. AI 코칭에서 보고서를 생성할 수 있습니다.

Desktop

데스크톱 앱

AI Worker는 Electron으로 패키징되어 macOS, Windows에서 독립 실행 파일로 사용할 수 있습니다.

🍎

macOS

AI Worker-0.1.0-arm64.dmg 파일을 열어 Applications 폴더에 드래그합니다. Apple Silicon(M1/M2/M3) 기반입니다.

🪟

Windows

AI Worker Setup 0.1.0.exe를 실행하면 자동으로 설치됩니다. 별도의 Node.js 설치가 필요하지 않습니다.

📦
빌드 명령어
macOS: npm run electron:build:mac
Windows: npm run electron:build:win
결과물은 dist-electron/ 폴더에 생성됩니다.

electron:prepare 단계

scripts/prepare-standalone.js가 수행하는 작업:

  • .next/standalone/에서 server.js 위치를 찾아 .next/standalone-app/으로 복사
  • 정적 에셋 (.next/static)을 standalone 디렉토리에 복사
  • public 에셋을 standalone 디렉토리에 복사
  • node_modules를 deps로 이름 변경 (electron-builder가 node_modules를 제외하므로)

서버 구동

ELECTRON_RUN_AS_NODE=1로 Electron 바이너리를 순수 Node.js로 실행하여 Next.js standalone 서버 구동.

모듈 경로

NODE_PATH 환경변수로 deps 폴더를 지정. Program Files 등 보호된 경로에서도 동작.

윈도우 설정

1400×900 (최소 900×600), macOS hiddenInset 타이틀바, 다크 배경색.

Overview

API 통신 구조

모든 API는 Next.js Route Handler (/src/app/api/)로 구현되며, 클라이언트에서 서버로 POST 요청을 보내면 서버가 Jira/AI 외부 API를 호출하고 결과를 반환합니다. 설정 정보는 브라우저 localStorage에 저장됩니다.

브라우저 (React)
→
Next.js API Route
→
Jira / Confluence / AI API
→
JSON 응답
→
화면 렌더링

왜 POST를 사용하는가?

모든 요청에 Jira/AI 인증 정보(API 토큰, 키)가 포함되기 때문에 보안상 GET이 아닌 POST body로 전달합니다. API 키는 서버 환경변수가 아닌 클라이언트 localStorage에서 관리되므로 매 요청마다 body에 포함됩니다.

⚙️

설정 저장 방식

localStorage에 jira_config, ai_config 키로 JSON 저장. 서버 DB 불필요.

🔒

인증 방식

Jira: Basic Auth (email + API token). AI: 각 프로바이더 API Key 사용.

⚡

응답 형식

모든 API는 JSON으로 응답하며, 에러 시 { error: string }과 적절한 HTTP 상태코드를 반환.

Jira REST API v3와 통신하여 이슈 조회, 상태 전환, 프로젝트/라벨/사용자 정보를 가져옵니다.

JQL 쿼리 빌더

필터 조건에 따라 동적으로 JQL(Jira Query Language)을 생성합니다.

// 필터 조건 → JQL 변환 예시 project = "PROJ" AND labels = "frontend" AND labels = "sprint-1" // AND 모드 AND labels IN ("frontend", "sprint-1") // OR 모드 AND updated >= "2024-01-01" AND updated <= "2024-03-31" AND assignee IN ("user-id-1", "user-id-2") ORDER BY updated DESC

최대 1,000건까지 조회하며, 100건씩 병렬 페이지네이션으로 가져옵니다. Jira ADF(Atlassian Document Format) 설명은 자동으로 Plain Text로 변환됩니다.

대기 중

라벨 조회 방식

전체 라벨 조회

프로젝트 미선택 시 Jira /rest/api/3/label 엔드포인트로 전체 라벨을 가져옵니다.

프로젝트별 라벨

프로젝트 선택 시 해당 프로젝트 이슈들의 라벨을 JQL로 수집하여 중복 제거 후 반환합니다.

AND / OR 연산자

라벨 필터링 모드

// AND 모드: 선택한 모든 라벨을 가진 이슈만 labels = "frontend" AND labels = "sprint-1" // OR 모드: 선택한 라벨 중 하나라도 가진 이슈 labels IN ("frontend", "sprint-1")

UI에서 라벨 선택 후 AND/OR 토글로 모드를 전환할 수 있습니다. AND는 교집합(더 엄격), OR는 합집합(더 넓은 범위)입니다.

라벨 활용 위치
  • 태스크 필터: 다중 라벨 선택으로 이슈 필터링
  • 이슈 목록: 각 이슈에 라벨 배지 표시
  • 통계 차트: 상위 10개 라벨 빈도 분석 (수평 바 차트)
  • AI 리포트: 이슈 데이터에 라벨 정보 포함되어 AI 분석에 활용
Architecture

전체 데이터 흐름

각 기능별 API 호출 순서와 데이터 변환 과정입니다.

태스크 페이지 데이터 플로우
1. 페이지 로드 localStorage → loadJiraConfig() → JiraConfig 2. 사용자 정보 조회 POST /api/jira/me → { accountId, displayName } 3. 프로젝트 & 라벨 조회 POST /api/jira/projects → { projects[] } POST /api/jira/labels → { labels[] } 4. 이슈 검색 (사용자 "조회" 클릭) POST /api/jira/issues + ReportFilter → JQL 빌더 → Jira API (100건 × N 페이지 병렬) → ADF → Plain Text 변환 → { issues[], summary } 5. 클라이언트 통계 계산 (useMemo) issues[] → 상태 분포, 우선순위 분포, 완료 추이, 요일별 패턴, 라벨 분포, KPI 산출 6. 인라인 액션 상태 변경: POST /api/jira/transitions → POST /api/jira/transition 메모 저장: localStorage (issue_{key}_note)

KPI 계산 완료율, 진행 중, 마감 초과, 7일+ 정체 수 4.
