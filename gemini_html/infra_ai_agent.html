⚡ 이런 불편함이 있었습니다

기존 수작업 방식의 한계를 자동화로 해결합니다.

BEFORE
기존 방식 — 수작업 점검
  • 설정 파일을 수동으로 열어 항목별로 직접 확인
  • 반복적인 작업으로 많은 시간 소요
  • 담당자에 따라 점검 결과가 달라질 수 있음
  • 조치 방법을 별도로 검색하고 정리해야 함
  • 보고서 작성도 수작업으로 추가 시간 필요
AFTER
AI Agent — 자동화 점검
  • Agent 실행 한 번으로 설정 자동 수집 및 분석
  • 수분 내 전체 항목 점검 완료
  • 룰 기반으로 일관된 PASS/FAIL 판정
  • AI가 위험 설명과 구체적인 조치 가이드 즉시 제공
  • 점검결과보고서 자동 생성 — 감사 대응도 간편하게

🚀 주요 기능

네 가지 핵심 기능이 순서대로 자동으로 동작합니다.

⚙️
보안 설정 자동 수집 및 분석
Tomcat의 주요 설정 파일(server.xml, context.xml, web.xml 등)에서 보안 관련 설정값을 자동으로 읽어 분석합니다.
📋
룰 기반 준수 여부 자동 판정
주정통 기반 보안취약점 점검 기준에 따라 각 항목의 PASS / FAIL / N/A를 자동으로 판정합니다. 담당자에 상관없이 일관된 결과를 제공합니다.
🤖
AI 기반 위험 설명 및 조치 가이드
FAIL 항목에 대해 AI가 위험도와 영향을 설명하고, 구체적인 조치 방법과 설정 예시를 자동으로 생성합니다.
📄
점검결과보고서 자동 생성
점검 완료 후 동일 경로에 구조화된 보고서 파일이 자동으로 생성됩니다. 정기 점검 및 감사 대응 시 즉시 활용 가능합니다.
🔍
예외 처리 자동 안내
OS 환경에 따라 직접 점검이 어려운 항목은 N/A로 자동 분류하고, 수동 점검이 필요한 사항을 명확히 안내합니다.
🪶
설치 없는 Portable 실행
별도 설치 없이 실행 파일(.exe) 하나만으로 동작합니다. Tomcat이 설치된 서버에서 바로 실행할 수 있어 배포와 사용이 간편합니다.

🛡️ 점검 항목

주정통 기반 보안취약점 점검 기준에 따라 총 13개 항목을 점검합니다.

🗂️ 관리자/기본 앱 관리
  • › Tomcat 버전 최신화 여부
  • › 기본 웹 앱(docs, examples) 제거 여부
  • › Manager 앱 접근 제한 설정
  • › 관리자 계정 취약 비밀번호 여부
🔌 Connector 및 포트 설정
  • › AJP Connector 비활성화 여부
  • › HTTPS Connector 설정 여부
  • › 서버 버전 정보 노출 방지 설정
  • › Shutdown 포트 비활성화 여부
🔐 인증·권한 및 보안 옵션
  • › 세션 쿠키 HttpOnly / Secure 설정
  • › 디렉토리 리스팅 비활성화
  • › 서비스 실행 계정 권한 최소화
  • › 파일 시스템 권한 설정
📋 로그 및 오류 처리
  • › AccessLogValve 설정 여부

💡 사용 방법

단 3단계로 점검을 완료할 수 있습니다.

1

Agent 파일 수령

담당자로부터 security-agent-win.exe 파일을 전달받습니다.

2

Tomcat Home 경로로 파일 이동

다운로드한 Agent 파일을 Tomcat이 설치된 폴더(Tomcat Home)로 복사합니다.

3

명령 프롬프트에서 실행

Tomcat Home 경로에서 명령 프롬프트(cmd)를 열고 아래와 같이 실행합니다.
