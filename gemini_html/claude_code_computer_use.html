01 — What Changed

기존 Claude Code와 뭐가 다른가

터미널 안에만 머물던 Claude가 화면을 보기 시작했다.

BEFORE — 기존 Claude Code
터미널 안에서만 동작
코드 읽기, 수정, 테스트 실행, git 커밋
전부 텍스트(CLI) 기반
GUI 앱 조작 불가
AFTER — Computer Use 추가
화면(스크린샷)을 직접 보고 인식
마우스 클릭 + 키보드 입력 전송
SwiftUI·Electron·CLI 없는 GUI 도구 조작
Mac에서 열 수 있으면 모두 조작 가능
💡 실제 데모: SPM3000이라는 픽셀 아트 앱을 대상으로 코드를 컴파일하고, 앱을 열고, 화면을 보고, 렌더링 문제를 찾아서 수정하는 과정을 프롬프트 하나로 수행했습니다.
02 — Architecture

커넥터 우선(Connector-First) 구조

화면 제어는 최후의 수단. API가 있으면 API를 쓴다.

🔌
커넥터 우선
Slack, Google Calendar 등 API 커넥터가 있으면 그쪽을 먼저 사용합니다. OpenClaw, Manus 같은 경쟁 에이전트와의 핵심 차이점입니다.
📸
화면 제어는 최후 수단
화면 제어는 스크린샷을 계속 찍어야 해서 토큰 소비가 매우 큽니다. API를 쓸 수 없을 때만 화면 제어로 넘어갑니다.
🔒
앱별 권한 시스템
Claude가 새 앱을 열거나 클릭할 때마다 사용자 허락을 요청합니다. 프롬프트 인젝션(외부 콘텐츠가 명령을 삽입하는 공격) 스캐닝도 함께 실행됩니다.
03 — Dispatch Integration

Dispatch와 합치면 달라지는 것

Dispatch: 폰에서 시킨 작업이 데스크톱에서 실행되는 기능.

1
출근길에 폰으로 지시
"어제 대시보드에서 주간 리포트 뽑아서 정리해둬"라고 Dispatch로 전송합니다.
2
Mac에서 Claude가 자동 실행
데스크톱에서 대시보드를 열고, 필터를 설정하고, CSV를 다운로드합니다.
3
스프레드시트로 정리 완료
도착할 즈음에는 리포트가 이미 정리되어 있습니다.
🎯 노리는 틈새: API가 없는 내부 대시보드, CRM(고객관리), 레거시 시스템. 화면을 보고 클릭하는 수밖에 없었던 영역이 Computer Use의 주요 타겟입니다.
04 — Limitations

Anthropic이 직접 인정한 한계

공개 문서에 명시된 제약입니다. 임의로 추가한 내용 없음.

🚨 보안 주의: Computer Use는 실제 데스크톱에서 직접 실행됩니다. Cowork의 VM 격리 환경과 달리 샌드박스 밖입니다. 민감한 정보는 아직 사용하지 않을 것을 Anthropic이 권고합니다.
🍎
macOS 전용
Windows 지원 시점은 미정입니다.
🔁
복잡한 작업은 재시도 필요
공식 문서에 "sometimes need a second try"라고 명시되어 있습니다.
⏱️
한 작업에 100초 이상
화면 조작은 API 연결보다 느립니다. 스크린샷을 반복 촬영해야 하기 때문입니다.
🪙
토큰 소비 매우 많음
일반 채팅 대비 토큰 소비가 훨씬 많습니다. Pro 플랜은 사용량 제한에 금방 도달할 수 있습니다.

05 — Takeaway

총평

Anthropic이 "아직 완벽하지 않다"고 전면에 내세우면서 공개한 게 인상적이에요. 완성도를 높여서 출시하는 게 아니라, 사용자 피드백을 받으면서 빠르게 개선하겠다는 접근. 코드를 짜는 에이전트가 자기 결과물을 직접 눈으로 확인하는 구조가 드디어 열렸습니다.
