바이브 코딩의 고질적 문제

AI 코딩 도구에게 "Button 만들어줘"를 시키면 어떤 일이 벌어지나요?

⚠️
AI는 학습 데이터 기준으로 작동합니다
공식 API가 업데이트돼도 AI는 모릅니다. prop 이름을 틀리고, 이미 deprecated(더 이상 사용하지 않는) 패턴을 쓰고, 존재하지 않는 variant를 호출합니다. 버전이 올라갈수록 격차가 커집니다.

🛡️ AI 오류 방지

AI 실수를 세 겹으로 막는다

HeroUI v3가 바이브 코딩의 고질적 문제를 해결하는 방식

🔌
1. MCP 서버
Claude Code, Cursor, VS Code Copilot, Windsurf 같은 AI 도구에 연결합니다. AI가 컴포넌트 문서, props, 소스 코드, 테마 변수를 직접 읽어요. 학습 데이터에서 추측하는 게 아니라 원본을 참조합니다.

"HeroUI 최신 버전으로 업데이트해줘"라고 하면 버전 비교 → 브레이킹 체인지 탐색 → 코드 수정을 자동으로 처리합니다.
🧠
2. Agent Skills
Cursor와 Claude Code용 지식 팩입니다. 컴포넌트 패턴, variant 사용법, 테마 설정, 업그레이드 가이드가 미리 들어 있어요.

AI가 HeroUI 코드를 처음부터 올바르게 작성합니다. 잘못된 API를 사용할 가능성 자체를 줄이는 방식입니다.
📄
3. LLMs.txt
구조화된 문서 파일을 /llms.txt와 /llms-components.txt로 공개합니다.

모든 LLM 도구가 읽을 수 있는 기계 친화적 API 요약본입니다. 특정 도구에 종속되지 않고, 어떤 AI든 최신 API를 참조할 수 있습니다.
🏗️ 아키텍처

v2 → v3, 무엇이 바뀌었나

단순 기능 추가가 아니라 전체를 다시 설계했습니다

항목 v2 (이전) v3 (새로) 영향
컴포넌트 구조 블랙박스 — 내부 수정 불가, className prop 범위 내에서만 커스터마이징 Compound Component — Card.Header, Card.Body, Card.Footer가 독립적 엘리먼트 커스터마이징 자유도 대폭 향상
애니메이션 Framer Motion 의존 (JS 런타임 번들 포함) CSS 트랜지션 + 키프레임 (data attribute 연결) 번들 경량화, GPU 가속
스타일 분리 스타일과 동작이 하나의 패키지에 묶임 @heroui/styles (독립 CSS 패키지) + @heroui/react (동작만) Headless 사용 가능
테마 JS 테마 객체, Provider 컴포넌트 필요 CSS 변수 (OKLCH 색상), Tailwind v4 네이티브, CSS 2줄로 완성 설정 간소화
오버라이드 className prop 전달 방식 BEM 클래스명 — CSS에서 직접 전역 오버라이드 CSS 본연의 방식으로 처리
AI 지원 없음 MCP 서버 + Agent Skills + LLMs.txt AI 코딩 정확도 향상
React Native 없음 HeroUI Native — 37개 컴포넌트, 디자인 토큰 공유 웹/앱 동시 지원

HeroUI Native — 웹과 동일한 패턴

37개 컴포넌트, 같은 이름·같은 prop·디자인 토큰 공유

💡
Adaptive Presentation Modes
Popover, Select, Menu가 prop 하나로 popover → bottom-sheet → dialog 사이를 전환합니다. 같은 컴포넌트인데 맥락에 따라 다르게 표시됩니다. 현재 다른 React Native 라이브러리에는 없는 기능입니다.
TSX — 웹 vs 네이티브 비교
// 웹 (heroui/react) import { Alert } from '@heroui/react'; <Alert variant="danger">에러 메시지</Alert> // 네이티브 — 거의 동일한 패턴 import { Alert } from '@heroui/native'; <Alert variant="danger">에러 메시지</Alert> // Adaptive Presentation Mode <Select presentation="bottom-sheet" // popover | bottom-sheet | dialog > ... </Select>
ℹ️
디자인 토큰(accent, surface, danger 등)이 웹과 네이티브에서 동일하게 적용됩니다. 브랜드 색상을 두 시스템에서 따로 관리할 필요가 없습니다.

⚖️ 평가

장점과 한계

도입 전에 확인해야 할 실질적인 트레이드오프

✅ 장점
AI 정확도 향상 — MCP 서버로 AI가 최신 API를 직접 참조. 잘못된 prop 사용 빈도가 줄어듦
번들 경량화 — Framer Motion 제거로 JS 애니메이션 런타임이 번들에서 빠짐
커스터마이징 자유도 — Compound Component 패턴으로 컴포넌트 내부 구조를 자유롭게 제어
Headless 선택지 — @heroui/styles 없이 @heroui/react만 써서 스타일을 직접 제어 가능
Tailwind v4 네이티브 — CSS 변수 레이어 위에서 동작, 설정 오버헤드 최소화
웹 + 앱 일관성 — 웹과 React Native가 동일한 디자인 토큰 공유
Figma 1:1 매칭 — 디자인-개발 간 gap 최소화
⚠️ 한계 및 주의사항
v2 → v3 마이그레이션 비용 — 컴포넌트 구조가 완전히 바뀌어 기존 v2 코드는 대규모 수정이 필요
Tailwind v4 의존 — Tailwind v3 기반 프로젝트는 CSS 레이어가 달라 별도 설정이 필요
Framer Motion 대체 불완전 — CSS 애니메이션으로 커버되지 않는 복잡한 제스처/인터랙션은 직접 구현 필요
MCP 서버 설정 필요 — AI 도구 연동 효과를 보려면 팀 내 모든 개발자가 MCP 서버를 개별 설정해야 함
커뮤니티 생태계 성숙도 — v3가 새로 출시되어 서드파티 확장, Stack Overflow 답변 등이 아직 적음
React Native 별도 설치 — 웹과 네이티브는 별도 패키지(@heroui/native)로 코드 공유는 개념 수준
💡 활용 예시

바이브 코딩에 실제로 적용하면

AI 코딩 도구와 HeroUI v3를 함께 쓰는 구체적인 시나리오

🤖
시나리오 1: AI에게 자동 업그레이드 위임
"HeroUI v2에서 v3로 업그레이드해줘"라고 하면 AI가 MCP 서버로 체인지로그를 읽고, 브레이킹 체인지를 찾아 코드를 자동 수정합니다. Codemod처럼 동작하는데 맥락을 이해하며 수정한다는 차이가 있습니다.
📊
시나리오 2: 대시보드 빠르게 조립
Table(정렬+가상화), Tabs(뷰 전환), DateRangePicker(기간 필터), ProgressBar(현황 시각화)를 AI에게 지시. MCP 서버가 연결돼 있어 각 컴포넌트의 정확한 props를 그대로 사용합니다.
🎨
시나리오 3: 브랜드 테마 적용
Theme Builder에서 색상·라운딩을 시각적으로 설정하고 CSS를 내보냅니다. 브랜드 CSS 변수를 파일에 붙여넣는 것만으로 전체 컴포넌트에 테마가 반영됩니다. Provider 설정이나 JS 객체 수정 없이 끝납니다.
📱
시나리오 4: 웹+앱 동시 개발
웹은 @heroui/react, 앱은 @heroui/native. 같은 디자인 토큰과 같은 컴포넌트 이름을 공유해서, 웹에서 만든 디자인 결정이 앱에도 자동으로 반영됩니다. 브랜드 색상을 두 번 관리할 필요가 없습니다.
🔧
시나리오 5: Headless로 완전 커스텀 UI
@heroui/styles를 제거하면 접근성(React Aria)과 키보드 네비게이션은 유지하면서 스타일을 완전히 직접 제어합니다. 디자인 시스템이 엄격한 기업 환경에서 적합합니다.
🌐
시나리오 6: 국제화 앱 Calendar 구현
Calendar 컴포넌트에 calendar prop 하나로 불교·페르시아·그레고리안 달력을 전환합니다. 날짜 국제화 라이브러리를 별도로 설치하거나 복잡한 로직을 작성할 필요가 없습니다.
🎯 적합성

누구에게 적합한가

대상 적합도 이유
AI 코딩 도구로 프로토타입 빠르게 만드는 팀 높음 MCP 서버로 AI 오류 감소, 컴포넌트 조합이 명확해 AI 지시 효율 향상
웹 + React Native 동시 개발팀 높음 같은 토큰·같은 패턴으로 두 플랫폼 일관성 유지
Tailwind v4 신규 프로젝트 높음 CSS 변수 레이어가 맞아 설정 오버헤드 거의 없음
기존 Tailwind v3 + v2 HeroUI 프로젝트 중간 마이그레이션 비용 발생. 신규 기능이 꼭 필요한지 먼저 평가
엄격한 디자인 시스템이 있는 기업 중간 Headless 모드로 사용 가능하지만 팀 내 학습 비용 발생
복잡한 제스처 애니메이션이 핵심인 앱 낮음 Framer Motion 제거로 복잡한 인터랙션 구현 시 직접 코드 작성 필요
