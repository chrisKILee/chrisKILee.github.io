Browser Use CLI 2.0

속도 2배, 비용 절반. Playwright를 완전히 제거하고 CDP(Chrome DevTools Protocol)로 재설계된 브라우저 자동화 도구. 실행 중인 내 Chrome에 직접 붙어 로그인 세션·쿠키·상태를 그대로 활용할 수 있습니다.

💡 핵심 차이점: 기존 도구들은 새 브라우저를 띄우거나 세션을 별도 저장·복원해야 했지만, Browser Use CLI 2.0은 이미 내가 로그인해 놓은 Chrome을 그대로 사용합니다. 사내 대시보드나 레거시 시스템처럼 로그인 자동화가 까다로운 환경에서 특히 강점을 발휘합니다.

2.0 핵심 개선점

BU 모델 2.0(2026년 1월 27일) 기준 OnlineMind2Web 벤치마크에서 평균 소요 시간 68초, 정확도 83.3%를 기록했습니다.

⚡
속도 2배 이상
평균 68초 처리. Gemini 2.5(225s), Claude Sonnet(285s), OpenAI(330s) 대비 3~5배 빠릅니다.
💰
비용 절반
액션당 10~15 출력 토큰만 사용. BU-30B-A3B-Preview 오픈소스 모델은 $1당 200태스크(초기 대비 4배 효율).
🔗
CDP 직접 연결
Playwright 의존성 완전 제거(2025년 8월). 실행 중인 Chrome을 CDP(Chrome DevTools Protocol)로 직접 제어합니다.
🧩
멀티세션 데몬
Unix 소켓 기반 백그라운드 데몬이 브라우저를 상시 유지. 명령 지연 ~50ms, 명명된 다중 세션 독립 운영 가능.

Chrome 연결 방식 3가지

  1. 자동 탐지 (--connect)
    실행 중인 Chrome을 CDP로 자동 발견. 별도 설정 없이 바로 사용 가능합니다.
  2. CDP URL 명시 (--cdp-url)
    HTTP 또는 WebSocket 엔드포인트를 직접 지정. --cdp-url http://localhost:9222 형식으로 사용합니다.
  3. Chrome 프로필 사용 (--profile)
    실제 Chrome 사용자 프로필(Default, Work 등)을 그대로 로드. 모든 쿠키·로그인 세션이 살아있는 상태로 자동화합니다.
  4. 원격 디버깅 포트 활성화
    Chrome을 --remote-debugging-port=9222 옵션으로 실행하거나 chrome://inspect에서 토글합니다.

4가지 성능 최적화 기법

기법동작 방식효과
KV Cache 활용 프롬프트에서 대화 이력을 브라우저 상태보다 앞에 배치 → 전체 히스토리에 캐시 히트 반복 요청 시 토큰 비용 대폭 절감
선택적 스크린샷 DOM 추출 위주로 동작. 시각 정보가 반드시 필요할 때만 캡처 스크린샷 1장당 추론 지연 약 0.8초 절약
스마트 텍스트 추출 extract 도구로 DOM에서 필요한 부분만 마크다운 쿼리 2만 토큰 이상 페이지도 필요한 정보만 추출
간결한 액션 공간 액션명·파라미터를 짧게 설계 (출력 토큰이 입력 토큰보다 215배 느리고 비쌈) 대부분 액션을 10~15 출력 토큰으로 처리
⚠️ 실행 중인 Chrome 프로필에 직접 접근하므로, 사내 시스템 자동화 시 IT 보안 정책을 사전에 확인하세요. 세션 데이터는 ~/.browser-use/ 디렉토리에 저장됩니다.
설치 & 빠른 시작

설치 & 빠른 시작

원라인 설치 스크립트 또는 uv로 설치합니다. 40개 이상의 CLI 명령어를 제공합니다.

설치

원라인 설치 (macOS / Linux 권장)
# 원라인 설치 curl -fsSL https://browser-use.com/cli/install.sh | bash # 또는 uv로 수동 설치 uv pip install browser-use browser-use install # Chromium 다운로드 browser-use doctor # 설치 검증

Chrome 연결

연결 방식별 예시
# 1. 실행 중인 Chrome 자동 탐지 browser-use --connect open https://example.com # 2. CDP URL 명시 browser-use --cdp-url http://localhost:9222 open https://example.com # 3. 내 Chrome 프로필 그대로 사용 (로그인 상태 유지) browser-use --profile "Default" open https://company-dashboard.internal # Chrome 원격 디버깅 포트 활성화 (별도 터미널) google-chrome --remote-debugging-port=9222

주요 명령어

40개 이상의 명령어를 제공합니다. 카테고리별 핵심 명령어입니다.

browser-use open [URL]
페이지 열기 (--headed로 화면 표시)
browser-use state
클릭 가능한 요소 + 인덱스 출력
browser-use click [N]
인덱스 N번 요소 클릭
browser-use type [텍스트]
현재 포커스된 요소에 텍스트 입력
browser-use input [N] [값]
N번 인풋 필드에 값 입력
browser-use screenshot out.png
스크린샷 저장 (--full: 전체 페이지)
browser-use -s NAME open [URL]
명명된 세션으로 브라우저 열기
browser-use get text
페이지 텍스트 추출
browser-use eval [JS]
JavaScript 코드 실행
browser-use upload [N] [파일]
파일 업로드
browser-use python [코드]
Python 지속 세션 실행 (변수 유지)
browser-use sessions
현재 활성 세션 목록 보기

Python 지속 세션

Python 변수를 세션 간에 유지할 수 있습니다. 브라우저 객체에도 직접 접근 가능합니다.

browser-use python "x = 42" browser-use python "print(x)" # 42 (변수 유지됨) browser-use python "print(browser.url)" # 현재 URL 출력
✅ 멀티세션 데몬이 백그라운드에서 브라우저를 항상 열어두므로, 다음 명령은 새 Chrome을 띄우지 않고 약 50ms 지연으로 즉시 실행됩니다. browser-use close --all로 모든 세션을 종료할 수 있습니다.
핵심 기술

핵심 기술 — CDP & 데몬 아키텍처

Playwright를 완전 제거하고 CDP(Chrome DevTools Protocol) 직접 통신으로 전환한 2.0의 내부 구조를 설명합니다.

멀티세션 데몬 아키텍처

멀티세션 데몬이 여러 Chrome 인스턴스를 관리. -s NAME으로 세션을 구분합니다.

CDP vs Playwright

Browser Use 2.0은 2025년 8월에 Playwright 의존성을 완전히 제거하고 CDP로 전환했습니다.

항목1.x (Playwright)2.0 (CDP)
브라우저 제어 Playwright API 래핑 CDP 직접 통신
실행 중인 Chrome 연결 제한적 --connect / --profile 즉시 지원
의존성 Playwright (무거움) 경량 CDP 클라이언트
프로세스 모델 명령마다 새 프로세스 데몬 + Unix 소켓 (~50ms)
멀티 세션 단일 세션 명명된 다중 세션 (-s NAME)

KV 캐시 최적화 — 프롬프트 구조

2.0에서는 대화 이력을 프롬프트 앞에 배치하여 KV 캐시 히트율을 극대화합니다. 현재 브라우저 상태(매 스텝마다 바뀌는 부분)만 새로 처리하므로 반복 작업에서 토큰·비용이 크게 절감됩니다.

Claude Code 연동

Claude Code 연동 방법

Browser Use CLI는 Claude Code를 포함한 모든 CLI 에이전트와 연동할 수 있습니다. 3가지 방식 중 용도에 맞게 선택하세요.

방법 A — Skill 파일 설치 (가장 간단)

Claude Code의 SKILL.md 시스템을 활용합니다. Claude Code가 파일을 읽고 어떤 CLI 명령을 실행할지 자동으로 이해합니다.

# 스킬 디렉토리 생성 후 SKILL.md 다운로드 mkdir -p ~/.claude/skills/browser-use curl -o ~/.claude/skills/browser-use/SKILL.md \ https://raw.githubusercontent.com/browser-use/browser-use/main/skills/browser-use/SKILL.md
💡 설치 후 Claude Code에서 "browser-use로 X 페이지 열어줘" 같이 자연어로 요청하면 됩니다. Claude Code가 SKILL.md를 읽고 적절한 browser-use 명령을 자동으로 실행합니다.

방법 B — 로컬 MCP 서버 (오픈소스, 자체 API 키)

stdio MCP 서버로 실행하는 방식입니다. 별도 클라우드 계정 없이 로컬에서 동작합니다.

MCP 서버 실행
uvx --from browser-use[cli] browser-use --mcp
Claude Code mcp.json 등록
{ "mcpServers": { "browser-use": { "command": "uvx", "args": ["--from", "browser-use[cli]", "browser-use", "--mcp"] } } }

제공 MCP 도구: browser_task, list_browser_profiles, monitor_task

방법 C — 클라우드 API MCP (Browser Use 계정 필요)

Browser Use Dashboard에서 API 키를 발급받아 사용하는 방식입니다. 원격 실행 및 모니터링이 가능합니다.

# Claude Code에 Browser Use MCP 서버 추가 claude mcp add --transport http browser-use https://api.browser-use.com/mcp

실제 사용 시나리오 — 사내 대시보드 자동화

# 이미 로그인된 Chrome으로 사내 대시보드 접근 browser-use --profile "Default" open https://internal-dashboard.company.com # 현재 페이지 상태 확인 (클릭 가능한 요소 인덱스 출력) browser-use state # 데이터 추출 browser-use get text # 스크린샷 저장 browser-use screenshot report.png --full
✅ 별도 로그인 자동화 없이 내가 이미 로그인한 Chrome 프로필을 그대로 사용합니다. 2FA나 SAML SSO가 적용된 사내 시스템에서도 별도 인증 설정 없이 동작합니다.

Browser Use CLI 2.0 vs agent-browser

Vercel Labs의 agent-browser와 Browser Use CLI 2.0을 기술적으로 비교합니다.

항목별 비교

항목 Browser Use CLI 2.0 agent-browser (Vercel Labs)
구현 언어 Python Rust
브라우저 엔진 CDP 직접 / Chromium / 실제 Chrome 프로필 Chrome for Testing (Google 공식 자동화 채널)
로그인 처리 실제 Chrome 프로필 그대로 사용 (--profile, --connect) 세션 파일 저장/복원 (--session-name)
컨텍스트 효율 DOM + 스마트 텍스트 추출, 선택적 스크린샷 accessibility tree 스냅샷 (refs: @e1, @e2), Playwright MCP 대비 82% 절약

🏢
Browser Use CLI 2.0 선택
이미 로그인된 Chrome을 그대로 쓰고 싶을 때. 사내 대시보드·레거시 시스템·2FA가 걸린 서비스 자동화. 여러 Chrome 프로필을 동시에 사용할 때.
🤖
agent-browser 선택
Claude Code와 네이티브 통합이 필요할 때. 토큰 효율이 최우선일 때 (accessibility tree, 82% 절약). Vercel 생태계에서 개발 중일 때.
변경 이력

1.x → 2.0 주요 변경점

Browser Use CLI 2.0에서 달라진 아키텍처와 기능을 정리합니다.

아키텍처 변경사항

항목1.x2.0
브라우저 자동화 엔진 Playwright 기반 순수 CDP (Playwright 의존성 완전 제거, 2025년 8월)
프로세스 모델 명령마다 새 프로세스 멀티세션 데몬 (Unix 소켓, ~50ms 지연)
Chrome 연결 Playwright가 관리하는 브라우저만 --connect, --cdp-url, --profile 직접 연결
프롬프트 구조 브라우저 상태 먼저 대화 이력 먼저 → KV 캐시 최대 활용
정보 추출 방식 스크린샷 위주 + DOM DOM 추출 위주 + 선택적 스크린샷
텍스트 처리 전체 페이지 컨텍스트 로드 extract 도구로 필요한 부분만 쿼리
멀티 세션 단일 세션 명명된 다중 세션 (-s NAME)
MCP 지원 없음 --mcp 플래그로 즉시 MCP 서버 실행
클라우드 연동 없음 cloud connect, tunnel, REST API
