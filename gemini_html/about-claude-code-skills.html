핵심 개념

스킬은 마크다운 파일이 아니다

가장 먼저 깨야 할 오해. 스킬은 폴더이고, 하나의 지식 체계입니다.

💡 핵심: SKILL.md 하나에 모든 걸 때려넣는 게 아니라, 폴더 전체를 하나의 지식 체계로 설계하는 거예요. 설정 옵션과 폴더 구조를 창의적으로 쓰고 있다는 게 Anthropic이 "가장 흥미로운 스킬들"이라고 부르는 것들의 공통점입니다.
my-billing-skill/ ├── SKILL.md # 핵심 지침 + Gotchas 섹션 ├── references/ │ └── api.md # 상세 API 사용법 (필요할 때만 읽음) ├── examples/ │ ├── basic-usage.ts │ └── edge-cases.ts # 함정 예제 ├── assets/ │ └── output-template.md # 출력 형식 템플릿 └── config.json # 셋업 설정 (비어있으면 Claude가 질문)
⚠️ 점진적 공개(Progressive Disclosure): 모든 정보를 한꺼번에 보여주지 않고, 필요할 때만 꺼내 보는 구조. 분리하면 필요한 것만 읽으니까 토큰이 절약됩니다.
카테고리 프레임워크

9가지 스킬 유형

Anthropic이 사내 스킬을 전수 조사한 결과. 좋은 스킬은 하나에 딱 속하고, 헷갈리는 스킬은 여러 개에 걸쳐 있었다고 합니다.

1
라이브러리 / API 레퍼런스
Claude가 모르는 사내 라이브러리 사용법, 함정, 엣지 케이스를 담는 스킬. "이렇게 하면 안 돼" 목록이 핵심.
billing-lib internal-platform-cli frontend-design
2
제품 검증 (Product Verification)
Playwright, tmux 등과 짝을 이뤄 Claude가 직접 테스트를 돌리고 결과를 검증하게 만드는 스킬. Anthropic이 "엔지니어 한 명이 일주일을 투자할 가치가 있다"고 말한 유형.
signup-flow-driver checkout-verifier tmux-cli-driver
3
데이터 패칭 / 분석
회사의 데이터 스택, 모니터링 도구에 연결하는 방법을 담는 스킬. 어떤 테이블, 어떤 이벤트를 조인해야 하는지까지.
funnel-query cohort-compare grafana
4
비즈니스 프로세스 / 팀 자동화
매일 반복하는 업무를 한 커맨드로 자동화. 이전 실행 결과를 로그 파일에 저장해두면 Claude가 delta-only 방식으로 일관성을 유지.
standup-post create-ticket weekly-recap
5
코드 스캐폴딩 / 템플릿
새 기능 뼈대를 자동 생성. 조직의 인증 방식, 로깅 설정, 배포 구성이 미리 연결된 상태로 파일 구조를 잡아줌.
new-workflow new-migration create-app
6
코드 품질 / 리뷰
조직의 코드 품질 기준을 강제. adversarial-review — 서브에이전트가 비판 → 수정 → 반복, 지적이 사소해질 때까지.
adversarial-review code-style testing-practices
7
CI/CD / 배포
babysit-pr: PR 모니터링 → 불안정 CI 재시도 → 머지 충돌 해결 → 오토 머지. 배포는 트래픽 점진적 롤아웃 → 에러 시 자동 롤백.
babysit-pr deploy-service cherry-pick-prod
8
런북 (Runbook)
"이런 증상이 나타나면 이렇게 조사해라"를 자동화. 요청 ID 하나로 모든 시스템 로그를 뽑아주는 log-correlator.
service-debugging oncall-runner log-correlator
9
인프라 운영
정기 유지보수와 운영 절차 자동화. "실수하면 큰일 나는" 작업에 가드레일 추가. 자동이되 사람의 확인을 거치는 구조.
resource-orphans dependency-management cost-investigation
실전 노하우

잘 만드는 법 — 8가지 팁

Anthropic이 수백 개의 스킬을 운용하며 얻은 결론.

1
당연한 걸 적지 마라
Claude는 코딩에 대해 이미 많이 알아요. "변수명은 의미 있게 지어라" 같은 일반 상식은 토큰만 낭비합니다. 스킬에는 Claude가 평소에 모르거나 틀리는 것만 적어야 해요.
❌ 나쁜 예: "일반적인 좋은 디자인 원칙을 따른다"
✅ 좋은 예: "Inter 폰트, 보라색 그라데이션 같은 AI 티 나는 패턴을 사용하지 않는다"
2
Gotchas 섹션이 가장 중요하다
모든 스킬에서 가장 가치 있는 부분. "Claude가 이 스킬을 쓸 때 자주 빠지는 함정" 목록. 처음에는 하나둘로 시작하지만, Claude가 새 엣지 케이스를 만날 때마다 추가합니다.
📅 1일차 — "내부 빌링 라이브러리 사용법"
📅 2주차 — Gotchas 추가: "비례 배분 계산 시 반올림이 아닌 내림 사용"
📅 1개월차 — Gotchas 3개 누적: 실제 운용에서 검증된 함정들
3
파일 시스템을 활용해라 — 점진적 공개
SKILL.md에는 핵심 지침만. 상세한 API 사용법은 references/에, 템플릿은 assets/에, 예제 코드는 examples/에 분리. Claude에게 "이 파일들이 있으니 필요하면 읽어"라고 알려주면 적절한 타이밍에 가져옵니다.
4
Claude를 너무 가두지 마라
지시사항이 너무 구체적이면 상황이 조금만 달라져도 안 맞습니다. 필요한 정보를 주되, 판단의 유연성을 남겨두라는 것.
❌ 나쁜 예: "반드시 A를 호출하고, 그 다음 B를 호출하고, 결과를 C 형식으로 저장하라"
✅ 좋은 예: "이 함수들이 있고, 각각의 용도는 이렇다. 상황에 맞게 조합해서 써라"
5
셋업을 설계해라
스킬 폴더 안에 config.json을 두는 패턴. 설정 파일이 비어있으면 Claude가 사용자에게 질문합니다. 답을 받아서 저장하면 다음부터는 묻지 않아요. AskUserQuestion 도구를 활용하면 구조화된 질문 제시 가능.
6
description은 "언제 쓸지"를 적는 곳이다
세션이 시작되면 Claude Code는 모든 스킬의 description을 스캔해서 "이 요청에 맞는 스킬이 있나?"를 판단합니다. description은 요약이 아니라 트리거 조건입니다.
❌ 나쁜 예: "코드 리뷰를 도와주는 스킬입니다"
✅ 좋은 예: "PR이 올라왔을 때 보안 취약점, 누락된 테스트, 동작 리그레션을 검토합니다. 사용자가 '리뷰해줘', 'PR 체크'라고 말할 때 호출."
7
스킬에 기억을 넣어라
스킬 안에 데이터를 저장할 수 있어요. 텍스트 로그, JSON, 심지어 SQLite까지. standup-post 스킬이 매일 standups.log에 기록을 남기면 다음 실행 때 delta-only로 비교 가능.
📌 주의: 스킬 업그레이드 시 디렉토리가 삭제될 수 있음. ${CLAUDE_PLUGIN_DATA} 같은 안정적인 경로에 저장.
8
스크립트를 넣어라 — 코드가 가장 강력한 도구다
데이터 분석 스킬에 데이터 페칭 함수 라이브러리를 넣어두면, Claude는 매번 코드를 처음부터 쓰는 대신, 이 함수들을 조합해서 분석에 집중할 수 있어요. 보일러플레이트에 턴을 쓰지 않으니까 토큰도 줄어요.

팀에 어떻게 퍼뜨리나

두 가지 방법. 팀 규모와 스킬 개수에 따라 선택.

📁

레포에 체크인

.claude/skills/ 폴더에 넣어서 Git으로 관리. 팀 전원이 같은 스킬을 사용합니다. 소규모 팀에 적합.

단점: 스킬이 많아지면 전부 Claude 컨텍스트에 올라간다는 것.

🏪

사내 플러그인 마켓플레이스

규모가 커지면 이쪽. 팀원이 필요한 스킬만 골라서 설치하는 구조.

Anthropic 방식:
① 스킬을 만들면 GitHub 샌드박스 폴더에 올림
② Slack에서 "이거 써봐" 공유
③ 견인력이 생기면 마켓플레이스에 PR

⚠️ Anthropic의 경고: "나쁘거나 중복된 스킬을 만드는 건 쉽다. 릴리스 전에 큐레이션 과정이 반드시 필요하다."
📊 스킬 사용량 측정: Anthropic은 PreToolUse 훅으로 사내 스킬 사용량을 로깅. 기대보다 안 쓰이면 description(트리거 조건)을 다시 쓰고, 인기 있는 스킬은 더 다듬는다.
"
대부분의 스킬은 몇 줄과 Gotcha 하나로 시작했다.

핵심 한 줄 요약

완벽하게 만들어서 배포하는 게 아닙니다. 작게 시작하고, 실패할 때마다 Gotchas에 한 줄 추가하는 것. 그게 Anthropic이 수백 개의 스킬을 운용하면서 얻은 결론이에요.
