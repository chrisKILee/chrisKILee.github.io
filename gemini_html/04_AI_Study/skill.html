Claude에게 새로운
스킬(Skills)을 가르쳐주세요

스킬은 단순히 명령어를 추가하는 것이 아닙니다. Claude의 지식 체계를 확장하고, 복잡한 워크플로우를 자동화하며, 팀의 코딩 컨벤션을 Claude의 본능으로 만드는 방법입니다.

🎯 핵심 정의

SKILL.md 파일 하나로 Claude의 기능을 확장합니다. 모든 커스텀 슬래시 명령어는 이제 스킬로 통합되었으며, Agent Skills 오픈 표준을 준수하여 도구 간 호환성을 보장합니다.

📂 디렉토리 기반 관리

스킬은 단일 파일이 아닌 폴더입니다. 지침뿐만 아니라 템플릿, 예제 코드, 실행 스크립트 등을 한곳에 모아 관리할 수 있습니다.

my-skill/
├── SKILL.md (필수 - 지침 및 설정)
├── template.md (Claude가 채울 서식)
├── examples/sample.md (결과물 예시)
└── scripts/tool.py (실행용 스크립트)

📍 스킬이 머무는 곳과 우선순위

스킬은 4가지 레벨에서 로드될 수 있습니다. 동일한 이름의 스킬이 존재할 경우, 상위 레벨이 우선권을 갖습니다.

🏢

Enterprise Level (최상위)

관리형 설정을 통해 조직의 모든 사용자에게 강제로 적용되는 스킬입니다.

👤

Personal Level (~/.claude/skills/)

어떤 프로젝트에서도 내가 항상 사용할 수 있는 나만의 도구 상자입니다.

📦

Project Level (.claude/skills/)

특정 리포지토리의 팀원들이 공유하는 프로젝트 전용 스킬입니다.

🔍 중첩 디렉토리 자동 탐색

Claude Code는 모노레포 환경을 위해 하위 디렉토리의 스킬도 자동으로 찾습니다.

예: packages/ui/ 경로에서 작업 중이라면 packages/ui/.claude/skills/ 폴더를 자동으로 스캔합니다.

🔌 플러그인 스킬

플러그인은 plugin:skill 형식의 네임스페이스를 사용하므로 다른 레벨과 충돌하지 않습니다.

📘 프론트매터(Frontmatter) 레퍼런스

SKILL.md 파일 최상단의 YAML 블록을 통해 스킬의 메타데이터와 행동을 정의합니다.

name: (String)

표시 이름 및 슬래시 명령어 이름입니다. 소문자, 숫자, 하이픈만 허용됩니다. 미지정 시 디렉토리명을 사용합니다.

description: (Recommended)

언제 이 스킬을 사용할지 설명합니다. Claude가 자동 실행 여부를 판단하는 가장 중요한 지표입니다.

allowed-tools: (Array)

스킬 실행 중 Claude가 승인 없이 사용할 수 있는 도구를 제한합니다. (예: Read, Grep, Bash)

disable-model-invocation: (Boolean)

Claude가 자동 판단으로 이 스킬을 실행하는 것을 금지합니다. 수동(/) 호출 전용으로 만듭니다.

user-invocable: (Boolean)

false로 설정하면 슬래시(/) 메뉴에서 사라집니다. 배경 지식용 스킬에 적합합니다.

context: (String)

'fork'로 설정하면 격리된 서브에이전트 환경에서 실행됩니다.

agent: (String)

Fork 실행 시 사용할 에이전트 유형을 지정합니다. (Explore, Plan 등)

argument-hint: (String)

자동 완성 시 나타날 힌트 텍스트입니다. (예: "[issue-number]")

🔄 인자($)와 변수 치환

스킬 실행 시 입력받은 인자나 시스템 정보를 동적으로 지침에 삽입합니다.

사용 가능한 특수 변수

$ARGUMENTS 전달된 모든 인자 텍스트
$N (또는 $ARGUMENTS[N]) N번째 특정 인자 (0부터 시작)
${CLAUDE_SESSION_ID} 현재 세션의 고유 식별자
💡 자동 인자 추가 규칙: 스킬 본문에 $ARGUMENTS 변수가 없더라도 인자를 입력하고 호출하면, Claude Code는 자동으로 지침 하단에 ARGUMENTS: <입력값>을 덧붙여 전송합니다.
# Variable Substitution Example
---
name: migrate-component
---

Migrate the $0 component from $1 to $2.
Preserve all existing behavior.

// 호출: /migrate-component SearchBar React Vue
// 결과: Migrate the SearchBar component from React to Vue...

⚖️ 호출 주체 제어 매트릭스

누가 스킬을 호출할 수 있고, 언제 데이터가 로드되는지 결정하는 규칙입니다.

설정 조합 사용자 호출 Claude 자동 로드 데이터 로드 시점
(Default) 가능 가능 설명은 항상 로드, 본문은 호출 시
disable-model-invocation: true 가능 불가능 사용자가 호출할 때만 전체 로드
user-invocable: false 메뉴 숨김 가능 설명은 항상 로드 (배경 지식용)
context: fork 시 - - 전체 본문이 시작 시 주입됨

⚡ 동적 컨텍스트 주입 (!command)

스킬 실행 직전에 로컬 환경의 실시간 데이터를 가져옵니다.

# Real-time PR Context Skill
---
name: pr-summary
context: fork
---

## Pull Request Context
- Diff: !`gh pr diff`
- Comments: !`gh pr view --comments`
- Modified: !`git diff --name-only`

Summarize this PR based on the info above.
!

전처리(Preprocessing) 방식

이것은 Claude가 명령어를 직접 실행하는 것이 아닙니다. 시스템이 먼저 쉘 명령을 수행하고 그 출력 결과물을 마크다운 본문에 끼워 넣은 뒤 Claude에게 전송합니다.

활용 시나리오

  • 🔹 GitHub CLI 연동을 통한 최신 PR 분석
  • 🔹 로컬 로그 파일의 실시간 tail 결과 분석
  • 🔹 DB 스키마 정보를 dump하여 지침에 포함

🤝 서브에이전트(Fork Context) 전략

context: fork는 스킬을 별도의 격리된 컨텍스트에서 실행합니다.

언제 사용하나요?

현재 대화 맥락(History)이 너무 길어 작업 효율이 떨어지거나, 오직 스킬의 지침에만 집중해야 하는 무거운 리서치 작업에 적합합니다.

💡 작동 메커니즘:

  • 기존 대화 기록에 접근하지 않음
  • 에이전트 타입(Explore, Plan 등)의 고유 시스템 프롬프트 사용
  • SKILL.md 본문이 메인 'Task'가 됨
  • 최종 요약 결과만 본 대화로 반환

에이전트 유형

Explore 코드베이스 탐색 및 읽기 최적화
Plan 복잡한 수정 단계 설계 최적화
general-purpose 기본 범용 에이전트 (미지정 시 기본값)

커스텀 에이전트(.claude/agents/)도 지정 가능합니다.

📊 시각적 출력 및 실전 시나리오

스킬은 단순 텍스트 지침을 넘어 복잡한 보고서나 도구를 번들링할 수 있습니다.

시나리오 A: 코드베이스 시각화 (Visual Output)

고급 패턴

스킬 폴더 내에 Python 스크립트를 포함하고, Claude에게 이 스크립트를 실행해 HTML 리포트를 생성한 뒤 브라우저를 열도록 지시합니다.

# SKILL.md 지침 예시
1. Run script: python visualize.py .
2. 스크립트는 map.html을 생성합니다.
3. webbrowser.open()을 통해 리포트를 보여줍니다.
🖥️

인터랙티브 트리 맵 생성

파일 크기, 타입, 폴더 구조를 시각화하여 거대한 리포지토리를 한눈에 분석합니다.

시나리오 B: 배경 지식 스택 (Reference Content)

지식 주입

"우리 팀의 API 설계 원칙을 Claude에게 상시 주입하고 싶을 때"

---
name: api-guidelines
user-invocable: false
description: API 엔드포인트 작성 시 따라야 할 규칙
---

When writing API endpoints:
- Always use snake_case for parameters.
- Return errors in the standard GlobalError format.
- Include request validation using Joi.

* user-invocable: false이므로 메뉴에는 안 뜨지만, Claude는 코드를 짤 때 이 규칙을 자동으로 로드하여 적용합니다.

❓ 상세 트러블슈팅

스킬이 기대와 다르게 작동할 때의 점검 목록입니다.

Q1. 스킬이 자동으로 트리거되지 않습니다. ▼
Solution 1:

description 필드가 너무 모호하지 않은지 확인하세요. 사용자가 입력할 법한 핵심 키워드들을 포함시키는 것이 좋습니다.

Solution 2:

disable-model-invocation: true가 설정되어 있는지 확인하세요. 이 경우 수동 호출(/)만 가능합니다.

Solution 3:

What skills are available?를 입력하여 Claude가 해당 스킬을 성공적으로 인식하고 있는지 목록을 확인하세요.

Q2. 스킬 이름 충돌이 발생합니다. ▼

우선순위는 Enterprise > Personal > Project 순입니다. 하위 레벨의 스킬을 사용하고 싶다면 이름을 변경하거나, 상위 레벨의 SKILL.md를 수정해야 합니다.

Q3. !command 실행 결과가 비어있습니다. ▼

쉘 명령어가 에러를 반환하거나 경로를 찾지 못할 수 있습니다. !`command 2>&1`과 같이 에러 출력까지 캡처하도록 설정하여 디버깅해 보세요.
