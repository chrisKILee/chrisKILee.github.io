클러스터 구조 — 윤종원 제안

End User(내부 개발자)에게는 Prod IDP만 노출하고, GKE·IDP·KMM 리소스는 환경별로 분리해 상호 영향을 차단합니다.

"End User에게는 Prod IDP·KMM만 제공하고, Dev IDP는 R&D 전용 기능 검증에만 사용한다."

02

IDP · KMM 환경별 역할 정의

운영(Prod)과 개발(Dev) 환경의 IDP·KMM 역할과 관리 주체를 명확히 구분합니다.

Prod IDP / KMM — End User 대상
운영 환경 (End User 접근)
  • 내부 개발자(End User) 전체가 사용하는 공식 IDP
  • 공용 서비스(파일서비스, 노티피케이션) 포함 모든 서비스 관리
  • 환경변수 주입·배포·롤백 등 전체 플로우 제공
  • 24/7 지속 운영 — Cattle 구조 + 상시 가용
Dev IDP / KMM — R&D 전용
개발 환경 (내부 검증 전용)
  • UI·기능 변경 사항 검증 및 e2e 테스트 전용
  • 사용자 서비스 관리 없음 — 조회만 허용
  • Prod IDP와 혼동·충돌 방지를 위해 추가/수정 플로우 제외
  • 사용 시에만 Up — 주말·야간 Down (비용 절감)
구분 Prod IDP / KMM Dev IDP / KMM 비고
접근 주체 내부 개발자 전체 (End User) R&D팀 전용 —
서비스 관리 전체 (공용 서비스 포함) 없음 (조회만) 충돌 방지
주요 용도 배포·환경변수·롤백 기능 검증, e2e 테스트 —
운영 방식 24/7 상시 운영 필요 시에만 기동 Cattle 구조
공용 서비스 위치 Prod IDP 관리 해당 없음 파일서비스·노티 포함
