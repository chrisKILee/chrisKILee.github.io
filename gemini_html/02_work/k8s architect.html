Q. Docker가 Container인가요?

  • Container (컨테이너): 애플리케이션이 실행되는 격리된 "공간" 혹은 "상자" 그 자체입니다.
  • Docker (도커): 이 컨테이너를 만들고, 실행하고, 관리하는 "도구(브랜드)"입니다. (마치 '스카치테이프'가 접착테이프의 대명사인 것처럼요)
  • Pod (파드): Kubernetes만의 개념입니다. 도커 컨테이너를 하나 또는 여러 개 감싸고 있는 "껍데기"입니다. K8s는 컨테이너를 직접 관리하지 않고, 이 Pod를 관리합니다.

2. 네트워크 흐름 (접속은 어떻게 이루어지나?)

사용자가 웹사이트에 접속했을 때, 트래픽이 실제 컨테이너까지 도달하는 경로입니다.

1. Ingress

공항의 입국 심사대와 같습니다. 외부에서 들어오는 요청을 규칙(URL 등)에 따라 적절한 서비스로 연결해줍니다.

2. Service

내부 전화번호부이자 안내원입니다. 파드(Pod)들은 수시로 죽고 새로 생기면서 IP가 바뀌는데, Service는 고정된 주소로 항상 올바른 파드를 찾아줍니다.

3. Pod

실제 일꾼입니다. 요청을 받아 처리합니다. 하나의 서비스 뒤에 수십 개의 파드가 숨어있을 수 있습니다.

쉬운 비유 (해운 물류 시스템)

  • Cluster = 항구 전체 (모든 시스템을 포함하는 공간)
  • Node = 거대한 화물선 (컨테이너를 싣고 다니는 물리적 서버)
  • Pod = 컨테이너 하나를 감싼 포장 (크레인이 집어 올리는 최소 단위)
  • Container = 규격화된 철제 박스 (실제 물건/앱이 들어있음)
  • Docker = 박스 제조사/크레인 (박스를 만들고 배에 싣는 도구)
  • Kubernetes = 항구 관제 시스템 (어떤 배에 어떤 박스를 실을지 결정하는 선장)
