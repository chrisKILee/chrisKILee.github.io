ArgoCD REST API 상세 구조

API 서버는 gRPC를 기반으로 하며, HTTP 인터페이스를 위해 REST Gateway를 사용합니다.

애플리케이션의 생성, 수정, 삭제 및 동기화 정책(SyncPolicy)을 관리합니다.

  • GET /api/v1/applications/{name}: 앱 상세 정보
  • POST /api/v1/applications/{name}/rollback: 특정 버전 복구
  • 주요 필드: automated: { prune: true, selfHeal: true }

멀티 클러스터 환경을 위한 외부 클러스터 인증 정보를 관리합니다.

  • POST /api/v1/clusters: 신규 클러스터 자격 증명 등록
  • 주요 필드: server, config: { tlsClientConfig }

JWT 토큰 발행 및 사용자 세션을 관리합니다.

  • POST /api/v1/session: 로그인 및 토큰 획득
  • 사용처: 자동화 파이프라인(CI)의 API 접근 인증

KMM 오퍼레이터 API 심화

커널 모듈의 수명 주기를 쿠버네티스 선언적 객체로 정의합니다.

🔍 KMM의 3대 핵심 로직

BUILD LOGIC

현재 커널 헤더를 감지하여 컨테이너 내에서 `.ko` 파일을 컴파일합니다.

SIGNING LOGIC

Secure Boot가 켜진 노드를 위해 빌드된 모듈에 디지털 서명을 입힙니다.

LOADING LOGIC

드라이버가 로드될 때 노드의 오염(Taint)을 방지하고 안정성을 검증합니다.

Module CRD 상세 필드

selector: 어떤 하드웨어가 있는 노드에 로드할지 결정 (Label 사용)
moduleLoader: 모듈 로드 이미지를 관리하는 핵심 섹션
devicePlugin: (선택사항) GPU 등을 K8s 자원으로 노출하는 플러그인 설정
Module Custom Resource Definition (Specific) YAML 
apiVersion: kmm.sigs.x-k8s.io/v1beta1
kind: Module
metadata:
  name: ml-accelerator-driver
spec:
  moduleLoader:
    container:
      modprobe:
        moduleName: ml_accel
        dirName: /opt/lib/modules
      image: "company-registry.io/drivers/ml-accel:1.2.3"
      # 커널 버전별 매핑 (구체적 명세)
      kernelMappings:
        - regexp: '^5\.15\..*'
          containerImage: "company-registry.io/drivers/ml-accel:1.2.3-k5.15"
        - literal: "6.1.0-1011-azure"
          containerImage: "company-registry.io/drivers/ml-accel:1.2.3-azure"
  selector:
    feature.node.kubernetes.io/pci-10de.present: "true"
  build:
    dockerfileConfigMap: 
      name: ml-accel-dockerfile

ArgoCD vs KMM API 비교 매트릭스

구분 ArgoCD (REST API) KMM (Operator API)
주요 관리 대상 K8s 애플리케이션 및 매니페스트 (GitOps) 호스트 커널 모듈 (드라이버, 하드웨어 가속기)
API 형태 RESTful API / gRPC Kubernetes Custom Resource (YAML)
실행 방식 Push/Sync Controller 기반 Operator/DaemonSet 기반
주요 사용자 DevOps / Application Engineer Infrastructure / SRE / HPC Admin
장점 배포 히스토리 관리 및 쉬운 롤백 커널 업데이트 시 드라이버 자동 빌드
