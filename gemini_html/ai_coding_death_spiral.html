AI 코딩 데스 스파이럴을
탈출하는 법

Claude Code, Cursor로 코딩하다 에러가 에러를 부르는 무한루프에 빠진 적 있으신가요?
이건 당신 실력의 문제가 아닙니다. LLM의 본질적인 특성입니다.

원문: The AI Coding "Death Spiral" — Marcelo Bairros (White Prompt)
🌀 데스 스파이럴이란?
AI 코딩 어시스턴트를 쓰다 보면 누구나 한 번쯤 겪는 바로 그 상황입니다.

당신도 이런 경험 있으신가요?

하나를 고치면 두 개가 망가진다. 변경을 되돌리면 AI가 또 같은 잘못된 해결책을 제안한다. 어느새 에러 메시지가 47개, 터미널은 매트릭스처럼 흘러내리고, 진지하게 vim으로 돌아갈까 고민하게 된다.

🔄

재귀적 디버깅 지옥

AI가 제안한 수정이 새로운 에러를 만들고, 그 에러를 고치려는 AI가 또 다른 에러를 만드는 무한루프. 시간이 빠르게 사라집니다.

🎭

자신감 있는 환각

존재하지 않는 라이브러리를 import하고, 없는 메서드를 호출하고, 그럴싸해 보이지만 작동하지 않는 코드를 자신 있게 제안합니다.

🛠️

기존 해결책의 한계

유닛 테스트, 린팅, 잦은 검증… 모두 도움이 되지만 근본 문제를 해결하지는 못합니다. AI는 통과하는 테스트를 위한 코드를 만들기 때문입니다.

🌍

모든 AI 도구에서 발생

Claude Code, Cursor, GitHub Copilot 어디서나. Python, JavaScript, Rust 어디서나. 데스 스파이럴은 현재 LLM의 본질적인 특성입니다.

💡 핵심 인사이트
저자가 Rich Hickey의 2011년 Strange Loop 강연 "Simple Made Easy"에서 발견한 근본 원인입니다.

"AI 코딩 어시스턴트는 'Simple(단순함)'이 아닌 'Easy(익숙함)'에 최적화되어 있다."

— Marcelo Bairros, 원문 저자
❌ Easy (익숙한 것)
AI가 기본적으로 제안하는 방식

AI가 학습한 패턴과 비슷한 코드를 만들어냅니다. 익숙하고 그럴싸해 보이지만 실제로 옳거나 유지보수 가능하다는 보장이 없습니다.

데이터 가져오기, 변환, 렌더링이 한 컴포넌트에 뒤섞이고, 인증·상태·UI가 복잡하게 얽힌 "clever한" 해결책이 나옵니다.

✅ Simple (단순한 것)
우리가 원하는 방식

Hickey의 정의: 하나의 역할만 하고, 다른 것과 얽히지 않은 것. 복잡해 보이지 않더라도 실제로 작동하고, 나중에 고칠 수 있는 코드입니다.

데이터 소스, 데이터 변환, 데이터 표현을 각각 독립된 단위로 분리. 지루할 만큼 단순하지만 실제로 동작합니다.

🔧 해결 방법론
AI의 본성과 싸우는 대신, 더 나은 원칙을 가르치는 접근법입니다.
저자는 이 방법으로 simple-mindset.md 규칙 파일을 만들어 AI 행동을 근본적으로 바꿨습니다.
1

지혜 추출하기

가치 있는 기술 강연, 블로그 포스트, 책에서 원칙을 뽑아냅니다. Rich Hickey의 "Simple Made Easy", SOLID 원칙, DDD 개념 등이 좋은 소스입니다.

💡 Google NotebookLM에 YouTube 링크를 넣으면 구조화된 노트를 자동 생성해줍니다.
2

학습 환경 만들기

Claude Desktop 프로젝트를 생성하고 여기에 세 가지를 추가합니다:

① 좋은 Cursor/Claude Rules 작성법 리서치
② NotebookLM으로 추출한 강연 노트
③ AI 코딩 규칙에 무엇이 중요한지 컨텍스트

3

실행 가능한 규칙 생성

위 컨텍스트를 바탕으로 Claude에게 원칙을 구체적인 규칙으로 만들어달라고 요청합니다.

결과물을 CLAUDE.md 또는 .cursor/rules/에 배치합니다.

💡 이게 바로 Cursor Rules, AGENTS.md의 본질적 활용법입니다.
4

배포하고 반복 개선

실제 프로젝트에서 규칙을 적용하고, 부족한 부분을 발견하면 규칙을 보강합니다.

규칙은 한 번 만들고 끝이 아닙니다. 새로운 패턴을 발견할 때마다 지속적으로 발전시킵니다.

✏️ 실제 적용 예시
"Simple Mindset" 규칙을 적용했을 때 AI의 접근 방식이 어떻게 달라지는지 비교합니다.
❌ 규칙 없이 — Easy 방식
요청: "이 앱에 유저 인증을 추가해줘"

AI 결과: 인증 로직, 상태 관리, UI 렌더링, API 호출이 하나의 컴포넌트에 뒤섞인 복잡한 코드. 처음엔 작동하는 것처럼 보이지만 수정하면 전체가 무너집니다.
✅ 규칙 적용 후 — Simple 방식
AI가 스스로 분리해서 접근:

1. 유저 Identity 값 객체 생성
2. 인증 상태(State) 분리
3. 자격 증명 검증 함수 별도 작성
4. 이 세 가지를 각각 독립 유지

지루해 보이지만 실제로 작동하고, 나중에 고치기도 쉽습니다.
❌ 규칙 없이 — Easy 방식
요청: "데이터 대시보드 컴포넌트 만들어줘"

AI 결과: 데이터 fetch, 변환(transform), UI 렌더링이 하나의 거대한 컴포넌트 안에서 처리됩니다. 재사용 불가, 테스트 어려움, 수정 시 사이드이펙트 다수.
✅ 규칙 적용 후 — Simple 방식
AI가 자연스럽게 분리:

- 데이터 소스: API 호출만 담당
- 데이터 변환: 포맷 처리만 담당
- 데이터 표현: UI 렌더링만 담당

각각이 독립적이라 테스트하기 쉽고, 하나를 바꿔도 다른 것이 깨지지 않습니다.
📚 어떤 원칙이든 규칙으로 만들 수 있다
Simple Made Easy뿐만 아니라 어떤 소프트웨어 원칙이든 AI 규칙으로 변환할 수 있습니다.
🔨

Kent Beck 원칙

"작동하게 → 올바르게 → 빠르게" (Make it work, make it right, make it fast). AI가 처음부터 최적화하려다 망치는 것을 방지합니다.

🏛️

SOLID 원칙

단일 책임, 개방-폐쇄, 리스코프 치환, 인터페이스 분리, 의존성 역전. 이 원칙들을 구체적인 코딩 가이드라인으로 변환합니다.

🗺️

DDD (도메인 주도 설계)

도메인 언어를 코드에 반영하고, 바운디드 컨텍스트를 명확히 구분하도록 AI를 가이드합니다.

📖

당신만의 원칙

팀의 코딩 철학, 사내 아키텍처 패턴, 프로젝트 특화 규칙 등 어떤 것이든 AI가 따라야 할 가이드라인으로 만들 수 있습니다.

🚀 지금 바로 시작하기
나만의 AI 코딩 철학을 만드는 5단계입니다.
  • 1

    소스 자료 찾기

    내 코딩 방식을 근본적으로 바꾼 기술 강연이나 글이 무엇인가요? 그것이 출발점입니다. (예: Clean Code, DDD, Reactive Programming 등)

  • 2

    핵심 추출하기

    NotebookLM이나 Claude에게 해당 자료의 핵심 원칙을 구조화된 노트로 정리해달라고 요청합니다.

  • 3

    규칙 생성 프로젝트 만들기

    Claude Desktop 프로젝트에 "좋은 AI 코딩 규칙이란 무엇인가"에 대한 리서치와 추출한 원칙 노트를 함께 넣습니다.

  • 4

    CLAUDE.md / Cursor Rules 생성

    Claude에게 해당 원칙을 구체적이고 실행 가능한 AI 코딩 규칙으로 변환해달라고 요청합니다. 결과물을 CLAUDE.md 또는 .cursor/rules/에 배치합니다.

  • 5

    실전 적용 & 지속 개선

    실제 프로젝트에서 사용하면서 부족한 점을 발견할 때마다 규칙을 보강합니다. 규칙은 살아있는 문서입니다.

🎯 결론

  • 데스 스파이럴은 사라지지 않는다 — LLM의 본질적 특성이다.
  • 하지만 더 나은 사고 패턴을 규칙으로 주입하면 AI를 가르칠 수 있다.
  • AI를 블랙박스가 아닌 가르칠 수 있는 파트너로 대하는 것이 핵심이다.
  • 결과: 더 적은 디버깅, 더 유지보수 가능한 코드, 더 많은 실제 작업.
