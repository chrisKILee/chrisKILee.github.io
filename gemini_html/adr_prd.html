PRD는 스펙(Spec)인가?

결론적으로 PRD는 '요구사항 명세(Requirement Spec)'입니다. 하지만 실무에서 개발자가 코드 작성을 위해 참조하는 '상세 명세(Detailed Spec)'와는 레이어가 다릅니다. 그 차이를 정량적으로 분석해 보았습니다.

1. 추상화 수준 (Abstraction)

PRD는 유저의 관점에서 '무엇이 필요한지'를 정의하며 높은 추상화 수준을 유지합니다. 반면 SDD/Spec은 기계와 시스템의 관점에서 '어떻게 작동하는지'를 상세히 정의합니다.

2. 대상 독자 (Audience)

PRD는 기획자, 디자이너, 마케터 등 모든 이해관계자를 위한 문서입니다. Spec은 주로 개발자와 QA 엔지니어를 위해 작성됩니다.

3. 변경 주기 (Change Cycle)

비즈니스 가치(PRD)는 쉽게 변하지 않지만, 기술적 구현 상세(Spec)는 구현 과정에서 성능이나 한계로 인해 자주 업데이트됩니다.

개발 방법론과 Claude Code 활용

문서는 작성하는 것보다 AI가 읽기 좋은 상태로 배치하는 것이 중요합니다. Claude Code와 같은 AI 도구가 프로젝트의 맥락을 완벽히 이해할 수 있는 최적의 구조를 제안합니다.

SDD 기반 개발 프로세스

Phase 1. 분석 PRD 활용

요구사항을 분석하고 구현 가능성을 타진합니다.

Phase 2. 결정 ADR 활용

중요한 기술 스택과 아키텍처 방향을 결정합니다.

Phase 3. 설계 SDD 활용

구체적인 코드 청사진을 그리고 AI에게 전달합니다.
