표준 장애 대응 프로세스 (Incident Management)

장애 발생 시 혼선을 줄이고 체계적으로 대응하기 위한 5단계 표준 절차입니다. 각 단계를 클릭하여 상세 행동 지침을 확인하세요.

🚨

1. 감지 및 선언 (Detection & Declaration)

모니터링 시스템 알람 혹은 사용자 신고를 통해 장애를 인지하고, 심각도(Severity)를 판별하여 전파하는 단계입니다.

✅ Key Actions (행동 지침)

  • 모니터링 대시보드 이상 징후 확인
  • 장애 등급(Sev 1~3) 판단
  • 초기 전파(SMS, Slack, 사내방송)

⚠️ Artifacts (산출물)

  • 장애 티켓 생성 (Jira/ITSM)
  • 장애 전파 메시지

Sev 1 (Critical)

생산 중단, 전사 업무 마비

  • CTO 즉시 보고
  • 전사 비상 연락망 가동
  • 워룸(War Room) 개설 필수
  • 목표 복구: 1시간 이내

Sev 2 (Major)

일부 기능 불가, 성능 저하

  • 담당 팀장 보고
  • 유관부서 전파
  • 담당자 즉시 투입
  • 목표 복구: 4시간 이내

Sev 3 (Minor)

내부 업무 불편, 우회 가능

  • 정기 배포 시 수정 가능
  • 티켓 접수 후 순차 처리
  • 목표 복구: 24시간 이내

보고서 작성 원칙 (Golden Rules)

  • 1.
    Fact 위주 작성

    추측성 발언("~인 것 같다")을 배제하고 로그와 데이터에 기반합니다.

  • 2.
    Blameless (비난 금지)

    "누가" 실수했냐가 아니라 "왜" 시스템이 실수를 허용했는가에 집중합니다.

  • 3.
    Action Item의 구체성

    담당자(Who)와 기한(When)이 없는 개선 사항은 희망 사항일 뿐입니다.

회고 프로세스 및 개선 문화

장애를 성장의 기회로 만드는 것은 '회고'의 질에 달려 있습니다. '5 Whys' 기법을 실습해보세요.

🛠️ 5 Whys 실습 도구

표면적인 원인을 넘어 근본 원인을 찾을 때까지 '왜'를 반복합니다.

운이 좋았던 경우 vs 고쳐진 경우

❌ Lucky (운이 좋음)

"담당자가 마침 모니터를 보고 있어서 빨리 발견했다."

→ 시스템적 개선 아님. 재발 위험 높음.

✅ Fixed (고쳐짐)

"CPU 80% 도달 시 자동 알림이 오도록 임계치를 설정했다."

→ 시스템적 방어 체계 구축.

회고 진행자(Facilitator) 가이드

  • 1. 안전한 분위기 조성: "오늘 우리는 누군가를 탓하러 모인 게 아닙니다." 선언
  • 2. 타임라인 재구성: 참가자들의 기억을 모아 사실 관계 확립
  • 3. 패턴 발견: 반복되는 문제나 구조적 결함 식별
  • 4. 실행 가능한 계획: 티켓 할당까지 그 자리에서 완료

제조 IT 장애 대응 우수 사례

일반적인 제조 환경에서 발생하는 주요 장애 유형과 모범 대응 시나리오입니다.

MES 데이터 정합성

생산 실적 누락 사고

PLC에서 MES로 전송되는 패킷 손실로 인해 실제 생산량과 시스템 재고가 불일치, 출하 지연 발생.

🛠️ 개선 포인트
  • PLC-MES 간 Handshake 로직 추가
  • 미들웨어(MQ) 도입으로 버퍼링 구현
  • 일 마감 전 자동 대사 스크립트 적용
Infra HW 노후화

공장 허브 스위치 셧다운

먼지와 고온으로 인한 현장 스위치 과열로 네트워크 루핑 발생, 전체 라인 통신 마비.

🛠️ 개선 포인트
  • 산업용(Industrial) 등급 스위치 교체
  • 이중화 구성 (Ring Topology)
  • NMS 도입으로 온도/트래픽 감시
Process 휴먼 에러

잘못된 패치 배포

검증되지 않은 펌웨어 업데이트를 주간 가동 중에 수행하여 설비 오작동 발생.

🛠️ 개선 포인트
  • 변경 관리 위원회(CAB) 승인 절차
  • PM(유지보수) 시간 외 작업 금지
  • Rollback 시나리오 사전 검증 의무화
