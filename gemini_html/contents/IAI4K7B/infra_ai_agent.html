⚡ 이런 불편함이 있었습니다

기존 수작업 방식의 한계를 자동화로 해결합니다.

BEFORE
기존 방식 — 수작업 점검
  • 설정 파일을 수동으로 열어 항목별로 직접 확인
  • 반복적인 작업으로 많은 시간 소요
  • 담당자에 따라 점검 결과가 달라질 수 있음
  • 조치 방법을 별도로 검색하고 정리해야 함
  • 보고서 작성도 수작업으로 추가 시간 필요
AFTER
AI Agent — 자동화 점검
  • Agent 실행 한 번으로 설정 자동 수집 및 분석
  • 수분 내 전체 항목 점검 완료
  • 룰 기반으로 일관된 PASS/FAIL 판정
  • AI가 위험 설명과 구체적인 조치 가이드 즉시 제공
  • 점검결과보고서 자동 생성 — 감사 대응도 간편하게

🚀 주요 기능

세 가지 핵심 기능이 순서대로 자동으로 동작합니다.

⚙️
보안 설정 자동 수집 및 분석
Tomcat의 주요 설정 파일(server.xml, context.xml, web.xml 등)에서 보안 관련 설정값을 자동으로 읽어 분석합니다. 별도의 설정 없이 Agent를 실행하면 즉시 시작됩니다.
📋
룰 기반 준수 여부 자동 판정
주정통 기반 보안취약점 점검 기준에 따라 각 항목의 PASS / FAIL / N/A를 자동으로 판정합니다. 담당자가 다르더라도 동일한 기준으로 일관된 결과를 제공합니다.
🤖
AI 기반 위험 설명 및 조치 가이드
FAIL 판정된 항목에 대해 AI가 위험도와 영향을 설명하고, 구체적인 조치 방법과 설정 예시를 자동으로 생성합니다. 보안 전문 지식 없이도 바로 조치할 수 있습니다.
📄
점검결과보고서 자동 생성
점검이 완료되면 동일한 경로에 구조화된 보고서 파일이 자동으로 생성됩니다. 정기 점검 및 감사 대응 시 즉시 활용 가능합니다.
🔍
예외 처리 자동 안내
OS 환경에 따라 직접 점검이 어려운 항목(예: Windows 파일 권한)은 N/A로 자동 분류하고, 수동 점검이 필요한 사항을 명확히 안내합니다.
🪶
설치 없는 Portable 실행
별도 설치 없이 실행 파일(.exe) 하나만으로 동작합니다. Tomcat이 설치된 서버에서 바로 실행할 수 있어 배포와 사용이 간편합니다.

🛡️ 점검 항목

주정통 기반 보안취약점 점검 기준에 따라 총 13개 항목을 점검합니다.

🗂️ 관리자/기본 애플리케이션 관리
  • › Tomcat 버전 최신화 여부
  • › 기본 웹 애플리케이션(docs, examples) 제거 여부
  • › Manager 앱 접근 제한 설정
  • › 관리자 계정 취약 비밀번호 여부
🔌 Connector 및 포트 설정
  • › AJP Connector 비활성화 여부
  • › HTTPS Connector 설정 여부
  • › 서버 버전 정보 노출 방지 설정
  • › Shutdown 포트 비활성화 여부
🔐 인증·권한 및 보안 옵션
  • › 세션 쿠키 HttpOnly / Secure 설정
  • › 디렉토리 리스팅 비활성화
  • › 서비스 실행 계정 권한 최소화
  • › 파일 시스템 권한 설정
📋 로그 및 오류 처리 설정
  • › AccessLogValve 설정 여부

💡 사용 방법

단 3단계로 점검을 완료할 수 있습니다.

1

Agent 파일 다운로드

담당자로부터 security-agent-win.exe 파일을 전달받습니다.

2

Tomcat Home 경로로 이동

다운로드한 Agent 파일을 Tomcat이 설치된 폴더(Tomcat Home)로 복사합니다.
예: C:\apache-tomcat-10.1.52\

3

Agent 실행

Tomcat Home 경로에서 명령 프롬프트(cmd)를 열고 아래 명령어를 실행합니다.

security-agent-win.exe audit
4

결과 보고서 확인

점검이 완료되면 동일 경로에 보고서 파일이 자동으로 생성됩니다. 파일을 열어 점검 결과와 AI 조치 가이드를 확인하세요.

📊 결과 예시

점검 완료 후 생성되는 보고서의 실제 내용입니다.

✅ PASS: 5
❌ FAIL: 5
➖ N/A: 3
PASS
[WAS-TOMCAT-002] AJP Connector 비활성화

AJP Connector가 비활성화되어 있습니다.

FAIL
[WAS-TOMCAT-004] 기본 웹 애플리케이션 제거

기본 웹 애플리케이션이 삭제되지 않고 존재합니다: docs, examples, manager, host-manager

🤖 AI 분석 — 설치 시 기본 제공되는 웹 앱에 알려진 취약점이 존재할 수 있으며, 공격자에게 시스템 구조나 샘플 코드가 노출되어 2차 공격의 빌미를 제공할 수 있습니다. 사용하지 않는 기본 앱은 즉시 삭제하거나 비활성화하세요.
FAIL
[WAS-TOMCAT-009] 세션 쿠키 보안 설정

<session-config> 내에 <cookie-config> 설정이 없습니다.

🤖 AI 분석 — HttpOnly와 Secure 속성이 설정되지 않으면 XSS 공격을 통해 세션 쿠키를 탈취당하거나 암호화되지 않은 구간에서 쿠키가 노출될 수 있습니다. web.xml에 <cookie-config>를 추가하여 두 속성을 모두 true로 설정하세요.
N/A
[WAS-TOMCAT-010] 서비스 실행 계정 권한

Windows 환경에서는 서비스 소유자 확인이 수동 점검으로 제한됩니다.

🎯 기대 효과

인프라취약점 점검 AI Agent 도입으로 얻을 수 있는 변화입니다.

⚡
업무 시간 대폭 절감
반복적인 수작업 점검 업무를 자동화하여 보안팀과 인프라팀의 실질적인 업무 부담을 줄입니다.
🎯
점검 품질 표준화
룰 기반 자동 판정으로 담당자에 상관없이 동일한 기준의 일관된 점검 결과를 제공합니다.
📋
감사 대응 효율화
보고서 자동 생성으로 정기 점검 및 외부 감사 대응 시 즉시 활용 가능한 산출물을 확보합니다.
🔭
확장 가능한 기반
향후 다른 WAS 및 인프라 보안 점검으로 확장할 수 있는 기반을 갖추고 있습니다.
