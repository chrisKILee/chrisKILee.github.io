어떤 문제를 해결하는가

✗ Before PRAI
✗ 수 시간 소요되는 에러 발견 — Slack이나 모니터링 툴을 직접 확인해야 함
✗ 반복적 수작업 프로세스 — 에러 분석 → 코드 수정 → 리뷰 요청을 수동으로 반복
✗ 리뷰 없는 핫픽스 배포 위험 — 긴급 수정은 리뷰를 건너뛰는 경우가 많음
✗ 중복 대응 문제 — 여러 명이 같은 에러를 동시에 수정하려다 충돌 발생
✓ After PRAI
✓ 즉시 Slack + 대시보드 알림 — 에러 발생 즉시 자동으로 팀에 알림
✓ AI 자동 분석 및 PR 생성 — Claude가 원인을 분석하고 수정 PR을 자동 생성
✓ 5관점 AI 리뷰로 품질 보장 — 보안·성능·아키텍처 등 5가지 관점으로 자동 검증
✓ 중복 요청 자동 방지 — 동일 에러에 대한 중복 Fix 요청을 시스템이 자동 차단

파이프라인 흐름 디테일

1
Error 발생
NestJS Global Exception Filter가 운영서버의 예외를 캐치합니다.
2
Webhook 전송
에러 정보(스택 트레이스, 컨텍스트)를 n8n Webhook으로 전송합니다.
3
Supabase 저장
에러 레코드를 Supabase(PostgreSQL)에 저장하고 상태를 pending으로 설정합니다.
4
Slack 알림
팀 채널에 에러 정보와 Fix / Ignore 인터랙티브 버튼을 포함한 메시지를 전송합니다.
5
Fix 요청
대시보드 또는 Slack 버튼으로 Fix를 요청합니다. 중복 요청은 자동으로 방지됩니다.
6
코드 분석
Claude CLI(Opus)가 저장소를 클론하고 에러 원인을 심층 분석합니다.
7
코드 수정
분석 결과를 바탕으로 AI가 최적의 수정 코드를 자동 생성합니다.
8
5관점 리뷰
Correctness · Security · Architecture · Performance · Codex 교차검증으로 품질을 보장합니다.
9
Branch 생성 → Commit → PR
리뷰 PASS 시 새 브랜치를 생성하고 커밋 후 GitHub PR을 자동으로 올립니다.
10
Slack 결과 알림
PR 링크와 리뷰 결과를 Slack에 전송하여 팀이 최종 병합을 결정합니다.
⏱ 평균 처리 시간: 5분

E2E 테스트 시나리오

1
에러 수집
NestJS → n8n → Supabase → Slack 알림까지 전체 흐름 검증
2
대시보드 표시
수집된 에러가 대시보드에 정확히 렌더링되는지 확인
3
Ignore 처리
Ignore 요청 시 상태가 ignored로 올바르게 변경되는지 검증
4
Fix → PR 생성
Fix 요청부터 GitHub PR 생성까지 전체 자동화 파이프라인 검증
5
Slack Fix 요청
Slack 인터랙티브 버튼으로 Fix를 트리거하는 시나리오
6
중복 요청 방지
동일 에러에 대한 중복 Fix 요청이 올바르게 차단되는지 확인
7
상세 결과 표시
에러 상세 페이지에서 AI 리뷰 결과와 PR 링크가 표시되는지 검증
8
실행 이력 페이지
Runs 페이지에서 파이프라인 실행 이력이 올바르게 표시되는지 확인
