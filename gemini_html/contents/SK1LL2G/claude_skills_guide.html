  • 패턴 C: 협업/지식 플랫폼형 (밝은 톤)
  • 패턴 D: 자유형

개발 tmux 세션을 켜거나 끕니다. on 시 backend·frontend·test·terminal 4개 창 자동 구성. tmux-dev.sh 있으면 해당 스크립트 사용, 없으면 기본 레이아웃으로 즉시 생성.
개발 환경 tmux
▼ ▾ 팁 보기
명령어
/tmux on → 세션 시작 /tmux off → 세션 종료 /tmux status → 현재 상태 확인
창 구성 (on 실행 시)
  • [1] backend — 상단: 서버 / 하단: DB
  • [2] frontend — React 개발 서버
  • [3] test — 좌: BE 테스트 / 우: FE 테스트
  • [4] terminal — 일반 터미널
tmux-dev.sh 없으면 기본 레이아웃으로 자동 생성 후 실행 · 접속: tmux attach -t [세션명]

Dirtree
/dirtree [경로] [깊이]
프로젝트 디렉토리 구조를 tree 형태로 시각화합니다. 깊이·시작 경로·--all 옵션 지정 가능. node_modules, .git, .claude 등 노이즈 디렉토리는 자동 제외.
파일 탐색 개발 환경
▼ ▾ 팁 보기
명령어
/dirtree → 현재 디렉토리, 깊이 3 /dirtree 4 → 깊이 4로 탐색 /dirtree backend → backend 디렉토리 탐색 /dirtree backend 4 → 경로 + 깊이 조합 /dirtree --all → 숨김 도구 디렉토리(.claude 등) 포함
자동 제외 목록
  • 항상 제외: node_modules, dist, build, .git, __pycache__, .venv, .next
  • 기본 제외: .claude, .cursor, .gemini, .vscode (--all 시 포함)
tree 명령이 없으면 find + awk 로 자동 대체 · 출력 후 주요 구조 한국어 요약 제공

ValidateData
/validatedata YYYYMM
NAC 보고서 데이터 정합성 검증. 전체 계열사의 4개 섹션(S1 전체노드·S2 정책현황·S3 OS요약·S4 운영체제별) PC 카운트 일치 여부를 검증. DB 쿼리 → cron worker 전송 → 마크다운 표로 PASS/FAIL 출력.
데이터 검증 NAC
▼ ▾ 팁 보기
사용법
/validatedata 202602 → 2026년 2월 검증 (전월 자동 계산)
4개 섹션 정합성 기준
  • S1 전체노드 PC — 기준값 (nl_genidev=20 전체 COUNT)
  • S2 PC별 정책현황 — S1과 동일해야 함
  • S3 PC별 OS 요약 — Win7/Win8/Mac 제외 → S1보다 작을 수 있음
  • S4 운영체제별 PC — S1과 동일해야 함
판정 기준
✅ PASS: S1 = S2 = S4 (S3는 참고) ❌ FAIL: 하나라도 다르면 FAIL
결과는 계열사별 마크다운 표로 출력 · gcloud cron worker 경유 실행
