심사 전 안내사항

심사위원이 미리 알아야 할 사항

1

결과물 직접 실행 없음

제출된 프로젝트를 직접 실행하거나 UI를 눈으로 확인하지 않았습니다. 평가는 제출된 소스코드 분석과 체크리스트 기재 내용을 근거로 합니다.

2

AI 기반 자동 판정

사전 수립된 평가 기준에 따라 Claude(AI)가 소스코드를 분석하여 점수를 산정합니다. AI 판정 결과를 심사위원이 최종 검토하는 구조입니다.

3

소스코드 분석 관점

코드 분석 시 아래 네 가지 관점을 중심으로 검토합니다.

▸

파일 구조 및 실행 흐름 — 트리거 → 처리 → 출력의 전체 흐름을 파악하여 자동화 구조 확인

▸

AI 활용 증거 검증 — AI API 호출 코드, 프롬프트 정의, 모델 참조 여부를 코드에서 직접 확인

▸

자동화 실체 판단 — 자동화 로직이 실제로 구현되어 있는지, 수동 실행 수준에 그치는지 구분

▸

체크리스트 사실 검증 — 제출자가 기재한 내용이 코드상 실제로 구현되어 있는지 대조

4

체크리스트 충실도의 중요성

체크리스트를 얼마나 구체적으로 작성했느냐에 따라 AI가 판단할 수 있는 정보량이 달라집니다. 체크리스트가 불충분하면 실제 가치가 있더라도 낮게 평가될 수 있습니다.

③ 업무 효율성 — 35점

이 과제는 얼마나 시간 효율성을 가져왔는가?

같은 "60분 → 3분"이라도 빈도에 따라 실질 가치가 크게 달라집니다. 연간 절감 시간으로 객관 비교합니다.

연간 절감 시간  =  (1회 절감 시간) × (연간 빈도)

④ 아이디어 적절성 — 25점

문제점 개선을 위한 해결 방법이 얼마나 적절했는가?

문제 정의의 명확성, 해결 방법의 적합성, 현실 제약 내 실행 가능성을 종합 평가합니다.

문제 명확성

해결하려는 문제가 구체적으로 정의되어 있는가?

방법 적합성

선택한 방법이 문제에 맞는가? 과도하거나 너무 단순하지 않은가?

현실 실행 가능성

권한·데이터·시간 제약 안에서 실행 가능한 접근인가?

점수 구간기준
20~25점문제가 공감되고, 방법 선택이 명쾌하며, 실용적으로 구현됨
13~19점문제는 명확하나 해결 방식에 아쉬운 점 있거나 구현이 부분적
6~12점방향은 맞으나 문제·방법 간 연결이 약하거나 아이디어가 모호
0~5점문제 정의 불명확하거나 방법 선택 근거 없음

⑤ 확산 가능성 — 25점

얼마나 많은 사람들이 사용하는가? 더 확산될 수 있는가?

핵심 변경: Phase 개념 도입. Phase 1 완성은 정상 평가이며, 타 팀 확산은 추가 성과(가점 성격)로 봅니다.

Phase 1 완성 = 정상 평가

현재 목표 범위 내에서 완성된 과제라면 감점 없음. 타 팀에 확산되지 않았다고 Phase 1 미완성으로 해석하지 않습니다.

타 팀 확산 논의 = 가산점 성격

타 팀 검토 중인 경우, 확산을 위한 노력으로 인정하여 소폭 가점. 실제 사용 중인 경우와는 소폭 구분합니다.

점수 구간기준
22~25점타 팀/부서에서 실제 사용 중
16~21점타 팀 확산 논의·검토 진행 중 (가점 성격), 또는 같은 팀 전원 사용
10~15점확산 가능 구조이나 진입 장벽 존재, 또는 팀 내 일부 사용
4~9점개인·소수만 유효, 확장 구조 미비
0~3점특정 환경에 종속, 확산 어려움

⑥ 조직 목표 연결 — 15점

얼마나 팀과 회사를 향한 목표가 있는 제품인가?

배점 하향 (20 → 15점). "디지털 전환 방향 연결"은 AI 심사자가 검증 불가하여 제외. 검증 가능한 기준으로 단순화.

점수 구간기준
12~15점팀·부서 전체 업무 개선을 목표로 하며, 타 팀도 관심·확산 중
8~11점실제 업무 효율화 목적 명확 — 본인·소수이지만 팀 업무 맥락에서 활용
3~7점업무 관련이나 개인 편의 성격이 강하거나 효과가 간접적
0~2점개인 취미·학습 목적, 또는 업무와 무관
실제 업무에 쓰이는 과제라면 기본 8점 보장
