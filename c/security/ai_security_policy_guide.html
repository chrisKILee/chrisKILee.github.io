정책 개요 및 핵심 원칙

사내 생성형 AI 및 LLM 활용에 적용되는 정보보호 거버넌스의 배경, 목적, 핵심 원칙을 안내합니다.

⚠️
왜 AI 보안 정책이 필요한가?
생성형 AI는 기업의 지식 노동 방식을 근본적으로 바꾸고 있습니다. 그러나 확률론적 추론 방식을 채택하는 LLM은 기존 경계 기반 보안 모델을 무력화할 수 있습니다. 사내 기밀, 소스 코드, 개인정보가 외부 모델로 유출되거나 악의적 프롬프트가 보안 로직을 우회하는 사례가 현실화되었습니다. 본 정책은 이러한 위협에 대응하는 제로 트러스트 기반 다층 방어 체계를 수립합니다.

한국 AI 기본법 (2026.1 시행)
역외 적용 조항 — 핵심 주의
한국 사용자·시장에 영향을 미치는 모든 AI 활동에 적용됩니다. 해외 서버 기반 클라우드 LLM API도 국내 고객 서비스 시 적용 대상입니다. 위반 시 최대 3,000만 원 과태료가 부과됩니다.
고위험(High-impact) AI 의무
보건의료, 공공서비스, 에너지 분야 AI에 위험관리 계획 수립, 결과 설명 의무, 인적 감독, 개발 문서화를 요구합니다.
생성형 AI 출력물 라벨링 의무
AI가 생성한 텍스트·이미지·영상은 "AI 제작 콘텐츠"임을 명시하는 워터마크 또는 라벨을 의무 표기해야 합니다.
📜
개인정보보호법 (PIPA) · PIPC 가이드
  • AI 라이프사이클 전반에 걸친 데이터 통제 기준 적용
  • 목적 외 데이터로 Fine-tuning·RAG 색인 원천 차단
  • 자동화된 결정에 대한 정보 주체의 거부권·설명 요구권·인적 검토 요구권 보장
  • 데이터 유출 발생 시 규모에 따라 72시간 내 관할 당국 통지
  • 외부 LLM API 사용은 개인정보 처리 위탁으로 문서화 필수
🏛️
KISA · 국가정보원 보안 가이드
  • 딥시크(DeepSeek) 등 과도한 메타데이터 수집 서비스 전사 차단 권고
  • 개인정보·내부 문서·IP를 외부 AI 프롬프트에 입력 전사 금지
  • 외부 API 계약 시 "No Training on Your Data" 조항 명시 필수
  • 데이터 국외 이전 요건 충족 여부 (데이터 주권) 면밀 검토
  • 중국·지정학 리스크 국가의 AI 서비스는 네트워크 수준에서 접속 차단

OWASP LLM Top 10 위협 분석

사내 LLM 환경에 특화된 10대 보안 위협과 기술적 완화 전략을 안내합니다.

🔗
연쇄 공격 시나리오 — 간접 프롬프트 인젝션
사내 RAG 시스템에서 일반 직원이 악성 지시어가 숨겨진 마크다운 문서를 위키에 업로드 → 경영진이 LLM으로 정보 검색 시 해당 문서가 컨텍스트로 로드 → 간접 프롬프트 인젝션 트리거 → 경영진 권한으로 비인가 명령 실행. 이러한 연쇄 공격을 방어하기 위해 SAST/DAST 파이프라인에 LLM 특화 Red-teaming을 통합해야 합니다.
LLM01
🔴 치명
프롬프트 인젝션
악의적인 자연어 프롬프트로 모델의 보안 지침을 덮어씌워 인가되지 않은 명령 수행 유도. 사내 망 스캐닝, 기밀 출력 등을 야기.
✅ 완화 전략
시스템 프롬프트·사용자 입력 완전 분리 / 입력값 엄격 검증 / 프롬프트 방화벽(Prompt Firewall) 도입 / 비정상 패턴 실시간 차단
LLM02
🔴 치명
민감 정보 노출
학습 데이터에 포함된 PII, 기밀 코드, 이전 세션 컨텍스트가 무단으로 다른 사용자에게 출력됨.
✅ 완화 전략
입력 전 난독화·비식별화 / 세션 완벽 격리 / 런타임 출력 동적 필터링 / 데이터 정제 정책 강제 적용
LLM03
🔴 치명
공급망 취약점
Hugging Face 등 외부 사전학습 모델·플러그인·학습 데이터셋이 사전에 훼손되거나 백도어가 심어진 채 사내 도입.
✅ 완화 전략
서드파티 모델 무결성 검증 / AI-BOM 작성·추적 / 외부 API 연결 구간 Zero Trust 적용
LLM04
🟡 높음
데이터·모델 오염
Fine-tuning 데이터나 RAG 벡터 DB에 악성 정보 주입 → 특정 트리거에 편향·악의적 답변 생성.
✅ 완화 전략
학습 데이터 출처 강력 검증 / 암호학적 서명 확인 / 임베딩 전 데이터 무결성 검사 / 이상치 탐지 알고리즘 적용
LLM05
🔴 치명
부적절한 출력 처리
LLM 생성 SQL·쉘 스크립트를 백엔드가 검증 없이 실행 → XSS, SQL 인젝션, RCE(원격 코드 실행)로 이어짐.
✅ 완화 전략
LLM 출력 Zero Trust 원칙 / 격리된 샌드박스 동적 분석 / 콘텐츠 타입 엄격 필터링
LLM06
🟡 높음
과도한 자율성 부여
AI 에이전트에 파일 수정·이메일 발송 등 과도한 권한 부여 시, 환각(Hallucination)이 실제 데이터 삭제·잘못된 송금으로 이어짐.
✅ 완화 전략
최소 권한 원칙(PoLP) 엄수 / 파괴적 작업 전 반드시 Human-in-the-loop 승인 절차 강제
LLM07
🟡 높음
시스템 프롬프트 유출
특수 설계된 질의로 독점 AI 지시어·내부 규칙·보안 제약 조건을 탈취, 방어 로직 무력화 정보로 활용.
✅ 완화 전략
시스템 프롬프트 접근 통제·암호화 / 방어적 프롬프팅(Defensive Prompting) 적용 / 프롬프트 추출 시도 휴리스틱 탐지
LLM08
🟡 높음
벡터·임베딩 취약점
RAG 검색 결과 조작, 벡터 데이터 유출을 통한 원본 텍스트 리버스 엔지니어링, 임베딩 공간 충돌 유도.
✅ 완화 전략
벡터 DB ACL 세분화 / 임베딩 모델 API Rate Limiting / 검색 쿼리 비정상 패턴 모니터링
LLM09
🟡 중간
잘못된 정보·환각
그럴싸한 허위 정보를 검증 없이 의사결정·법률 문서에 활용, 기업 신뢰성 하락 및 법적·재무적 손실 발생.
✅ 완화 전략
출처(Citation) 표기 강제 / 신뢰 소스와 실시간 교차 검증 / 불확실성 임계값 이하 시 답변 거부 로직
LLM10
🟡 중간
무제한 리소스 소비
대량의 복잡한 요청으로 GPU 인프라 고갈 또는 클라우드 API 비용 폭탄(Economic DoS) 유발.
✅ 완화 전략
사용자·앱 단위 API 토큰 할당 / QPS 제한 / 장기 실행 쿼리 타임아웃·Hard Limit 강제 적용

임직원 AI 수용 정책 (AUP)

사내 생성형 AI 및 LLM 서비스를 사용할 때 임직원이 반드시 준수해야 하는 행동 지침입니다.

🚫
절대 금지 사항
❌
기밀·개인정보 입력 금지 주민등록번호, 고객 PII, 미공개 소스 코드, 재무 데이터, 파트너사 협의 내용을 어떠한 AI에도 입력 불가
❌
개인 계정 업무 활용 금지 개인 이메일·소셜 계정을 통한 업무 문서 요약·번역 등 일체 금지. 반드시 회사 공식 계정만 사용
❌
미승인 서비스 사용 금지 (Shadow AI) CISO가 승인하지 않은 외부 AI 서비스를 업무 목적으로 사용하는 행위 엄격 금지
❌
딥시크(DeepSeek) 등 특정 서비스 사용 금지 과도한 메타데이터 수집이 확인되었거나 데이터 주권 위험이 있는 서비스는 사내 네트워크 접속 차단
❌
AI 결과물 무검증 사용 금지 생성된 내용을 사실 확인 없이 의사결정·고객 응대·법률 문서에 그대로 반영하는 행위 금지
✅
허용 및 권장 활용
✅
일반 문서 요약·교열 공개 정보 또는 비민감 내부 문서의 요약, 맞춤법 교정, 번역 (개인정보 사전 제거 후)
✅
코드 생성·검토 (비민감 로직) 알고리즘 로직, 유틸리티 함수 등 핵심 비즈니스 로직이 포함되지 않는 코드 작성·리뷰
✅
마케팅·커뮤니케이션 초안 작성 제품 소개 문구, 이메일 초안, 공개 자료 작성 (검토 후 사용)
✅
정보 조사·학습 업무 관련 개념 학습, 기술 트렌드 조사, 일반적인 Q&A
⚠️
조건부 허용 (승인 필요)
⚠️
가명처리된 데이터 분석 정보보호팀이 가명처리를 완료하고 승인한 데이터셋에 한하여 허용
⚠️
고객 응대 자동화 Human-in-the-loop 검토 절차 필수 / 생성 결과물에 "AI 작성" 라벨 표기 의무
⚠️
신규 AI 서비스 파일럿 CISO 주관 보안 심의 위원회 → 법무 검토 → 최종 승인 절차 완료 후 제한적 사용 가능
📝
법적 서약 의무
비밀유지계약(NDA) 강화 조항
  • 재직 및 퇴사 후에도 AI 관련 기술·영업 비밀 영구 유지 의무
  • 미승인 외부 플랫폼에 내부 문서 업로드 시 징계 및 손해배상 청구 조항 명시
  • AI 생성 결과물의 사실 오류로 인한 문제는 사용자 본인 일차 책임
AI 신규 도입 승인 프로세스
  • 담당 부서 요청 → 정보보호부서 검토
  • 법무팀 법적 검토 → CISO 최종 승인
  • 개인정보 영향평가(PIA) 의무 수행
  • 미승인 사용은 내부 정책 위반으로 즉시 차단

모든 트래픽은 중앙 LLM Gateway를 반드시 경유합니다. 입력·출력 양방향에서 필터링이 수행되며, 모든 상호작용이 감사 로그에 기록됩니다.

🏛️
LLM API Gateway — 3단계 심층 방어
1️⃣
입력 단계 — 사전 프롬프트 스캐닝 PII(주민번호·카드번호·MRN) 및 기밀 키워드 탐지 즉시 드랍 또는 토큰화 / Amazon Bedrock Guardrails 유사 Jailbreak 서명 패턴 실시간 차단
2️⃣
출력 단계 — 응답 필터링 및 런타임 스키마 검증 합의된 JSON 스키마 위반 응답 자동 폐기 / 생성된 코드·SQL은 격리 샌드박스에서 선실행 검증 후 전달 / Over-sharing 방지
3️⃣
RAG 파이프라인 — 검색 증강 통제 필터 사용자 직급·부서 권한 초과 문서 접근 차단 / 문서 보안 태그 기반 정책 필터링 강제 / LLM이 민감 문서를 참조 데이터로 읽는 사고 원천 차단
🔧
비식별화 파이프라인 (Presidio)
  • 구조화 식별자: 이메일·전화·계좌번호 → 결정론적 토큰화 (형식 보존)
  • 비정형 텍스트: 이름·주소·병력 → 맥락 기반 교정(NLP)
  • 한국어 특화: 주민등록번호·사업자번호·휴대전화 패턴을 위해 spaCy KO 모델, KoBERT 연동
  • 멀티모달: 영상 내 얼굴 블러, 음성 스크러빙 처리
  • 재식별 위험 시 차등 프라이버시·연합학습·합성데이터 병행
📋
감사 로깅 — 핵심 원칙
  • 로깅 필수 항목: 프롬프트 내용, 응답 텍스트, 토큰 수, 모델 버전, 타임스탬프, 사용자 ID
  • 대용량 처리: 32KB 초과 메시지는 청크 분할 + CorrelationId 부여
  • 비식별화 기본값: 로그 저장 시 민감 정보 Redact by default 원칙
  • 로그 자체 보호: 일반 IT 환경과 완벽 격리, 최고 권한자 무단 접근 시 즉시 알람
  • DataSunrise 등 컴플라이언스 자동화 솔루션으로 PIPA·GDPR 상시 심사

AI 보안 사고 대응 플레이북

LLM 관련 보안 사고 발생 시 단계별 대응 절차와 역할을 안내합니다.

👥
대응 팀 구성 및 역할
  • CISO: 사고 전체 지휘, 경영진 보고, 규제 당국 통지 결정
  • 보안팀(IR팀): 기술 분석, 격리 조치, 포렌식 수집
  • 법무팀: 법적 책임 분석, 통지 의무 여부 판단
  • PR/커뮤니케이션: 대외 커뮤니케이션 조율
  • 데이터팀: 모델 롤백, 재훈련, 데이터 파기
  • IT운영팀: 서비스 격리·복구
⏱️
법적 통지 의무 타임라인
  • 72시간 내: GDPR 및 국내 PIPA 규정에 따라 일정 규모 이상 개인정보 유출 시 관할 당국(PIPC 등) 통지 의무
  • 즉시: 정보 주체(피해자)에게 유출 사실 및 피해 방지 조치 안내
  • 사후: 영향 보고서 작성 및 재발 방지 계획 제출
📋
6단계 사고 대응 절차
1
감지 (Detect)
의심스러운 LLM 출력, 보안 경보, 이상 로그 발생 시 즉시 CISO 및 보안팀 알림. 모니터링 대시보드·SIEM 경보를 통한 자동 탐지 우선.
2
분석 (Analyze)
사고 범위(영향 시스템·데이터), 원인(입력값·모델 이상·외부 공격) 파악. 감사 로그·CorrelationId로 전체 공격 체인 재구성.
3
격리 (Contain)
피해 확산 방지를 위해 해당 LLM 서비스 접속 일시 차단. 영향받은 API 엔드포인트·사용자 계정 즉시 비활성화.
4
대응 조치 (Remediate)
노출된 정보 파기, 모델 롤백 또는 재훈련, 취약점 패치 적용. 법무팀과 함께 규제 통지 의무 여부 결정.
5
복구 (Recover)
정상 서비스 복원, 추가 모니터링 강화 배치. 서비스 재개 전 보안 검증 재수행 필수.
6
보고 및 학습 (Review)
영향 보고서 작성·관계기관 통지. 재발 방지를 위한 정책·기술 보완 실시. 사례를 교육 자료로 활용하여 전사 인식 제고.
🎯
주요 AI 보안 사고 시나리오
