🤔 왜 만들었나요?
IT 인프라 환경의 데이터베이스 및 시스템 백업 상태를 매일 수동으로 점검하는 과정에서 세 가지 문제가 반복되고 있었습니다.

❌ 기존 방식의 문제

  • 🖥️ 20여 대 서버를 RDP·SSH로 일일이 개별 접속
  • ⏱️ 백업 크기·로그 확인에 일평균 40~60분 소요
  • ⚠️ VEEAM, NetVault, RMAN, SQL Backup 등 다양한 백업 로그를 육안으로 확인 → 누락·오판독 위험
  • 📋 점검 결과를 '백업 일지' 양식에 맞게 다시 타이핑하는 이중 작업

✅ 백업 모니터링의 해결

  • 🌐 모든 서버 백업 상태를 웹 한 곳에서 조회
  • ⚡ Ansible이 매일 오전 8시 자동 수집·정리
  • 🤖 AI(Gemini)가 복잡한 로그를 한눈에 요약 브리핑
  • 📄 백업 일지 보고서 자동 생성 및 PDF 출력
⚙️ 주요 기능
수집부터 요약·보고서 출력까지, 백업 점검의 전 과정을 자동화했습니다.
📋

로그 중앙 집중 조회

각 서버별 백업 덤프 파일 크기, 생성 경로, 상세 로그를 웹 브라우저에서 클릭 한 번으로 확인. 개별 서버 접속 불필요.

🤖

Ansible 기반 완전 자동 수집

Ansible 플레이북을 쉘 스크립트로 모듈화. crontab으로 매일 오전 8시 정각에 자동 실행하여 전 서버 데이터를 수집·저장.

🔍

정규식 기반 데이터 자동 추출

비정형 텍스트 로그에서 시작 시간, 종료 시간, 최종 백업 용량(GB) 등 핵심 데이터만 정확히 추출하는 맞춤형 파싱 엔진.

📄

백업 일지 자동 생성 및 PDF 출력

추출된 데이터를 그룹웨어 보고 양식(Table)에 자동 매핑. PDF 다운로드 버튼 한 번으로 보고서 완성.

✨

AI 로그 요약 (Gemini API)

수십 개의 복잡한 백업·플레이북 실행 로그를 Gemini AI가 1차 분석하여 성공/실패 현황을 직관적으로 브리핑.

📱

멀티 디바이스 접근

스마트폰·태블릿 등 다양한 환경에서 접근 가능한 웹 페이지. IT 인프라 가시성과 운영 편의성 대폭 향상.

②

플레이북 실행 로그 조회

Ansible 플레이북 실행 결과 및 오류 내역 확인

③

⑤

백업 덤프 로그 조회
