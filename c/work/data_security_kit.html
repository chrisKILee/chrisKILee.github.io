01

왜 만들었는가

레거시 전환 시 AI와 개발자가 실데이터에 접근하면 개인정보 보호법 위반 위험이 생긴다. 이 도구는 그 접점을 차단한다.

문제
실데이터 노출 위험
ERP, HR, MES 등 레거시 시스템에는 직원 이름·주민번호·급여·인사평가 등 고감도 개인정보가 포함되어 있다. AI가 역추출(분석)을 위해 이 데이터에 접근하면 정보 유출 및 법적 책임이 발생한다.
해결
마스킹된 데이터만 공급
개발자와 AI는 마스킹된 샘플 데이터만 접근한다. 실데이터는 운영 전환 시에만 DBA가 직접 다룬다. 마스킹 정책은 정보보안 담당자가 승인한다.
02

4단계 파이프라인

분류 → 사람 검토 → 마스킹 실행 → 검증. 사람이 반드시 개입하는 단계가 포함된다.

1
classify-schema.py — 스키마 자동 분류
DDL 파일 또는 PostgreSQL·Oracle에 직접 접속하여 컬럼명·타입 패턴을 분석한다. CRITICAL / HIGH / LOW / UNCERTAIN 4등급으로 분류한 뒤 masking-config.yaml, masking-policy.md, classification-report.json 3개 파일을 생성한다.
2
사람 검토 + 승인 — UNCERTAIN 항목 처리
AI가 자동 분류하지 못한 UNCERTAIN 컬럼은 정보보안 담당자가 직접 등급을 결정한다. masking-policy.md에 승인 서명 후 다음 단계로 진행. AI는 UNCERTAIN을 절대 임의 판단하지 않는다.
3
apply-masking.py — 마스킹 실행
masking-config.yaml을 기반으로 소스 DB에서 데이터를 추출하며 동시에 마스킹을 적용한다. --mode sample은 Phase 1 역추출용 CSV(기본 1,000건), --mode full은 전체 처리. --dry-run으로 실행 계획만 확인할 수 있다.
4
verify-masking.py — 검증 및 CI/CD 연동
마스킹된 CSV 또는 DB를 검사하여 실제 이름(한글 2~4자)·주민번호(13자리 숫자)·전화번호·이메일이 남아있는지 확인한다. 위반 시 exit code 1을 반환하므로 CI/CD 파이프라인에 직접 연동 가능하다. 위반 로그에는 실제 값을 출력하지 않는다.
03

민감도 분류 기준

컬럼명 패턴 매칭이 1차, 데이터 타입이 2차 기준이다. 한국 레거시 시스템의 명명 규칙(한글 포함)을 반영한다.

"UNCERTAIN 항목은 AI가 판단하지 않는다. 반드시 사람이 분류한다."

classify-sensitive.md — 주의사항
등급 대상 정보 컬럼명 패턴 예시 데이터 타입 힌트
🔴 CRITICAL
반드시 마스킹		 이름, 주민번호, 전화번호, 이메일, 주소, 계좌번호 *_nm, *name, *jumin*, *tel*, *email*, *addr*, *acct* VARCHAR(13/14) → 주민번호 의심
🟡 HIGH
마스킹 권장		 급여, 인사평가, 징계, 건강정보, 비밀번호, 코멘트 *salary*, *eval*, *grade*, *discipline*, *pwd*, *remark* —
🟢 LOW
마스킹 불필요		 코드값, 날짜, PK/FK, 수량, 상태값, 시스템 메타 *_cd, *_dt, *_id, *_seq, *_yn, *_flag 신뢰도 0.95
⚪ UNCERTAIN
사람 확인 필요		 위 패턴에 매칭 안 되는 모든 컬럼 패턴 없음 또는 VARCHAR(13/14)이나 LOW 코드가 아닌 경우 신뢰도 0.0~0.5
04

마스킹 방법 5종

등급과 컬럼 성격에 따라 마스킹 방법이 다르다. 급여처럼 통계 분포가 중요한 경우 범위 내 랜덤으로 처리한다.

방법 적용 대상 동작 방식 예시
pseudonym 이름 (CRITICAL) 가명으로 치환. 동일 원본 → 동일 가명 (JOIN 로직 유지) 홍길동 → 사용자_0001
partial_mask 전화, 주민번호, 이메일, 주소, 계좌 (CRITICAL) 일부만 *로 대체. 형식별 규칙 적용 010-1234-5678 → 010-****-5678
홍*@domain.com
range_shuffle 급여, 금액 (HIGH) 원본값 ±20% 범위 내 랜덤값. 통계 분포 유지. seed 고정으로 재현 가능 3,000만 → 2,870만~3,130만 사이 랜덤
shuffle 인사평가 등급 (HIGH) 값 목록을 셔플하여 개인-값 매핑만 끊음. 값 자체의 분포는 유지 A/B/C 등급이 다른 사람에게 배분
hash 비밀번호 (HIGH) SHA-256 해시 앞 16자리로 치환 password123 → a7f3c2d8e1b09f4a
05

스크립트 사용법

DDL 파일 또는 PostgreSQL·Oracle DB에 직접 연결하여 실행한다. dry-run으로 먼저 계획을 확인하는 것을 권장한다.

1단계 — 스키마 분류 (DDL 파일 기준)

python scripts/classify-schema.py \
  --ddl schema.sql \
  --output masking-config.yaml

# PostgreSQL 직접 연결
python scripts/classify-schema.py \
  --pg "postgresql://user:pass@host:5432/db" \
  --output masking-config.yaml

# 의존성 설치
pip install pyyaml psycopg2-binary   # PostgreSQL
pip install pyyaml cx_Oracle         # Oracle

3단계 — 마스킹 실행

# dry-run으로 먼저 계획 확인
python scripts/apply-masking.py \
  --config masking-config.yaml \
  --source "postgresql://user:pass@host/db" \
  --mode sample \
  --dry-run

# 실제 실행 (마스킹된 CSV → ./masked-samples/)
python scripts/apply-masking.py \
  --config masking-config.yaml \
  --source "postgresql://user:pass@host/db" \
  --mode sample \
  --output ./masked-samples/

4단계 — 검증 (CI/CD 연동 가능)

# CSV 검증
python scripts/verify-masking.py \
  --config masking-config.yaml \
  --masked-dir ./masked-samples/

# exit code 1이면 마스킹 누락 → 파이프라인 중단
echo $?
06

핵심 설계 원칙

코드에서 읽힌 비기능 요구사항. 보안과 재현성이 최우선이다.

재현 가능성
seed=42 고정
동일 설정 파일로 실행하면 항상 동일한 마스킹 결과가 나온다. 개발팀 간 데이터 일관성 유지에 필수.
일관성
동일 원본 → 동일 가명
pseudonym 방법은 원본값을 키로 시퀀스를 부여하므로 "홍길동"이 여러 테이블에 있어도 항상 같은 가명이 된다. 외래키 JOIN 로직이 깨지지 않는다.
보안
검증 로그에 실값 없음
verify-masking.py는 위반 시 행 번호·컬럼명·길이만 출력하고 실제 값은 절대 출력하지 않는다. 검증 과정 자체가 또 다른 유출 경로가 되지 않도록 설계됨.
Human Gate
AI는 UNCERTAIN 판단 안 함
자동 분류가 불가한 컬럼은 UNCERTAIN으로 남긴다. AI가 임의로 등급을 결정하는 것을 명시적으로 금지하고, 반드시 정보보안 담당자가 결정하도록 설계됨.
07

Claude Code 스킬 연동

classify-sensitive.md를 Claude Code 스킬로 설치하면 자연어 명령으로 파이프라인 전체를 실행할 수 있다.

# 스킬 설치
cp skills/classify-sensitive.md ~/.claude/skills/

# Claude Code에서 사용
/classify-sensitive

스킬은 Vinification 프로젝트의 Phase 0에 위치한다. Phase 1 역추출(/analyze-legacy) 착수 전에 반드시 완료해야 하며, UNCERTAIN 항목이 0건이고 정보보안 담당자의 승인이 완료된 상태에서만 다음 단계로 진행한다.
