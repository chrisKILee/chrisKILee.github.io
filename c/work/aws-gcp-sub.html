GCP 서버리스: "통합"의 진실

Cloud Functions(2세대)와 Cloud Run의 관계 정립

💡 왜 "통합되었다"고 하나요?

구글은 Cloud Functions 2세대(2nd gen)를 출시하면서 인프라를 완전히 새로 구축했습니다. 과거의 독자적인 환경 대신, Cloud Run(Knative 기반) 위에서 함수가 돌아가도록 설계를 바꾼 것입니다.

  • 함수를 배포하면 내부적으로 Cloud Run 서비스가 자동 생성됨
  • 모든 트래픽 제어는 Eventarc가 담당
  • 결과적으로 기술적 뿌리가 같아짐

"Lambda = Cloud Run" 인가요?

네, 개념적으로는 그렇습니다. Lambda가 컨테이너 이미지를 지원하기 시작하면서 둘의 경계가 모호해졌습니다.

"함수 하나만 짜서 바로 올리고 싶어" → Cloud Functions
"Docker로 말아서 서버리스하게 돌리고 싶어" → Cloud Run

중요한 점은 GCP에서 Cloud Functions는 이제 Cloud Run의 '특수한 하위 활용 사례'처럼 취급된다는 것입니다.
