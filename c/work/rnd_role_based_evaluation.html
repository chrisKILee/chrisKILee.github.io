왜 기존 직무 분류는 칸반에서 무의미한가

칸반에서는 모두가 같은 보드를 보고 티켓을 당긴다. "시니어는 설계, 주니어는 구현"이라는 분리는 실제로 작동하지 않는다.

의미 있는 분류 기준 → "어떤 종류의 문제를 주로 해결하는가"

  • 문제의 불확실성 수준이 다르다
  • 문제의 영향 범위가 다르다
  • 그 차이를 만드는 사람이 실질적으로 다른 역할을 하는 것

분류 원칙

원칙 설명
직함 무관 시니어/미들/주니어 기준 아님
문제 유형 기준 "이 사람이 주로 어떤 문제를 푸는가"
중복 허용 한 사람이 복수 카테고리에 기여 가능 (주 기여 영역 평가)
측정 가능 칸반 보드의 티켓 태그로 추적 가능해야 함
