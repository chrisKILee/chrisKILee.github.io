🚀 Getting Started

Getting Started 2-1단계: 새 프로젝트 시작

Terroir 가이드 문서 (Beta) · R&D실
ℹ️ 안내

이 문서는 Github 레포지토리 생성 → 로컬 개발환경 부트스트랩까지 전 과정을 다룹니다.

시작 전 준비사항

항목

설명

GitHub 계정

VntgCorp 조직에 초대된 개인 GitHub 계정.

GitHub 계정 연동

Terroir IDP Settings에서 GitHub OAuth 연동이 완료되어 있어야 합니다.
(미연동 상태면 안내 다이얼로그가 뜹니다)

로컬 OS

macOS, Linux, Windows(WSL2) 중 택1.
Windows는 반드시 WSL2(Ubuntu)가 설치되어 있어야 합니다.

🪟 Windows 사용자: WSL2가 아직 설치되어 있지 않다면, 이 문서를 읽기 전에 먼저 WSL2를 설치해 주세요. 본 가이드는 WSL2 + Ubuntu 환경을 전제로 작성되었습니다. [사전 준비(윈도우)]

새 프로젝트 시작하기

Terroir IDP(링크) 접속 > 사이드바 메뉴 > 프로젝트 시작하기 > 새 프로젝트 시작

  • 새 프로젝트 시작하기에는 사용자의 github 계정으로 새로운 레포지토리가 생성이 됩니다. Github 로그인이 되지 않았다면 아래와 같은 팝업창이 뜹니다. [SETTINGS 이동하기] 버튼을 눌러 Github 연동 페이지로 이동합니다.

  • [GITHUB 계정 연동] 버튼을 눌러 Github에 로그인을 합니다.

  • 연동이 완료되면 아래와 같이 연동된 Github 계정 아이디가 표시됩니다. 회사와 연결된 계정만 VntgCorp 조직 레포지토리에 접근이 가능합니다. 잘못된 계정을 연동 했을 경우 [다른 계정으로 재연동] 버튼을 눌러 다시 로그인 해주세요.

  • 권한이 필요하다면 플랫폼 개발팀 문의채널에 문의해주세요.

프로젝트 시작하기

  • Github 연동이 완료 되었다면 다시 프로젝트 시작하기 메뉴로 이동합니다.

새 프로젝트 만들기

  • 레포지토리 이름은 소문자 + 하이픈(-) 조합을 권장합니다. (예: my-project)

  • [중복 검사] 버튼을 눌러 작성된 레포지토리 이름이 중복이 되었는지 검증을 합니다. 중복이 있다면 레포지토리 이름을 재작성하고 [중복 검사]를 진행합니다.

  • 레포지토리 설명은 선택사항 입니다. 작성이 완료가 되었다면 [검토] 버튼을 눌러 다음으로 진행합니다.

  • 작성한 레포지토리 이름과 설명을 확인 후 [생성] 버튼을 눌러 다음을 진행을 합니다.

  • 레포지토리 생성이 완료되면 아래와 같은 스크립트를 제공합니다. macOS와 Windows 환경은 차이가 있으니 내용을 확인하시어 진행을 하면 됩니다.

macOS / Linux 로컬 개발환경 셋업

 

전체 흐름: git/gh 설치 → gh 인증 → git clone → gh 익스텐션 설치 → gh terroir-bootstrap

1. (선택) git / gh CLI 설치

이미 git과 gh가 설치되어 있다면 이 단계는 건너뛰세요. 확인 방법:

git --version    # git version 2.x.x ...
gh --version     # gh version 2.x.x ...

설치되어 있지 않다면, 회사 표준 셋업 스크립트를 받아서 실행합니다.

# 1) 작업 디렉토리로 이동 (예시 — 원하는 위치 어디든 OK)
cd ~/Downloads

# 2) 셋업 스크립트 다운로드 (브라우저에서 받아도 됩니다)
#    https://storage.cloud.google.com/vntg-rnd-dev-backstage/download/setup-git-gh.sh

# 3) 실행 권한 부여
chmod +x setup-git-gh.sh

# 4) 실행
./setup-git-gh.sh

2. gh CLI 인증 (필수)

GitHub Actions workflow 파일(.github/workflows/*.yml)을 push하려면 OAuth 토큰에 workflow scope 가 반드시 포함되어야 합니다. 인증 상태에 따라 아래 두 명령 중 하나만 실행하면 됩니다.

# (A) 처음 인증하거나 깔끔하게 다시 인증할 때 — workflow scope 포함해서 한 번에 부여
gh auth login --scopes "repo,workflow,read:org"

# (B) 이미 gh auth login은 했지만 workflow scope만 빠진 경우 — scope만 덧붙이기
gh auth refresh -h github.com -s workflow

인증 후 아래 명령으로 workflow scope 포함 여부를 확인하세요.

gh auth status

출력 예시 — Token scopes: 줄에 'workflow'가 있어야 합니다.

✓ Logged in to github.com as your-id (oauth_token)
✓ Token scopes: 'gist', 'read:org', 'repo', 'workflow'

3. 레포지토리 클론

여러 프로젝트를 한 곳에서 관리하기 위해, 전용 작업 디렉토리 아래에 클론하는 것을 권장합니다.

# 작업 디렉토리 생성 (최초 1회) — 경로는 자유
mkdir -p ~/workspace/vntg
cd ~/workspace/vntg

# 클론 (URL은 Terroir IDP 완료 화면에 표시된 URL을 그대로 복사)
git clone https://github.com/VntgCorp/<레포지토리-이름>.git

# 레포지토리 안으로 이동
cd <레포지토리-이름>

4. gh 익스텐션 설치

부트스트랩에 사용할 익스텐션(gh-terroir-bootstrap)을 설치합니다. 최초 1회만 실행하면 되며, 이후 다른 신규 프로젝트에서도 그대로 재사용됩니다.

gh extension install VntgCorp/gh-terroir-bootstrap

설치 확인:

gh extension list
# terroir-bootstrap  VntgCorp/gh-terroir-bootstrap  v?.?.?

5. 부트스트랩 실행 — 표준 구조 자동 생성

레포지토리 디렉토리(~/workspace/vntg/<레포지토리-이름>) 안에서 아래 명령을 실행하면, 회사 표준 개발환경/디렉토리 구조가 자동으로 세팅됩니다.

gh terroir-bootstrap

실행이 끝나면 레포 안에 다음 파일/폴더들이 생성됩니다 (실제 산출물은 익스텐션 버전에 따라 다를 수 있음).

6. 다음 단계

부트스트랩 결과로 docs/getting-started.md (또는 README.md의 Getting Started 섹션)가 생성됩니다. 앱 실행, 환경변수 설정, 브랜치 전략 등 후속 작업은 이 문서를 참고하세요.

Windows (WSL2) 로컬 개발환경 셋업

 

작업을 시작하기 전 — WSL 터미널 준비

  1. 시작 메뉴에서 Ubuntu (또는 설치한 WSL 배포판)을 검색해 실행합니다.

  2. 프롬프트가 <user>@<hostname>:~$ 형태로 보이면 WSL 안입니다.

  3. 아래 명령으로 현재 위치가 WSL 홈인지 반드시 확인하세요.

    pwd
# 결과: /home/<user>     ← OK
# 결과: /mnt/c/...        ← ❌ 절대 여기서 작업하지 마세요

1. 왜 /mnt/c 하위에서 작업하면 안 되나요?

WSL에서 /mnt/c는 Windows 파일시스템(NTFS) 을 마운트한 공간입니다. 이 위에서 빌드/실행을 하면 다음 문제가 자주 발생합니다.

문제

증상

파일 권한 손실

chmod +x 가 영구 적용되지 않아 permission denied 발생

심볼릭 링크 실패

node_modules 안의 심링크가 깨짐 → 빌드 에러

빌드 성능 저하

I/O 가 5~10배 느려짐 (대형 프로젝트일수록 체감 큼)

파일 감시 미작동

hot-reload, watch 모드가 동작하지 않거나 누락 발생

따라서 모든 코드/스크립트는 반드시 WSL 홈(~/, 즉 /home/<user>/) 아래에 두세요.

2. (선택) git / gh CLI 설치

브라우저로 setup-git-gh.sh를 받으면 보통 C:\\Users\\<user>\\Downloads\\ 에 저장됩니다. 이 파일을 그대로 실행하면 안 됩니다. 먼저 WSL 홈으로 옮긴 뒤 실행해야 합니다.

# 1) Windows 다운로드 폴더의 파일을 WSL 홈으로 이동
#    <user> 부분은 본인 Windows 사용자명으로 바꿔주세요
mv /mnt/c/Users/<user>/Downloads/setup-git-gh.sh ~/

# 2) 홈으로 이동
cd ~

# 3) 실행 권한 부여 (Windows에서 받은 파일은 실행 비트가 꺼져 있습니다)
chmod +x setup-git-gh.sh

# 4) 실행
./setup-git-gh.sh

자주 하는 실수

  • ❌ cd /mnt/c/Users/<user>/Downloads && ./setup-git-gh.sh → 권한 이슈로 실패합니다.

  • ❌ PowerShell 에서 bash setup-git-gh.sh 시도 → bash가 없거나 다른 환경이라 실패할 수 있습니다.

  • ✅ 위 4단계를 그대로 따라가면 안전합니다.

3. gh CLI 인증

macOS와 동일합니다. WSL 터미널에서 실행하세요.

gh auth login --scopes "repo,workflow,read:org"
# 또는
gh auth refresh -h github.com -s workflow

브라우저 인증 단계에서는 Windows의 기본 브라우저가 자동으로 열립니다. 거기서 GitHub 로그인 후 화면이 "You may close this tab" 으로 바뀌면 WSL 터미널로 돌아오세요.

4. 레포지토리 클론 — 반드시 WSL 홈에

# 1) WSL 홈에 작업 디렉토리 생성 (최초 1회)
mkdir -p ~/workspace/vntg
cd ~/workspace/vntg

# 2) 클론
git clone https://github.com/VntgCorp/<레포지토리-이름>.git

# 3) 레포 안으로 이동
cd <레포지토리-이름>

# 4) 위치 확인 — /home/... 이어야 정상
pwd

🚨 절대 하지 마세요

  • ❌ git clone ... C:\\Users\\<user>\\Documents\\...

  • ❌ cd /mnt/c/work && git clone ...

  • ❌ Windows 탐색기로 클론한 폴더를 \\\\wsl$\\... 경로로 열고 거기서 빌드

5. gh 익스텐션 설치 & 부트스트랩 실행

이후는 macOS와 동일합니다.

# 익스텐션 설치 (최초 1회)
gh extension install VntgCorp/gh-terroir-bootstrap

# 레포 디렉토리에서 부트스트랩 실행
gh terroir-bootstrap

6. 다음 단계

부트스트랩 결과로 docs/getting-started.md (또는 README.md의 Getting Started 섹션)가 생성됩니다. 앱 실행, 환경변수 설정, 브랜치 전략 등 후속 작업은 이 문서를 참고하세요.

PR 생성

로컬 개발 환경에서 작업 완료 후, PR 단계에서 merge가 진행이되면 Github Action이 실행됩니다.

약 5분 뒤에 Terroir 접속(링크) > 배포관리에서 해당 프로젝트 확인이 가능합니다.
