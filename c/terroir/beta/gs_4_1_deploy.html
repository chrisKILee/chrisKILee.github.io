🚀 Getting Started

Getting Started 4-1단계: 배포 관리 (최초 배포)

Terroir 가이드 문서 (Beta) · R&D실

1. 사전 조건

배포 관리 화면에서 프로젝트를 보려면 아래 두 가지가 충족되어야 합니다.

  • VntgCorp 조직 GitHub 레포지토리여야 합니다.

    • Terroir 배포 파이프라인은 VntgCorp org 소속 레포만 인식합니다.

  • 각 환경에 맞는 브랜치에 머지되어 있어야 합니다.

    • 머지 시점에 CI가 실행되어 BE 이미지가 빌드되고 배포 시스템에 자동으로 등록되며, 그 이후부터 배포 관리 화면 목록에 노출됩니다.

    • (FE 이미지는 환경 설정 입력 이후에 별도로 빌드됩니다 — 전체 흐름 Step 3 참고)

ℹ️ 안내

💡 확인 방법
머지 후에도 화면에 프로젝트가 보이지 않는다면, GitHub Actions 에서 CI 워크플로우가 성공적으로 끝났는지 먼저 확인하세요.

➡ 2. 전체 흐름

최초 환경 설정 시 권장 순서는 DB → BE → FE 입니다.

ℹ️ 안내

💡 순서는 강제가 아닙니다.
DB 가 첫 번째인 이유는 BE 환경변수에 DB 접속 정보를 참조하기 때문입니다.
BE 와 FE 사이에는 환경 설정 의존성이 없으므로 순서를 바꿔도 동작에는 문제가 없습니다.

ℹ️ 안내

💡 팁: FE 빌드 시간을 활용하세요.
FE 는 적용 시점에 이미지 빌드가 트리거되어 수 분이 소요됩니다.
FE 를 먼저 적용해두면 빌드가 진행되는 동안 BE 설정 작업을 동시에 할 수 있습니다.

ℹ️ 안내

💡 두 번째 변경부터는 DB 단계를 건너뛰세요.
DB 환경 설정은 최초 1회만 의미가 있습니다 (초기 생성 이후에는 화면에서 값을 변경해도 반영되지 않음).
이후 변경 작업에서는 BE / FE 만 다시 설정하면 됩니다.

[사전: 머지 시점에 BE 이미지 빌드 완료]
      │
      ▼
Step 1: DB 환경 설정
      │   입력: 리소스(CPU/Memory) / 계정 ID / PW / DB 이름
      ▼
Step 2: BE 환경 설정
      │   입력: 리소스(CPU/Memory) / Port / 환경변수
      ▼
Step 3: FE 환경 설정
      │   입력: 리소스(CPU/Memory) / Port / 환경변수
      │   ⚠️ 적용 시점에 FE 이미지 빌드가 즉시 트리거됨
      ▼
Step 4: 배포
          • DB → 초기 계정 + 데이터베이스 자동 생성
          • BE → (머지 시점에 빌드된 이미지) 배포 + 런타임 환경변수 동적 주입
          • FE → (Step 3 에서 빌드된 이미지) 배포 + 런타임 환경변수 동적 주입
ℹ️ 안내

💡 공통 입력값
· 모든 단계 공통: 리소스 설정 (CPU / Memory)
· BE / FE 공통: Port

ℹ️ 안내

💡 Step 1~3 은 값을 "저장"만 합니다.
데이터베이스 생성, 환경변수 주입 등 실제 동작은 Step 4 배포 시점에 한 번에 일어납니다.
단, FE 만 예외 — Step 3 적용 시점에 이미지 빌드가 즉시 트리거되며, 배포는 그 빌드 결과로 진행됩니다.

각 단계의 입력값이 어떻게 적용되는지는 다음과 같습니다.

  • DB — 입력한 계정 ID / 비밀번호 / DB 이름은 배포 시점에 초기 계정과 데이터베이스 생성에 사용됩니다.

    • ⚠️ 초기 생성 이후에는 화면에서 값을 변경해도 반영되지 않습니다.

    • 계정/DB 이름 등을 바꿔야 한다면 [가이드] DB 접근방법 (DBeaver) 를 따라 DB에 직접 접속해서 변경해야 합니다.

  • BE — 이미지는 사전 조건의 머지 시점에 이미 빌드되어 있습니다. 환경 설정은 배포 시점에 런타임 환경변수로 동적 주입되므로, 이미지 재빌드 없이 값만 바꿔서 재배포하면 새 값이 반영됩니다. (내부적으로는 ConfigMap / Secret 으로 저장됩니다.)

  • FE — BE 와 달리 환경변수가 빌드 결과물(.env)에 박혀야 하므로, 환경 설정을 적용하는 시점에 이미지 빌드가 즉시 트리거됩니다. 이후 배포 시점에 빌드된 이미지가 올라가면서 동시에 런타임 환경변수로도 같은 값이 주입됩니다.

    • 빌드타임 정적 주입: 입력값을 .env 파일로 만들어 번들에 포함시킵니다.

    • 런타임 동적 주입: 배포된 컨테이너에 환경변수로도 다시 주입됩니다.

    • 즉, FE는 환경변수를 변경하면 재빌드 + 재배포 가 모두 필요합니다 (재빌드는 적용 시점에 자동 트리거).

3. 최초 배포 — 첫 환경 설정부터 배포 완료까지

머지 직후 처음으로 환경을 설정하고 배포하는 시나리오입니다. 권장 순서(DB → BE → FE → 배포)를 따릅니다.

Step 1 — 프로젝트 상세 진입

배포 관리 화면(/deploy-management)에서 상단 배포 환경 토글이 원하는 환경(예: Develop)으로 선택되어 있는지 확인한 뒤, 대상 프로젝트 카드의 상세보기 버튼을 클릭합니다.

Step 2 — DB 환경 설정

DB 앱 카드의 환경 설정 버튼을 클릭하면 모달이 열립니다. (앱 카드 좌측의 타입 라벨로 DB 앱을 식별할 수 있습니다.)

다음 값을 입력하고 적용을 누릅니다.

  • 리소스 설정: CPU / Memory (preset 또는 직접 입력)

  • 환경변수: 계정 ID / 비밀번호 / DB 이름

ℹ️ 안내

💡 임시저장
작성 중인 변경사항을 잠깐 저장만 해두고 싶다면 모달의 임시저장 버튼을 사용할 수 있습니다. 다음에 모달을 다시 열면 "임시저장 있음 · 미적용" 배지로 표시되며, 복원 배너가 노출됩니다.

앱 카드의 상태가 준비됨으로 변경된 것을 확인합니다.

📝 참고

⚠️ 주의
DB 환경 설정 값은 최초 1회만 의미가 있습니다. 한 번 배포된 이후 값을 바꿔도 반영되지 않으므로, 신중하게 입력하세요.

Step 3 — BE 환경 설정

BE 앱 카드의 환경 설정 버튼을 클릭하고, 다음 값을 입력 후 적용을 누릅니다.

  • 리소스 설정: CPU / Memory

  • Port: BE 가 동작하는 Port 번호

  • 환경변수: DB 접속 정보 등 (Step 2 에서 입력한 값을 참조)

예시 BE는 3000번 포트로 동작하므로 3000을 입력합니다.

📝 참고

⚠️ containerPort 와 환경변수 APPLICATION_PORT 는 반드시 일치해야 합니다.
값이 다르면 K8s Service가 트래픽을 전달하는 포트와 앱이 실제 listen 하는 포트가 어긋나 503 / connection refused 가 발생합니다.

하단의 항목 추가 또는 .env 붙여넣기 기능으로 필요한 환경변수를 모두 입력합니다.

📝 참고

⚠️ .env.example 에 포함된 모든 키는 필수 값으로 등록됩니다.

로컬에서만 쓰고 배포 환경에서는 필요 없는 변수가 있다면, .env.example 파일에서 미리 지우거나 의미 없는 임의 값(공백 아닌)을 넣어주세요.

DB 를 사용하는 BE 의 경우

DATABASE_* 환경변수에는 Step 2 (DB 환경 설정) 에서 입력했던 값을 그대로 사용합니다.

DATABASE_URL 은 입력하지 않으면 자동으로 주입됩니다. 직접 명시해야 하는 경우(예시처럼 ORM에서 단일 URL 형태가 필요한 경우)에는 아래 양식대로 조합합니다.

  1. 앱 목록에서 DB 앱의 내부 접속 주소를 확인합니다.

  1. 해당 주소와 Step 2 에서 입력했던 계정 정보를 조합하여 DATABASE_URL 을 만듭니다.

양식: postgresql://{{DATABASE_USER}}:{{DATABASE_PASSWORD}}@{{내부 접속 주소}}:5432/{{DATABASE_DB}}
예시: postgresql://guide_user:guide_pw@app-db.terroir-guide.svc.cluster.local:5432/guide_db

## .env 파일 예시

# Application
APPLICATION_NAME=be-api-server
APPLICATION_PORT=3000

# Database
DATABASE_URL=postgresql://guide_user:guide_pw@app-db.terroir-guide.svc.cluster.local:5432/guide_db
DATABASE_DB=guide_db
DATABASE_USER=guide_user
DATABASE_PASSWORD=guide_pw
DATABASE_PORT=5432

# Authentication
JWT_ACCESS_TOKEN_SECRET=random-local-access-secret-key

# Infrastructure
## FRONTEND_URL도 앱 목록에서 확인하시면 됩니다.
FRONTEND_URL=https://terroir-guide-fe-user-client.dev.terroir.vntgcorp.com

# Observability
LOG_LEVEL=info

완성된 .env 내용을 .env 붙여넣기 기능으로 입력하면 자동으로 키-값으로 분리되어 등록됩니다.

Step 4 — FE 환경 설정 (이미지 빌드 트리거)

FE 앱 카드의 환경 설정 버튼을 클릭하고, 다음 값을 입력 후 적용을 누릅니다.

환경 설정 입력 방식은 BE 와 동일합니다.

  • 리소스 설정: CPU / Memory

  • Port: 권장 80

  • 환경변수: BE_URL 등 (BE 의 서비스 URL은 프로젝트 상세의 앱 목록에서 확인할 수 있습니다)

적용 시 "이미지 빌드를 시작하시겠습니까?" 다이얼로그가 뜨며, 빌드 시작을 누르면 GitHub Actions 워크플로우가 즉시 트리거됩니다.

적용을 누르면 "이미지 빌드를 시작하시겠습니까?" 다이얼로그가 뜹니다.

빌드 시작을 클릭하면 GitHub Actions 워크플로우가 즉시 트리거되고, 모달 상단에서 진행 상황을 확인할 수 있습니다.

📝 참고

⚠️ 주의
FE 빌드는 수 분이 소요되며, 모달을 닫아도 백그라운드에서 계속 진행됩니다.
진행 상황은 GitHub Actions 페이지 또는 모달 상단의 빌드 상태 표시로 확인할 수 있습니다.

Step 5 — 배포

FE 빌드가 완료되면 프로젝트 상세 화면 상단 우측의 배포 버튼을 클릭합니다. 확인 다이얼로그에서 진행하면 배포가 시작됩니다.

확인 다이얼로그에는 이번 배포에 포함될 앱 목록과 버전이 표시됩니다.

다이얼로그 하단의 배포 버튼을 클릭하면 배포가 시작됩니다.

Step 6 — 배포 결과 확인

  • 상단 배포 상태가 Synced + Healthy 인지 확인합니다.

  • 각 앱 카드의 현재 배포 버전이 최신 빌드 버전과 일치하는지 확인합니다.

  • 각 앱 카드의 서비스 URL 로 접속해서 동작을 확인합니다.

  • (옵션) 상단의 Grafana 버튼으로 로그/메트릭을 확인합니다.
