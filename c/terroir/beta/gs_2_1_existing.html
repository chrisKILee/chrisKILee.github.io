🚀 Getting Started

Getting Started 2-1단계: 기존 프로젝트에서 시작

Terroir 가이드 문서 (Beta) · R&D실
ℹ️ 안내

이 문서는 Terroir IDP에 외부 레포지토리를 등록하고, 배포 관리 화면에 내 앱 조회까지의 흐름을 안내합니다.

1. 목표 상태

이 문서를 끝까지 따라가면 다음 상태에 도달합니다.

  • ✅ Terroir IDP에 내 레포지토리가 등록됨

  • ✅ develop 브랜치에 머지 시 이미지가 자동으로 빌드 및 푸시됨

  • ✅ Terroir IDP 배포 관리 화면에 내 앱이 노출됨

전체 흐름

[1] Terroir IDP "기존 프로젝트에서 시작" 메뉴에서 레포지토리 등록
        ↓
[2] 등록 후 레포지토리 설정 (terroir.json / 워크플로우 / Dockerfile / health check)
        ↓
[3] 브랜치 머지 → CI 자동 실행 → 이미지 빌드 및 푸시
        ↓
[4] Terroir IDP 배포 관리 화면에 앱 노출 ✅

배포(ArgoCD 실배포)·런타임 운영은 별도 문서입니다.

2. Terroir IDP 등록 최소 요건

등록을 시작하려면 이것만 있으면 됩니다.

  • GitHub VntgCorp org 소속 레포지토리 (https://github.com/orgs/VntgCorp/repositories)

📝 terroir.json / 워크플로우 파일 / Dockerfile 등은 등록 후에 채워도 됩니다.
Terroir IDP는 등록 시점에 레포지토리 내부 파일을 검증하지 않습니다.
단, 파이프라인이 정상 동작하려면 3장의 조건도 만족해야 합니다.

3. 외부 프로젝트 등록 조건

등록하려는 프로젝트가 아래 조건을 만족해야 파이프라인이 정상 동작합니다. 조건을 만족하지 않아도 등록은 가능하지만, 빌드·배포가 실패할 수 있습니다.

  • Dockerfile 기반 빌드가 가능한 앱일 것

  • BE / FE 앱은 health check 엔드포인트(BE: GET /api/health, FE: GET /health) 제공

📝 그 외 세부 규칙(네이밍, 워크플로우 파일 취급, Dockerfile 위치, DB 지원 범위 등)은 각 섹션에서 안내합니다.

4. Terroir IDP에 레포지토리 등록

Terroir IDP(링크) 접속 > 사이드 메뉴 > 프로젝트 시작하기 > 기존 프로젝트에서 시작

등록할 레포지토리의 GitHub URL 입력 (예: https://github.com/VntgCorp/demo-fun )

5. 등록 후 레포지토리 설정

등록된 레포지토리에 Terroir 동작에 필요한 파일을 배치하고 애플리케이션을 설정합니다.

📝 이 섹션의 예시는 DEV(개발) 환경 배포를 기준으로 작성되어 있습니다.
develop 브랜치 → DEV 환경 매핑을 전제로 하니, 운영 환경(PROD)까지 확장할 때는 environments 에 PROD 를 추가하면 됩니다.

5.1 워크플로우/메타데이터 파일 배치

아래 3개의 파일을 다운로드하여, 레포지토리에 배치하세요.

최종 디렉터리 구조

<프로젝트 루트>/
├── terroir.json
└── .github/workflows/
    ├── terroir-docker-delivery.yml          ← 머지 시 자동 빌드 (BE/DB)
    └── terroir-fe-build.yml                 ← FE 전용 재빌드 (workflow_dispatch)

workflows 디렉터리 생성 및 파일 복사

# '.github/workflows/' 디렉터리가 없다면 먼저 생성하세요.
mkdir -p <프로젝트 루트>/.github/workflows

cp terroir.json <프로젝트 루트>/terroir.json
cp terroir-docker-delivery.yml <프로젝트 루트>/.github/workflows/terroir-docker-delivery.yml
cp terroir-fe-build.yml <프로젝트 루트>/.github/workflows/terroir-fe-build.yml

⚠️ 동일 파일명이 이미 있다면 백업 후 덮어쓰기 하세요.
⚠️ terroir-docker-delivery.yml, terroir-fe-build.yml 은 수정 시 파이프라인 동작을 보장하지 않습니다. 수정이 필요하다고 느껴지면 플랫폼개발 팀에 먼저 문의하세요.

5.2. terroir.json 작성

terroir.json 은 Terroir에 앱을 배포하기 위한 정보를 담는 메타데이터 파일입니다. Terroir가 이 파일을 읽어 어떤 앱을, 어느 브랜치에서, 어떻게 빌드·배포할지 결정합니다.

BE / FE / DB 앱을 하나의 apps[] 배열에 선언합니다.

스키마 한눈에 보기

{
  "schema": "1",                      // 스키마 버전 (현재 "1" 고정)
  "environments": {                   // Terroir 환경명 → 레포지토리 브랜치
    "DEV":  "develop",                //   develop 브랜치를 DEV 환경으로 인식
    "PROD": "main"                    //   main    브랜치를 PROD 환경으로 인식 (현재 지원하지 않음)
  },
  "apps": [
    {
      "name":    "my-api",            // 앱 이름 (소문자 + 하이픈)
      "type":    "BE",                // BE | FE | DB
      "group":   "my-project",        // 이 앱이 속한 프로젝트 그룹명
      "root":    ".",                 // 빌드 컨텍스트 디렉터리
      "version": "0.1.0"              // 변경 시 CI가 빌드/배포 트리거
    }
  ]
}

environments 상세

"환경명": "브랜치명" 형태의 매핑입니다. 키(환경명)는 Terroir가 인식하는 이름, 값(브랜치명)은 레포지토리의 실제 브랜치입니다.

예) "DEV": "develop" → develop 브랜치에 머지되면 DEV 환경용 이미지가 빌드됩니다.

  • 지원 환경: DEV, PROD 만 사용 가능

  • 키는 반드시 대문자

  • 값은 레포지토리의 실제 브랜치명과 일치 (예: 레포지토리에서 dev 브랜치를 쓰면 "DEV": "dev")

apps[].group 상세

group 은 여러 앱을 하나의 프로젝트(서비스)로 묶는 그룹명입니다. 한 서비스의 BE/FE/DB는 모두 같은 group 을 사용해야 합니다.

my-shop

→ 세 앱 모두 "group": "my-shop" 으로 묶임 = "my-shop 프로젝트"

📝 이 값은 빌드된 이미지의 식별자로도 사용되니 같은 서비스 안에서 동일하게 유지하세요.

DB 선언 시 유의사항

ℹ️ 안내

자체 DB를 사용할 경우 DB 선언은 스킵해주세요.

DB는 Terroir가 제공하는 기본 이미지(예: postgres:16-alpine) 로 배포됩니다.

{
  "name": "my-db",
  "type": "DB",
  "engine": "postgres",
  "group": "my-project"
}

  • root / version 은 선언하지 않음 (기본 이미지 사용이라 빌드 불필요)

  • 지원 엔진: postgres 만

  • 커스텀 DB 현재 미지원

예시 — BE + FE + DB 및 여러 환경 조합

{
  "schema": "1",
  "environments": {
    "DEV": "develop",
    "PROD": "main"
  },
  "apps": [
    { "name": "my-api", "type": "BE", "group": "my-project", "root": ".",   "version": "0.1.0" },
    { "name": "my-web", "type": "FE", "group": "my-project", "root": "web", "version": "0.1.0" },
    { "name": "my-db", "type": "DB", "engine": "postgres", "group": "my-project" }
  ]
}

이 예시가 의미하는 것

  • my-project 그룹으로 묶인 BE + FE + DB 3개 앱

  • develop → DEV, main → PROD 두 환경 매핑

  • BE는 루트에서, FE는 web/ 에서 Dockerfile 빌드. DB는 기본 이미지 사용

5.3. Dockerfile 준비

BE/FE 앱은 Dockerfile로 빌드됩니다. 로컬에서 빌드되지 않으면 CI에서도 동일하게 실패합니다.

  • 위치: {root}/Dockerfile 또는 {root}/docker/Dockerfile

    • {root} = terroir.json 의 apps[].root 값 (예: ., web)

    • 둘 다 있으면 docker/Dockerfile 우선

  • 로컬 빌드 확인: docker build 로 정상 빌드되는지 미리 확인

5.4. Health check 엔드포인트 구현 확인

타입

경로

응답

BE

GET /api/health

HTTP 200

FE

GET /health

HTTP 200

왜 필요한가

Terroir 내부 런타임(Kubernetes)이 앱이 정상적으로 떠 있는지, 계속 살아있는지 확인하기 위해 위 경로를 주기적으로 호출합니다. 200을 받지 못하면 Kubernetes는 앱이 준비되지 않았거나 죽었다고 판단합니다.

없으면 생기는 문제

  • 배포가 완료되지 않고 멈추거나, 타임아웃으로 롤백

  • 앱이 반복 재시작되어 서비스 불가 상태(CrashLoopBackOff)에 빠질 수 있음

구현 팁

  • DB 등 외부 의존성은 검사하지 말고 앱 자체 기동 여부만 가볍게 확인

  • 인증이 걸려 있다면 이 경로는 인증 제외 처리

  • 응답 바디는 자유(OK, {} 등), HTTP 200만 보장되면 됨

5.5. 셀프 체크리스트

  • terroir.json 이 레포지토리 루트에 존재

  • .github/workflows/terroir-docker-delivery.yml, terroir-fe-build.yml 이 존재

  • terroir.json 의 apps[].name / group 이 소문자 + 하이픈 규칙 준수

  • Dockerfile 로컬 빌드 성공

  • Health check 엔드포인트 응답 확인

  • 위 내용이 기본 브랜치(main 또는 develop)에 머지됨

6. 이미지 빌드 & 푸시

5장 설정이 끝나고 environments 에 선언한 브랜치(예: DEV → develop)에 변경이 반영되는 순간 terroir-docker-delivery.yml 이 자동 실행되어 이미지를 빌드·푸시합니다.

CI 트리거 예시 (demo-fun 예시)

demo-fun 레포지토리에서 DEV 환경용 이미지를 빌드하려면 develop 브랜치에 변경이 반영되면 됩니다.

terroir.json 의 "environments": { "DEV": "develop" } 매핑을 전제로 합니다.

# develop 브랜치에 커밋/푸시
git checkout develop
git add .
git commit -m "feat: update api"
git push origin develop
# → terroir-docker-delivery.yml 자동 실행 → DEV 이미지 빌드·푸시

📝 PR 머지·직접 푸시·fast-forward 등 어떤 방식으로든 develop 에 변경이 도달하면 동일하게 트리거됩니다. 팀 브랜치 전략은 그대로 사용하세요.

실패 시

  • GitHub Actions 로그 확인 (가장 먼저) 예) demo-fun repo의 경우 : https://github.com/VntgCorp/demo-fun/actions

  • terroir.json 형식 오류가 빈번 → JSON 린트 후 재커밋

  • 그 외에는 8장 문의 채널을 이용하세요.

7. 배포 관리 화면 확인

Terroir IDP 배포 관리 화면에 내 앱이 표시되면 온보딩은 완료입니다.

  • 화면 위치: 사이드 메뉴 > 배포 관리

  • 확인 포인트: 최신 이미지 태그, 환경별 상태
