소개 & 아키텍처

Grafana Alloy는 Grafana Labs의 차세대 텔레메트리(Telemetry, 원격 데이터 수집) 에이전트입니다. 기존 Grafana Agent를 대체하며, 서버에 설치하여 메트릭(성능 수치)과 로그를 수집 → Kafka로 전송합니다. 설정 파일은 .alloy 확장자의 HCL(HashiCorp Configuration Language) 형식을 사용합니다.

전체 데이터 흐름

모든 에이전트는 OTel(OpenTelemetry) 형식의 JSON으로 메트릭/로그를 Kafka로 전송합니다. 로컬 Kafka에 쌓인 데이터는 MirrorMaker2(MM2)가 GCP 중앙 Kafka로 단방향 복제합니다.

배포 타입 3종

① Linux 서버 (Rocky Linux · Oracle Linux · SUSE)

일반 애플리케이션 서버에 설치되는 에이전트입니다. OS 메트릭과 시스템 로그를 수집하고, 필요에 따라 MySQL·PostgreSQL·Oracle DB 모듈을 추가로 활성화합니다.

수집 대상Alloy 컴포넌트설명
OS 메트릭prometheus.exporter.unixCPU, 메모리, 디스크, 네트워크
시스템 로그loki.source.file/var/log/messages
MySQLprometheus.exporter.mysqlInnoDB, 슬로우 쿼리, 에러 로그
PostgreSQLprometheus.exporter.postgres커스텀 YAML 쿼리 지원
Oracle DBprometheus.exporter.oracledbAlert Log + Listener Log

② Windows 서버 (WS 2016 · 2019 · 2022)

Windows 서버에 설치되는 에이전트입니다. Windows 이벤트 로그와 OS 메트릭을 수집하고, MSSQL·IIS·Tomcat·Oracle·MariaDB 모듈을 지원합니다.

수집 대상Alloy 컴포넌트설명
OS 메트릭prometheus.exporter.windowscpu, memory, disk, net, service, process 등
이벤트 로그loki.source.windowseventSystem 이벤트 로그
MSSQLprometheus.exporter.mssql기본 21종 + 커스텀 YAML 5종
IISprometheus.exporter.windows (iis)IIS 액세스 로그, HTTP 상태코드 분석
Tomcatprometheus.scrape (JMX)JMX Prometheus Agent (포트 9404)
MariaDBprometheus.exporter.mysqlMySQL 호환 익스포터 사용
⚠️

Tomcat 서버 — 추가 수동 설정 필요 (Ansible 자동화 불가 항목)

Tomcat WAS를 모니터링하려면 JMX Prometheus Agent를 Tomcat JVM에 주입해야 합니다. 이 설정은 Tomcat 서비스 GUI(Tomcat10w.exe)를 통해 진행하므로 Ansible로 완전 자동화하기 어렵습니다.

  1. C:\jmx 폴더 생성
  2. 드라이브에서 tomcat.yml과 jmx_prometheus_javaagent-1.5.0.jar을 C:\jmx\에 복사
  3. Tomcat 경로의 Tomcat10w.exe를 관리자 권한으로 실행
  4. Java 탭 → Java Options에 아래 옵션 추가 후 적용:
-javaagent:C:\jmx\jmx_prometheus_javaagent-1.5.0.jar=9404:C:\jmx\tomcat.yml

설정 후 Tomcat 서비스 재시작 → Alloy가 9404 포트에서 JMX 메트릭 수집

③ 거점(Hub) 서버 — vSphere 전용 (Linux)

여러 서버를 에이전트 없이(Agentless) 중앙에서 모니터링하는 거점 서버입니다. vSphere API로 VM 메트릭을 수집하고, 각 ESXi 호스트의 Syslog를 UDP 514 포트로 받습니다. ICMP Ping과 TCP 포트 헬스체크도 수행합니다.

💡

거점 서버는 Agentless 방식이므로 server_ip와 hostname을 덮어쓰지 않습니다. 각 VM의 원래 IP/이름이 유지됩니다.

config.alloy 핵심 구조

모든 설정 파일은 아래 3개의 블록으로 구성됩니다.

#블록역할
1OTel 파이프라인회사명·사이트·IP 속성 주입 → Batch → Kafka 전송
2OS 수집Linux: unix exporter + syslog / Windows: windows exporter + windowsevent
3앱 모듈 로드import.file로 modules 디렉토리 감시 + 각 앱 파이프라인 활성화

서버별 주요 변수

config.alloy에서 서버마다 달라지는 값들입니다. Ansible 인벤토리에서 호스트 변수로 관리합니다.

변수명예시 값설명
p_company"stl"회사 식별자 (OTel 속성)
p_site"test"사이트/거점 식별자
server_ip"172.17.1.163"서버 IP (OTel 속성)
p_env"prod"환경 구분 (prod/dev)
kafka_brokers"172.17.40.40:9092"로컬 Kafka 브로커 주소
kafka_metrics_topic"prod.stl.telemetry.metrics"메트릭 Kafka 토픽명
kafka_logs_topic"prod.stl.telemetry.logs"로그 Kafka 토픽명
DB 연결 문자열"alloy_monitor:pw@tcp(127.0.0.1:3306)/"각 앱 모듈별 접속 정보
로그 경로"/var/log/mysql/mysqld.log"각 앱 로그 파일 경로

Kafka 토픽 네이밍 규칙

📌

토픽명 패턴: {env}.{domain}.telemetry.{signal}

필드 예시 설명

예시: prod.stl.telemetry.metrics / prod.stl.telemetry.logs

Ansible 구현 가능 여부

✅ 완전 자동화 가능 Linux 서버 (Rocky · Oracle Linux · SUSE)
  • • SSH 기반 — 별도 사전 설정 없이 바로 사용 가능
  • • dnf / rpm_key / yum_repository 모듈로 패키지 설치 자동화
  • • Jinja2 템플릿(.j2)으로 서버별 config.alloy 자동 생성
  • • systemd 모듈로 서비스 시작/재시작 자동 처리
  • • SUSE Linux는 패키지 관리자가 zypper이므로 별도 태스크 분기 필요
⚠️ WinRM 사전 설정 필요 Windows 서버 (WS 2016/2019/2022)
  • • WinRM(Windows Remote Management) 또는 OpenSSH를 사전 활성화해야 함
  • • win_file, win_template, win_service, win_command 모듈 사용
  • • 설치 파일(.exe)을 Ansible control node에 미리 보관하거나 파일 서버에서 다운로드
  • • pywinrm 라이브러리가 Ansible 제어 노드에 필요 (pip install pywinrm)
✅ Linux이므로 가능 거점(Hub) 서버 — vSphere 모니터링
  • • Linux 배포와 동일하나, 추가 Linux 권한 설정이 필요
  • • CAP_NET_BIND_SERVICE: UDP 514 포트(Syslog) 수신 권한
  • • CAP_NET_RAW: ICMP Ping 헬스체크 권한
  • • /etc/systemd/system/alloy.service.d/override.conf에 권한 추가 후 daemon-reload
  • • 방화벽에서 UDP 514 포트 오픈 필요

주의사항 8가지

1. 비밀 관리 — ansible-vault 필수

⚠️

DB 비밀번호, vSphere 비밀번호 등 민감 정보는 인벤토리 파일에 평문으로 넣으면 안 됩니다. ansible-vault encrypt로 암호화하거나 별도 vault.yml 파일로 분리하세요.

# vault.yml 생성
ansible-vault create vault.yml

# 암호화된 변수 사용 예시 (inventory.yml)
alloy_vsphere_password: "{{ vault_vsphere_password }}"

# 플레이북 실행 시 vault 패스워드 입력
ansible-playbook deploy_alloy.yml --ask-vault-pass

2. Windows WinRM 사전 설정

Windows 서버에서 Ansible을 사용하려면 대상 서버에서 먼저 WinRM을 활성화해야 합니다.

# Windows PowerShell에서 실행 (관리자 권한)
winrm quickconfig -q
winrm set winrm/config/winrs '@{MaxMemoryPerShellMB="512"}'
winrm set winrm/config '@{MaxTimeoutms="1800000"}'
winrm set winrm/config/service '@{AllowUnencrypted="true"}'
winrm set winrm/config/service/auth '@{Basic="true"}'

3. 거점 서버 — Linux 특권 포트(514) 설정

거점 서버에서 Syslog(UDP 514)를 수신하려면 Alloy 서비스에 특권 포트 권한을 부여해야 합니다.

# /etc/systemd/system/alloy.service.d/override.conf
[Service]
AmbientCapabilities=CAP_NET_BIND_SERVICE CAP_NET_RAW

4. 멱등성(Idempotency) — 설정 변경 시 자동 재시작

멱등성이란 같은 플레이북을 여러 번 실행해도 결과가 동일해야 한다는 원칙입니다. config.alloy가 변경되면 Alloy 서비스를 재시작해야 하므로 반드시 notify: Restart alloy 핸들러를 등록합니다.

5. OS별 분기 — ansible_os_family 변수 활용

# SUSE Linux는 zypper 사용
- name: Install Alloy (RedHat 계열)
  ansible.builtin.dnf:
    name: alloy
    state: present
  when: ansible_os_family == "RedHat"

- name: Install Alloy (SUSE 계열)
  community.general.zypper:
    name: alloy
    state: present
  when: ansible_os_family == "Suse"

6. 오프라인(인터넷 차단) 환경

💡

인터넷이 없는 폐쇄망 환경에서는 Grafana RPM 패키지(.rpm)와 Windows 설치 파일(.exe)을 Ansible control node 또는 내부 파일 서버에 미리 저장해야 합니다.

7. 모듈 디렉토리 먼저 생성

modules/ 디렉토리가 없으면 모듈 파일 복사가 실패합니다. file 모듈로 디렉토리를 먼저 생성하는 태스크를 앞에 위치시킵니다.

8. Tomcat JMX 에이전트 — 수동 설정 항목

Tomcat 모니터링은 JMX Prometheus Agent를 Tomcat JVM에 직접 주입해야 합니다. Ansible로 파일 복사는 가능하지만, Java Options 설정은 Tomcat10w.exe GUI로만 가능합니다.

⚠️

Ansible 플레이북 실행 후 Tomcat 서버에서 수동으로: Tomcat10w.exe(관리자 권한) → Java 탭 → Java Options에 -javaagent:C:\jmx\jmx_prometheus_javaagent-1.5.0.jar=9404:C:\jmx\tomcat.yml 추가 후 Tomcat 서비스 재시작

9. Jinja2 템플릿 내 alloy 문법 충돌 주의

⚠️

config.alloy 안의 {{ "{{" }} ... {{ "}}" }} 형태 텍스트가 Jinja2 변수로 해석될 수 있습니다. Alloy 자체 변수(constants.hostname 등)는 Jinja2가 건드리지 않도록 raw 블록으로 감싸거나, 백틱(`)을 사용하는 alloy 문법의 경우 별도 처리가 필요합니다.

Jinja2 템플릿 — config_linux.alloy.j2

Jinja2 템플릿은 {{ "{{" }} 변수명 {{ "}}" }} 문법으로 서버별 인벤토리 변수를 주입합니다. 앱 모듈은 alloy_apps 딕셔너리 키에 따라 조건부로 활성화됩니다.

⚠️

AWX / Ansible Tower 오픈소스 Ansible 공식 웹 UI. Job Template, RBAC, 실행 이력 관리. Kubernetes 또는 Docker로 설치. 중·대규모 팀, 권한 관리 필요 시
Semaphore 경량 오픈소스 Ansible 웹 UI (Go 단일 바이너리). Docker 한 줄로 설치. 소규모 팀에 적합. 추천 소규모 팀, 빠른 설치
커스텀 웹앱 FastAPI(Python) 백엔드 + React 프론트엔드로 인벤토리 관리 UI + subprocess로 ansible-playbook 실행. UI를 완전히 커스터마이징 원할 때
