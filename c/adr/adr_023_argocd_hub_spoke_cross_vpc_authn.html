배경

Hub-Spoke 구조와 GKE Standard 전환의 새 제약

ADR-019 에서 dev-infra ArgoCD 가 dev-service 클러스터를 원격 관리(Hub-Spoke)하는 구조가 확정됐다. 기존 Autopilot 환경은 PSC consumer endpoint + bearer token 패턴으로 동작했으나, GKE Standard 1.32+ 로 전환하면서 PSC ServiceAttachment URI 가 외부에 노출되지 않아 동일 패턴 재현이 기술적으로 불가능해졌다.

Hub — vntg-nfw-infra-common
dev-infra-standard-gke-cluster
· ArgoCD application-controller · applicationset · server
· network: dev-network
Spoke — vntg-nfw-services-dev
dev-services-standard-gke-cluster
· ArgoCD 미설치 (Hub 에서 원격 관리)
· Shared VPC host: vntg-nfw-network-dev
신규 환경에서 발생한 제약 — 검증 완료
  • C-01GKE Standard 1.32+ 는 privateEndpointSubnetwork 자동 PSC 로 control plane endpoint 이 호스트 VPC 안 PSC consumer subnet 에 자동 배치됨
  • C-02VPC peering 으로는 PSC consumer endpoint 도달 불가 — GCP Connectivity Test 결과 PSC_ENDPOINT_ACCESSED_FROM_PEERED_NETWORK (2026-04-27 확정)
  • C-03cluster API / Cloud Logging / service-attachments list 어디에도 ServiceAttachment URI 노출 없음 (raw API 검증 완료) → 외부 VPC 에서 신규 PSC consumer endpoint 생성 불가능
  • C-04정적 SA bearer token 회전 부담: 클러스터 재생성 / SA·token 재생성 시마다 SealedSecret 재봉인 + commit 사이클 발생
결정 1

인증·연결 — GKE DNS endpoint + Workload Identity 채택

5개 Option 검토 후 Option 2 (GKE DNS endpoint + Workload Identity) 를 환경(Dev/Prod) 무관 통일 채택. Option 1 은 기술적으로 불가능 확정됐고, 나머지 Option 은 운영 부담 해소 측면에서 열위.

Option 방식 채택 주요 사유
Option 1 PSC forwarding rule + bearer token (Autopilot 패턴 재현) 불가 Standard 1.32+ 에서 ServiceAttachment URI 미노출 → 기술적 불가능 확정
Option 2 GKE DNS endpoint + Workload Identity 채택 bearer token 자체 제거, 네트워크 작업 0, 클러스터 재생성 강건
Option 3 GKE Connect Gateway + Fleet Membership 보류 단일 spoke 에 over-engineering, Fleet 비용 추가
Option 4 Public endpoint + dev-infra NAT IP whitelist 기각 트래픽 인터넷 경유 + 정적 NAT IP + bearer token 회전 잔존
Option 5 dev-infra-standard 를 Shared VPC 로 이주 기각 network 는 immutable → 클러스터 재생성 필요, ROI 낮음
채택 근거 — Option 2
  • R-01Option 1 기술 불가 확정 — Connectivity Test PSC_ENDPOINT_ACCESSED_FROM_PEERED_NETWORK / raw API 에 pscServiceAttachmentUri 없음 / Console hidden / 공식 문서 인용 확정
  • R-02bearer token 자체가 사라짐 — execProviderConfig: argocd-k8s-auth gcp 로 GCP 가 매 호출 단명 OAuth 토큰 자동 발급, 회전 부담 0
  • R-03클러스터 재생성에 강함 — DNS endpoint hostname 한 줄 patch + commit 만 (SealedSecret 재봉인 사이클 없음)
  • R-04네트워크 인프라 작업 0 — PSC / VPC peering / Cloud DNS / Firewall 신규 작업 불필요
  • R-05보안 — GCP IAM 인증 필수(anonymous 차단) + audit log 통합, IAM binding 즉시 회수 가능
IAM 역할 — roles/container.admin 선택 근거
GKE 는 IAM ∧ K8s RBAC AND 게이트 구조라 K8s RBAC 만으로는 부족하다. ApplicationSet 이 sync 하는 Helm chart (external-dns, sealed-secrets 등) 가 ClusterRole·ClusterRoleBinding 을 생성하는데, IAM 측에서 container.clusterRoles.create 권한이 필요해 container.developer 이하 역할로는 불가. Google 공식 Connect Gateway with ArgoCD 가이드와 동일한 구성.
결정 2

cluster Secret — SealedSecret → 평문 Secret 전환

Option 2 채택으로 cluster Secret 안에 정적 비밀이 0 이 됐다. SealedSecret 의 존재 이유(봉인)가 사라졌으므로 평문 git 관리로 전환하여 봉인 작업을 영구 제거한다.

"config 에 execProviderConfig (binary 호출 명세) 만 들어있어 정적 비밀 0 — 모든 필드가 평문 공개 가능."

AS-IS
sealedsecret-cluster-dev-service.yaml
· SealedSecret 으로 봉인, controller 로 복호화
· 클러스터 재생성 시 SealedSecret 재봉인 사이클
· controller-name 혼동 / 봉인 실수 위험
· token 재추출 → 봉인 → commit 반복
TO-BE

· 정적 비밀 0 → 봉인 불필요 → 평문 git 관리
· 클러스터 재생성 시 server 한 줄 patch + commit 만
· 봉인 작업·controller 헷갈림 영구 제거
· execProviderConfig 로 IAM 단명 토큰 자동 발급 
# secret-cluster-dev-service.yaml (평문, 정적 비밀 없음)
apiVersion: v1
kind: Secret
metadata:
  name: cluster-dev-service
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: cluster
stringData:
  name: dev-services-standard
  server: https://<dns-endpoint-hostname>    # 클러스터 재생성 시 이 한 줄만 patch
  config: |
    {
      "execProviderConfig": {
        "command": "argocd-k8s-auth",
        "args": ["gcp"],
        "apiVersion": "client.authentication.k8s.io/v1beta1"
      },
      "tlsClientConfig": { "insecure": false, "caData": "..." }
    }
결과 및 영향

긍정·부정 영향

✅ 긍정 영향
  • ✅운영자 토큰 회전 부담 영구 해소 — bearer token 자체 부재, GCP 가 단명 IAM 토큰 자동 회전
  • ✅봉인 작업 영구 제거 — cluster Secret 정적 비밀 0, SealedSecret 불필요. 클러스터 재생성 시 server 한 줄 patch + commit 만
  • ✅네트워크 인프라 작업 0 — PSC / Cloud DNS / VPC peering / Firewall 신규 설정 불필요
  • ✅신규 spoke 클러스터 확장에 강함 — allowExternalTraffic: true + IAM _member 1줄로 동일 패턴 즉시 복제
  • ✅보안 회수성 향상 — IAM binding 즉시 회수 + GCP audit log 통합
❌ 부정 영향 / 주의사항
  • ❌DNS endpoint 인터넷 표면 — GCP IAM 인증 필수라 anonymous 차단되나, compliance / audit 검토 필요 시 별도 정리
  • ❌Workload Identity 의존 — ArgoCD upgrade 시 SA annotation 보존 검증 필요
  • ❌argocd-k8s-auth binary — ArgoCD image 버전별 내장 여부 확인 필요
