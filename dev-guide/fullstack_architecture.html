01 / ARCHITECTURE

전체 아키텍처

사용자의 브라우저에서 데이터베이스까지, 요청이 흐르는 경로. 전체 구성요소는 Docker 컨테이너로 격리되어 함께 실행된다.

그림 1 · 요청 흐름 — 브라우저 → React → NestJS → Prisma → PostgreSQL (전체 Docker 격리)
02 / LAYERS

레이어별 역할

각 기술이 담당하는 책임. 관심사를 분리(separation of concerns)해 유지보수성과 테스트 용이성을 확보한다.

React + TSFrontend
컴포넌트 기반 UI. 상태 관리·라우팅·API 호출을 담당한다. TypeScript로 타입 안정성을 확보하고, Vite로 빠르게 빌드한다. 서버의 JSON 응답을 화면으로 렌더링.
NestJSBackend / API
Controller(요청 라우팅) → Service(비즈니스 로직) → Repository(데이터 접근)의 계층 구조. 의존성 주입(DI), 모듈 시스템, Guard·Pipe·Interceptor로 인증·검증·로깅을 일관되게 처리.
PrismaORM
스키마 파일(schema.prisma)로 DB 모델을 정의하고, 타입 안전한 쿼리 클라이언트를 자동 생성. 마이그레이션으로 DB 스키마 버전을 관리한다.
PostgreSQLDatabase
관계형 데이터베이스. 트랜잭션·인덱스·JSON 컬럼·강력한 쿼리를 지원. 실제 데이터가 영속 저장되는 곳(Docker 볼륨에 보존).
DockerInfra
프론트·백엔드·DB를 각각 컨테이너로 격리하고 docker compose로 한 번에 실행. "내 컴퓨터에선 됐는데" 문제를 제거하고 배포 환경을 통일.
03 / STRUCTURE

모노레포 폴더 구조

프론트·백엔드를 한 저장소에 두는 모노레포 예시. 각자 독립 배포도 가능하다.

myapp/ ├── # 프론트엔드 │ web/ │ ├── src/ │ │ ├── components/ # UI 컴포넌트 │ │ ├── pages/ # 라우트 페이지 │ │ ├── api/ # API 클라이언트 │ │ └── main.tsx │ ├── Dockerfile │ └── package.json │ ├── # 백엔드 │ api/ │ ├── src/ │ │ ├── app.module.ts # 루트 모듈 │ │ ├── users/ │ │ │ ├── users.controller.ts # 라우팅 │ │ │ ├── users.service.ts # 비즈니스 로직 │ │ │ └── users.module.ts │ │ └── prisma/ │ │ └── prisma.service.ts # DB 연결 │ ├── prisma/ │ │ ├── schema.prisma # 데이터 모델 │ │ └── migrations/ │ ├── Dockerfile │ └── package.json │ └── docker-compose.yml # 전체 오케스트레이션
04 / CODE

레이어별 핵심 코드

데이터 모델 정의부터 API 엔드포인트, 프론트 호출까지 한 흐름으로.

prisma/schema.prismaprisma
// 데이터 모델 정의 → 타입 안전 클라이언트 자동 생성
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  posts     Post[]
  createdAt DateTime @default(now())
}

model Post {
  id       Int     @id @default(autoincrement())
  title    String
  author   User    @relation(fields: [authorId], references: [id])
  authorId Int
}

npx prisma migrate dev --name init

npx prisma generate
api/src/users/users.service.tstypescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class UsersService {
  constructor(private prisma: PrismaService) {}

  // 타입 안전 — 반환 타입이 자동 추론된다
  findAll() {
    return this.prisma.user.findMany({ include: { posts: true } });
  }

  create(email: string, name?: string) {
    return this.prisma.user.create({ data: { email, name } });
  }
}
api/src/users/users.controller.tstypescript
@Controller('users')
export class UsersController {
  constructor(private users: UsersService) {}

  @Get()                       // GET /users
  findAll() { return this.users.findAll(); }

  @Post()                      // POST /users
  create(@Body() dto: CreateUserDto) {
    return this.users.create(dto.email, dto.name);
  }
}

05 / DEPLOY

docker-compose 로 전체 실행

세 컨테이너(web·api·db)를 한 파일로 정의하고 docker compose up 한 번에 띄운다.

docker-compose.ymlyaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports: ["5432:5432"]

  api:
    build: ./api
    depends_on: [db]
    environment:
      DATABASE_URL: "postgresql://app:secret@db:5432/app"
    ports: ["3000:3000"]

  web:
    build: ./web
    depends_on: [api]
    ports: ["5173:5173"]

volumes:
  pgdata:
실행bash
docker compose up -d --build     # 빌드 + 백그라운드 실행
docker compose logs -f api       # API 로그 확인
docker compose down              # 정지 + 제거
💡 핵심 포인트. 컨테이너끼리는 서비스 이름(db, api)을 호스트명처럼 쓴다. 그래서 DATABASE_URL의 호스트가 localhost가 아니라 db다. 데이터는 pgdata 볼륨에 보존되어 컨테이너를 지워도 살아남는다.

ReactUI거대한 생태계, 컴포넌트 재사용, 풍부한 라이브러리
