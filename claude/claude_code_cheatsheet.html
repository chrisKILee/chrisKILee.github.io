1. 시작하기 (Getting Started)

Claude Code는 Node.js 18+ 환경이 필요합니다. 아래 명령어로 설치 후 프로젝트에서 초기화합니다.

curl -fsSL https://claude.ai/install.sh | bash
cd your-project
claude
/init
💡

/init를 실행하면 코드베이스를 스캔해서 스타터 CLAUDE.md를 자동 생성합니다. 첫 세션에서 반드시 실행하세요.

2. CLAUDE.md 이해하기

CLAUDE.md는 Claude의 프로젝트 영구 메모리입니다. 매 세션 시작 시 자동으로 로드됩니다.

WHAT — 무엇을
  • · 기술 스택
  • · 디렉토리 맵
  • · 아키텍처
WHY — 왜
  • · 각 모듈의 목적
  • · 설계 결정 이유
HOW — 어떻게
  • · 빌드/테스트 명령어
  • · 워크플로우
  • · 주의사항

좋은 CLAUDE.md 예시:

# 프로젝트: MyApp
FastAPI REST API + React SPA + Postgres

## 명령어
npm run dev
npm run test
npm run lint

## 아키텍처
/app  → Next.js App Router 페이지
/lib  → 공유 유틸리티
/prisma → DB 스키마 & 마이그레이션

3. 메모리 계층구조

CLAUDE.md는 4단계 계층 구조를 가집니다. 하위 파일은 상위 컨텍스트를 추가하며, 덮어쓰지 않습니다.

~/.claude/CLAUDE.md
전역 — 모든 프로젝트에 적용
~/CLAUDE.md
부모 — 모노레포 루트
./CLAUDE.md
프로젝트 — Git으로 팀 공유
./frontend/CLAUDE.md
서브폴더 — 범위 지정 컨텍스트
⚠️
각 파일은 200줄 이하로 유지하고, 하위 파일이 상위 컨텍스트를 절대 덮어쓰지 않도록 주의하세요.

4. CLAUDE.md 베스트 프랙티스

  • /init 먼저 실행 — 자동 생성된 결과를 다듬는 방식이 직접 작성보다 효율적
  • 구체적인 지시사항 — "버튼 만들어줘" ❌ / "파란 배경, hover 시 진한 파란색, /api/login 호출 버튼" ✅
  • 주의사항 명시 — Claude가 코드에서 추론 불가한 gotchas를 반드시 기록
  • @파일명으로 참조 — @README.md, @src/api/routes.ts 등 직접 참조
  • 워크플로우 규칙 추가 — 테스트 작성 순서, 커밋 형식 등 팀 규칙 명시
  • 메모리 간결하게 — 장편 소설이 아닌 핵심 지침서로 유지
  • Git 커밋 — 팀원들과 설정 공유를 위해 반드시 버전 관리

5. 프로젝트 파일 구조

Claude Code를 제대로 구성한 프로젝트의 표준 파일 구조입니다:

your-project/ ├── CLAUDE.md ← 프로젝트 컨텍스트 & 규칙 ├── .claude/ │ ├── settings.json ← 권한 & hooks 설정 │ ├── settings.local.json ← 개인 로컬 설정 (gitignore) │ ├── skills/ │ │ ├── code-review/ │ │ │ └── SKILL.md ← 코드리뷰 스킬 │ │ └── testing/ │ │ └── SKILL.md ← 테스트 스킬 │ └── helpers.py ├── commands/ │ └── deploy.md ├── agents/ │ └── security-reviewer.md ├── arc/ └── .gitignore

6. Skills 추가하기 (슈퍼파워)

Skills는 Claude가 자연어로 자동 호출하는 마크다운 가이드입니다. description 필드가 자동 활성화의 핵심입니다.

📁 프로젝트 스킬
.claude/skills/<이름>/SKILL.md

해당 프로젝트에서만 사용

🌐 개인 스킬
~/.claude/skills/<이름>/SKILL.md

모든 프로젝트에서 사용

SKILL.md 예시:

---
name: testing-patterns
description: Jest 테스트 패턴 가이드 (테스트 작성, 팩토리 목 사용)
allowed tools: Read, Grep, Glob
---

# 테스트 패턴
describe + it + AAA 패턴 사용
팩토리 목(Factory Mocks) 활용...
✅

description 필드에 트리거 키워드를 명시하세요. "테스트 작성해줘"라는 말에 자동으로 testing-patterns 스킬이 활성화됩니다.

7. AI 엔지니어를 위한 스킬 아이디어

🔍 코드 리뷰 🧪 테스트 패턴 💬 커밋 메시지 🐳 Docker 배포 📊 코드베이스 시각화 🔌 API 설계 📝 문서 생성 🔒 보안 리뷰 🚀 CI/CD 파이프라인 🗄️ DB 마이그레이션

8. Hooks 설정

Hooks는 도구 실행 전/후에 결정론적으로 실행되는 콜백입니다. CLAUDE.md 규칙은 ~70% 준수되지만, Hooks는 100% 강제 실행됩니다.

PreToolUse PostToolUse Notification 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "scripts/security-check.sh",
            "timeout": 5
          }
        ]
      }
    ]
  }
}

Exit code: 0 → 허용, 2 → 차단

9. 권한 & 안전 설정

.claude/settings.json에서 allow/deny 규칙으로 Claude의 행동 범위를 정의합니다.

{
  "permissions": {
    "allow": [
      "Read:*",
      "Bash:git:*",
      "Write:*:*.md"
    ],
    "deny": [
      "Read:env:*",
      "Bash:sudo:*"
    ]
  }
}

10. 4-Layer 아키텍처

Claude Code는 터미널 챗봇이 아니라 4개 레이어로 구성된 시스템입니다. 대부분의 엔지니어가 L1만 사용하고 나머지 3개를 놓칩니다.

레이어 구성요소 역할 강제 실행
L1CLAUDE.md영구 컨텍스트 & 규칙~70%
L2Skills자동 호출 지식 팩트리거 시 100%
L3Hooks안전 게이트 & 자동화항상 100%
L4Agents독립 컨텍스트 서브에이전트명시적 호출

11. 일일 워크플로우 패턴

Claude Code 파워 유저의 하루 루틴입니다:

$ cd project && claude
↓
⌨ Shift + Tab + Tab → Plan Mode
↓
💬 기능 의도 설명
↓
⌨ Shift + Tab → Auto Accept
↓
📦 /compact
↓
⌨ Esc Esc → 되감기
↓
✓ 자주 커밋 · 기능별 새 세션
