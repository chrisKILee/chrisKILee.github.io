🧠

딱 두 가지 카테고리 + 하나의 포장지

Claude Code 확장 기능이 왜 이렇게 많은지 혼란스러웠다면, 이 멘탈 모델 하나로 정리됩니다. Knowledge(아는 것)와 Workers(따로 일하는 것), 그리고 이를 패키징하는 Plugins. 이게 전부입니다.

Claude Code 확장 기능 전체 구조 — 원글: Dean Blank (Level Up Coding)

✦

핵심 원리: 모든 설계 결정은 "컨텍스트를 쓸 것이냐, 지킬 것이냐"로 귀결됩니다. CLAUDE.md는 쓰는 것(항상 로드), Skills와 Subagents는 지키는 것(필요할 때만)입니다.

📄

CLAUDE.md — 항상 켜져 있는 규칙

프로젝트 루트에 두는 마크다운 파일입니다. Claude가 세션 시작 시 읽고, 매 대화 턴마다 컨텍스트에 포함합니다. "Claude가 항상 알고 있어야 할 것"을 여기에 넣습니다.

✅ CLAUDE.md에 넣을 것
· 커밋 메시지 접두사 규칙 (feat:, fix:, chore:)
· 건드리면 안 되는 폴더 (src/legacy/ 수정 금지)
· 매 세션 필요한 프로젝트 컨벤션
· 디렉토리 구조 요약
❌ Skills로 빼야 할 것
· PR 리뷰 체크리스트 (가끔만 필요)
· 아키텍처 다이어그램 생성 방법
· 특정 상황에서만 쓰는 워크플로우
· 배포 절차 (직접 실행할 때만 필요)

3단계 범위: project-level(루트), user-level(~/.claude/CLAUDE.md — 모든 프로젝트 적용), subdirectory-level(모노레포에서 패키지별 다른 규칙). 하위 디렉토리 파일은 Claude가 그 폴더의 파일을 실제로 읽을 때만 지연 로드됩니다.

⚠️

컨텍스트는 가장 중요한 자원입니다. CLAUDE.md를 길게 만들수록 매 턴마다 낭비가 발생합니다. 매번 필요한 규칙인지, 가끔 필요한 워크플로우인지 이 질문 하나로 어디에 넣을지 결정하세요.

⚡

Skills — 필요할 때만 불러오는 워크플로우

스킬은 SKILL.md 파일 하나가 들어있는 폴더입니다. 세션 시작 시 Claude는 이름과 설명만 봅니다. 관련 작업이 생기면 그때 전체 내용을 로드합니다.

~/.claude/skills/arch-diagram/SKILL.md 
---
name: architecture-diagram
description: Use this when generating architecture or system diagrams
allowed-tools: Read, Grep
---

Use Mermaid format for all diagrams.
Include service boundaries, data flow direction, and external dependencies.
Label every connection with the protocol (REST, gRPC, Kafka, etc.).
Keep it to one page.
💡

description 필드가 핵심입니다. Claude가 스킬을 언제 쓸지 결정하는 유일한 기준입니다. "helps with documents" 같은 모호한 설명은 작동하지 않습니다. "Use when working with PDF files and need to extract text and tables"처럼 구체적으로 쓰세요.

🤖

자동 트리거

기본 동작. Claude가 현재 작업과 description을 비교해서 스스로 판단해 로드합니다. 아무것도 타이핑하지 않아도 됩니다.

⌨️

수동 호출 (/슬래시)

/deploy처럼 직접 부릅니다. 실제 배포처럼 부작용이 있는 스킬에 적합합니다.

🔒

자동 트리거 비활성화

frontmatter에 disable-model-invocation: true를 추가하면 직접 부를 때만 실행됩니다.

Commands와 Skills의 차이

구분 Commands Skills
실행 방식 내가 직접 /슬래시로 부를 때만 Claude가 판단해서 자동 실행 가능 + 수동도 됨
파일 구조 마크다운 파일 하나 폴더 안에 SKILL.md + 참조 파일들
고급 기능 없음 frontmatter 트리거, fork(컨텍스트 분리), 파일 참조
현황 Skills에 통합됨 (동일하게 작동) 권장 신규 작성은 Skills로
🤖

Subagents — 별도 컨텍스트에서 일하는 워커

서브에이전트는 별도의 컨텍스트 윈도우에서 실행되는 독립적인 Claude 인스턴스입니다. 결과만 메인 세션으로 돌아옵니다. 파일 50개를 리서치해야 할 때 메인 세션에서 직접 하면 컨텍스트가 순식간에 찹니다. 서브에이전트에게 시키면 메인 대화는 깨끗하게 유지됩니다.

💡

경험칙: 파일 5개 이상을 건드려야 하는 작업은 서브에이전트로 분리하는 게 낫습니다.

내장 서브에이전트 4종

🔍

Explore

빠른 읽기 전용. Haiku 모델로 실행. "X가 어디 있어?", "Y를 임포트하는 파일 찾아줘"에 적합.

📋

Plan

플랜 모드 전용. 코드베이스를 스캔하고 요약만 반환. 메인 세션이 계획 단계에서 비대해지지 않도록 보호.

⚙️

General-purpose

무거운 작업 담당. 읽기, 쓰기, 실행 모두 가능. 커스텀 서브에이전트도 이 유형.

📚

Claude Code Guide

"스킬 어떻게 써?", "Claude Code가 X 할 수 있어?" 같이 Claude Code 자체에 대한 질문 시 자동 실행. 공식 문서에서 답 찾아옴.

커스텀 서브에이전트 예시

.claude/agents/code-reviewer.md 
---
name: code-reviewer
description: Reviews code for quality and best practices. Use after writing or modifying code.
tools: Read, Grep, Glob, Bash
model: sonnet
---

You are a senior code reviewer.

When invoked:
1. Run git diff to see recent changes
2. Focus on modified files
3. Review for readability, error handling, security, and test coverage

Feedback priority:
- Critical (must fix)
- Warnings (should fix)
- Suggestions (nice to have)
👥

Agent Teams — 서로 소통하는 워커

에이전트 팀은 서브에이전트 개념을 확장합니다. 리드 에이전트가 태스크 리스트를 공유하고, 팀원들이 직접 서로 메시지를 주고받으며 협업합니다.

Subagents 쓸 때
· 각 작업이 독립적일 때
· A가 찾은 것을 B가 알 필요 없을 때
· 대부분의 일상 작업
· 토큰 비용 절약 중요할 때
Agent Teams 쓸 때
· 프론트 에이전트가 백엔드 에이전트가 아직 만들고 있는 타입이 필요할 때
· 보안 리뷰에서 한 영역의 발견이 다른 영역 탐색 방향을 바꿔야 할 때
· 대규모 코드베이스 마이그레이션
⚠️

Agent Teams는 실험적 기능으로 기본 비활성화되어 있습니다. 환경변수 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS를 설정해야 합니다. 팀원 간 메시지 오버헤드로 토큰 비용이 크게 증가합니다. 대부분의 일상 작업은 개별 Subagents로 충분합니다.

📦

Plugins — 패키징해서 공유하는 것

잘 만들어놓은 Skills와 Agents가 있다면 Plugin으로 묶어서 팀이나 다른 프로젝트에 공유하세요. 파일 복붙 없이 npm처럼 설치하면 됩니다.

플러그인 구조 예시 
team-conventions/
  .claude-plugin/
    plugin.json       ← 메타데이터
  skills/
    commit-message/SKILL.md
    pr-review/SKILL.md
    code-style/SKILL.md
  agents/
    migration-agent.md
plugin.json 
{
  "name": "team-conventions",
  "description": "Shared engineering conventions",
  "version": "1.0.0"
}
1

로컬 테스트

claude --plugin-dir ./team-conventions로 설치 없이 현재 세션에서만 로드해서 테스트합니다. 스킬은 슬래시 메뉴에 나타나고, 에이전트는 @"team-conventions:migration-agent"처럼 네임스페이스가 붙습니다.

2

마켓플레이스에 공유

Anthropic 공식 마켓플레이스(claude.ai/settings/plugins/submit)에 제출하거나, 팀 마켓플레이스(git 레포 + marketplace.json)를 만들어 배포합니다.

3

설치

설치 시 ~/.claude/plugins/cache/에 캐시되어 모든 프로젝트에서 사용 가능합니다.

bash 
/plugin marketplace add https://github.com/your-org/claude-plugins
/plugin install team-conventions@your-org-plugins

Skills ↔ Subagents 연결하기

Skills와 Subagents는 따로 있는 게 아닙니다. 두 방향으로 연결할 수 있습니다.

방향 1: Subagent에 Skill 주입

서브에이전트의 frontmatter에 skills: 필드를 추가하면, 시작 시 해당 스킬 전체가 에이전트 컨텍스트에 바로 로드됩니다. 에이전트가 따로 스킬을 발견할 필요가 없습니다.

.claude/agents/api-developer.md 
---
name: api-developer
description: Implement API endpoints following team conventions
skills:
  - api-conventions
  - error-handling-patterns
---

Implement API endpoints following the preloaded skills.

방향 2: Skill을 별도 컨텍스트에서 실행

스킬의 frontmatter에 context: fork를 추가하면 별도 서브에이전트로 실행되어 메인 대화를 보호합니다.

SKILL.md (fork 예시) 
---
name: research-auth
description: Research authentication patterns in the codebase
context: fork
---

Analyze how authentication is implemented across the codebase.
Summarize patterns and identify inconsistencies.
⚠️

context: fork 주의: 실제 작업(태스크)이 담긴 스킬에만 의미가 있습니다. 가이드라인만 있는 스킬을 fork하면 에이전트가 지침을 받고 아무것도 할 게 없어서 빈손으로 돌아옵니다. 아예 새로운 것을 만든다면 그냥 별도 agent 파일로 만드세요.

🚀

권장 도입 순서

한꺼번에 다 할 필요 없습니다. 이 순서대로 필요에 따라 확장하세요.

1

CLAUDE.md 먼저

매 세션마다 반복하는 지시사항, 프로젝트 컨벤션을 여기에 담습니다. 가장 빠른 품질 향상 방법입니다.

2

특정 상황 워크플로우 → Skills로

"매번 필요한 건 아닌데 특정 작업 시 쓰는 것들"을 Skills로 분리합니다. PR 리뷰, 아키텍처 다이어그램, 배포 절차 등.

3

무거운 작업 → Subagents

파일 여러 개를 건드려야 하거나, 리서치·분석·리뷰처럼 컨텍스트를 많이 먹는 작업은 서브에이전트로 격리합니다.

4

공유 가치가 생기면 → Plugin

혼자 쓰는 거면 .claude/ 폴더로 충분합니다. 팀 전체가 쓰거나 여러 레포에서 쓴다면 Plugin으로 묶습니다.

5

대규모 병렬 협업 → Agent Teams

개별 Subagents로 해결 안 되는, 에이전트 간 실시간 조율이 필요한 작업에만 사용합니다. 토큰 비용이 큽니다.

한 문장 요약

매번 적용되는 규칙 → CLAUDE.md
특정 상황 워크플로우 → Skills
독립적 병렬 작업 → Subagents
협업 필요한 작업 → Agent Teams
공유 / 재사용 → Plugins
