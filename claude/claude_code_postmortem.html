01

사고 개요

세 이슈가 서로 다른 시기에 배포되어 누적 효과로 "광범위한 품질 저하"처럼 인식됐다.

영향 범위
Claude Code 구독자 전체
API 레이어에는 직접 영향 없음. Claude Code 애플리케이션에 특화된 이슈. 단, Issue 2(캐싱 버그)로 인한 캐시 미스 증가로 간접적 토큰 소모 증가 발생.
Anthropic 입장
의도적 품질 저하 없음
세 이슈는 모두 의도치 않은 버그 또는 부작용. 내부 테스트 환경과 운영 환경 간 차이로 일부 이슈가 배포 전 감지되지 않았음. 전체 구독자 사용 한도 리셋(2025-04-23).

"의도적인 모델 품질 저하는 없었습니다. 세 개의 독립적인 버그와 설정 변경이 누적되어 문제가 발생했으며, 이를 신속하게 해결하지 못한 점을 반성합니다."

ISSUE 1 상세 — Reasoning Effort
변경 내용
high → medium
UI 프리징·레이턴시 감소 목적으로 기본 reasoning effort를 낮춤. 복구 후 Opus 4.7은 xhigh, 기타 모델은 high로 설정.
감지 경로
사용자 피드백
내부 평가에서는 탐지되지 않았고 사용자 보고를 통해 인지. 배포 후 34일 만에 수정.
교훈
UX 개선 ≠ 품질 저하 허용
레이턴시 개선을 위한 reasoning 감소가 응답 품질에 직접 영향을 미침. 두 지표의 trade-off를 동시에 평가해야 함.
ISSUE 2 상세 — Thinking Cache Bug
의도된 동작
유휴 1시간 후 1회 정리
세션 비활성 1시간 이상 후 이전 추론 기록을 세션당 1회만 정리하도록 설계됨.
실제 동작 (버그)
매 턴마다 반복 실행
캐시 정리 함수의 실행 조건 설정 오류로 인해 대화의 매 턴(turn)마다 thinking 캐시가 삭제됨.
부가 피해
사용 한도 급소모
캐시 미스 증가 → 의도치 않은 토큰 재생성 → 구독 사용 한도 빠른 소모. 이 피해에 대한 보상으로 전체 한도 리셋 조치.

04

재발 방지 대책

Anthropic이 공식 발표한 4가지 구체적 조치.

  • 01
    직원 공개 빌드 사용 의무화
    Anthropic 직원들이 내부 빌드가 아닌 공개 버전(public builds)을 직접 사용하도록 강제. 내부 테스트 환경과 운영 환경 간 격차를 줄여 문제를 더 빠르게 감지한다.
  • 02
    시스템 프롬프트 변경 관리 강화
    모델 성능에 영향을 미치는 시스템 프롬프트 변경에 더 광범위한 코드 리뷰 도입. 모델별 세분화된 평가 스위트로 다양한 시나리오에서 품질 영향을 사전 검증.
  • 03
    코드 리뷰 저장소 컨텍스트 확대
    캐싱·상태 관리 로직 리뷰 시 관련 코드를 더 넓은 범위로 검토. Issue 2와 같은 정교한 캐싱 버그를 배포 전에 발견하기 위한 조치.
  • 04
    사용자 커뮤니케이션 채널 구축
    @ClaudeDevs 공식 커뮤니티 채널 개설. 사용자 피드백이 내부 팀에 더 빠르게 전달되어 조기 대응이 가능해진다.
