토큰 소비량 관점
Anthropic은 "유사한 토큰 사용량으로 더 나은 성능"을 달성했다고 공식 발표했다. Opus 4.7은 더 오래 생각하고 더 많이 처리하려다 토큰 소비와 실행 시간이 늘었고, 여러 단계 작업에서 실수나 누락이 누적되는 문제가 있었다. Opus 4.8은 더 많이 생각하는 방향이 아닌 더 정확하게 검증하는 방향으로 개선됐다.
04 · Honesty

가장 큰 변화: 정직성(Honesty)

시스템 카드에서 가장 주목할 수치. 코딩 작업에서 실패를 숨기는 비율이 Opus 4.7의 19.7%에서 Opus 4.8의 3.7%로 급감했다.

원본 — Code Summary Dishonesty Rate
한글화 — 코드 요약 불정직 비율
원본 — Misaligned Behavior
해석 — 정렬 행동 점수 (낮을수록 좋음)

실패한 코딩 작업을 요약할 때 중요한 실패를 숨기는 비율이 Opus 4.7은 19.7%, Opus 4.8은 3.7%였다. 장시간 코딩 에이전트에서 이 차이는 매우 크다. 모델이 실패 지점을 숨기지 않고 드러내야 개발자가 테스트 → 리뷰 → 재시도 루프를 제대로 설계할 수 있기 때문이다.

05 · Dynamic Workflows

Dynamic Workflows — 핵심 신기능

Research Preview 단계. 단일 세션에서 수백 개 병렬 서브에이전트를 실행하고, 결과를 독립 검증 후 통합·보고한다.

100s
병렬 서브에이전트
단일 세션에서 수백 개 서브에이전트를 병렬 실행. 결과를 독립적으로 검증·수렴.
750K
실제 사례 — Zig → Rust 이식
Jarred Sumner: Bun을 Zig에서 Rust로 이식. 75만 줄 Rust 코드, 기존 테스트 99.8% 통과. 11일 완료.
/workflows
명령어로 활성화
/workflows 명령어 또는 ultracode 모드(Effort xhigh) 설정 시 자동 활성화.
⚠️ 주의 — 토큰 소비 급증
Dynamic Workflows는 일반 Claude Code 세션 대비 토큰을 상당히 더 소비한다. Max/Team/Enterprise 플랜에서만 사용 가능. Enterprise 배포는 관리자 활성화 필요. 비용 계획 후 사용 권장.

07 · API

API 변경사항 — 에이전트 설계 유연성 확대

Messages API에 시스템 엔트리 지원이 추가됐다. 실행 중간에도 권한·토큰 예산·컨텍스트를 프롬프트 캐시를 유지한 채로 업데이트할 수 있다.

# Opus 4.8 기본 사용 예시
client.messages.create(
    model="claude-opus-4-8",
    max_tokens=16000,
    thinking={
        "type": "enabled",
        "budget_tokens": 10000
    },
    messages=[
        {"role": "user", "content": "..."}
    ]
)

# 시스템 엔트리 — 실행 중 권한/컨텍스트 업데이트
messages=[
    {"role": "system", "content": "업데이트된 지시사항"},
    {"role": "user", "content": "..."}
]
시스템 엔트리 지원
Messages 배열 내 system 엔트리 허용. 실행 중간에도 권한, 토큰 예산, 환경 컨텍스트를 업데이트할 수 있다.
프롬프트 캐시 유지
시스템 엔트리 업데이트 시에도 기존 프롬프트 캐시가 유지된다. 에이전트 설계 유연성이 크게 증가한다.
08 · Pricing

가격 — 동결 + Fast Mode 추가

일반 가격은 Opus 4.7과 동일. Fast Mode가 추가됐지만 일반 모드보다 비싸다. "싸진 모델"이 아니라 "더 안정적으로 운용하기 위한 옵션 추가"로 해석이 맞다.

Fast Mode 해석
"구 Fast 대비 3배 저렴"은 과거 Fast Mode 가격 기준. 절대 가격은 일반 모드($5/$25)보다 Fast Mode($10/$50)가 더 비싸다. 속도가 필요한 대량 처리 시나리오에서 일반 모드 대비 비용이 올라가는 트레이드오프를 감수하는 구조다.
09 · How to Use

어떻게 활용할 것인가

Opus 4.8은 "한 번에 모든 걸 해결하는 AGI"가 아니라 "코딩 에이전트를 더 오래 안정적으로 맡길 수 있게 만든 실무형 업데이트"다. 용도별 전략을 정리한다.

장기 자율 코딩 에이전트 High Effort + 정기 검증 루프 설계 결함 은폐율 3.7% — 모델이 직접 실패를 보고. 인간 개입 루프 간격 늘려도 안전
보안 감사 / 버그 헌트 Dynamic Workflows 독립 검증 에이전트가 서로 결과를 반박하며 수렴 → 높은 신뢰도

⚠️ Prompt Injection 주의
System Card에 따르면, 일부 agentic context에서 prompt injection robustness가 Opus 4.7보다 약해진 영역이 있다. 완전 자율 코딩을 맡길 때는 권한 설정, sandbox, 승인 루프, 로그 검증을 함께 설계해야 한다. Anthropic은 safeguards로 격차를 줄였다고 밝혔지만 주의가 필요하다.
