Module 04 — 일반적인 실수

메트릭 수집 시 흔한 실수

실수 1: scrape_interval이 너무 짧음

기본 30초~1분이 적절합니다. 너무 짧으면 타깃에 부하를 주고 카디널리티가 폭발합니다.

// ❌ 5초는 대부분 과도함
prometheus.scrape "too_frequent" {
  scrape_interval = "5s"
}

// ✅ 메트릭 종류에 따라 적절히 설정
prometheus.scrape "normal" {
  scrape_interval = "30s"  // 인프라 메트릭
}

prometheus.scrape "sla" {
  scrape_interval = "15s"  // SLA 핵심 메트릭만

실수 2: honor_labels로 레이블 충돌

honor_labels = true는 타깃이 보내는 레이블이 Alloy가 추가하는 레이블보다 우선합니다. 의도치 않은 레이블 덮어쓰기가 발생할 수 있습니다.

// ❌ job 레이블을 타깃이 덮어쓸 수 있음
prometheus.scrape "risky" {
  honor_labels = true  // 타깃의 job 레이블이 Alloy의 job을 덮어씀
}

// ✅ honor_labels는 필요할 때만 명시적으로 사용
// Prometheus federation, pushgateway 등 특수 케이스에서만

실수 3: 높은 카디널리티 레이블

UUID, 요청 ID, 사용자 ID 같은 고유 값을 레이블로 사용하면 시계열이 폭발합니다.

// ❌ request_id는 카디널리티 폭발 원인
rule {
  source_labels = ["request_id"]
  target_label  = "request_id"  // 절대 금지!
}

// ✅ 불필요한 고카디널리티 레이블은 드롭
rule {
  action      = "labeldrop"
  regex       = "request_id|user_id|session_id"
}

실수 4: remote_write 큐 설정 부재로 OOM

대량의 메트릭을 처리할 때 기본 큐 설정으로는 메모리가 부족할 수 있습니다.

// ✅ 대용량 환경 큐 설정
prometheus.remote_write "mimir" {
  endpoint {
    url = "http://mimir:9009/api/v1/push"
    queue_config {
      capacity             = 2500
      max_shards           = 200
      min_shards           = 1
      max_samples_per_send = 500
      batch_send_deadline  = "5s"
    }
  }
}
