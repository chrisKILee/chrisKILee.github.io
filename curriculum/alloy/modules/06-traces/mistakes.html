Module 06 — 일반적인 실수

트레이스 수집 시 흔한 실수

실수 1: Head-based 샘플링으로 에러 트레이스 누락

Head-based 샘플링은 트레이스 시작 시점에 결정하므로 나중에 에러가 발생해도 이미 버린 트레이스는 복구 불가합니다.

// ❌ 에러 트레이스도 90% 버림
otelcol.processor.probabilistic_sampler "bad" {
  sampling_percentage = 10  // 에러도 10%만 저장
}

// ✅ Tail-based 샘플링으로 에러는 항상 저장
otelcol.processor.tail_sampling "good" {
  policy {
    name = "errors-always"
    type = "status_code"
    status_code { status_codes = ["ERROR"] }
  }
  policy {
    name = "random-10"
    type = "probabilistic"
    probabilistic { sampling_percentage = 10 }
  }
}

실수 2: Alloy를 stateless로 배포 시 Tail-based 샘플링 오작동

Tail-based 샘플링은 하나의 트레이스에 속한 모든 span이 같은 Alloy 인스턴스에 모여야 합니다. 여러 인스턴스로 부하 분산하면 span이 분산되어 결정을 못 내립니다.

해결책 Alloy 클러스터링(Module 07)을 사용하거나, tail-based 샘플링은 단일 인스턴스 또는 sticky 라우팅(trace_id 기반 일관 해싱)으로 구성해야 합니다.

실수 3: decision_wait가 너무 짧음

// ❌ 복잡한 마이크로서비스에서 30초 안에 모든 span이 오지 않을 수 있음
otelcol.processor.tail_sampling "fast" {
  decision_wait = "5s"  // 너무 짧으면 불완전한 트레이스로 결정
}

// ✅ 서비스 구조에 맞게 설정 (일반적으로 30s~2m)
otelcol.processor.tail_sampling "appropriate" {
  decision_wait = "30s"
}
