Module 06 — 개념

트레이스 수집

트레이스 파이프라인 개요

Alloy는 OTel Collector의 otelcol.* 컴포넌트로 분산 트레이스를 수집합니다.

// OTLP 수신 → 배치 처리 → Tempo 전송
otelcol.receiver.otlp "default" {
  grpc { endpoint = "0.0.0.0:4317" }
  http { endpoint = "0.0.0.0:4318" }

  output {
    traces = [otelcol.processor.batch.default.input]
  }
}

otelcol.processor.batch "default" {
  timeout             = "5s"
  send_batch_size     = 1000
  send_batch_max_size = 2000

  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

otelcol.exporter.otlp "tempo" {
  client {
    endpoint = "tempo:4317"
    tls { insecure = true }
  }
}

샘플링 전략

모든 트레이스를 저장하면 비용이 너무 많이 들기 때문에 샘플링이 필요합니다.

Head-based 샘플링 (단순)

// 10%만 수집하는 probabilistic 샘플링
otelcol.processor.probabilistic_sampler "head" {
  sampling_percentage = 10

  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

Tail-based 샘플링 (권장)

// 트레이스 완료 후 결과를 보고 결정 (에러는 100%, 정상은 10%)
otelcol.processor.tail_sampling "smart" {
  decision_wait = "30s"
  num_traces    = 100000

  policy {
    name = "errors-always"
    type = "status_code"
    status_code {
      status_codes = ["ERROR"]
    }
  }

  policy {
    name = "slow-requests"
    type = "latency"
    latency {
      threshold_ms = 1000  // 1초 이상 걸린 요청
    }
  }

  policy {
    name = "random-10-percent"
    type = "probabilistic"
    probabilistic {
      sampling_percentage = 10
    }
  }

  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

트레이스와 메트릭 연동 (Span Metrics)

// 트레이스에서 RED 메트릭 자동 생성
otelcol.connector.spanmetrics "default" {
  histogram {
    explicit {
      buckets = ["2ms", "4ms", "6ms", "8ms", "10ms", "50ms", "100ms", "200ms", "400ms", "800ms", "1s", "1400ms", "2s", "5s", "10s", "15s"]
    }
  }

  output {
    metrics = [otelcol.exporter.prometheus.default.input]
  }
}

// Span Metrics를 Prometheus 형식으로 노출
otelcol.exporter.prometheus "default" {
  forward_to = [prometheus.remote_write.mimir.receiver]
}
