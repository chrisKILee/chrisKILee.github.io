컴포넌트 & 파이프라인

Alloy의 핵심인 컴포넌트 모델과 파이프라인 설계 방법을 심층적으로 이해합니다.

컴포넌트 아나토미

Alloy의 모든 기능 단위는 컴포넌트입니다. 각 컴포넌트는 Arguments(입력)와 Exports(출력)를 가집니다.

컴포넌트 데이터 흐름

    e1["exports\ntargets[]"]:::exp

  subgraph c2["prometheus.scrape apps"]

  e1 -->|"targets"| a2

컴포넌트 참조 문법

컴포넌트 간 데이터를 연결할 때 [타입].[레이블].[export이름] 형식으로 참조합니다.

// 컴포넌트 A: 타깃 디스커버리
discovery.kubernetes "pods" {
  role = "pod"
}

// 컴포넌트 B: A의 exports.targets를 argument로 사용
prometheus.scrape "pods" {
  // discovery.kubernetes.pods.targets 참조
  targets    = discovery.kubernetes.pods.targets
  forward_to = [prometheus.remote_write.mimir.receiver]
}

// 컴포넌트 C
prometheus.remote_write "mimir" {
  endpoint {
    url = "http://mimir:9009/api/v1/push"
  }
}
참조 형식 [컴포넌트 타입].[레이블].[export 이름]
예: discovery.kubernetes.pods.targets — kubernetes 타입, "pods" 레이블의 targets export

컴포넌트 카테고리

수신기 (Sources / Receivers)

외부에서 데이터를 받아오는 컴포넌트

컴포넌트역할
prometheus.scrapePrometheus 형식 메트릭 스크래핑
loki.source.file로컬 파일에서 로그 읽기
loki.source.kubernetesKubernetes Pod 로그 수집
otelcol.receiver.otlpOTLP 프로토콜로 데이터 수신
otelcol.receiver.jaegerJaeger 형식 트레이스 수신

처리기 (Processors)

데이터를 변환/필터링하는 컴포넌트

컴포넌트역할
prometheus.relabel메트릭 레이블 변환/필터
loki.process로그 처리, 파싱, 레이블 추가
otelcol.processor.batchOTel 데이터 배치 처리
otelcol.processor.filterOTel 데이터 필터링
discovery.relabel서비스 디스커버리 결과 가공

내보내기 (Exporters)

처리된 데이터를 외부로 전송하는 컴포넌트

컴포넌트역할
prometheus.remote_writePrometheus remote_write 프로토콜 전송
loki.writeLoki로 로그 전송
otelcol.exporter.otlpOTLP로 데이터 전송 (Tempo 등)
otelcol.exporter.prometheusPrometheus exposition format으로 변환

서비스 디스커버리 패턴

Kubernetes 환경에서 동적으로 스크래핑 대상을 찾는 일반적인 패턴입니다:

// 1단계: Kubernetes Pod 디스커버리
discovery.kubernetes "app_pods" {
  role = "pod"
  namespaces {
    names = ["production", "staging"]
  }
}

// 2단계: 불필요한 타깃 필터링 및 레이블 변환
discovery.relabel "app_pods" {
  targets = discovery.kubernetes.app_pods.targets

  // prometheus.io/scrape: "true" 어노테이션이 있는 Pod만 수집
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_scrape"]
    action        = "keep"
    regex         = "true"
  }

  // 포트 어노테이션으로 스크래핑 포트 오버라이드
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_port"]
    action        = "replace"
    target_label  = "__address__"
    regex         = "(.*)"
    replacement   = "$1"
  }

  // 네임스페이스 레이블 추가
  rule {
    source_labels = ["__meta_kubernetes_namespace"]
    target_label  = "namespace"
  }

  // Pod 이름을 pod 레이블로
  rule {
    source_labels = ["__meta_kubernetes_pod_name"]
    target_label  = "pod"
  }
}

// 3단계: 필터링된 타깃 스크래핑
prometheus.scrape "app_pods" {
  targets         = discovery.relabel.app_pods.output
  scrape_interval = "30s"
  forward_to      = [prometheus.remote_write.mimir.receiver]
}

otelcol 컴포넌트 파이프라인

OpenTelemetry 컴포넌트는 otelcol.* 접두사를 사용하며, receiver → processor → exporter 구조를 따릅니다.

OTel 파이프라인 구조
flowchart LR
  app["애플리케이션\n(OTLP 계측)"]:::src

  subgraph alloy["Grafana Alloy"]
    recv["otelcol.receiver.otlp\nreceiver"]:::otel
    batch["otelcol.processor.batch\n배치 처리"]:::otel
    filter["otelcol.processor.filter\n샘플링/필터"]:::otel
    exp["otelcol.exporter.otlp\nexporter"]:::otel

    recv -->|"output"| batch --> filter --> exp
  end

  tempo["Grafana Tempo"]:::be

  app -->|"OTLP gRPC/HTTP"| recv
  exp -->|"OTLP"| tempo

  classDef src fill:#f0fdf4,stroke:#22c55e,stroke-width:2px,color:#15803d
  classDef otel fill:#ede9fe,stroke:#7c3aed,stroke-width:2px,color:#5b21b6
  classDef be fill:#e8f0fe,stroke:#1a73e8,stroke-width:2px,color:#0b3a8c
      
// OTel 파이프라인 예시
otelcol.receiver.otlp "default" {
  grpc { endpoint = "0.0.0.0:4317" }
  http { endpoint = "0.0.0.0:4318" }

  output {
    traces = [otelcol.processor.batch.default.input]
  }
}

otelcol.processor.batch "default" {
  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

otelcol.exporter.otlp "tempo" {
  client {
    endpoint = "tempo:4317"
    tls { insecure = true }
  }
}
