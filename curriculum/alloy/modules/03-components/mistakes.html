일반적인 실수

컴포넌트와 파이프라인 구성 시 흔히 발생하는 오류와 해결법

실수 1: forward_to와 output 혼동

Prometheus 컴포넌트와 OTel 컴포넌트는 연결 방식이 다릅니다.

// ❌ OTel 컴포넌트에 forward_to 사용
otelcol.receiver.otlp "default" {
  grpc { endpoint = "0.0.0.0:4317" }
  forward_to = [otelcol.processor.batch.default.input]  // 오류!
}

// ✅ OTel 컴포넌트는 output 블록 사용
otelcol.receiver.otlp "default" {
  grpc { endpoint = "0.0.0.0:4317" }
  output {
    traces = [otelcol.processor.batch.default.input]
  }
}

// ✅ Prometheus 컴포넌트는 forward_to 사용
prometheus.scrape "self" {
  targets    = prometheus.exporter.self.alloy.targets
  forward_to = [prometheus.remote_write.mimir.receiver]  // 올바름
}

실수 2: relabel rule의 action 이해 부족

가장 혼란스러운 부분 중 하나입니다. keep와 drop이 반대로 작용한다고 착각하기 쉽습니다.

// ❌ 잘못된 이해: keep = 이 규칙에 해당하는 것을 버림
rule {
  source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_scrape"]
  action        = "keep"   // 실제로는 regex에 일치하는 것만 "유지"
  regex         = "true"
}

// ✅ 올바른 이해
// action = "keep"  → regex와 일치하는 타깃만 남김 (나머지 삭제)
// action = "drop"  → regex와 일치하는 타깃을 삭제 (나머지 유지)
// action = "replace" → 레이블 값을 치환
// action = "labelmap" → 레이블 이름을 regex로 추출/변환

실수 3: 순환 참조

컴포넌트 A가 B를 참조하고, B가 다시 A를 참조하면 오류가 발생합니다.

// ❌ 순환 참조 — 시작 불가
prometheus.relabel "a" {
  targets    = prometheus.relabel.b.output  // b를 참조
  forward_to = [prometheus.remote_write.mimir.receiver]
}

prometheus.relabel "b" {
  targets    = prometheus.relabel.a.output  // a를 참조 — 순환!
  forward_to = [prometheus.remote_write.mimir.receiver]
}
Alloy의 DAG 구조 Alloy 파이프라인은 DAG(Directed Acyclic Graph — 방향성 비순환 그래프)여야 합니다. UI의 Graph 탭에서 화살표가 항상 한 방향으로만 흘러야 합니다.

실수 4: 존재하지 않는 컴포넌트 참조

// ❌ 레이블 오타 — "mimir_write"가 아니라 "mimir"인데 오타
prometheus.scrape "self" {
  forward_to = [prometheus.remote_write.mimir_write.receiver]
}
// 오류: component "prometheus.remote_write.mimir_write" does not exist

// ✅ 정확한 레이블 사용
prometheus.remote_write "mimir" {  // 레이블: mimir
  endpoint { url = "http://mimir:9009/api/v1/push" }
}

prometheus.scrape "self" {
  forward_to = [prometheus.remote_write.mimir.receiver]  // 올바름
}
