일반적인 실수

Alloy를 처음 사용할 때 흔히 하는 실수와 해결 방법을 알아봅니다.

실수 1: Grafana Agent 설정을 그대로 가져오려 함

위험 Grafana Agent의 YAML 설정은 Alloy에서 직접 사용할 수 없습니다.

Grafana Agent는 YAML 형식을 사용했지만, Alloy는 완전히 다른 설정 언어를 씁니다.

잘못된 접근

# ❌ Grafana Agent YAML (Alloy에서 동작 안 함)
metrics:
  global:
    scrape_interval: 15s
  configs:
    - name: default
      scrape_configs:
        - job_name: node
          static_configs:
            - targets: ['localhost:9100']

올바른 접근

// ✅ Alloy 설정 언어
prometheus.scrape "node" {
  targets = [{ "__address__" = "localhost:9100", "job" = "node" }]
  scrape_interval = "15s"
  forward_to = [prometheus.remote_write.mimir.receiver]
}
마이그레이션 도구 Grafana가 공식 마이그레이션 도구를 제공합니다: alloy convert --source-format=agent --output=config.alloy agent-config.yaml

실수 2: 컴포넌트 레이블 중복

같은 타입의 컴포넌트를 여러 개 쓸 때 레이블을 다르게 해야 합니다.

잘못된 예

// ❌ 레이블이 같아서 오류 발생
prometheus.scrape "default" {
  targets = [{ "__address__" = "localhost:9100" }]
  forward_to = [prometheus.remote_write.mimir.receiver]
}

prometheus.scrape "default" {  // 동일한 레이블!
  targets = [{ "__address__" = "localhost:9090" }]
  forward_to = [prometheus.remote_write.mimir.receiver]
}

올바른 예

// ✅ 각자 고유한 레이블 사용
prometheus.scrape "node_exporter" {
  targets = [{ "__address__" = "localhost:9100" }]
  forward_to = [prometheus.remote_write.mimir.receiver]
}

prometheus.scrape "prometheus_self" {
  targets = [{ "__address__" = "localhost:9090" }]
  forward_to = [prometheus.remote_write.mimir.receiver]
}

실수 3: forward_to 참조 오류

컴포넌트 간 데이터를 연결할 때 exports 이름을 정확히 알아야 합니다.

잘못된 예

// ❌ .input이 아니라 .receiver가 맞음
prometheus.scrape "self" {
  forward_to = [prometheus.remote_write.mimir.input]  // 오류!
}

올바른 예

// ✅ prometheus.remote_write의 export는 .receiver
prometheus.scrape "self" {
  forward_to = [prometheus.remote_write.mimir.receiver]
}
exports 이름 확인 방법 Alloy UI → Components → 해당 컴포넌트 클릭 → Exports 탭에서 확인하거나, 공식 문서의 각 컴포넌트 페이지에서 "Exported fields" 섹션을 참조합니다.

실수 4: .alloy 파일 인코딩 문제

설정 파일에 한글 주석이나 비ASCII 문자가 있으면 인코딩을 확인해야 합니다.

# 파일 인코딩 확인
file config/alloy.alloy
# 출력 예: config/alloy.alloy: UTF-8 Unicode text

# UTF-8이 아닌 경우 변환
iconv -f EUC-KR -t UTF-8 config/alloy.alloy -o config/alloy.alloy

실수 5: 리로드 없이 설정 변경 효과 기대

설정 파일을 수정했을 때 Alloy는 자동으로 감지하지 않습니다. 명시적으로 리로드해야 합니다.

# ✅ 설정 변경 후 리로드
# 방법 1: SIGHUP
docker kill --signal=SIGHUP alloy

# 방법 2: HTTP API
curl -X POST http://localhost:12345/-/reload

# 방법 3: Alloy 재시작
docker restart alloy
운영 환경 팁 Kubernetes에서는 ConfigMap 변경 + 롤링 업데이트 또는 alloy.extraArgs: ["--stability.level=generally-available"]와 함께 사이드카 패턴으로 자동 리로드를 구현할 수 있습니다.
