Module 07 — 일반적인 실수

고급 기능 운영 시 흔한 실수

실수 1: 클러스터링 없이 여러 인스턴스 배포 → 중복 수집

클러스터링 없이 DaemonSet + 중앙 Scraper를 함께 운영하면 같은 타깃을 두 번 스크래핑합니다.

// ❌ 두 인스턴스가 모두 같은 타깃 스크래핑
// 모든 인스턴스가 동일한 설정으로 독립 실행

// ✅ 클러스터링으로 타깃 분배
prometheus.scrape "no_dup" {
  targets    = discovery.kubernetes.pods.targets
  clustering {
    enabled = true   // 클러스터 멤버 간 타깃 자동 분배
  }
  forward_to = [prometheus.remote_write.mimir.receiver]
}

실수 2: WAL 경로가 emptyDir → Pod 재시작 시 데이터 유실

WAL은 network 단절 시 데이터를 임시 버퍼합니다. emptyDir이면 Pod 재시작 시 사라집니다.

# ❌ emptyDir → 재시작 시 WAL 유실, 메트릭 갭 발생
# volumes:
#   - name: alloy-storage
#     emptyDir: {}

# ✅ PVC 사용 (StatefulSet에서)
# volumeClaimTemplates:
#   - metadata:
#       name: alloy-storage
#     spec:
#       accessModes: ["ReadWriteOnce"]
#       resources:
#         requests:
#           storage: 5Gi

실수 3: 메모리 limits 없이 배포 → OOM Kill

스크래핑 타깃이 많거나 로그 볼륨이 크면 메모리가 빠르게 증가합니다.

# ✅ 항상 resource limits 설정
# resources:
#   requests:
#     cpu: 100m
#     memory: 256Mi
#   limits:
#     cpu: 1
#     memory: 1Gi    # 모니터링 후 조정

# WAL 크기도 제한
# prometheus.remote_write의 queue_config.max_shards 조정
