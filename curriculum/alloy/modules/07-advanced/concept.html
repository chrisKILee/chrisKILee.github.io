Alloy 클러스터링

Alloy는 내장 클러스터링을 지원합니다. 여러 인스턴스가 협력하여 스크래핑 타깃을 자동으로 분배합니다.

// 클러스터링 활성화 (모든 인스턴스에 동일 설정)
alloy run config.alloy \
  --cluster.enabled \
  --cluster.node-name=$(hostname) \
  --cluster.advertise-address=$(hostname -I | awk '{print $1}'):12345 \
  --cluster.join-peers=alloy-0:12345,alloy-1:12345,alloy-2:12345

// 설정에서 cluster 사용 선언
clustering {
  enabled = true
}

// clustering 활성화 시 자동 샤딩
prometheus.scrape "clustered" {
  targets    = discovery.kubernetes.pods.targets
  clustering { enabled = true }  // 타깃을 클러스터 멤버 간 자동 분배
  forward_to = [prometheus.remote_write.mimir.receiver]
}
Kubernetes에서 클러스터링 StatefulSet으로 배포하고 headless Service로 피어를 발견합니다. 각 Pod가 alloy-0.alloy-headless:12345 형식으로 서로를 찾습니다.

Kubernetes 프로덕션 배포 패턴

패턴 1: DaemonSet (노드 레벨 수집)

// 메트릭 + 로그: 각 노드에서 실행
controller:
  type: daemonset

// tolerations 설정으로 모든 노드 커버
tolerations:
  - operator: Exists

패턴 2: StatefulSet (트레이스, 클러스터링)

// 트레이스 + 클러스터링: StatefulSet으로 HA 구성
controller:
  type: statefulset
  replicas: 3

// Persistent Volume for WAL
volumeClaimTemplates:
  - metadata:
      name: alloy-storage
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 10Gi

TLS 보안 설정

// 수신기에 TLS 적용
otelcol.receiver.otlp "secure" {
  grpc {
    endpoint = "0.0.0.0:4317"
    tls {
      cert_file = "/etc/alloy/tls/tls.crt"
      key_file  = "/etc/alloy/tls/tls.key"
      ca_file   = "/etc/alloy/tls/ca.crt"
    }
  }
  output {
    traces = [otelcol.processor.batch.default.input]
  }
}

// remote_write TLS
prometheus.remote_write "secure_mimir" {
  endpoint {
    url = "https://mimir:9009/api/v1/push"
    tls_config {
      cert_file = "/etc/alloy/tls/client.crt"
      key_file  = "/etc/alloy/tls/client.key"
      ca_file   = "/etc/alloy/tls/ca.crt"
    }
  }
}

리소스 제한 및 성능 튜닝

// Kubernetes resource limits (Helm values)
// resources:
//   requests:
//     cpu: 100m
//     memory: 256Mi
//   limits:
//     cpu: 1000m
//     memory: 1Gi

// WAL 크기 제한 (메모리 보호)
prometheus.remote_write "mimir" {
  endpoint {
    url = env("MIMIR_URL")
    queue_config {
      max_shards           = 50   // 동시 전송 샤드 수 제한
      capacity             = 2500  // 각 샤드의 큐 크기
    }
  }
  wal {
    truncate_frequency = "2h"   // WAL 정리 주기
    max_keepalive_time = "8h"   // WAL 최대 보관 시간
    min_keepalive_time = "5m"
  }
}

원격 설정 (Remote Configuration)

ConfigMap이나 원격 URL에서 설정 일부를 동적으로 로드할 수 있습니다:

// Kubernetes ConfigMap에서 설정 로드
remote.kubernetes.configmap "scrape_targets" {
  namespace = "monitoring"
  name      = "alloy-scrape-targets"
}

// HTTP에서 설정 로드
remote.http "dynamic_config" {
  url             = "http://config-server/alloy-config"
  poll_frequency  = "5m"
}
