일반적인 실수

설치 및 설정 시 흔히 하는 실수와 해결 방법

실수 1: UI 외부 접근 불가

기본적으로 Alloy UI는 127.0.0.1:12345에 바인딩됩니다. 외부에서 접근하려면 명시적으로 주소를 변경해야 합니다.

# ❌ 기본 설정 — localhost에서만 접근 가능
alloy run config.alloy

# ✅ 모든 인터페이스에서 접근 허용
alloy run config.alloy \
  --server.http.listen-addr=0.0.0.0:12345
보안 주의 프로덕션 환경에서는 0.0.0.0으로 열지 마세요. VPN 또는 ingress 인증 게이트웨이 뒤에 배치하거나 kubectl port-forward를 사용하세요.

실수 2: Kubernetes RBAC 권한 부족

Kubernetes에서 Alloy가 Pod/Node 정보를 수집하려면 적절한 RBAC 권한이 필요합니다.

# 오류 메시지 예시
level=error msg="error listing pods" err="pods is forbidden: User \"system:serviceaccount:monitoring:alloy\" cannot list resource \"pods\""

# 해결: ClusterRole 생성
kubectl create clusterrolebinding alloy-cluster-reader \
  --clusterrole=cluster-reader \
  --serviceaccount=monitoring:alloy

# 또는 Helm values에서 RBAC 활성화
# rbac:
#   create: true

실수 3: WAL 경로 권한 문제

Alloy는 내부적으로 WAL(Write-Ahead Log)을 사용합니다. 저장 경로에 쓰기 권한이 없으면 시작 실패합니다.

# 오류
level=error msg="error creating WAL" path="/var/lib/alloy/data" err="permission denied"

# 해결
sudo mkdir -p /var/lib/alloy/data
sudo chown alloy:alloy /var/lib/alloy/data

# Kubernetes의 경우 PVC 또는 emptyDir 사용
# (Helm chart에서 persistence 설정)

실수 4: Helm values의 설정 들여쓰기 오류

values.yaml에서 multiline 설정을 쓸 때 들여쓰기가 중요합니다.

# ❌ 잘못된 들여쓰기
alloy:
  configMap:
    content: |
prometheus.scrape "self" {   # 들여쓰기 없음 → YAML 오류
}

# ✅ 올바른 들여쓰기 (파이프 다음 줄부터 2스페이스 이상)
alloy:
  configMap:
    content: |
      prometheus.scrape "self" {
        targets = prometheus.exporter.self.alloy.targets
        forward_to = [prometheus.remote_write.local.receiver]
      }
