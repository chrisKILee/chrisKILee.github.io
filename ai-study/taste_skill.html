01 / 문제 정의

'slop'은 AI가 게을러서가 아니라, 안전한 평균값으로 수렴하기 때문이다

대형 언어모델은 디자인 요청을 받으면 brief를 읽기 전에 학습 데이터의 평균 미학으로 점프한다. 그 결과가 어디서 본 듯한 templated UI, 즉 slop이다. Taste Skill은 이 수렴을 강제로 깨뜨린다.

기본값 · AI Slop

에이전트가 알아서 만들면

  • 보라/파랑 그라디언트 글로우(AI-purple)와 다크 메시 위 가운데 정렬 hero
  • 똑같은 3등분 feature 카드, 모든 카드에 glassmorphism
  • Inter + slate-900, 모든 섹션 위 똑같은 uppercase eyebrow
  • div로 만든 가짜 스크린샷, 끝없는 무한 루프 마이크로 애니메이션
교정 후 · Taste Skill

brief를 먼저 읽으면

  • 페이지 종류·대상·vibe를 추론해 한 줄 "Design Read"를 먼저 선언
  • 중립 배경 + 단일 고대비 액센트, 의미 있는 곳에만 elevation
  • Geist·Outfit 등 brand에 맞는 폰트, eyebrow는 3섹션당 1개로 제한
  • 실제 이미지 우선, 동기 있는 모션만, 출고 전 Pre-Flight 전수 검사
02 / 핵심 설정

모든 결정을 가르는 세 개의 다이얼

brief를 읽은 뒤 세 값을 설정한다. 이 프레임워크의 레이아웃·모션·밀도 규칙은 전부 이 세 변수에 의해 게이팅된다. 기본 baseline은 8 / 6 / 4이며, Design Read가 이를 덮어쓴다.

DESIGN_VARIANCE

레이아웃 실험성

1은 완벽한 대칭 그리드, 10은 비대칭 masonry와 거대한 여백. 4 초과면 가운데 정렬 hero를 피하고 split·asymmetric으로 강제한다.

MOTION_INTENSITY

애니메이션 깊이

4 초과면 페이지가 실제로 움직여야 한다. 3 초과 모든 모션은 prefers-reduced-motion을 반드시 존중한다. 동기 없는 GSAP 남용은 금지.

VISUAL_DENSITY

뷰포트당 정보량

1은 거대한 여백의 아트 갤러리, 10은 데이터가 빼곡한 콕핏. 7 초과면 카드 컨테이너를 버리고 1px 라인으로 데이터를 호흡시킨다.

03 / 작동 흐름

brief 추론에서 Pre-Flight까지, 한 방향 파이프라인

이 스킬의 모든 규칙은 contextual이다. 자동으로 발동하지 않는다. 먼저 방을 읽고(Read the room), 필요한 규칙만 끌어다 쓴다.

05 / 핵심 규칙

AI의 기본 반사를 덮어쓰는 규칙들

이 페이지 자체가 아래 규칙을 따라 만들어졌다. off-black 한 가지 테마, emerald 단일 액센트, em-dash 전면 금지.

THE LILA RULE

AI-purple 글로우 금지

보라·파랑 글로우 그라디언트는 기본값에서 차단. Zinc·Slate·Stone 중립 베이스에 Emerald, Electric Blue, Deep Rose 같은 고대비 단일 액센트를 쓴다. 한 페이지엔 하나의 액센트만.

TYPOGRAPHY

Inter는 기본값이 아니다

기본 폰트로 Inter·serif 남용을 지양. Geist·Outfit·Cabinet Grotesk 등 brand에 맞는 sans display를 먼저 고른다. headline 강조는 같은 폰트의 italic·bold로, 엉뚱한 serif 한 단어 끼워넣기 금지.

EM-DASH BAN

대시 기호 전면 금지

em-dash(—)는 LLM의 1순위 시각적 tell. headline·body·버튼·캡션 어디에도 금지. 제로 톨러런스. 일반 하이픈(-)만 허용한다. 이 규칙을 설명하는 코드 예시 외에는, 이 페이지 어디에도 쓰지 않았다.

ANTI-CENTER

가운데 정렬 hero 탈피

VARIANCE 4 초과면 split-screen, 좌측 콘텐츠·우측 에셋, 비대칭 여백으로 강제. 8개 섹션이면 최소 4개의 다른 레이아웃 family를 써야 한다.

REAL IMAGES

가짜 스크린샷 금지

div로 만든 가짜 대시보드·터미널은 1순위 tell. 이미지 생성 도구 우선, 없으면 실제 사진 소스. hand-rolled 장식 SVG와 순수 텍스트 미니멀리즘은 미완성 작업이다.

HERO DISCIPLINE

hero는 한 화면에

headline 최대 2줄, subtext 20단어 이내, CTA는 스크롤 없이 보여야 한다. hero 텍스트 요소는 최대 4개. trust 로고월·태그라인·가격 티저는 전부 hero 아래 별도 섹션으로.

06 / 금지 패턴

실전 테스트에서 걸러진 AI Tells

"디자인된 것처럼 보이려" 할 때 모델이 반사적으로 꺼내는 서명들. brief가 명시적으로 요구하지 않는 한 하드 밴이다.

✕
섹션 번호 eyebrow00 / INDEX, 06 · how it works 같은 번호 라벨
✕
3등분 동일 feature 카드가로로 똑같은 카드 3개. zig-zag·비대칭 그리드로 대체
✕
Jane Doe 효과"John Doe", "Acme", 99.99% 같은 가짜-완벽 데이터와 generic 이름
✕
커스텀 마우스 커서구식이고 접근성·성능에 모두 해롭다
✕
scroll 유도 문구"Scroll to explore", 마우스휠 애니메이션. 사용자는 스크롤을 안다
✕
locale·날씨 스트립"Lisbon 14:23 · 18°C" 같은 에이전시 포트폴리오 장식
✕
장식용 status dot모든 nav·리스트 앞 컬러 점. 실제 의미 상태에만 허용
✕
모든 행에 border-t + border-b10행 스펙 테이블에 행마다 hairline = 가장 게으른 레이아웃
✕
버전 라벨 in heroBETA, V0.6, INVITE-ONLY를 기본 eyebrow로 쓰는 것
✕
window scroll 리스너addEventListener('scroll')는 하드 밴. useScroll·IntersectionObserver 사용
07 / 마지막 필터

출고 전 Pre-Flight Check

코드를 내보내기 전 매트릭스를 돌린다. 단 한 칸이라도 정직하게 체크할 수 없으면, 그 페이지는 끝난 게 아니다.

pre-flight.check · 50+ 항목 전수 검사
✓Brief inference 한 줄 선언 Section 0.B
✓페이지 전체에 em-dash 제로 Section 9.G · 협상 불가
✓Page Theme Lock: 전 섹션 단일 테마, 중간 반전 없음
✓Color Consistency Lock: 단일 액센트를 전 섹션 동일 적용
✓eyebrow 개수 ≤ ceil(섹션수 / 3) 기계적 카운트
✓hero가 뷰포트 안에: headline ≤ 2줄, subtext ≤ 20단어
✓CTA 라벨이 desktop에서 2줄로 wrap되지 않음
✓모션 > 3은 전부 reduced-motion 존중, 모든 모션은 동기 있음
✓실제 이미지 사용: div 가짜 스크린샷·장식 SVG 없음
✓Core Web Vitals: LCP < 2.5s, INP < 200ms, CLS < 0.1
