Architecture

3가지 핵심 메커니즘

Gemini CLI가 단순 챗봇과 다른 이유 — 이 3가지 구조가 핵심이다

🔄
Pillar 01

ReAct Loop

Reasoning + Acting의 합성어. 즉시 답변을 생성하는 대신, 문제를 분석(Reason)하고 → 도구를 실행(Act)하고 → 결과를 관찰(Observe)하는 루프를 반복한다.

💭 Reason
→
⚡ Act
→
👀 Observe
↺
grep / 파일탐색 터미널 명령 실행 자율 반복
🌉
Pillar 02

MCP 프로토콜

Model Context Protocol — AI와 외부 시스템(GitHub, DB, API)을 연결하는 표준 브릿지. 복사-붙여넣기 없이 AI가 직접 실시간 데이터에 접근한다.

AI ←[MCP]→ GitHub API
AI ←[MCP]→ PostgreSQL
AI ←[MCP]→ Slack / Jira
표준 프로토콜 실시간 컨텍스트 플러그인 확장
🛡️
Pillar 03

Safety Features

자율 에이전트의 부작용을 방지하는 두 가지 안전장치. AI가 행동하기 전에 먼저 분석하고, 모호할 때는 사람에게 확인한다.

📋 Plan Mode

모호한 상황에서 AI가 사람에게 직접 질문하는 양방향 소통
읽기 전용 모드 양방향 소통
Deep Dive

MCP 아키텍처 심층 분석

MCP가 없으면 AI는 "복사-붙여넣기"에 의존한다. MCP는 그 벽을 허문다.

MCP 연결 구조도
❌ MCP 없는 세계 (기존 방식)
  • 1. GitHub에서 이슈 복사 → 챗봇에 붙여넣기
  • 2. DB 스키마 복사 → 다시 붙여넣기
  • 3. 코드 스니펫 복사 → 또 붙여넣기
  • 4. AI 답변 → 수동으로 컨텍스트 연결
✅ MCP 있는 세계 (Gemini CLI)
  • 1. AI가 GitHub MCP로 직접 이슈 조회
  • 2. AI가 DB MCP로 직접 스키마 분석
  • 3. AI가 파일 시스템 직접 탐색 → 코드 수정
  • 4. 모든 컨텍스트가 자동 연결
핵심 통찰

MCP는 단순한 API 연결이 아니다. AI가 컨텍스트 단절(Context Gap) 없이 작업할 수 있도록 만드는 표준 언어다. USB-C처럼, 어떤 도구든 같은 방식으로 연결된다.

How It Works

ReAct Loop 실전 동작 방식

"레거시 코드의 인증 버그를 찾아서 수정해줘" 라고 입력했을 때

1
REASON

문제 분석

어떤 파일을 봐야 할지 추론한다. auth 관련 파일 목록을 먼저 확인하기로 결정.

2
ACT

도구 실행

파일 탐색 도구를 사용해 auth 관련 파일 조회.

find . -name "*.js" | xargs grep -l "auth\|jwt\|token" | head -20
3
OBSERVE

결과 관찰

auth.js, middleware/jwt.js 발견. 두 파일 내용 분석.

4
REASON →

재추론 (루프)

auth.js:147에서 JWT 검증 누락 발견. 수정 계획 수립 후 실제 파일 수정 실행.

✓

완료

버그 수정, 테스트 파일 업데이트, 변경 사항 요약 리포트 출력까지 자동으로 완료.

Gemini CLI는 AI를 고립된 "답변 기계"에서 개발자의 네이티브 환경에 내장된 협업 파트너로 전환한다. IDE, 브라우저, 슬랙을 오가던 컨텍스트 전환 비용이 사라진다.
