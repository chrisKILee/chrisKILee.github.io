  • Obsidian + Claude Code 조합

Core
Insight
Karpathy는 이제 토큰의 상당 부분을 코드 조작이 아닌 지식 조작에 씁니다. LLM이 위키를 직접 쓰고 관리합니다. 사람은 방향만 잡으면 됩니다. 전체 아이디어 파일은 GitHub Gist에 공개됐고, 본인의 LLM 에이전트에 복붙하면 바로 시작할 수 있습니다.
상세 비교
항목 RAG (기존 방식) LLM Wiki (Karpathy 방식)
지식 처리 방식 질문마다 원본 청크를 검색해서 답변 원본을 한 번 컴파일 → 위키로 축적
지식 축적 없음. 매번 처음부터 탐색·질문이 쌓일수록 위키가 강화
복잡한 질문 여러 청크를 매번 조합해야 함 이미 컴파일된 위키에서 바로 응답
누가 쓰는가 LLM이 검색만 함 LLM 에이전트가 위키를 직접 작성·유지
대표 도구 NotebookLM, ChatGPT 파일 업로드 Obsidian + Claude Code / OpenAI Codex
Karpathy의 평가 매번 처음부터 발견, 정제 없음 지금 자신이 직접 쓰는 워크플로우
세 가지 핵심 변화
변화 01
컴파일 → 축적
원본을 한 번 컴파일하면 지식이 위키에 쌓입니다. 질문마다 다시 검색하지 않거든요.
RAG와 가장 큰 차이
변화 02
에이전트가 쓴다
사람이 위키를 직접 편집하지 않습니다. LLM 에이전트가 쓰고 유지합니다. 사람은 방향만 잡으면 됩니다.
핵심 원칙
변화 03
출력이 귀환한다
Q&A 결과물을 다시 위키에 넣습니다. 탐색할수록 지식 베이스가 강해지는 구조거든요.
복리 효과
후속 아이디어 파일: 트위터 바이럴 이후 Karpathy가 전체 아키텍처를 담은 GitHub Gist를 공개했습니다. Claude Code, OpenAI Codex 등 어떤 LLM 에이전트에든 복붙해서 바로 시작할 수 있습니다.
