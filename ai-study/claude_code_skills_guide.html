Skills 마스터 가이드

Anthropic 내부 문서 기반. 9가지 스킬 유형, 10가지 베스트 프랙티스, 수백 건의 실제 구현 사례에서 도출한 스킬 설계 & 배포 전략을 정리합니다.

✍️ Thariq Shihipar (Anthropic) 원문 보기 → 공식 문서 →
✦ 핵심 메시지: 스킬은 강력하고 유연하지만 아직 초기 단계입니다. 이것을 최종 가이드가 아닌 실전 팁으로 생각하세요. 실험하고, 반복하고, 팀과 공유하세요.

스킬이란?

Claude Code 스킬은 마크다운 파일이 아닌 폴더 구조입니다. SKILL.md가 YAML 프론트매터 메타데이터를 포함한 진입점 역할을 합니다.

📁
폴더 구조
SKILL.md가 진입점. references/, assets/, scripts/ 등 하위 파일로 상세 콘텐츠를 분리해 컨텍스트를 절약합니다.
🎯
범위별 저장 위치
우선순위: Enterprise > Personal > Project > Plugin. 위치에 따라 적용 범위와 오버라이드 순서가 결정됩니다.
⚡
호출 방식
사용자와 Claude 모두 실행 가능(기본). disable-model-invocation으로 사용자 전용, user-invocable: false로 Claude 전용 설정.
📂
콘텐츠 분류
참고 자료(컨벤션, 패턴 → 인라인 실행)와 작업 콘텐츠(단계별 절차 → 슬래시 명령어 호출)로 구분합니다.

스킬 디렉토리 구조

my-skill/ ├── SKILL.md # 필수 진입점 (YAML 프론트매터 포함) ├── reference.md # 상세 API 문서 ├── examples.md # 사용 예시 ├── config.json # 설정 (Slack 채널 등) ├── references/ # 보조 자료 (on-demand 로드) ├── assets/ # 템플릿, 리소스 └── scripts/ # 실행 가능 유틸리티

슬래시 명령어

프론트매터의 name 필드가 슬래시 명령어가 됩니다. 예: name: deploy → /deploy

💡 스킬 이름은 사용자가 기억하기 쉬운 동사형으로 지정하세요. /standup, /review, /deploy 같은 형태가 이상적입니다.
🗂️ 스킬 분류

9가지 스킬 유형

실제 구현 사례 수백 건에서 도출한 9가지 스킬 유형. 각 유형별 목적과 실전 예시를 확인하세요.

📚
1. 라이브러리 & API 참고
코드 스니펫과 주의사항으로 흔한 실수를 방지합니다. 내부 라이브러리나 비표준 API 문서에 특히 효과적.
예: billing-lib, internal-cli
✅
2. 제품 검증
외부 도구를 활용해 기능 테스트 및 검증. UI 플로우나 CLI 도구 동작을 자동으로 확인합니다.
예: signup-flow, tmux-cli-driver
📊
3. 데이터 수집 & 분석
모니터링 시스템과 쿼리, 대시보드를 연결. 지표를 자동으로 수집하고 분석합니다.
예: funnel-query, grafana
🤖
4. 비즈니스 프로세스 자동화
반복적인 업무를 단일 명령어로 자동화. 팀 루틴이나 티켓 작성 같은 작업에 적합.
예: standup-post, create-ticket
🏗️
5. 코드 스캐폴딩 & 템플릿
보일러플레이트 코드 구조를 자동 생성. 새 서비스나 기능 추가 시 일관된 패턴을 보장합니다.
예: new-workflow, create-app
🔍
6. 코드 품질 & 리뷰
팀 표준을 강제하고 코드 리뷰를 지원. adversarial 리뷰로 취약점을 사전에 발견합니다.
예: adversarial-review, testing-practices
🚀
7. CI/CD & 배포
안전 검사와 함께 pull/push/deploy를 처리. PR 모니터링이나 서비스 배포를 자동화합니다.
예: babysit-pr, deploy-service
📖
8. 런북 (운영 가이드)
증상에서 시작한 체계적인 리포트로 문제 해결을 안내. 온콜 대응 시 빠른 진단을 돕습니다.
예: service-debugging, oncall-runner
🛠️
9. 인프라 운영
파괴적 작업에 보호장치를 추가한 일일 유지보수. 고아 리소스 정리나 비용 조사에 활용.
예: orphan-cleanup, cost-investigation

🏆 Best Practices

10가지 베스트 프랙티스

수백 건의 실제 스킬 구현에서 도출한 핵심 원칙. 이 10가지를 지키면 스킬의 효과가 극적으로 향상됩니다.

  • 1
    당연한 내용은 생략하라
    기초 프로그래밍 지식은 제외. Claude의 기본 패턴을 깨는 비표준 정보에만 집중하세요. 스킬 크기를 줄이면 컨텍스트 비용도 줄어듭니다.
  • 2
    Gotchas 섹션을 만들어라
    "모든 스킬에서 정보밀도가 가장 높은 부분이 Gotchas입니다." — Claude가 반복해서 실수하는 사항을 축적하는 공간. 사용할수록 품질이 올라갑니다.
  • 3
    파일 시스템으로 점진적 공개하라
    상세 콘텐츠(references/, assets/, scripts/)를 분리해 Claude가 필요할 때만 로드하도록 설계. 기본 SKILL.md는 최소화하고, 나머지는 on-demand 로드합니다.
  • 4
    과도한 제약을 피하라
    스킬이 상황에 맞게 적응하도록 유연성을 허용하세요. 너무 구체적인 지시는 예상치 못한 상황에서 Claude가 막히게 만듭니다.
  • 5
    description은 "언제 사용할지"를 써라
    기능 설명이 아닌 트리거 조건(if-then 스타일)을 작성하세요. Claude가 사용자 요청과 스킬을 매칭할 때 이 필드를 참조합니다.
  • 6
    초기 설정을 고려하라
    config.json에 설정을 저장하고, Slack 채널 같은 필수 정보는 AskUserQuestion으로 최초 1회만 수집합니다. 이후에는 저장된 설정을 재사용.
  • 7
    메모리 시스템을 구현하라
    ${CLAUDE_PLUGIN_DATA}와 함께 append-only 로그 또는 SQLite로 영구 저장소를 구축하세요. 세션 간 학습이 누적됩니다.
  • 8
    헬퍼 스크립트를 번들화하라
    scripts/ 폴더에 유틸리티 함수를 제공해 Claude가 오케스트레이션에만 집중하도록 설계. 보일러플레이트는 스킬이 처리합니다.
  • 9
    On-Demand 훅을 활용하라
    /careful로 파괴적 명령어를 차단하고, /freeze로 편집 범위를 제한하세요. 안전장치가 있는 스킬은 더 과감하게 실행할 수 있습니다.
  • 10
    영향도를 측정하라
    PreToolUse 훅으로 스킬 사용 현황을 추적하세요. 인기 스킬을 파악하고 개선 기회를 발굴할 수 있습니다.
⚙️ 프론트매터 & 변수

SKILL.md 설정 레퍼런스

SKILL.md의 YAML 프론트매터 필드와 동적 변수를 모두 정리합니다.

주요 프론트매터 필드

--- name: deploy-service # /deploy-service 슬래시 명령어 description: | # 트리거 조건 (if-then 스타일 권장) Use when: deploying a service to production disable-model-invocation: true # 사용자 전용 (Claude 자동 실행 금지) user-invocable: false # Claude 전용 (백그라운드 지식) allowed-tools: [Bash, Read] # 허용된 도구 제한 context: fork # 서브-에이전트로 실행 hooks: # 라이프사이클 이벤트 - event: PreToolUse command: ./scripts/track.sh ---

동적 변수

변수설명용도
$ARGUMENTS 슬래시 명령어 뒤 전달된 전체 인자 /deploy production → production
$0, $1, $2 공백으로 분리된 개별 인자 위치 기반 인자 파싱
${CLAUDE_SESSION_ID} 현재 세션의 고유 ID 세션 추적, 로그 분리
${CLAUDE_SKILL_DIR} 현재 스킬 디렉토리 경로 상대 경로로 파일 참조
${CLAUDE_PLUGIN_DATA} 영구 저장소 경로 세션 간 데이터 유지

동적 컨텍스트 주입

백틱으로 감싼 명령어는 Claude에 전달되기 전에 실행되어 실제 데이터로 대체됩니다.

# SKILL.md 내에서 사용 예시 현재 브랜치: `git branch --show-current` 최근 커밋: `git log --oneline -5` 현재 시간: `date` # Claude가 받을 때는 실제 값으로 치환됨 현재 브랜치: feature/login 최근 커밋: abc1234 feat: 로그인 기능 추가

🚀 배포 전략

스킬 배포 방법 3가지

팀 규모와 거버넌스 요구에 따라 적합한 배포 전략을 선택하세요.

  1. 저장소 체크인 (.claude/skills/)
    가장 단순한 방식. 프로젝트 레포에 스킬을 직접 포함하고 버전 관리합니다.
    장점 git 히스토리, PR 리뷰, 자동 공유
    단점 대규모 팀에서 확장성 부족, 레포별 관리 필요
  2. 플러그인 마켓플레이스
    엄선된 스킬을 마켓플레이스에 등록. 사용자가 선택해서 설치합니다.
    장점 검증된 품질, 조직 전체 배포
    단점 검토 프로세스 필요, 배포까지 시간 소요
  3. 엔터프라이즈 관리 (Managed Settings)
    조직 관리자가 Managed Settings를 통해 전체 조직에 배포. 최고 우선순위로 오버라이드됩니다.
    장점 중앙 집중 관리, 강제 적용, 보안 정책 통합
    단점 엔터프라이즈 플랜 필요, 관리자 권한 요구

우선순위 체계

범위저장 위치우선순위적합한 용도
EnterpriseManaged Settings1 (최고)조직 전체 정책, 보안 가이드라인
Personal~/.claude/skills/2개인 워크플로우, 개인 자동화
Project.claude/skills/3프로젝트별 컨벤션, 팀 루틴
Plugin플러그인 설치4 (최저)서드파티 스킬, 커뮤니티 도구
✅ 추천 시작점: 프로젝트 레포의 .claude/skills/에 먼저 구축하세요. 팀에서 검증되면 플러그인이나 엔터프라이즈 배포로 확장합니다.
💡 핵심 인사이트

실전에서 배운 것들

가이드 전체에서 반복해서 강조되는 핵심 원칙과 자주 하는 실수를 정리합니다.

스킬 설계 원칙

좋은 스킬의 조건

  • 비표준 정보에만 집중 — Claude가 이미 아는 것은 쓰지 않는다
  • Gotchas 섹션이 있다 — 반복 실수를 방지하는 핵심 공간
  • on-demand 로드를 활용한다 — SKILL.md는 최소화, 나머지는 하위 파일로
  • description이 트리거 조건을 명확히 설명한다 — "언제 이 스킬을 써야 하나?"
  • 헬퍼 스크립트가 있다 — Claude는 오케스트레이션만, 실행은 스크립트가

자주 하는 실수

⚠️ SKILL.md를 너무 크게 만드는 것: 모든 내용을 SKILL.md에 넣으면 컨텍스트가 낭비됩니다. 상세 내용은 references/, assets/ 등으로 분리하세요.
⚠️ description을 기능 설명으로 쓰는 것: "이 스킬은 X를 한다" 대신 "X 상황에서 사용한다"처럼 트리거 조건으로 작성해야 Claude가 올바르게 매칭합니다.
⚠️ 과도하게 구체적인 지시: 스킬이 너무 세세하게 행동을 지정하면 예상 밖 상황에서 막힙니다. 핵심 원칙만 제공하고 유연성을 허용하세요.

스킬 진화 사이클

  1. 문제 발견
    Claude가 반복해서 같은 실수를 하거나, 팀 루틴이 불편하다고 느껴질 때 스킬을 만들 시점입니다.
  2. 초안 작성
    SKILL.md에 핵심 정보만 담아 최소 버전을 만듭니다. Gotchas 섹션은 처음부터 포함.
  3. 실전 테스트
    실제 작업에서 사용하며 문제를 발견합니다. Claude가 예상과 다르게 행동하면 스킬을 개선.
  4. Gotchas 누적
    반복 실수를 Gotchas 섹션에 추가합니다. 사용할수록 스킬의 품질이 높아지는 선순환.
  5. 팀 공유 & 배포
    검증된 스킬을 팀과 공유합니다. 프로젝트 레포 체크인 → 플러그인 → 엔터프라이즈 순으로 확장.
✦ "스킬은 강력하고 유연하지만 아직 초기 단계입니다. 이것을 최종 가이드가 아닌 실전 팁으로 생각하세요. 실험하고, 반복하고, 팀과 공유하세요." — Thariq Shihipar, Anthropic
