A2UI가 무엇인가요?

2024년 12월 15일 구글이 공개한 "Generative UI" 방법론입니다. AI(에이전트)가 대화 흐름에 맞춰 동적으로 UI를 생성하지만, 보안을 위해 코드를 직접 작성하는 것이 아니라 "의도(Intent)"가 담긴 JSON 데이터를 전달하는 방식입니다.

🛡️

Security First (보안 우선)

AI가 HTML이나 JS 코드를 직접 생성하여 실행하는 것은 매우 위험(XSS 등)합니다. A2UI는 데이터(JSON)만 전달하고, 렌더링은 클라이언트의 안전한 컴포넌트가 담당합니다.

🧩

Framework Agnostic (독립성)

에이전트는 JSON만 보내므로, 받는 쪽이 React, Flutter, Android, iOS 무엇이든 상관없습니다. 화면 그리는 방식은 클라이언트가 결정합니다.

⚡

Generative Interaction

단순 텍스트 채팅을 넘어, 상황에 필요한 슬라이더, 날짜 선택기, 폼 등을 즉석에서 조합하여 사용자에게 제공합니다.

A2UI 작동 흐름 (Workflow)

Gemini Powered
Step 1: Server Side

AI Agent (LLM)

사용자의 요청을 분석하고, 필요한 UI 요소를 결정합니다. 코드를 짜지 않고 JSON 구조를 만듭니다.

Step 2: Protocol

JSON Payload

{ "type": "form", "fields": [...] }
Step 3: Client Side

Renderer (React/Web)

사전에 정의된 컴포넌트 맵(Map)을 사용하여 JSON을 실제 UI 컴포넌트로 변환하여 화면에 그립니다.

A2UI 시뮬레이터 Powered by Gemini ✨

실제 A2UI 에이전트처럼 작동합니다. 원하는 UI(예: "호텔 예약 폼 만들어줘")를 입력하면 Gemini가 JSON을 생성하고 화면에 그려줍니다.

* Gemini가 미리 정의된 컴포넌트(슬라이더, 드롭다운 등)를 조합하여 JSON을 만듭니다.

                            VS
                            왜 A2UI인가? (Analysis)
                        

                        

                            전통적인 방식과 AI가 직접 HTML을 짜는 방식, 그리고 A2UI를 비교했을 때,
                            A2UI는 보안(Safety)과 유연성(Flexibility)의 균형을 가장 잘 맞춥니다.
                        

                        

                            
                        

                    


                    
                    

                        

                            🛠️
                            개발 가이드: Agent 수정 방법
                        

                        

                            

                                

                                    1

                                

                                    
프롬프트 수정 (System Prompt)

                                    

                                        "HTML 코드를 주지 말고, 다음 스키마에 맞는 JSON 객체만 반환해"라고 지시하세요. 

                                        Ex: { type: "widget", props: {...} }
                                    

                                

                            

                            

                                

                                    2

                                

                                    
UI 컴포넌트 라이브러리 정의

                                    

                                        에이전트에게 "사용 가능한 도구 목록"을 알려주듯,
                                        "사용 가능한 UI 컴포넌트 목록(DatePicker, Slider 등)"을 프롬프트에 포함시키세요.
                                    

                                

                            

                            

                                

                                    3

                                

                                    
클라이언트 매핑 (Client Mapping)

                                    

                                        프론트엔드 코드에 Map을 만드세요. JSON의 'type' 필드를 보고 어떤 React/Flutter 컴포넌트를 그릴지
                                        결정하는 switch 문이 필요합니다.
