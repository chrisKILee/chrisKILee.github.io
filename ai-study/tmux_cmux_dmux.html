tmux

Ctrl+b prefix |% 수직분할 |" 수평분할 |c 새창 |d 분리

    장점

  • SSH 끊겨도 세션·프로세스 생존
  • 무제한 커스터마이징 (tmux.conf)
  • 강력한 플러그인 생태계 (TPM)
  • 스크립팅으로 레이아웃 자동화
  • Copy mode 스크롤백 검색

    단점

  • 초기 학습 곡선이 가파름
  • prefix 키 습관 필요
  • 256색 이상 설정 복잡
  • GUI 환경에서는 과잉 기능

tmux는 하나의 터미널 창 안에서 여러 세션·윈도우·패인을 관리하는 터미널 멀티플렉서입니다. 1990년대 GNU Screen의 현대적 대안으로 개발되어 현재 DevOps·개발자 워크플로우의 표준 도구입니다.

가장 강력한 특징은 세션 영속성입니다. SSH 연결이 끊겨도 tmux 세션 안의 프로세스는 계속 실행되며, 재접속 시 그대로 복원됩니다. 서버 장기 작업, CI/CD 실행, 원격 개발에 필수적인 이유입니다.

세션 → 윈도우 → 패인의 3단계 계층 구조로 하나의 터미널에서 수십 개의 작업을 동시에 관리할 수 있습니다.

Ubuntu
macOS
Arch
$sudo apt update && sudo apt install tmux
$tmux new -s mysession
# 설정: ~/.tmux.conf
$brew install tmux
# TPM 플러그인 매니저
$git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
$pacman -S tmux
# AUR: tmux-git for latest

cmux

cmux
Connection Multiplexer — 복수의 독립 프로젝트 (Go / Swift / Ruby)
soheilhyGo 네트워크
manaflowAI 터미널
★2,700+GitHub
cmux — Connection Routing
── cmux: 단일 포트 → 다중 프로토콜 ──

:8080 → [matcher]
           → HTTP/2 ─→ gRPC handler
           → HTTP/1.1 → REST handler
           → TLS ────→ HTTPS handler

m := cmux.New(listener)
grpcL := m.Match(cmux.HTTP2...)
httpL := m.Match(cmux.HTTP1Fast())
go grpcServer.Serve(grpcL)
m.Serve()

    장점

  • 단일 포트로 gRPC + REST 동시 서비스
  • 방화벽 규칙 단순화
  • Go 생태계와 자연스러운 통합
  • macOS 네이티브 AI 터미널 (manaflow)

    단점

  • 이름이 같은 프로젝트 혼재 (혼란)
  • 터미널 멀티플렉서 기능은 없음
  • kakao/cmux는 유지보수 비활성
  • manaflow cmux는 아직 베타

cmux는 동일한 이름을 가진 여러 독립 프로젝트를 가리킵니다. 가장 널리 알려진 것은 soheilhy/cmux로, 단일 TCP 포트에서 gRPC, HTTP/1.1, HTTP/2, TLS 등 여러 프로토콜을 동시에 서비스합니다.

최근에는 manaflow-ai/cmux가 주목받습니다. "멀티태스킹을 위한 터미널"을 슬로건으로, AI 코딩 에이전트 여러 개를 한 화면에서 관리하는 macOS 네이티브 앱입니다.

카카오의 kakao/cmux는 Ruby 기반으로 CDH 클러스터를 관리하는 전혀 다른 용도의 CLI입니다.

Go (soheilhy)
AI Terminal
Kakao CDH
# Go 모듈로 가져오기
$go get github.com/soheilhy/cmux
# import "github.com/soheilhy/cmux"
# macOS 네이티브 앱
$brew install --cask cmux
# 또는 cmux.dev 에서 다운로드
# Ruby gem (kakao CDH 클러스터용)
$gem install cmux
$cmux --help

dmux

dmux — AI Agent Multiplexer
dmux│ feature/auth│ fix/perf│ refactor/db
feature/auth
▶ claude running
status: active
fix/perf
▶ claude running
status: pending
refactor/db
○ idle
status: ready
dmux new feat/X
worktree + agent
→ auto created ✓

    장점

  • Git worktree + AI 에이전트 자동 연결
  • 여러 AI 에이전트 병렬 관리
  • 브랜치별 독립 환경 자동 구성
  • Rust 구현으로 빠른 성능 (zdcthomas)

    단점

  • AI 에이전트 의존성 (비용 발생)
  • Git worktree 개념 이해 필요
  • 초기 생태계 (★350 수준)
  • hepsw/dmux (Docker)는 비활성

dmux도 목적이 다른 여러 프로젝트가 존재합니다. 가장 주목받는 것은 standardagents/dmux로, Git Worktree와 AI 코딩 에이전트를 결합한 개발자 멀티플렉서입니다. Claude Code, Cursor 등 여러 AI 에이전트를 각각 독립된 git worktree에서 병렬로 실행·관리합니다.

zdcthomas/dmux는 Rust로 작성된 tmux 워크스페이스 매니저로, 프로젝트별 tmux 세션 레이아웃을 선택·자동 생성하는 데 특화되어 있습니다.

작업이 완료되면 m 키로 변경사항을 메인 브랜치에 병합하고, AI 기반 커밋 메시지를 자동 생성합니다.

standardagents
zdcthomas (Rust)
hepsw (Docker)
# npm으로 설치
$npm install -g @standardagents/dmux
$dmux new feature/my-feature
# worktree 생성 + 에이전트 실행
# Cargo로 설치 (Rust)
$cargo install dmux
$dmux # 대화형 프로젝트 선택 UI
# pip 설치 (Python)
$pip install dmux
# docker + tmux 통합 (현재 비활성)

tmux — 단축키 (prefix: Ctrl+b)

🖥️
서버 / DevOps 엔지니어
tmux를 선택하세요. SSH 세션 보존, 여러 서버 동시 모니터링, 배포 스크립트 병렬 실행. 원격 작업의 생명줄입니다.
⚙️
Go 백엔드 개발자
cmux (soheilhy)를 선택하세요. 마이크로서비스에서 단일 포트로 gRPC와 REST를 동시에 노출해야 할 때 최적의 라이브러리입니다.
🤖
AI 에이전트 헤비 유저
dmux (standardagents)를 선택하세요. Claude Code, Cursor 등을 여러 브랜치에서 동시에 병렬 실행하고 싶은 개발자에게 최적화되어 있습니다.
📡
원격 개발 / 홈랩
tmux + .tmux.conf 커스터마이징으로 완성도 높은 워크스페이스를 구성하세요. TPM 플러그인으로 상태바, 테마, 저장 기능을 추가할 수 있습니다.
🍎
macOS + AI 개발자
cmux (manaflow)는 macOS 네이티브 앱으로, AI 코딩 에이전트를 GUI에서 편리하게 관리하고 싶은 분께 적합합니다. 터미널 설정 없이 즉시 사용 가능합니다.
🦀
Rust + tmux 파워유저
dmux (zdcthomas)는 Rust로 작성된 빠른 tmux 워크스페이스 매니저입니다. 프로젝트 전환 시 레이아웃을 자동 복원하는 기능이 강점입니다.
