AI 디자인 가드레일

AI가 반드시 피해야 할
디자인 패턴들

무엇을 할지보다 무엇을 하지 말아야 하는지가 더 중요합니다. 이미지 생성에서 negative prompt가 결과를 결정했던 것처럼, AI UI 생성에서도 금지 규칙이 허용 규칙보다 강력합니다. 타이포그래피·컬러·간격·모션·반응형 다섯 영역의 가드레일을 모아뒀습니다.

01

타이포그래피

AI가 기본값으로 선택하는 폰트와 텍스트 스타일 대부분은 구분이 없고, 위계가 없고, 개성이 없습니다.

NEVER Inter만 단독으로 쓰지 마라
하지 말 것

제품을 소개합니다

Inter 900 제목 + Inter 400 본문. 수백만 개의 AI 생성 UI와 동일한 조합.

할 것

제품을 소개합니다

Fraunces italic 제목 + Inter 본문. 세리프-산세리프 혼합으로 위계와 개성 동시 확보.

Inter는 UI 텍스트 본문에 탁월하지만 단독으로 제목까지 맡으면 단조롭습니다. 세리프(Fraunces, Playfair, Lora)나 디스플레이 폰트(Syne, Anybody)를 제목에 사용해 대비를 만드세요.

NEVER 제목에 그라디언트 텍스트를 남발하지 마라
하지 말 것

차세대 AI 플랫폼

보라→핑크 그라디언트. 2021년부터 모든 스타트업이 써온 패턴.

할 것

차세대 AI 플랫폼

한 단어만 이탤릭+경량 세리프로 강조. 그라디언트 없이 더 강렬한 대비.

그라디언트 텍스트는 한 페이지에 최대 1회, 핵심 키워드 1–3 단어에만 사용합니다. 제목 전체에 적용하면 가독성이 낮아지고 곧 낡아 보입니다.

NEVER 폰트 크기 계단을 무너뜨리지 마라
하지 말 것

제목 (20px)

소제목 (18px)

본문 (16px) — 크기 차이가 2px뿐. 위계가 없음.

할 것

제목 (28px)

소제목 (18px)

본문 (15px) — 비율이 명확해 스캔이 쉬움.

최소 1.25× 배율을 지킵니다: 본문 15 → 소제목 18–20 → 제목 24–32 → 디스플레이 40+. 인접 레벨 간 2–4px 차이는 위계 없는 텍스트 덩어리를 만듭니다.

CAUTION ALL CAPS는 레이블에만, 본문에는 절대 금지

ALL CAPS는 탐색 레이블, 메타 정보(날짜, 카테고리), 섹션 구분자에 font-size 11–13px + letter-spacing 0.08–0.12em 조합으로만 사용합니다. 문장이나 제목에 ALL CAPS를 적용하면 가독성이 40% 이상 떨어집니다.

02

컬러

AI가 기본으로 내놓는 보라·청록·인디고 그라디언트 조합은 이제 아무도 기억하지 않는 배경입니다.

NEVER 회색 텍스트를 유색 배경 위에 올리지 마라
하지 말 것

이 텍스트는 대비가 부족합니다. WCAG AA 기준 3:1 미만.

할 것

유색 배경 위에는 순백(#fff) 또는 고명도 색상. 불투명도 opacity 사용 금지.

유색 배경 위 텍스트에 rgba(255,255,255,0.6) 같은 반투명을 쓰면 WCAG AA(4.5:1) 기준을 통과하지 못합니다. 배경색에서 명도를 계산해 텍스트 색을 결정하거나, 배경을 어둡게 만들어 흰색 텍스트 대비를 확보하세요.

NEVER 순수 회색(#gray)을 본문에 쓰지 마라 — 항상 베이지로 기울여라
하지 말 것

이 텍스트는 #9ca3af (gray-400). 배경과 온도가 달라 차갑고 분리된 느낌.

할 것

이 텍스트는 #52524e (warm gray). 페이지 배경 온도와 맞아 자연스럽게 녹아듦.

Tailwind의 stone, zinc, warm-gray처럼 미세하게 베이지나 슬레이트로 기울어진 회색을 사용합니다. 배경이 #FAFAF8 같은 크림 계열이라면 텍스트도 같은 온도(warm)의 회색을 사용해야 페이지가 하나의 팔레트로 읽힙니다.

NEVER 보라-인디고 그라디언트를 기본 강조색으로 쓰지 마라

보라(#6366f1)→핑크(#ec4899) 그라디언트는 2020–2022년 SaaS 랜딩의 기본값이었습니다. AI가 가장 자주 선택하는 색이기도 합니다. 대신 단색 강조색(특히 검정, 테라코타, 올리브, 인디고-단색)을 사용하고, 그라디언트가 필요하다면 인접 색상 2개로 제한합니다.

ALWAYS 다크 모드에서 순백(#fff)·순흑(#000) 사용 금지
하지 말 것

#000 배경에 #fff 텍스트 — 강렬함이 눈을 피로하게 만듦

할 것

#09090B 배경에 #F4F4F5 텍스트 — 여전히 고대비, 눈 편안함

다크 모드 배경은 #09090B–#111115, 텍스트는 #E4E4E7–#F4F4F5 범위를 사용합니다. 순수 대비(21:1)는 AMOLED 환경을 제외하면 할로 이펙트(halo effect)로 장시간 읽기에 불편합니다.

03

간격·레이아웃

AI는 "카드 안에 카드"를 기본 레이아웃 단위로 사용합니다. 경계선이 많을수록 실제 내용은 줄어듭니다.

NEVER 카드 안에 카드를 넣지 마라
하지 말 것

외부 카드

내부 카드 — 테두리 2겹, 여백 2겹, 콘텐츠는 1개
할 것

섹션 레이블

테두리 없이 구분선·여백·레이블로 계층을 표현.

카드 중첩은 인지적 비용을 기하급수로 높입니다. 계층이 필요하면 border-bottom 구분선, 배경색 차이(1–2단계), 들여쓰기, 폰트 크기 차이를 사용하세요.

NEVER 카드 패딩을 8px 이하로 쓰지 마라
하지 말 것

padding: 8px — 내용이 테두리에 붙어 숨막힘.

할 것

padding: 24–32px — 내용이 숨쉬는 공간 확보.

카드 패딩 최솟값: 모바일 16px, 데스크탑 24–32px. 고밀도 데이터 테이블 셀도 최소 12px를 유지합니다. 8px 이하 패딩은 클릭 영역도 WCAG 44px 기준을 충족하지 못합니다.

NEVER 섹션 간격 없이 콘텐츠를 쌓지 마라

섹션 간 최소 여백: 48–64px (데스크탑), 32–40px (모바일). 8–16px 간격으로 섹션을 나누면 페이지 전체가 단일 덩어리로 읽혀 구분이 불가능합니다. 여백은 구조를 설명하는 언어입니다.

CAUTION CTA(행동 유도 버튼) 2개 이상을 나란히 놓지 마라
하지 말 것
할 것

Filled(채움)+Outlined(테두리) 또는 Filled+Text(텍스트만) 조합으로 시각적 우선순위를 명확히 합니다. 두 버튼 모두 filled이면 사용자는 어디를 눌러야 하는지 모릅니다.

04

모션

AI가 생성한 애니메이션은 대부분 너무 느리거나, 너무 많거나, 목적이 없습니다.

NEVER bounce / elastic easing을 UI에 쓰지 마라

cubic-bezier(0.68,-0.6,0.32,1.6)처럼 오버슈트가 있는 이징은 물리적 물체(공, 스프링)를 표현할 때만 적합합니다. 모달·드롭다운·알림 같은 UI 요소에 쓰면 장난스럽고 불안정하게 느껴집니다. ease-out 또는 cubic-bezier(0.16,1,0.3,1)(빠른 출발, 부드러운 정착)을 기본값으로 사용합니다.

NEVER transition 지속 시간을 300ms 이상으로 설정하지 마라

UI 트랜지션 기준: 마이크로인터랙션(버튼, 토글) 100–150ms, 요소 등장/사라짐 200–250ms, 페이지 전환 최대 300ms. 500ms 이상은 기다리는 느낌을 줘서 인터페이스가 느리다는 인식을 만듭니다. 또한 반드시 prefers-reduced-motion 미디어 쿼리를 지원해야 합니다.

NEVER 스크롤 트리거 애니메이션을 모든 요소에 적용하지 마라

스크롤 인트로 애니메이션(fade-in, slide-up)은 처음 보는 사용자에게는 인상적이지만, 두 번째 방문부터는 콘텐츠 로딩을 지연시키는 장애물입니다. 히어로 영역과 핵심 기능 소개 1–2곳에만 제한적으로 사용합니다. 리스트 아이템, 카드 그리드, 본문 텍스트 전체에 stagger(순차 등장) 적용은 금지입니다.

ALWAYS 모든 모션에 prefers-reduced-motion을 추가하라

전정 장애, 주의력 문제가 있는 사용자는 과한 모션에 불편함을 느낍니다. 모든 CSS 트랜지션·애니메이션에 아래 패턴을 적용합니다:

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
05

반응형

AI는 데스크탑을 먼저 만들고 모바일을 "축소"합니다. 이 순서가 모든 문제의 시작입니다.

NEVER 모바일에서 3열 이상 그리드를 유지하지 마라

모바일(375px)에서 카드 3열 그리드는 카드 하나가 100px 내외가 됩니다. 콘텐츠는 읽히지 않고, 터치 영역은 WCAG 44px 기준에 미치지 못합니다. grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))처럼 유동 그리드를 기본으로 사용합니다.

NEVER 고정 픽셀 너비로 레이아웃을 잡지 마라

width: 1200px 고정 대신 max-width: 1200px; width: 100%를 사용합니다. 좌우 패딩은 고정값(padding: 0 clamp(16px, 4vw, 48px))보다 반응형 값이 좋습니다. 가로 스크롤이 생기는 레이아웃은 레이아웃 실패입니다.

CAUTION 폰트 크기에 고정 px를 쓰지 마라 — clamp()를 사용하라

제목 폰트를 모바일에서 데스크탑과 동일한 크기로 유지하면 한 줄에 1–2 단어만 들어갑니다. clamp()로 최소-최대를 지정합니다:

/* 모바일 24px → 데스크탑 48px으로 유동 */
font-size: clamp(1.5rem, 4vw + 1rem, 3rem);
NEVER 터치 영역을 44px × 44px 이하로 만들지 마라

WCAG 2.5.8 기준: 모든 인터랙티브 요소의 최소 터치 영역은 24×24px (AA), 권장은 44×44px. 아이콘만 있는 버튼, 작은 체크박스, 링크가 줄 높이보다 작게 표시될 경우 padding이나 ::after 가상 요소로 터치 영역을 확장합니다.

## UI 디자인 금지 규칙 (Design Guardrails) ### 타이포그래피 - 제목과 본문 모두 Inter를 사용하지 마라. 제목에는 세리프(Fraunces, Lora, Playfair)나 디스플레이 폰트를 페어링하라. - 텍스트 전체에 그라디언트 색상을 적용하지 마라. 그라디언트는 1–3 단어 강조에만 허용한다. - 인접한 제목 레벨 간 폰트 크기 차이를 최소 1.25배(125%) 이상 유지하라. - 본문·제목에 ALL CAPS를 적용하지 마라. 레이블(11–13px + letter-spacing)에만 허용한다. ### 컬러 - 유색 배경 위에 rgba(255,255,255,0.5–0.8) 같은 반투명 텍스트를 쓰지 마라. 항상 불투명 색상으로 대비를 계산하라. - 본문 텍스트에 순수 회색(gray-400, #9ca3af)을 쓰지 마라. warm gray(stone, zinc)로 대체하라. - 보라-핑크 그라디언트(#6366f1→#ec4899)를 기본 강조색으로 사용하지 마라. - 다크 모드에서 순흑(#000) 배경과 순백(#fff) 텍스트를 쓰지 마라.
