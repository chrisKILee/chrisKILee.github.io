Google Stitch
vs Figma 심층 비교

Google Labs의 AI 기반 UI 생성 툴 Stitch를 Figma와 기능·가격·MCP 연동 관점에서 비교합니다. 완전 무료로 시작할 수 있지만, Figma를 대체하는 것은 아닙니다.

🆓 현재 완전 무료 🔌 Claude Code MCP 연동 📐 Figma와 병행 사용 권장 🧪 Google Labs 실험 단계
01 개요

Google Stitch란?

2025년 5월 Google I/O에서 공개된 AI 기반 UI 디자인 툴. 텍스트 프롬프트 한 줄로 앱 화면을 생성하고, Claude Code·Cursor 등 AI 코딩 에이전트와 MCP로 연결해 즉시 코드로 전환할 수 있습니다.

Stitch → DESIGN.md → MCP → Claude Code → 프로덕션 워크플로우

✍️
텍스트 → UI 자동 생성

자연어 프롬프트로 웹/모바일 앱 화면을 즉시 생성. 스케치·와이어프레임·스크린샷 이미지도 입력 가능. 한 번에 최대 5개 화면 동시 생성(2026.03 업데이트).

AI Generation
📄
DESIGN.md — 디자인 시스템 파일

색상 팔레트·타이포그래피·간격 기준을 마크다운 파일로 추출. AI 에이전트가 이 파일을 읽어 브랜드 일관성 유지. Git으로 버전 관리 가능.

Design System
🔌
MCP 서버 공식 지원

Claude Code, Cursor, Gemini CLI, VS Code, Codex, OpenCode와 직접 연결. 에이전트 채팅에서 자연어로 Stitch 프로젝트를 제어하고 HTML/CSS 코드를 가져올 수 있음.

MCP / Agent
📤
HTML/CSS Export

생성된 UI를 HTML/CSS로 즉시 내보내기 가능. Figma 붙여넣기도 지원(Standard 모드 한정). React 컴포넌트는 Claude Code가 MCP를 통해 변환.

03 비교 분석

Google Stitch vs Figma — 항목별 비교

두 툴은 "경쟁자"가 아니라 역할이 다릅니다. Stitch는 0→1 단계, Figma는 1→100 단계에 강합니다.

항목 Google Stitch Figma 비고
가격 무료 (현재) $15/월/유저~ Stitch 유료화 Q4 2026 예상
주요 강점 0→1 빠른 프로토타입 생성, AI 중심 1→100 정제·협업·프로덕션 사용 목적이 다름
AI 생성 능력 핵심 기능 (전체 워크플로우) 보조 기능 수준 Stitch가 압도적 우위
실시간 팀 협업 없음 완전 지원 Figma 강점
플러그인 생태계 없음 2,000+ 플러그인 Figma 압도적 우위
MCP 연동 공식 지원 (Claude Code, Cursor 등) 서드파티 플러그인 Stitch가 더 자연스러운 AI 통합
HTML/CSS Export 기본 지원 플러그인 필요 Stitch가 코드 출력 간편
Figma Export Standard 모드만 — Pro 모드에서는 미지원
인터랙션/애니메이션 정적 디자인만 완전 지원 Figma 강점
버전 관리 DESIGN.md로 Git 연동 가능 내장 버전 히스토리 Figma가 더 직관적
기업 안정성 실험 단계 (Labs) SOC2 준수, 엔터프라이즈급 Figma가 안정성 우위
Claude Code 통합 MCP 공식 지원 → 코드 자동화 서드파티 MCP 별도 설정 Stitch + Claude Code 조합이 최강

포지셔닝 맵: AI 자동화 vs 협업 완성도

04 설정 가이드

Claude Code에 Stitch MCP 연결하기

WSL + Node.js 환경에서 Google Cloud 계정만 있으면 5분 안에 설정 완료.

사전 요구사항
Google Cloud 계정, Node.js 18+, Claude Code CLI. Google Cloud 프로젝트에서 Stitch API 활성화 필요.
1
Google Cloud 인증
터미널에서 Google 계정으로 인증. WSL에서는 ! gcloud auth login 으로 실행 가능.
bash 
gcloud auth application-default login
2
Claude Code settings.json에 MCP 서버 추가
~/.claude/settings.json 파일을 열고 아래 내용 추가.
json 
{
  "mcpServers": {
    "stitch": {
      "command": "npx",
      "args": ["@_davideast/stitch-mcp", "proxy"]
    }
  }
}
3
Claude Code 재시작 후 연결 확인
Claude Code를 재시작하면 Stitch MCP 도구가 로드됨. 에이전트에게 "List my Stitch projects" 라고 입력해서 연결 확인.
4
MCP 주요 도구 활용
연결 후 사용 가능한 Stitch MCP 도구들:
build_site
프로젝트를 사이트로 빌드. 스크린을 라우트에 매핑하고 각 페이지의 디자인 HTML 반환.
get_screen_code
특정 스크린을 검색하고 HTML/CSS 코드를 다운로드.
get_screen_image
스크린샷을 base64로 다운로드. 시각적 확인용.
05 DESIGN.md

DESIGN.md — AI를 위한 디자인 시스템

README.md가 개발자를 위한 문서라면, DESIGN.md는 AI 에이전트를 위한 디자인 규칙집입니다. Stitch가 기존 웹사이트나 디자인에서 규칙을 자동 추출해 생성합니다.

🎨
저장되는 내용

색상 팔레트, 타이포그래피 규칙, 간격/패딩 기준, 컴포넌트 스타일, 브랜드 시각 규칙이 마크다운 형식으로 구조화.

Content
♻️
재사용 & 일관성

UI를 새로 생성할 때마다 DESIGN.md를 자동 참조해 브랜드 색상·폰트·간격을 일관되게 적용. 매번 규칙을 다시 설명할 필요 없음.

Consistency
🔀
Git 워크플로우 통합

일반 마크다운 파일이므로 Git으로 버전 관리 가능. PR로 리뷰하고, 브랜치로 실험하고, 팀원과 공유 가능.

Git-native
💡 활용 팁: Claude Code와 함께
DESIGN.md를 프로젝트 루트에 배치하면 Claude Code가 자동으로 읽어서 컴포넌트 생성 시 디자인 규칙을 준수합니다. CLAUDE.md처럼 프로젝트 컨텍스트로 활용하는 방식입니다.
06 한계 & 주의사항

Stitch의 현실적인 제약

실험 단계인 만큼 실무 투입 전에 반드시 알아야 할 제약이 있습니다.

제약 항목 상세 내용 우회 방법
생성 품질 AI가 UX 의도·접근성·사용성을 고려하지 않음. 프로덕션 바로 투입 불가. Figma로 import 후 디자이너 리뷰 필수
이미지 입력 인식 스케치·손그림 업로드 지원을 표방하지만 실제로는 해석 불가한 경우가 많음. 텍스트 프롬프트로 대체
Figma Export 제한 Pro(Experimental) 모드에서 Figma export 미지원. Standard 모드만 가능. Standard로 초안 생성 후 Pro로 정제
월 생성 한도 Standard 350회, Pro 200회. 초과 시 해당 월 추가 생성 불가. 생성 횟수 관리, 핵심 화면 우선 생성
정적 디자인만 지원 인터랙션, 트랜지션, 애니메이션 설계 불가. Figma에서 인터랙션 추가
팀 협업 없음 다중 편집, 댓글, 버전 히스토리 모두 미지원. DESIGN.md를 Git으로 공유
실험 단계 안정성 Google Labs 실험 단계. 버그·크래시 가능성, 서비스 중단 위험 있음. 중요 작업은 Figma 병행
07 권장 워크플로우

Stitch + Figma + Claude Code 통합 워크플로우

세 툴을 각자의 강점 단계에 배치하면 빠른 속도와 높은 완성도를 동시에 달성할 수 있습니다.

1
Stitch: 0→1 아이디어 검증
텍스트 프롬프트로 초기 화면 초안 5개 이하를 빠르게 생성. 방향성 검토 용도. DESIGN.md를 함께 생성해서 브랜드 규칙을 추출.
빠름 (5분) 정제 필요
2
Figma: 1→100 정제 & 협업
Stitch에서 생성한 초안을 Figma로 import(Standard 모드 한정). 디자이너가 UX·접근성·인터랙션을 정제. 팀 협업으로 최종 디자인 확정.
정밀 작업 팀 협업
3
Stitch MCP + Claude Code: 코드 자동화
MCP로 Stitch 스크린의 HTML/CSS를 가져와서 Claude Code가 React 컴포넌트로 변환. DESIGN.md를 컨텍스트로 활용해 스타일 일관성 유지.
prompt 
Stitch의 dashboard 스크린 HTML을 가져와서
DESIGN.md 규칙에 맞게 React 컴포넌트로 변환해줘.
4
배포 & 반복
생성된 컴포넌트를 코드베이스에 통합 후 배포. 피드백 기반으로 Stitch에서 다시 빠른 수정 반복.
💡 cardash.chrisnolja.dev 적용 예시
대시보드 신규 화면은 Stitch로 초안 생성 → DESIGN.md 추출 → Claude Code로 React 변환. 기존 화면 수정은 Figma(또는 직접 코드 수정). 두 흐름을 병행하면 UI 프로토타이핑 속도가 크게 향상됩니다.
