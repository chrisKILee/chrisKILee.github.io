😣 문제 정의 · 배경

기존의 어려움

  • 🔍 회의실 찾기 — 필터 설정 + 스크롤 탐색에 약 45초 소요
  • 📅 일정 조율 — 참석자 각각의 캘린더를 개별 조회·비교, 건당 약 3분
  • ✏️ 예약 변경 — 시스템 접속 → 상세 조회 → 수정·저장에 약 1분

✨ AI로 해결한 방식

  • 🤖 "6인실 찾아줘" → AI가 실시간 가용성 확인 후 추천 (5초)
  • 🗓️ "공통 시간 찾아줘" → 참석자 캘린더 자동 교차 분석 (10초)
  • 🔄 "1시간 미뤄줘" → 예약 수정 완료 (5초) + 초대장 자동 발송

③ 업무 효율성
  • 🔹 회의실 검색 45초 → 5초 (89% 단축)
  • 🔹 일정 조율 3분 → 10초 (94% 단축)
  • 🔹 예약 변경 1분 → 5초 (91% 단축)
  • ✅ DX팀 전원 + 타 팀 실운영 중

  • 💡기존 Google Workspace 인증 재활용으로 실용적 접근.
⑤ 확산 가능성
  • ✅ 전사 11개 회의실 통합 이미 완료

  • ✅ 타 팀 구성원(Brett, Gyro 등) 실사용 확인
⑥ 조직 목표 연결
  • 🎯사내 비효율 업무 DX·AI 자동화 방향 직결.
  • 💡재사용 가능한 AI 에이전트 아키텍처 자산화로 타 AI 프로젝트 기반 제공.

⚡ 주요 기능

🗣️ 자연어 예약

"내일 오후 3시 10명 회의실 예약해줘" — AI가 조건 파악 후 가용 회의실 검색·예약·초대장 발송 자동 처리

🤝 공통 시간 탐색

참석자 이름 입력 → 이메일 자동 검색 → Google Calendar FreeBusy API로 모두 가능한 시간대 자동 도출

🎙️ 음성 인식

Web Speech API 기반 음성 명령 지원. 모바일에서도 말 한 마디로 예약 가능

🔄 예약 수정·취소

"1시간 미뤄줘", "오늘 3시 예약 취소해줘" — 자연어로 기존 예약 즉시 변경

📊 대시보드 통계

위치별 주간 예약 건수·사용 시간 통계. 선호 지역 설정으로 자주 쓰는 곳 우선 추천

📧 초대장 자동 발송

예약·변경·취소 시 참석자 전원에게 Google Calendar 초대장 및 Google Meet 링크 자동 발송

🧠 AI 활용 방식 · 기술 스택

AI 모델 · 프레임워크

  • 🔹 Google ADK (LlmAgent + Runner)
  • 🔹 Gemini 3.1 Flash Lite Preview
  • 🔹 9종 FunctionTool (Zod 스키마 검증)
  • 🔹 InMemorySessionService (Multi-turn 대화)

기술 스택

  • 🔹 Next.js 14.2 + TypeScript 5.0+
  • 🔹 Google Calendar API v3
  • 🔹 Google OAuth 2.0 (Cookie 기반)
  • 🔹 Tailwind CSS 4.1 · Docker

예약 처리 흐름 (Multi-turn Tool Chain)

자연어 입력
→ ① searchContacts (이름 → 이메일)
→ ② findCommonSlots (FreeBusy API 교차 분석)
→ ③ searchRooms (가용 회의실 탐색)
→ ④ createBooking (예약 생성 + Meet 링크)
→ ⑤ 참석자 초대장 자동 발송 (sendUpdates: all)
