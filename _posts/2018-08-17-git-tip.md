> 협업과 버전 관리의 표준. 기본기부터 `rebase`·`bisect` 같은 중급 기술까지 실전에서 자주 쓰는 명령을 정리했다.

# 설치 & 초기 설정

```bash
# macOS (Homebrew)
brew install git

# Ubuntu / Debian
sudo apt update && sudo apt install git

# Windows
winget install --id Git.Git -e

# 버전 확인
git --version
```

처음 설치하면 반드시 사용자 정보를 등록한다. 모든 커밋에 기록되는 정보다.

```bash
git config --global user.name  "Chris Lee"
git config --global user.email "you@example.com"

# 기본 브랜치 이름을 main 으로
git config --global init.defaultBranch main

# 컬러 출력 + 보기 좋은 로그 alias
git config --global color.ui auto
git config --global alias.lg "log --oneline --graph --decorate --all"

# 현재 설정 확인
git config --list
```

# 기본 워크플로우

```bash
git init                  # 새 저장소 생성
git clone <url>           # 원격 저장소 복제

git status                # 변경 상태 확인
git add <file>            # 스테이징 (git add . 는 전체)
git commit -m "메시지"    # 커밋
git commit -am "메시지"   # 추적 중인 파일은 add + commit 한 번에

git log --oneline         # 한 줄 로그
git lg                    # 위에서 만든 alias (그래프)
git diff                  # 워킹 디렉토리 vs 스테이징
git diff --staged         # 스테이징 vs 마지막 커밋
```

## 작업 단위 이해 (3개 영역)

| 영역 | 설명 | 이동 명령 |
|------|------|-----------|
| Working Directory | 실제 파일을 수정하는 곳 | `git add` → Staging |
| Staging (Index) | 다음 커밋에 포함될 변경 | `git commit` → Repository |
| Repository (HEAD) | 커밋으로 확정된 히스토리 | `git restore` / `git reset` |

# 브랜치 & 병합

```bash
git branch                # 브랜치 목록
git branch <name>         # 브랜치 생성
git switch <name>         # 브랜치 이동 (구: git checkout <name>)
git switch -c <name>      # 생성 + 이동

git merge <name>          # 현재 브랜치에 <name> 병합
git branch -d <name>      # 병합된 브랜치 삭제
git branch -D <name>      # 강제 삭제

# 원격 브랜치 추적해서 로컬 생성
git switch -c feature origin/feature
```

## package.json 사후 추가 (원본 팁)

`node_modules`만 있고 `package.json`이 없을 때 의존성을 역으로 복원한다.

```bash
npm init -y
ls node_modules/ | xargs npm install --save
```

# 원격 저장소

```bash
git remote -v                       # 원격 목록
git remote add origin <url>         # 원격 추가
git push -u origin main             # 최초 push (-u: 추적 설정)
git push                            # 이후 push
git pull                            # fetch + merge
git fetch                           # 원격 변경만 가져오기(병합 X)

# 원격 URL 변경 (SSH ↔ HTTPS)
git remote set-url origin git@github.com:user/repo.git
```

# 되돌리기 (실전 빈도 높음)

```bash
# 워킹 디렉토리 변경 취소
git restore <file>            # 구: git checkout -- <file>

# 스테이징 취소 (add 되돌리기)
git restore --staged <file>   # 구: git reset HEAD <file>

# 마지막 커밋 메시지 수정 / 파일 추가
git commit --amend

# 커밋은 되돌리되 변경은 유지 (soft)
git reset --soft HEAD~1

# 커밋 + 스테이징 되돌리고 변경은 유지 (mixed, 기본값)
git reset HEAD~1

# 완전히 되돌리기 — 변경까지 삭제 (위험!)
git reset --hard HEAD~1

# 이미 push한 커밋을 안전하게 되돌리기 (새 커밋 생성)
git revert <commit>
```

> ⚠️ `reset --hard`와 force push는 히스토리를 파괴한다. 공유 브랜치에서는 `revert`를 쓴다.

# Advanced — 중급 이상

## rebase — 히스토리를 깔끔하게

```bash
# feature 브랜치를 main 최신 위로 재배치 (merge commit 없이 직선 히스토리)
git switch feature
git rebase main

# 인터랙티브 rebase — 커밋 합치기/순서변경/메시지수정
git rebase -i HEAD~3
#   pick   → 그대로
#   squash → 이전 커밋과 합침
#   reword → 메시지 수정
#   drop   → 커밋 삭제
```

## stash — 작업 임시 저장

```bash
git stash                     # 현재 변경 임시 저장
git stash -u                  # untracked 파일까지 포함
git stash list                # 목록
git stash pop                 # 복원 + stash 삭제
git stash apply stash@{1}     # 특정 stash 복원(유지)
git stash drop stash@{0}      # 삭제
```

## cherry-pick — 특정 커밋만 가져오기

```bash
git cherry-pick <commit>          # 다른 브랜치의 커밋 1개를 현재 브랜치로
git cherry-pick <c1>^..<c2>       # 범위 지정
```

## reflog — "사라진" 커밋 복구

`reset --hard`로 날린 커밋도 reflog에 약 30일간 남는다. 사실상 최후의 안전망.

```bash
git reflog                    # HEAD가 거쳐온 모든 위치
git reset --hard HEAD@{2}     # 원하는 시점으로 복구
```

## bisect — 버그가 생긴 커밋 이진 탐색

```bash
git bisect start
git bisect bad                # 현재(버그 있음)
git bisect good <commit>      # 정상이던 과거 커밋
# git이 중간 커밋으로 체크아웃 → 테스트 후 good/bad 반복
git bisect reset             # 종료
```

## 기타 유용한 명령

```bash
git blame <file>              # 각 줄을 누가/언제 수정했는지
git log -p <file>            # 파일 변경 이력 + diff
git log --author="chris"     # 특정 작성자 커밋
git clean -fd                # untracked 파일/폴더 삭제 (위험)
git tag v1.0.0               # 태그
git push --tags              # 태그 push
git shortlog -sn             # 기여자별 커밋 수
```


# 협업 권장 워크플로우 (요약)

1. `git switch -c feature/login` — 기능 브랜치 생성
2. 작업 → `git add` → `git commit`
3. `git fetch && git rebase origin/main` — 최신 반영
4. `git push -u origin feature/login`
5. Pull Request 생성 → 리뷰 → squash merge
6. `git switch main && git pull && git branch -d feature/login`
