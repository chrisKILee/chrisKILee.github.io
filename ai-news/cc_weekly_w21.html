FEATURE 01 · PERMISSIONS

Auto Mode — 권한 프롬프트 대신, 백그라운드 안전 검사로.

이제 Pro 플랜에서도 켤 수 있다. Opus에 더해 Sonnet 4.6도 지원. 일상 작업은 묻지 않고 그대로 흐르고, 위험한 작업만 멈춰 세워 보여준다.

기존에는 도구를 실행할 때마다 권한 프롬프트가 흐름을 끊었다. Auto Mode는 그 자리를 백그라운드 안전 검사(분류기)로 대체한다. 사용자 메시지·도구 호출·프로젝트 규칙(CLAUDE.md)을 함께 보고, 매 작업이 안전한지 자동으로 판단한다.

핵심은 “맡기되, 보이게”다. 파일 수정이나 의존성 설치 같은 일상은 그냥 진행하고, force push나 외부 전송처럼 되돌리기 어려운 작업은 차단하고 표시한다. 전환은 Shift+Tab 토글 한 번이면 된다.

✅ 그냥 진행 (일상)

  • 작업 폴더 안의 파일 수정·생성
  • 잠금 파일대로 의존성 설치
  • 읽기 전용 요청
  • 내가 만든 브랜치에 push

⛔ 막고 표시 (위험)

  • curl | bash 다운로드·실행
  • 외부로 민감 데이터 전송
  • force push · main 직접 push
  • 기존 파일을 되돌릴 수 없는 삭제
FIG.1 · Auto Mode 권한 판단 흐름

켜는 법

# 1) 가장 간단 — 입력창에서 Shift+Tab 으로 모드 순환
#    default → acceptEdits → plan → (자격 되면) auto

# 2) 시작할 때 플래그로 지정
claude --permission-mode auto

# 3) 기본값으로 고정 — ~/.claude/settings.json
{
  "permissions": { "defaultMode": "auto" }
}

“맡기되, 보이게 — 일상은 흐르게 두고, 위험한 것만 멈춰 세운다.” — Claude Code 위클리 W21

Auto Mode 요약

  • 권한 프롬프트 → 백그라운드 안전 검사로 대체.
  • 이제 Pro 플랜에서도 사용 가능, Sonnet 4.6 지원.
  • 일상은 통과, force push·외부 전송·비가역 삭제는 차단·표시.
  • 전환은 Shift+Tab 토글.

FEATURE 02 · NEW COMMAND

/code-review — diff에서 정확성 버그를 잡는다.

변경된 diff를 노력 수준을 골라 검토하고, 정확성 버그를 보고한다. --comment를 붙이면 결과를 GitHub PR 인라인 댓글로 바로 달아준다.

이번 주 새로 추가된 명령어다. 현재 변경분(diff)을 읽고 논리·정확성 버그를 집어 보고한다. 가벼운 점검부터 꼼꼼한 검토까지, 들이는 노력 수준을 직접 고를 수 있다.

정리(리팩터링) 전용 검토인 /simplify는 그대로 분리돼 있다 — 버그 잡기는 /code-review, 코드 정돈은 /simplify. 결과를 바로 코드에 반영하려면 --fix를 쓴다.

FIG.2 · /code-review 흐름 — diff → 노력 수준 → 보고
TAB.1 · 노력 수준 가이드
수준성격언제
low빠르게, 확신 높은 버그만작은 변경·빠른 점검
medium기본값, 균형일반적인 PR 검토
high넓게, 깊게 — 더 꼼꼼히핵심 로직·놓치면 안 될 변경

사용법

# 노력 수준을 골라 정확성 버그 보고
/code-review high

# 결과를 GitHub PR 인라인 댓글로
/code-review medium --comment

# 발견 사항을 작업 트리에 바로 반영
/code-review --fix

# 정리(리팩터링)만 — 버그는 안 봄
/simplify

FEATURE 03 · IMPROVED

/usage — 내 한도, 뭐가 쓰는지.

최근 사용량을 스킬·서브에이전트·플러그인·MCP 서버별로 묶어서 보여준다. 한도를 주도하는 요소가 무엇인지 — 어디서 새는지 한눈에.

/usage는 현재 세션 비용과 플랜 한도를 보여주던 명령어다. 이번 개선으로 최근 사용량을 카테고리별로 쪼개서 보여준다. 막연히 “한도가 찼다”가 아니라, 무엇이 그 한도를 주로 썼는지가 드러난다.

이름도 정리됐다. “Extra usage”는 “usage credits”로, /extra-usage는 /usage-credits로 바뀌었다(옛 이름도 그대로 작동). /cost·/stats는 /usage의 별칭이다.
