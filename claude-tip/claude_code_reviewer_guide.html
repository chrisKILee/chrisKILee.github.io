Claude Code Reviewer 완전 가이드

Subagent, Skill, 그리고 context: fork 패턴까지 — 코드 리뷰 자동화의 모든 것.

난이도 · 중급 읽기 · 12분 업데이트 · 2026.04.26 대상 · Claude Code 사용자

1. Reviewer Agent란?

Claude Code에서 코드 리뷰를 자동화하는 방법은 크게 두 가지다: Subagent와 Skill. 이 두 개념의 차이를 이해하는 것이 좋은 리뷰어를 설계하는 출발점이다.

핵심 한 줄 요약

  • Skill = "레시피" — Claude에게 어떻게 할지를 가르치는 것
  • Subagent = "전문가 동료" — Claude가 독립된 맥락에서 작업을 위임하는 대상
  • 최적 조합: Skill + context: fork — 재사용성과 컨텍스트 격리를 동시에

2. Subagent와 Skill의 차이

구분 Skill Subagent
위치 .claude/skills/ .claude/agents/
실행 맥락 메인 대화 안에서 실행 독립된 컨텍스트 윈도우
컨텍스트 공유 메인 히스토리 공유 메인 대화 상속 안 함
결과 반환 인라인으로 현재 대화에 반영 최종 결과만 메인으로 반환
툴 권한 메인 Claude 툴 그대로 별도 툴 권한 설정 가능
메모리 없음 memory: user로 유지 가능
병렬 실행 불가 여러 개 동시 실행 가능
사용 가능 범위 Claude Code + 앱 + API Claude Code 전용

언제 무엇을 쓸까?

Skill 선택 시

  • 반복적으로 쓰는 절차·컨벤션·스타일 가이드
  • 여러 agent·프로젝트에서 공통 참조해야 하는 지식
  • 빠르고 가벼운 단일 작업 (파일 변환, 데이터 조회)

Subagent 선택 시

  • 히스토리 없이 편견 없는 독립 리뷰가 필요할 때
  • 코드 탐색 등 컨텍스트를 많이 소모하는 작업
  • 병렬로 동시에 여러 작업을 처리할 때
  • 특정 툴만 허용해야 할 때 (리뷰어는 Read만)

3. Reviewer는 Skill이 더 적합한 이유

코드 리뷰 특성상 여러 프로젝트에서 동일한 방법론을 재사용해야 하고, 보안/품질/스타일 등 다양한 관점의 체크 기준을 공유해야 한다. 이는 Skill의 강점과 정확히 일치한다.

주의 · 컨텍스트 오염 단순 Skill로 실행하면 수십 번의 파일 읽기/grep 툴 호출이 메인 대화 컨텍스트를 오염시킨다. 이를 해결하는 것이 바로 context: fork 패턴이다.

4. Skill + context: fork 패턴

context: fork를 SKILL.md frontmatter에 설정하면, 메인 대화 안에서 인라인 실행하는 대신 독립된 sub-agent를 스폰한다. 모든 툴 호출이 격리된 환경에서 실행되고, 완료 시 최종 결과만 메인 대화로 반환된다.

중요한 뉘앙스 Skill이 agent를 "호출"하는 게 아니라, Skill이 "어떤 agent 환경에서 실행될지"를 지정하는 것이다.

세 가지 방식 비교

일반 Skill Skill + context:fork 순수 Subagent
컨텍스트 격리 ✗ 메인 오염 ✓ 격리됨 ✓ 격리됨
호출 방식 /skill 또는 자동 /skill 또는 자동 명시적 또는 자동
지식 재사용 ✓ 이식 가능 ✓ 이식 가능 ✗ agent 파일 종속
비용 없음 부모 캐시 재사용 → 저렴 Fresh 스폰 → 비쌈
메인 히스토리 상속 ✓ ✓ (fork이므로) ✗ 빈 컨텍스트

5. 실제 구현 예시

Reviewer Skill SKILL.md 전체 예시: 

---
name: code-review
description: Reviews code for quality, security, and best practices.
             Use after writing or modifying code, or before commits.
context: fork
agent: Explore
allowed-tools: Read, Glob, Grep, Bash(git *)
model: sonnet
---

# Code Review

코드 변경사항을 분석하고 리뷰를 제공합니다.

## 리뷰 범위 결정 (우선순위)
1. 인자가 있으면 해당 파일/경로 리뷰: $ARGUMENTS
2. feature 브랜치면 → `git diff main...HEAD`
3. staged 변경사항 → `git diff --staged`
4. 최근 커밋 → `git diff HEAD~1`

## 체크 항목
- **Critical**: 보안 취약점, 데이터 손실 위험, 인증 문제
- **Major**: 성능 문제, 에러 핸들링 누락, 안티패턴
- **Minor**: 네이밍, 가독성, 중복 코드

## 출력 형식
각 이슈마다:
1. 심각도 레벨 (Critical / Major / Minor)
2. 파일명 + 라인 번호
3. 문제 설명
4. 개선 코드 예시

마지막에 전체 요약: Ready to Merge / Needs Attention / Needs Work

agent: 필드 옵션

값용도
Explore읽기 전용 탐색 최적화 — 리뷰어에 적합
Plan계획 수립 및 아키텍처 설계
general-purpose기본값, 범용
커스텀 이름.claude/agents/에 정의한 custom subagent 지정 가능

6. Subagent 만드는 방법 (참고)

방법 1: /agents 명령어

1

Claude Code에서 /agents 실행

→ Library 탭 열기

2

Create new agent 선택

→ Personal (개인 ~/.claude/agents/) 또는 Project (.claude/agents/) 선택

3

Generate with Claude

→ 설명을 입력하면 Claude가 SKILL.md 내용을 자동 생성

방법 2: 파일 직접 작성

.claude/agents/code-reviewer.md

---
name: code-reviewer
description: Reviews code for quality, security vulnerabilities,
             and best practices. Use proactively after writing or
             modifying code.
tools: Read, Glob, Grep
model: sonnet
memory: user
---

You are a senior code reviewer. When invoked, analyze the code and provide:

1. **Critical Issues** - Security vulnerabilities, bugs
2. **Major Issues** - Performance, missing error handling
3. **Minor Issues** - Style, readability, naming
4. **Suggestions** - Best practices

For each issue: show the problematic code, explain why,
provide an improved version.

7. 권장 디렉토리 구조

.claude/
├── skills/
│   └── code-review/
│       └── SKILL.md        ← context: fork + agent: Explore
│                              (팀/개인 공통 리뷰 방법론)
└── agents/
    └── security-reviewer.md ← 보안 특화 리뷰가 추가로 필요한 경우
설계 원칙 Skill은 공유 전문 지식 라이브러리, Subagent는 그것을 실행하는 전문가다. 보안 리뷰 체크리스트처럼 여러 곳에서 참조해야 하는 기준은 Skill로 만들고, Subagent는 그 Skill을 불러와 적용하는 역할로 구성하는 것이 가장 이상적이다.

8. 사용 방법

# 명시적 호출
/code-review

# 특정 파일 지정
/code-review src/auth.ts

# 자연어로 호출
"최근 변경사항 코드 리뷰해줘"
"커밋 전에 code-review skill로 확인해줘"
자동 트리거 description 필드가 명확하면 Claude가 코드 수정 후 자동으로 리뷰를 트리거하기도 한다. 예: "Use after writing or modifying code, or before commits."

업그레이드 체크리스트

  • SKILL.md frontmatter에 context: fork 설정 완료
  • agent: Explore로 읽기 전용 최적화 적용
  • allowed-tools를 Read, Glob, Grep, Bash(git *)로 제한
  • description 필드에 자동 트리거 문구 포함
  • 팀 공통 체크 기준(Critical/Major/Minor) SKILL.md에 문서화

9. 결론 요약

목적권장 방식
코드 리뷰 방법론 공유Skill
컨텍스트 격리 + 메인 대화 보호Skill + context:fork
편견 없는 독립 리뷰 (히스토리 없이)Subagent
병렬 다각도 리뷰 (보안/성능/스타일)병렬 Subagent
여러 프로젝트 공통 기준 적용Skill (이식 가능)
리뷰어 최적 조합
Skill + context: fork + agent: Explore
+ allowed-tools: Read, Glob, Grep

재사용성, 컨텍스트 보호, 읽기 전용 안전성, 비용 효율을 모두 만족하는 가장 균형 잡힌 선택.

용어 사전

Skill .claude/skills/
Claude에게 "어떻게 할지"를 가르치는 레시피 문서. 여러 프로젝트·agent에서 재사용 가능.
Subagent .claude/agents/
독립된 컨텍스트 윈도우에서 실행되는 전문가 agent. 병렬 실행 가능, Claude Code 전용.
context: fork SKILL.md frontmatter
Skill을 메인 대화가 아닌 격리된 sub-agent 환경에서 실행. 메인 컨텍스트 오염 방지.
agent: Explore Skill frontmatter 옵션
읽기 전용 탐색에 최적화된 agent 타입. 코드 리뷰어에 권장.
allowed-tools 툴 권한 제한
Skill/Subagent가 사용할 수 있는 툴 목록. 리뷰어는 Read, Glob, Grep, Bash(git *) 권장.
memory: user Subagent 전용
대화 간 학습을 유지하는 메모리 타입. 리뷰 패턴을 점진적으로 학습 가능.
