Agent View — 멀티 세션 관리 가이드

모든 Claude 백그라운드 세션을 한 화면에서. 상태 확인, 인라인 응답, 세션 스위칭을 터미널 탭 없이 처리하는 방법.

상태 · Research Preview 최소 버전 · v2.1.139 업데이트 · 2026.05.11 플랜 · 유료 전 플랜

개요 — Agent View란?

Agent View는 Claude Code CLI에 추가된 멀티 세션 관리 대시보드다. claude agents 명령 하나로 현재 실행 중인 모든 백그라운드 세션의 상태를 한 화면에서 볼 수 있고, 세션에 직접 들어가지 않아도 인라인으로 응답하거나 결과를 확인할 수 있다.

배경 기존에는 여러 Claude 세션을 병렬로 실행하려면 터미널 탭이나 tmux 창을 직접 관리해야 했다. 어느 에이전트가 무엇을 하는지 머릿속으로 추적해야 했고, 입력 대기 중인 세션을 찾으려면 창마다 들어가봐야 했다. Agent View는 이 문제를 해결한다.

이 가이드를 끝내면 다음을 할 수 있다.

  • Agent View를 열고 모든 세션 상태를 한눈에 확인한다
  • 새 세션을 백그라운드로 디스패치한다
  • Peek 패널로 세션에 들어가지 않고 인라인 응답한다
  • CLI 명령어로 세션을 중지·재시작·삭제한다
  • 키보드 단축키로 세션을 빠르게 전환한다

버전 업데이트 필수 claude update로 최신 버전으로 업데이트한다. Bedrock, Vertex AI, Foundry 연결 환경에서는 이전 버전에서 Agent View가 지원되지 않을 수 있다.
쿼터 소비 주의 백그라운드 세션은 인터랙티브 세션과 동일하게 구독 쿼터를 소비한다. 10개 에이전트를 동시에 실행하면 쿼터 소비도 약 10배가 된다.

Agent View 열기

두 가지 진입 방법이 있다.

1

터미널에서 직접 실행

claude agents
2

기존 세션에서 Agent View로 이동

빈 프롬프트에서 ← 화살표 키를 누른다. 현재 세션은 백그라운드로 전환된다.

TIP Agent View를 닫거나 터미널을 종료해도 백그라운드 세션은 계속 실행된다. Supervisor 프로세스가 세션을 별도로 관리하기 때문이다.

세션 테이블 & 상태

Agent View의 중앙은 세션 테이블이다. 세션은 상태별로 그룹핑되어 표시된다.

세션 상태 종류

상태배지의미
Working working Claude가 도구를 실행하거나 응답을 생성하는 중
Needs Input needs input Claude가 질문이나 권한 결정을 기다리는 중
Idle idle 다음 프롬프트 대기 상태
Completed completed 작업이 성공적으로 완료됨
Failed failed 에러로 종료됨
Stopped stopped Ctrl+X 또는 claude stop으로 중지됨

세션 아이콘 (프로세스 상태)

색상과 별개로, 아이콘 모양이 프로세스 실행 여부를 나타낸다.

아이콘의미
✻ / ✽프로세스 살아있음 (실행 중)
∙프로세스 종료 — claude respawn으로 재시작 가능
✢/loop 세션 — 다음 실행까지 카운트다운 표시

Peek 패널 & 인라인 응답

Peek 패널은 Agent View의 핵심 기능이다. 세션에 직접 연결하지 않고도 마지막 출력을 미리보고 바로 응답할 수 있다.

1

Space — Peek 패널 열기/닫기

선택된 세션의 마지막 출력 또는 Claude의 질문이 패널에 표시된다.

2

패널에서 바로 타이핑 → Enter

텍스트를 입력하면 해당 세션으로 응답이 전송된다. 전체 트랜스크립트 화면으로 이동할 필요 없다.

3

객관식 질문 처리

Claude가 선택지를 제시한 경우, 숫자 키로 선택하거나 Tab으로 추천 답변을 자동완성한다.

4

!로 시작 — Bash 명령 전송

Peek 패널 입력창에서 !로 시작하면 해당 세션에 Bash 명령으로 전송된다.

권장 흐름 여러 세션을 병렬로 돌릴 때, Agent View에 머물면서 ↑↓로 행을 이동하고 Space로 Peek → 응답 → Space로 닫기를 반복하면 된다. 각 세션에 들어갈 필요가 없다.

PR 상태 표시

세션이 PR을 열면 행 우측에 색상 점이 표시된다.

PR 상태 → 검토 대기 / CI 실패 CI 통과 머지됨 드래프트 / 클로즈

행 요약 (AI 자동 생성)

각 세션 행에 표시되는 요약 텍스트는 Haiku 클래스 모델이 자동으로 생성한다. 세션이 실행 중일 때 15초마다, 각 턴이 끝날 때마다 한 번 갱신된다. 일반 API 비용과 동일하게 과금된다.

세션 디스패치

백그라운드 세션을 시작하는 방법은 세 가지다.

Agent View 입력창에서 직접 디스패치

하단 입력창에 프롬프트를 입력하고 Enter를 누르면 새 백그라운드 세션이 시작된다.

CLI에서 직접 디스패치

# 기본 백그라운드 세션
claude --bg "플레키 테스트 원인 조사해줘"

# 특정 서브에이전트로 실행
claude --agent code-reviewer --bg "PR #1234 리뷰 댓글 반영해줘"

현재 세션을 백그라운드로 전환

# 현재 세션을 백그라운드로 (Agent View로 복귀)
/bg

# 추가 지시와 함께 전환
/bg 테스트 스위트 돌리고 실패 수정해줘

CLI 명령어

명령어동작
claude agentsAgent View 열기
claude attach <id>특정 세션에 인터랙티브 모드로 연결
claude logs <id>세션의 최근 출력 확인
claude stop <id>세션 중지
claude respawn <id>중지된 세션 재시작
claude respawn --all모든 중지 세션 재시작 (머신 재시작 후 복구)
claude rm <id>세션을 목록에서 삭제
세션 지속성 머신이 슬립/종료되면 세션이 중단된다. 재시작 후 claude respawn --all로 모든 세션을 복구할 수 있다. 트랜스크립트와 상태는 ~/.claude/jobs/<id>/에 디스크로 보존된다.

키보드 단축키

Agent View에서 모든 작업은 키보드로 처리할 수 있다. ?를 누르면 전체 단축키 목록이 표시된다.

내비게이션

행 이동 ↑↓
세션에 연결 Enter 또는 →
Agent View로 복귀 (세션 유지) ← (빈 프롬프트)
디스패치 후 즉시 연결 Shift+Enter
1~9번 세션에 즉시 연결 Alt+1~9
그룹 기준 전환 (상태 ↔ 디렉토리) Ctrl+S

Peek & 응답

Peek 패널 열기/닫기 Space
Peek에서 응답 전송 타이핑 + Enter
추천 답변 자동완성 Tab
Bash 명령 전송 !로 시작

세션 관리

세션 핀/언핀 Ctrl+T
세션 이름 변경 Ctrl+R
세션 중지 (2초 내 재입력 시 삭제) Ctrl+X
$EDITOR에서 프롬프트 편집 Ctrl+G
전체 단축키 보기 ?

필터 & 검색

디스패치 입력창에서 필터 접두사를 사용하면 특정 세션만 표시할 수 있다.

필터의미
a:<name>특정 서브에이전트가 실행 중인 세션
s:workingworking 상태인 세션만
s:blocked입력 대기 중인 세션만
#1234 또는 PR URL해당 PR을 담당하는 세션

실전 활용 시나리오

시나리오 01
병렬 작업 디스패치
버그 수정, PR 리뷰 댓글 반영, 플레키 테스트 원인 조사를 동시에 실행한다. claude --bg 3번으로 세션을 디스패치하고, Agent View에서 완료 순서대로 확인한다. 각 작업마다 터미널 탭을 열 필요가 없다.
시나리오 02
빠른 스위칭 루프
세션 A를 백그라운드로 두고 ←로 Agent View 복귀 → 세션 B 결과 Space로 Peek → 인라인 응답 → Space로 닫기 → 세션 C 핀업. 흐름이 끊기지 않는다.
시나리오 03
장기 실행 루프 에이전트
/loop로 실행한 PR babysitter나 대시보드 업데이터를 백그라운드로 두면 ✢ 아이콘과 함께 다음 실행까지 카운트다운이 표시된다. 머신을 켜둔 동안 자동으로 반복된다.
시나리오 04
여러 저장소 병렬 작업
서로 다른 git 저장소에서 실행된 세션들이 하나의 Agent View에 모인다. Ctrl+S로 그룹 기준을 디렉토리로 바꾸면 저장소별로 세션이 묶여 표시된다.
시나리오 05
PR 상태 실시간 추적
에이전트가 PR을 열면 행 우측에 색상 점이 생긴다. CI가 통과하면 초록, 실패하면 노랑으로 바뀐다. PR URL을 필터창에 입력하면 해당 PR을 담당하는 세션을 즉시 찾을 수 있다.

파일 격리 구조 (git worktree)

백그라운드 세션이 파일을 편집하기 전, Claude Code는 자동으로 .claude/worktrees/ 아래에 별도의 git worktree를 생성한다. 이를 통해 병렬로 실행되는 세션들이 서로의 파일 작업에 충돌하지 않는다.

비 git 저장소 git 저장소가 아닌 디렉토리에서는 파일 격리 없이 직접 쓰기가 일어난다. 병렬 세션 간 파일 충돌이 발생할 수 있으므로 주의가 필요하다.

트러블슈팅

Agent View가 보이지 않는다
claude --version으로 v2.1.139 이상인지 확인. 구버전이면 claude update로 업데이트. disableAgentView: true 설정이나 CLAUDE_CODE_DISABLE_AGENT_VIEW 환경변수가 설정되어 있지 않은지 확인.
머신 재시작 후 세션이 사라졌다
claude respawn --all로 복구. 트랜스크립트는 ~/.claude/jobs/<id>/에 보존되어 있다.
세션이 needs input인데 Peek 패널이 열리지 않는다
Space를 누른 후 Peek 패널이 열리면 타이핑으로 응답. Bedrock/Vertex AI 환경에서는 버전에 따라 일부 기능이 제한될 수 있다.
쿼터가 빠르게 소진된다
백그라운드 세션은 각각 독립적으로 쿼터를 소비한다. 동시 세션 수를 줄이거나, 완료된 세션은 claude rm <id>로 정리.
Agent View를 완전히 비활성화하고 싶다
Claude Code 설정에서 disableAgentView: true를 추가하거나 환경변수 CLAUDE_CODE_DISABLE_AGENT_VIEW=1을 설정.
