/grill-me & /grill-with-docs
완전 가이드

집요하게 용어 맞추고 구현 방향 파고드는 것 — 원래 구현 잘하는 개발자들이 하던 거, 그걸 그대로 해주는 Claude Code 스킬 2개.

출처 · mattpocock/skills 읽기 · 10분 업데이트 · 2026.05.27 라이선스 · MIT

이 스킬이 하는 것

Claude Code에서 /grill-me나 /grill-with-docs를 입력하면, Claude가 당신의 계획이나 설계에 대해 한 번에 하나씩 집요하게 질문을 던집니다. 단순한 인터뷰가 아닙니다 — 결정 트리의 모든 분기를 하나씩 해결할 때까지 멈추지 않습니다.

한 줄 요약

/grill-me → 계획을 집요하게 검증 (빈 프로젝트, ~45분)
/grill-with-docs → 기존 CONTEXT.md·ADR 기준으로 용어와 설계를 정렬 (~10-20분)

  • 한 번에 질문 하나씩, 항상 추천 답변을 먼저 제시
  • 코드베이스를 직접 탐색해서 불필요한 질문 제거
  • 공유된 이해(shared understanding)에 도달할 때까지 계속
  • grill-with-docs는 결론을 CONTEXT.md·ADR에 즉시 반영

개발자의 방식 그대로

구현 잘하는 시니어 개발자는 코딩 전에 꼭 하는 게 있습니다. 용어 정의, 범위 확인, 엣지케이스 탐색 — 아직 아무것도 없는 단계에서 질문을 쏟아내며 모호함을 제거합니다.

/grill-me는 Frederick P. Brooks의 "The Design of Design"에서 영감을 받았으며, 전통적인 러버 덕킹(rubber ducking)의 AI 버전입니다. 개발자가 아이디어를 대화로 풀어나가는 과정을 Claude가 체계적으로 진행합니다.

01/grill-me — 무엇인가

계획의 모든 측면에 대해 공유된 이해에 도달할 때까지 결정 트리의 각 분기를 하나씩 해결하는 스킬입니다. 브레인스토밍이 아닙니다 — 아이디어를 스트레스 테스트하는 것입니다.

스킬 핵심 지침 (원문 기반) Interview the user relentlessly about every aspect of a plan until reaching shared understanding. Walk down each branch of the design tree resolving dependencies one-by-one. Provide your recommended answer for each question. Ask the questions one at a time.

작동 원리

1

한 번에 하나의 질문

여러 질문을 한꺼번에 던지지 않습니다. 응답을 받고, 다음 질문으로 넘어갑니다.

2

항상 추천 답변 먼저

각 질문에 Claude가 먼저 권장 답변을 제시합니다. 동의하면 그냥 넘어가면 됩니다. 세션 속도가 2배 빨라집니다.

3

코드베이스 직접 탐색

기존 프로젝트라면 코드를 읽어서 답할 수 있는 질문은 스스로 해결합니다. 불필요한 질문이 줄어듭니다.

4

결정 트리 완전 탐색

모든 분기가 해결될 때까지 멈추지 않습니다. 세션이 끝나면 구현 가능한 수준의 명세가 완성됩니다.

실제 대화 예시 — 로그인 기능 설계

나
/grill-me 로그인 기능을 추가하려고 해
Claude
좋아요. 먼저 인증 방식부터 정해봅시다.

Q1. 어떤 인증 방식을 사용할 건가요?

저의 추천: 이메일 + 비밀번호 (가장 보편적이고 구현이 명확합니다)
대안: 소셜 로그인(Google/GitHub), 매직 링크, SSO
나
추천대로 이메일 + 비밀번호
Claude
Q2. 세션 관리는 어떻게 할 건가요?

저의 추천: JWT + Refresh Token (stateless, 모바일 확장성 좋음)
대안: 서버 세션(Redis), 쿠키 기반 세션
나
JWT로 가자
Claude
Q3. Refresh Token의 유효기간은?

저의 추천: Access Token 15분, Refresh Token 30일
— 보안과 UX의 균형. Refresh Token은 DB에 저장하고 단 한 번만 사용 가능하게 처리합니다.

이런 방식으로 계속 진행하며, 약 45분 후엔 구현에 바로 들어갈 수 있는 명세가 완성됩니다.

02/grill-with-docs — 무엇인가

/grill-me의 확장판입니다. 순수 대화가 아니라 프로젝트의 기존 도메인 모델과 대조하며 검증합니다. CONTEXT.md, ADR, 용어집을 기준으로 계획의 모순·충돌·누락을 찾아냅니다.

핵심 가치 세션이 끝나면 대화 결과가 사라지지 않습니다. 결정된 용어·설계가 즉시 CONTEXT.md와 ADR에 반영됩니다. 문서 갱신 부작용이 계획 자체보다 더 가치있는 경우가 많습니다.

CONTEXT.md 기반 검증 흐름

1

CONTEXT.md 색인화

프로젝트의 용어집(ubiquitous language)을 먼저 읽고 기존 정의를 파악합니다.

2

용어 충돌 즉시 감지

사용자가 쓴 단어가 CONTEXT.md의 기존 정의와 다를 경우 바로 지적합니다.
"CONTEXT.md에서 '취소'를 X로 정의했지만, 당신은 Y를 의미하는 것 같습니다 — 어느 것이 맞나요?"

3

실시간 문서 갱신

각 결정이 내려지는 즉시 CONTEXT.md에 반영합니다. 배치 처리 없이 실시간입니다.

4

ADR 자동 생성

결정이 어렵게 되돌릴 수 없고 진정한 트레이드오프가 있을 때만 ADR을 작성합니다. 사소한 결정은 ADR 없이 넘어갑니다.

실제 대화 예시 — "Pitch" 기능 추가

나
/grill-with-docs Pitch 기능을 추가하려고 해. 비디오에 여러 제목/설명을 붙이는 기능이야.
Claude
CONTEXT.md를 확인했습니다. 이미 StandaloneVideo가 정의되어 있네요.

Q1. Pitch와 StandaloneVideo의 관계는 무엇인가요?

저의 추천: Pitch는 StandaloneVideo의 대체 프레이밍 (1:N 관계, 한 Video → 여러 Pitch)
— 이 경우 Pitch는 Video를 소유하지 않고 참조합니다.
나
맞아, 추천대로
Claude
[CONTEXT.md 즉시 업데이트]
Pitch: StandaloneVideo의 대체 프레이밍. 1:N 관계.

Q2. Pitch를 삭제하면 원본 Video도 삭제되나요?

저의 추천: 아니오, 독립적 삭제 (Pitch는 Video의 view일 뿐, Video 자체가 아님)

세션이 끝나면 새로운 용어들이 CONTEXT.md에 정리되고, 중요한 결정들은 ADR로 문서화됩니다. 다음에 Claude에게 같은 개념을 설명할 필요가 없어집니다.

두 스킬 비교

⚡ /grill-me
  • 새 프로젝트, 빈 코드베이스에 최적
  • 순수 대화 기반 (문서 의존 없음)
  • 계획·아이디어 스트레스 테스트
  • 세션 약 45분
  • 결과를 직접 PRD 등으로 정리해야 함
📄 /grill-with-docs
  • 기존 코드베이스에 기능 추가 시 최적
  • CONTEXT.md·ADR 기반 검증
  • 용어 충돌 자동 감지 및 정렬
  • 세션 약 10-20분
  • 문서 갱신이 자동으로 이루어짐
특성/grill-me/grill-with-docs
주요 목적계획 추상적 검증기존 도메인 모델과 정렬
사용 시점Greenfield, 프로토타입기존 코드베이스 있을 때
문서 부작용없음CONTEXT.md·ADR 자동 갱신
세션 길이~45분~10-20분
용어 충돌 감지없음자동 감지
추천 상황탐색적 설계기능 확장·리팩토링
선택 기준 코드베이스가 없다면 → /grill-me
기존 코드베이스에 기능을 추가한다면 → /grill-with-docs

설치 방법

방법 A — npx로 자동 설치 (권장)

bash 
# /grill-me만 설치
npx skills add mattpocock/skills --skill grill-me

# /grill-with-docs만 설치
npx skills add mattpocock/skills --skill grill-with-docs

# 둘 다 설치
npx skills add mattpocock/skills --skill grill-me --skill grill-with-docs

Claude Code 다음 세션에서 자동으로 슬래시 명령어로 인식됩니다.

방법 B — 수동 설치

bash (macOS / Linux / WSL) 
# 스킬 디렉토리 생성
mkdir -p ~/.claude/skills/grill-me
mkdir -p ~/.claude/skills/grill-with-docs

# GitHub에서 SKILL.md 직접 다운로드
curl -o ~/.claude/skills/grill-me/SKILL.md \
  https://raw.githubusercontent.com/mattpocock/skills/main/grill-me/SKILL.md

curl -o ~/.claude/skills/grill-with-docs/SKILL.md \
  https://raw.githubusercontent.com/mattpocock/skills/main/grill-with-docs/SKILL.md

grill-with-docs를 위한 CONTEXT.md 설정

/grill-with-docs는 프로젝트 루트의 CONTEXT.md를 읽습니다. 없으면 빈 파일로 시작해도 됩니다.

CONTEXT.md 예시 
# 도메인 용어집

## User
- 서비스에 가입한 계정. 미가입자는 Visitor.

## Order
- 결제 완료된 구매 건. 결제 전은 Cart.
- 상태: pending → confirmed → shipped → delivered

## Product
- 판매 가능 상태의 상품. 판매 중단된 것은 ArchivedProduct.

## ADR 목록
- ADR-001: JWT 기반 인증 선택 (vs 서버 세션)

흔한 실수 6가지

공식 가이드(aihero.dev) 기반입니다.

#실수해결
1 고충실도 질문 그릴링
폼 필드 레이아웃, 색상 같은 프로토타입 수준 결정을 grilling		 설계·아키텍처 수준 결정에만 사용. UI 세부사항은 구현 후 조정
2 너무 큰 범위
한 번에 시스템 전체를 grill하려는 시도		 기능 단위로 나눠서 진행. 컨텍스트 한계(~120k 토큰) 이내로
3 수동적 참여
인터뷰 당하듯 짧게만 답함		 대화처럼 적극 참여. 추가 맥락·의도를 자유롭게 공유
4 결과 보존 안 함
세션 후 /clear 또는 컨텍스트 초기화로 작업 내용 손실		 세션 결과를 PRD, CONTEXT.md, ADR로 저장 후 초기화
5 약한 모델 사용
계획 단계에서 빠른 작은 모델 선택		 설계 단계는 Opus/Sonnet 등 강한 모델이 필수. 품질 차이가 큼
6 순차 세션만 사용
하나씩만 진행해서 시간 낭비		 병렬 세션 활용 — 대안 A, 대안 B를 동시에 grill해서 비교

활용 팁

팁 1 — 추천 답변을 신뢰하라 Claude가 제시하는 추천 답변이 맞다면 그냥 "맞아" 또는 Enter. 모든 질문에 깊이 고민하지 않아도 됩니다. 세션이 2배 빨라집니다.
팁 2 — grill-with-docs는 먼저 CONTEXT.md 정리 CONTEXT.md에 기존 용어가 잘 정리되어 있을수록 충돌 감지 품질이 올라갑니다. 빈 파일로 시작해서 grill 세션으로 채워나가도 됩니다.
팁 3 — 세션 결과를 반드시 보존 grill-me 세션 후 결과를 CONTEXT.md 또는 별도 PRD 파일에 저장한 뒤 컨텍스트를 초기화하세요. 저장 없이 /clear하면 45분 작업이 사라집니다.
주의 — 브레인스토밍과 구별 /grill-me는 가능성을 열어두는 브레인스토밍이 아닙니다. 결정을 수렴하고 모호함을 제거하는 설계 검증 도구입니다. 아이디어를 탐색하고 싶다면 일반 대화를 먼저 하세요.
