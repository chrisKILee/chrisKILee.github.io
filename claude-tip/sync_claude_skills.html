CLAUDE CODE · DOTFILES · GIT

한 레포 + 한 심링크

머신마다 따로 노는 Claude Code 스킬과 규칙을, git 레포 하나와 심볼릭 링크 하나로 함께 버전 관리한다. 두 번째 머신에서는 clone하고 심링크만 다시 걸면 끝. 단, 양쪽에서 같은 스킬을 고치면 함정이 하나 있다.

git repo symlink merge -s ours
01 — 개념

표준 경로는 그대로, git은 실파일을 추적

~/.claude/skills를 git 레포로 만들고, 전역 ~/.claude/CLAUDE.md를 그 레포로 옮긴 뒤 심링크로 원래 자리에 되돌린다. Claude는 여전히 표준 경로를 읽고, git은 심링크 뒤의 진짜 파일을 추적한다. 그래서 규칙과 스킬이 한 버전으로 묶인다.

02 — 셋업

레포로 만들고 심링크로 되돌린다

처음 한 번만 설정하면 된다. 이후 두 번째 머신은 clone + 심링크가 전부다.

1
skills를 git 레포로 만들고 push
~/.claude/skills를 git 레포로 초기화해 GitHub로 올린다.
bash$
cd ~/.claude/skills
git init && git add -A && git commit -m "skills"
git remote add origin git@github.com:you/claude-skills.git
git push -u origin main
2
CLAUDE.md를 레포로 옮기고 심링크
전역 규칙 파일을 레포 안으로 옮긴 뒤, 원래 자리에 심링크를 건다.
bash$
mv ~/.claude/CLAUDE.md ~/.claude/skills/CLAUDE.md
ln -s ~/.claude/skills/CLAUDE.md ~/.claude/CLAUDE.md
3
두 번째 머신: clone + 심링크
새 머신에서는 레포를 clone하고 심링크만 다시 걸면 끝난다.
bash$
git clone git@github.com:you/claude-skills.git ~/.claude/skills
ln -s ~/.claude/skills/CLAUDE.md ~/.claude/CLAUDE.md
심링크 주의
네이티브 Windows는 심링크에 별도 권한이 필요하다(WSL2는 정상 동작). 머신마다 경로가 다르면 상대 경로 심링크를 쓰거나, clone 후 심링크를 다시 생성하는 절차를 둔다. 그래서 일부는 이를 "nightmare symlink"라 부른다.
03 — 함정

아무도 경고 안 해주는 그것

두 머신에서 같은 스킬을 각각 고치면, push는 거부되고 pull은 충돌을 던진다. 두 히스토리가 갈라졌고, git은 어느 쪽이 이겨야 하는지 스스로 판단하지 않는다.

04 — 해결

한 머신을 '진실의 원천'으로

진실의 원천으로 삼을 머신을 하나 고른다. 그 머신에서 아래를 실행하면, 그 머신의 내용을 유지한 채 다른 머신의 히스토리를 접어 넣고(유실 없음), 원격이 이 머신과 일치하게 된다.

bash · source-of-truth 머신$
git merge -s ours origin/main
git push
단 하나의 함정
-s ours 전략은 다른 머신의 충돌하는 편집을 결과에서 버린다. 그 편집은 히스토리에는 남지만 대체(superseded)된다. "이 머신이 이긴다"를 정말로 의도할 때만 쓴다.
왜 -s ours 인가
git merge -s ours는 결과 트리를 현재 머신 그대로 두면서, origin/main을 머지 커밋의 부모로 기록한다. 그래서 git이 더는 "갈라졌다"고 보지 않아 push가 통과한다. (참고: 충돌난 부분만 우리 쪽으로 해결하고 나머지는 가져오고 싶다면 -X ours는 다른 동작이다.)
