multica가 뭐야?

GitHub 소개 문구 그대로: "Your next 10 hires won't be human."
Linear(이슈 트래커)처럼 생긴 UI에 AI 에이전트를 1등 시민(first-class citizen)으로 통합한 플랫폼이다. 동료한테 이슈를 배정하듯 에이전트에게 태스크를 주고, 실시간으로 진행 상황을 보고, 완료된 작업이 팀 공유 스킬로 쌓인다.

지원하는 에이전트 CLI: Claude Code, OpenAI Codex, OpenClaw, OpenCode, Hermes(Nous Research)

✦

multica는 에이전트 자체를 만드는 프레임워크가 아니다. 기존 코딩 에이전트(Claude Code 등)를 팀 수준에서 관리·조율하는 운영 플랫폼이다.

핵심 기능 3가지

README에서 확인된 핵심 기능. 순서대로 "배정 → 추적 → 누적"이다.

📋

① 태스크 배정 (Agents as Teammates)

이슈 트래커에서 동료한테 배정하듯 에이전트에게 태스크를 넘긴다. 보드에 상태가 표시되고, 에이전트가 댓글을 달고, 블로커를 직접 보고한다.

확인됨
📡

② 실시간 진행 추적 (Real-time Progress)

WebSocket 기반 실시간 스트리밍. 에이전트가 지금 뭘 하고 있는지, 얼마나 됐는지 UI에서 바로 볼 수 있다.

확인됨
🧠

③ 재사용 스킬 누적 (Reusable Skills)

완료된 태스크(배포, 마이그레이션, 코드 리뷰 등)가 팀 공유 Skills로 저장된다. 다음 비슷한 태스크에서 재활용.

부분 확인
⚠️

③에 대한 뉘앙스 차이: "AI가 스스로 성장·학습한다"는 개념이 아니다. 완료된 작업의 해결 방식이 팀 공유 스킬 템플릿으로 저장되는 구조다. "팀의 역량이 누적된다"는 표현이 더 정확하다.

기능설명확인
Autonomous Execution 태스크 전체 라이프사이클 관리 (enqueue → claim → start → complete/fail) ✓
Unified Runtimes 로컬 데몬 + 클라우드 런타임 통합 대시보드, CLI 자동 탐지 ✓
Multi-Workspace 팀별 워크스페이스 격리, 독립적 에이전트·이슈·설정 ✓
Desktop App Electron 기반 데스크톱 앱 (apps/desktop/ 확인) ✓
CLI 도구 multica login, daemon start/stop, issue list/create 등 ✓
⚡

아키텍처

Next.js 프론트엔드 + Go 백엔드 + PostgreSQL(pgvector) 구조다. 에이전트 데몬은 사용자 머신에서 실행되고, 백엔드와 WebSocket으로 통신한다.

레이어기술
프론트엔드Next.js 16 (App Router) + shadcn/ui (Base UI 기반)
데스크톱Electron (electron-vite)
백엔드Go + Chi 라우터 + sqlc + gorilla/websocket
데이터베이스PostgreSQL 17 + pgvector 확장
상태 관리TanStack Query (서버) + Zustand (클라이언트)
모노레포pnpm workspaces + Turborepo
실시간WebSocket

설치 방법

공식 문서 기준. 두 가지 방식이 있다: 클라이언트만 설치하거나 서버까지 직접 운영하거나.

1

CLI 설치 (클라이언트)

Homebrew 또는 공식 설치 스크립트로 빠르게 설치한다.

macOS / Linux 
# Homebrew
brew install multica-ai/tap/multica

# 또는 설치 스크립트
curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
Windows (PowerShell) 
irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex
2

셀프호스팅 서버 포함 설치

데이터를 외부로 보내지 않고 자사 서버에 직접 운영한다. Docker + Docker Compose 필요.

self-hosting 
# 서버 포함 설치
curl -fsSL .../install.sh | bash -s -- --with-server

# 초기 설정
multica setup self-host

완료 후 http://localhost:3000 에서 웹 UI 접속. 개발 환경 로그인 코드: 888888

3

에이전트 데몬 연결 & 첫 태스크 배정

CLI로 로그인 후 데몬을 시작하면 에이전트가 multica 워크스페이스와 연결된다.

CLI 기본 명령어 
multica login          # 인증
multica daemon start   # 에이전트 데몬 시작
multica issue list     # 이슈 목록
multica issue create   # 새 태스크 배정
💡

셀프호스팅 가이드는 저장소 내 SELF_HOSTING.md 에서 확인. 요구 조건: Node.js v20+, pnpm v10.28+, Go v1.26+, Docker.

사실성 검증

커뮤니티에서 공유되는 multica 설명 5가지를 GitHub 소스 코드·README 기준으로 검증했다.

설명검증 결과비고
① AI 에이전트한테 할 일을 배정할 수 있다 확인됨 README "assign to an agent like you'd assign to a colleague" 명시. CLI multica issue create 존재.
② 진행 상황을 실시간으로 볼 수 있다 확인됨 README "real-time progress streaming via WebSocket" 명시. Go 백엔드에 gorilla/websocket 실제 사용.
③ AI가 일하면서 쌓은 노하우가 누적된다 부분 확인 Reusable Skills 기능으로 확인됨. 단, 에이전트 자체 학습·성장이 아니라 완료 태스크 → 팀 공유 스킬 저장 구조.
④ 오픈소스라 무료로 가져다 쓸 수 있다 조건부 확인 Apache 2.0 기반 수정 라이선스. 내부 팀 사용은 무료. 단, 제3자에게 SaaS 형태로 재판매 시 상업 라이선스 필요.
⑤ 내 서버에 설치해서 데이터를 외부에 안 보낼 수 있다 확인됨 SELF_HOSTING.md 가이드 존재, Docker Compose 기반 로컬 서버 구성 지원.

핵심 요약:
5가지 모두 기본적으로 사실에 부합한다. 다만 ③은 "AI 개인 성장"이 아닌 "팀 노하우 축적" 개념이고, ④는 내부 사용은 무료이지만 완전한 MIT 라이선스는 아닌 점에 주의.
